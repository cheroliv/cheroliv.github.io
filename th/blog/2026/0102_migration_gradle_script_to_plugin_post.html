บริบทและเป้าหมาย

จุดเริ่มต้น

โครงการ`slider-gradle`สร้างการนำเสนอ Reveal.js จากไฟล์ AsciiDoc ผ่านปลั๊กอิน Gradle`org.asciidoctor.jvm.revealjs`. การตั้งค่างานหลัก`asciidoctorRevealJs`อยู่โดยตรงในสคริปต์บิลด์ราก`build.gradle.kts`:

plugins { id("org.asciidoctor.jvm.revealjs") }

apply<slides.SlidesPlugin>()

project.tasks.getByName<AsciidoctorJRevealJSTask>(TASK_ASCIIDOCTOR_REVEALJS) {
    repositories { ruby { gems() } }
    revealjs {
        version = "3.1.0"
        templateGitHub {
            setOrganisation("hakimel")
            setRepository("reveal.js")
            setTag("3.9.1")
        }
    }
    revealjsOptions {
        // ... configuration complète
    }
}

เป้าหมาย

ย้ายการตั้งค่าทั้งหมดนี้เข้าไปใน`buildSrc/src/main/kotlin/slides/SlidesPlugin.kt`เพื่อให้สคริปต์การบิลด์ของผู้บริโภคลดลงเหลือเพียง :

apply<slides.SlidesPlugin>()

ปลั๊กอินต้องทำงานได้อย่างสมบูรณ์โดยไม่พึ่งพาอื่น ๆ : มันจะจัดการการพึ่งพาในปลั๊กอินของตัวเอง, ตั้งค่า repository ของมัน, และจัดการ gems ของ Ruby ของมัน.

อุปสรรคแรก : `ruby { gems() }

สิ่งที่ซ่อนอยู่ในน้ำตาลเชิงไวยากรณ์ของ Groovy

บรรทัด`repositories { ruby { gems() } }`เป็นส่วนขยาย DSL ของ Groovy ที่พร้อมใช้งานเฉพาะในบริบทการทำงานของ buildscript เท่านั้น. ไม่มีอยู่ในรูปแบบ API Kotlin แบบคงที่ที่สามารถเข้าถึงได้จาก buildSrc

ขณะพยายามที่จะโทรจาก`SlidesPlugin.kt`, การคอมไพล์ล้มเหลวทันที。

หลังจากการวิเคราะห์แคช Gradle (~/.gradle/caches/modules-2/files-2.1/rubygems/), พบว่าในไฟล์`ivy-3.1.0.xml`:

<artifact type='gem' url='https://rubygems.org/gems/asciidoctor-revealjs-3.1.0.gem' />

`ruby { gems() }`จริง ๆ แล้วกำลังดำเนินการอยู่สามขั้นตอนที่แยกต่างหาก(But might need something like just a newline. I’ll put no characters.)

  1. บันทึกรีโพซิทอรี Ivy ชี้ไปที่`https://rubygems.org/gems/`

  2. ยกเว้นกลุ่ม`rubygems`คลัง Maven เพื่อหลีกเลี่ยงความขัดแย้ง

  3. บันทึกอัญมณีในการกำหนดค่า`asciidoctorGems`pourให้ JRuby โหลดมันขณะรันไทม์

ความรับผิดชอบทั้งสามนี้ต้องถูกดำเนินการแยกกันใน Kotlin

วิธีแก้ในสามส่วน

ส่วนที่ 1 : คลัง Ivy สำหรับ Rubygems

project.repositories.mavenCentral() {
    content { excludeGroup("rubygems") }
}
project.repositories.ivy {
    url = project.uri("https://rubygems.org/gems/")
    patternLayout { artifact("[module]-[revision].gem") } (1)
    metadataSources { artifact() }
    content { includeGroup("rubygems") }
}

ส่วนขยาย`.gem`ต้องเป็นฮาร์ดโค้ด.[ext]`แก้โดยค่าเริ่มต้นใน.jar`, ซึ่งทำให้เกิดข้อผิดพลาด`Resource missing`.

คลัง Ivy ประกาศโดยตรงบน`project.repositories`และไม่อยู่ในบล็อก`repositories { }`เพราะตัวรับของบล็อกนี้ไม่ใช่`RepositoryHandler`มาตรฐานของ Gradle แต่มี API กรอลิฟันต์ที่ไม่เข้ากันกับส่วนขยาย`ivy`Kotlin DSL

ส่วนที่ 2 : ความพึ่งพา asciidoctorGems

ปลั๊กอิน`org.asciidoctor.jvm.gems`ต้องนำไปใช้เป็นอันดับแรก — มันสร้างการกำหนดค่า`asciidoctorGems`และงาน`asciidoctorGemsPrepare`(empty)

project.plugins.apply("org.asciidoctor.jvm.gems")
project.plugins.apply("org.asciidoctor.jvm.revealjs") (1)

project.dependencies {
    add("asciidoctorGems", "rubygems:asciidoctor-revealjs:3.1.0@gem") (2)
}

ลำดับการใช้งานเป็นสิ่งสำคัญ :`gems`ก่อน`revealjs`. ผู้ผ่านการคัดเลือก`@gem`บังคับให้ใช้ส่วนขยายที่ถูกต้องกับการพึ่งพา

ส่วนที่ 3 : settings.gradle.kts

`dependencyResolutionManagement`ใน`settings.gradle.kts`ต้องอนุญาตให้โครงการประกาศคลังของตัวเองได้ :

@Suppress("UnstableApiUsage")
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.PREFER_PROJECT)
}

หากไม่มีบรรทัดนี้ Gradle จะไม่สนใจคลังที่กำหนดไว้ในปลั๊กอิน และการแก้ไขอัญมณีจะล้มเหลว

การตรวจสอบ API ด้วยไบต์โค้ด

ทำไม javap ?

ปลั๊กอิน`asciidoctor-gradle-jvm-slides`อยู่ในเวอร์ชัน`4.0.0-alpha.1`. เอกสารของมันไม่มีอยู่หรือไม่สมบูรณ์. แหล่งข้อมูลที่เชื่อถือได้เพียงแหล่งเดียวคือการตรวจสอบโดยตรงของคลาสที่คอมไพล์แล้ว.

ลำดับชั้นของงาน

javap -p -classpath asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar \
  org.asciidoctor.gradle.jvm.slides.AsciidoctorJRevealJSTask

ผลลัพธ์ :

public class AsciidoctorJRevealJSTask
  extends org.asciidoctor.gradle.jvm.AbstractAsciidoctorTask
  implements org.asciidoctor.gradle.base.slides.SlidesToExportAware

การค้นพบ `forkOptions

ขณะตรวจสอบ`AbstractAsciidoctorTask`(No visible characters)

javap -p -classpath asciidoctor-gradle-jvm-4.0.0-alpha.1.jar \
  org.asciidoctor.gradle.jvm.AbstractAsciidoctorTask | grep -i "fork\|exec\|jvm"

พบว่า :

final org.ysb33r.grolifant.api.v4.JavaForkOptions javaForkOptions;
public void forkOptions(org.gradle.api.Action<org.ysb33r.grolifant.api.v4.JavaForkOptions>);
public static final org.asciidoctor.gradle.base.process.ProcessMode JAVA_EXEC;

API ของคลาส JavaForkOptions (โกรลิแฟนท์)

`javaLauncher`ไม่มีอยู่ในงานนี้. API จริงของ`org.ysb33r.grolifant.api.v4.JavaForkOptions`แสดง :

public void executable(java.lang.Object);  (1)
public void setExecutable(java.lang.Object);

วิธีการ`executable(Object)`แทนที่การมอบหมาย`executable = …​`lequelไม่คอมไพล์ (`val`ไม่สามารถกำหนดใหม่ได้).

การตั้งค่า toolchain Java

ปัญหาของ JavaToolchainService

`JavaToolchainService`นี่ไม่ใช่ส่วนขยายของโครงการ. การเรียกครั้งต่อไปล้มเหลว:

// ERREUR : Extension of type 'JavaToolchainService' does not exist
project.extensions.getByType<JavaToolchainService>()

API ที่ถูกต้องคือ`serviceOf` :

import org.gradle.kotlin.dsl.support.serviceOf

project.tasks.getByName<AsciidoctorJRevealJSTask>(TASK_ASCIIDOCTOR_REVEALJS) {
    setInProcess("JAVA_EXEC")
    forkOptions {
        executable(
            project.serviceOf<JavaToolchainService>()
                .launcherFor {
                    languageVersion.set(JavaLanguageVersion.of(17))
                    vendor.set(JvmVendorSpec.ADOPTIUM)
                }
                .get()
                .executablePath
                .asFile
                .absolutePath
        )
    }
}

การตรวจจับอัตโนมัติ Docker

บริบท

ปลั๊กอิน Asciidoctor/JRuby ต้องการ Java 17. Kotlin 2.0.x ใน buildSrc ไม่รองรับ Java 25 (ผู้ประมวลผลเวอร์ชันทำให้ระบบล่มบน)"25.0.2"). ดีม่อน Gradle จึงต้องทำงานบน Java 17 หรือต้องใช้ Docker

กลยุทธ์

  1. Docker พร้อมใช้งาน → การทำงานผ่านคอนเทนเนอร์`eclipse-temurin:17`(พฤติกรรมเริ่มต้น)

  2. ไม่พบ Docker + Java 17 → การทำงานในเครื่อง

  3. ไม่พบ Docker + Java > 17 → ข้อผิดพลาดที่ชัดเจน

val isDockerAvailable = try {
    Runtime.getRuntime().exec(arrayOf("docker", "info")).waitFor() == 0
} catch (e: Exception) {
    false
}

val javaVersion = JavaVersion.current().majorVersion.toInt()

when {
    isDockerAvailable -> project.tasks.register<Exec>(TASK_ASCIIDOCTOR_REVEALJS) {
        group = GROUP_TASK_SLIDER
        description = "Slider settings and generation (via Docker)"
        dependsOn(TASK_CLEAN_SLIDES_BUILD)
        finalizedBy(TASK_DASHBOARD_SLIDES_BUILD)
        commandLine(
            "docker", "run", "--rm",
            "-v", "${project.rootDir.absolutePath}:/workspace",
            "-v", "${System.getProperty("user.home")}/.gradle:/root/.gradle",
            "-w", "/workspace",
            "eclipse-temurin:17",
            "./gradlew", TASK_ASCIIDOCTOR_REVEALJS
        )
        workingDir = project.rootDir
    }
    javaVersion == 17 -> {
        project.repositories.mavenCentral() {
            content { excludeGroup("rubygems") }
        }
        project.repositories.ivy {
            url = project.uri("https://rubygems.org/gems/")
            patternLayout { artifact("[module]-[revision].gem") }
            metadataSources { artifact() }
            content { includeGroup("rubygems") }
        }
        project.extensions.getByType<RevealJSExtension>().apply {
            version = "3.1.0"
            templateGitHub {
                setOrganisation("hakimel")
                setRepository("reveal.js")
                setTag("3.9.1")
            }
        }
        project.tasks.getByName<AsciidoctorJRevealJSTask>(TASK_ASCIIDOCTOR_REVEALJS) {
            setInProcess("JAVA_EXEC")
            forkOptions {
                executable(
                    project.serviceOf<JavaToolchainService>()
                        .launcherFor {
                            languageVersion.set(JavaLanguageVersion.of(17))
                            vendor.set(JvmVendorSpec.ADOPTIUM)
                        }
                        .get()
                        .executablePath
                        .asFile
                        .absolutePath
                )
            }
            // ... reste de la configuration
        }
    }
    else -> error(
        "Docker est requis pour exécuter $TASK_ASCIIDOCTOR_REVEALJS " +
        "avec Java $javaVersion. Installez Docker ou utilisez Java 17."
    )
}

วิธีการตรวจสอบ: อ่าน API ที่ไม่รู้จักด้วย javap

หลักการ

เมื่อเอกสารไม่อยู่หรือไม่สมบูรณ์ บั๊ตโค้ดจะเป็นแหล่งความจริง javap`เป็นเครื่องมือมาตรฐานของ JDK ที่ดีคอมไพล์ไฟล์.class`ในลายเซ็นต์ Java ที่อ่านง่าย โดยไม่จำเป็นต้องมีซอร์สโค้ด

ขั้นตอนที่ 1 : ค้นหาไฟล์ JAR ในแคชของ Gradle

Gradle ดาวน์โหลดการพึ่งพาทั้งหมดของมันใน`~/.gradle/caches/modules-2/files-2.1/`. ขั้นตอนแรกคือการค้นหาไฟล์ JAR ที่มีคลาสที่จะตรวจสอบ:

find ~/.gradle/caches -name "asciidoctor-gradle-jvm-slides*.jar" 2>/dev/null
ผลลัพธ์ :
/home/user/.gradle/caches/modules-2/files-2.1/org.asciidoctor/
asciidoctor-gradle-jvm-slides/4.0.0-alpha.1/.../
asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar

ขั้นตอนที่ 2 : รายการคลาสของไฟล์ JAR

ก่อนที่จะตรวจสอบคลาส เราจะตรวจสอบว่าคลาสนั้นมีอยู่ในไฟล์ JAR อย่างแท้จริง :

jar tf asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar | grep -i "RevealJS\|revealjs"

ขั้นตอนที่ 3 : ตรวจสอบคลาส

สิ่งนี้เปิดเผยคลาสทั้งหมดที่มีอยู่ : AsciidoctorJRevealJSTask, RevealJSExtension, RevealJSOptions, ฯลฯ
javap -p -classpath asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar \
org.asciidoctor.gradle.jvm.slides.AsciidoctorJRevealJSTask

ตัวเลือก`-p`แสดงสมาชิกทั้งหมดรวมถึงสมาชิกส่วนตัว ผลลัพธ์แสดงบรรทัดสำคัญทันที:

public class AsciidoctorJRevealJSTask
extends org.asciidoctor.gradle.jvm.AbstractAsciidoctorTask

ขั้นตอนที่ 4: เลื่อนขึ้นตามลำดับชั้น

งานขยาย`AbstractAsciidoctorTask`. พวกเขาตรวจสอบมันตามลำดับ โดยเริ่มจากการค้นหาไฟล์ JAR ของมัน :

find ~/.gradle/caches -name "asciidoctor-gradle-jvm-[0-9]*.jar" 2>/dev/null

javap -p -classpath asciidoctor-gradle-jvm-4.0.0-alpha.1.jar \
org.asciidoctor.gradle.jvm.AbstractAsciidoctorTask | grep -i "fork\|exec\|jvm\|java"

ที่นั่นล่ะที่เราค้นพบ`forkOptions`, JAVA_EXEC, et javaForkOptions ของประเภท`org.ysb33r.grolifant.api.v4.JavaForkOptions`.

ขั้นตอนที่ 5 : ติดตามประเภทที่ไม่รู้จัก

`JavaForkOptions`เป็นคลาสกอลิฟานต์ที่ไม่รู้จัก. เราพบตำแหน่งของไฟล์ jar ของมัน :

find ~/.gradle/caches -name "grolifant*.jar" 2>/dev/null

จากนั้นเราตรวจสอบมัน :

javap -p -classpath grolifant40-legacy-api-2.0.0-alpha.6.jar \
org.ysb33r.grolifant.api.v4.JavaForkOptions

พบได้ที่นั่น`executable(java.lang.Object)— วิธีที่ถูกต้องที่จะเรียกใช้, ตรงข้ามกับ`executable = …​`ซึ่งไม่สามารถคอมไพล์ได้เนื่องจากเป็นคุณสมบัติ`val.

ขั้นตอนที่ 6: ตรวจสอบส่วนขยายของโครงการ

เพื่อ`revealjs { }`คำถามคือ: นี้เป็นวิธีทำงานไหม? หรือการขยายโครงการ? การตรวจสอบของ`AsciidoctorJRevealJSTask` ไม่แสดงวิธีการใดๆ`revealjs`แล้วตรวจสอบ`RevealJSExtension`Could you please provide the French text that needs to be translated into Thai?

javap -p -classpath asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar \
org.asciidoctor.gradle.jvm.slides.RevealJSExtension | head -5
public class RevealJSExtension implements groovy.lang.GroovyObject {
public static final java.lang.String NAME;

การมีอยู่ของ`NAME`ยืนยันว่านี่เป็นส่วนขยายที่ลงทะเบียนในโครงการ, เข้าถึงผ่าน`project.extensions.getByType<RevealJSExtension>()`.

ขั้นตอนถัดไป

ปลั๊กอิน buildSrc จะถูกแยกออกเป็นโครงการอิสระที่เผยแพร่บน Gradle Plugin Portal หรือ Maven Local. สคริปต์การสร้างของผู้บริโภคจะแล้วกลายเป็น :

plugins { id("slides") version "1.0.0" }

Et settings.gradle.kts`จะลดเหลือเพียงระดับต่ำสุดอย่างเคร่งครัดโดยไม่มีการอ้างอิงถึง`foojay-resolver-convention, การเตรียม JDK จะได้รับการจัดการโดยปลั๊กอินตัวมันเอง หรือมีการบันทึกเป็นเงื่อนไขเบื้องต้น.
