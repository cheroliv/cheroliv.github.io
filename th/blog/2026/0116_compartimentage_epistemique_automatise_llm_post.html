ปัญหา: คิดอย่างอิสระโดยไม่เผยแพร่สิ่งใดอย่างไม่เลือกสรร

เมื่อนักพัฒนาคนเดียวบันทึกกระบวนการคิดของตนเองด้วย LLM เขาก็เผชิญกับความย้อนแย้ง:

CAPTURE TOUT (Cercle 0, jardin secret)
  ├→ Brain dump libre, pas de censure
  ├→ Idées brutes, spéculations, intuitions non vérifiées
  ├→ Allers-retours LLM : challenger, itérer, raffiner
  └→ Le LLM voit TOUT — le bon, le flou, l'embryonnaire

PUBLICATION SÉLECTIVE (Cercle 4, blog public)
  ├→ Uniquement les décisions actées
  ├→ Uniquement les patterns testés (>100 tests PASS)
  ├→ Uniquement ce qui a de la valeur pour le lecteur
  └→ JAMAIS une spéculation présentée comme une vérité

ระหว่างสองสุดขั้วนี้ มีตัวกรอง. คำถามคือ: ใครเป็นคนทำ? มนุษย์ที่เหนื่อยล้าในช่วงท้ายเซสชัน? สคริปต์ regex แบบง่าย ๆ? หรือตัว LLM เอง ที่อ่านทุกอย่างไปแล้ว?

คำตอบของฉัน: LLM

แพตเทิร์น STIMULUS — เกิด, ตรึง, เจือจาง, ตาย

STIMULUS เป็นไฟล์`.adoc`ชั่วคราวที่รากของเวิร์กสเปซ (วงกลม 0) ชื่อของมันเป็นไปตามธรรมเนียมที่สื่อความหมาย —PICTURE_ME_ROLLIN.adoc, HOLD_MY_BEER.adoc, ONCE_UPON_A_TIME.adoc— ซึ่งบันทึกเจตนาแห่งการสำรวจของช่วงเวลานั้น

วงจรชีวิตของมันโหดร้าย:

CRÉATION (Cercle 0)
  ├→ Fichier vide, brain dump libre
  ├→ Allers-retours LLM ← → développeur
  └→ Aucune pression de structure ou de publication

MATURATION
  ├→ Le contenu se densifie
  ├→ Des sections émergent naturellement
  └→ Le fichier devient une référence informelle de session

CLASSIFICATION ÉPISTÉMIQUE ← FAIT PAR LE LLM
  ├→ VISION    → publiable, diluer dans les docs publics + blog
  ├→ OPINION   → confiner au Cercle 0, pas de dilution externe
  └→ STRATÉGIE → dilution restreinte (docs racine, PAS de blog)

DILUTION (Cascade vers Cercles légitimes)
  ├→ VISION → WORKSPACE_AS_PRODUCT.adoc + WHAT_THE_GAMES.adoc + blog
  ├→ STRATÉGIE → WORKSPACE_AS_PRODUCT.adoc (section business)
  └→ OPINION → reste dans le stimulus, ne bouge pas

ARCHIVAGE + SUPPRESSION
  ├→ Snapshot dans configuration/vision-archive/ (trace historique)
  └→ rm du stimulus — il a fini son travail

สิ่งกระตุ้นที่อยู่รอดได้เกิน 2 เซสชันโดยไม่มีการเจือจางถือเป็นแอนติแพตเทิร์น ไม่ว่าข้อมูลจะสำคัญเกินกว่าจะปล่อยให้เน่าอยู่ในไฟล์ชั่วคราว (→ เจือจาง) หรือคลุมเครือเกินกว่าจะคู่ควรกับการมีอยู่ (→ ลบ)

การมอบหมายให้ LLM: ทำไม LLM จึงเป็นผู้กรอง

ฉันไม่ฮาร์ดโค้ดการจำแนกประเภท Vision/Opinion ใน Kotlin ฉันฉีดมันเข้าไปในพรอมต์ระบบของ LLM ผ่าน`AGENT_GOVERNANCE.adoc`No source text was provided to translate.

----
Pour chaque dilution de stimulus ou session, tu es responsable de classifier
le contenu :
- VISION : décision architecturale actée, pattern testé en production (>100 tests PASS),
  décision documentée dans BACKLOG ou ROADMAP
- OPINION : spéculation, hypothèse non validée par des tests, intuition
  sans ancrage expérimental
- STRATEGIE : positionnement business, pricing, marché cible

Règles :
- Si OPINION, le contenu reste confiné dans son cercle d'origine
- Si VISION, tu procèdes à la dilution dans les documents racine
- Si STRATEGIE, dilution restreinte (docs racine, pas de blog public)
- Cette classification détermine aussi si un article de blog est publiable
  sur cheroliv.com
----

LLM อ่านคำสั่งนี้**ก่อน**ในการประมวลผลเซสชัน มันอยู่ในบริบทโดยตรงของมัน ไม่ใช่ในไฟล์แยกต่างหาก นี่คือ *วิศวกรรมพรอมต์แบบดีเทอร์มินิสติก*: พฤติกรรมเกิดขึ้นจากข้อความที่ถูกฉีดเข้าไป ไม่ใช่จากตัวจำแนกประเภทภายนอก

=== ทำไมมันถึงได้ผล — และทำไมมันจึงขัดกับสัญชาตญาณ

ปฏิกิริยามาตรฐาน: “คุณมอบการจำแนกประเภทให้ AI งั้นหรือ? แล้วถ้ามันผิดพลาดล่ะ?”

คำตอบ: มนุษย์ก็ไม่ได้ทำได้ดีกว่าในช่วงตีสอง ความแตกต่างคือ LLM นั้นอ่านทุกอย่าง มันมีบริบทที่สมบูรณ์ของเซสชันและเอกสารเป้าหมาย มันรู้ว่า`VPS ECO-16 12€ HT`เป็นการตัดสินใจด้านโครงสร้างพื้นฐาน (VISION) ในขณะที่`« le TTS ElevenLabs sonne plus naturel que Coqui »`เป็นความคิดเห็นที่ยังไม่ได้รับการตรวจสอบโดย benchmark

มนุษย์ในช่วงท้ายของเซสชันจะอ่านแบบผ่านๆ และทำเท่าที่ทำได้ ส่วน LLM อ่านอย่างละเอียดถี่ถ้วนและใช้เกณฑ์อย่างเป็นระบบ ผลลัพธ์คือ**น่าเชื่อถือกว่า**, ไม่น้อย

และสำหรับ 20% ของกรณีที่กำกวม — พื้นที่สีเทาที่แม้แต่ LLM เองก็ยังลังเล — คำตอบไม่ใช่ «การเพิ่มโค้ด» คำตอบคือ**LangGraph4j**(EPIC 13): กราฟสถานะที่สำหรับกรณีกำกวม จะเปิดใช้งานโหนด Human-in-the-Loop และส่งต่อให้มนุษย์ตัดสินใจ แต่สำหรับ 80% ของกรณีที่ชัดเจน LLM ก็เพียงพอ

== ไปป์ไลน์ครบวงจร: จาก Brain Dump สู่ Blog Post

นี่คือโฟลว์ทั้งหมด — จากไอเดียดิบไปจนถึงบทความที่เผยแพร่ — โดยมี LLM เป็นตัวกรองเพียงตัวเดียว:

[source]
----
CERCLE 0 (jardin secret)
  PICTURE_ME_ROLLIN.adoc   ← brain dump, allers-retours LLM
       ↓
  [LLM classifie] → VISION / OPINION / STRATÉGIE
       ↓
  VISION → dilution dans WORKSPACE_AS_PRODUCT.adoc
         → dilution dans WHAT_THE_GAMES_BEEN_MISSING.adoc
         → dilution dans WORKSPACE_VISION.adoc (session context)
         → RÉDACTION ARTICLE BLOG ← le LLM écrit, pas le dev
       ↓
CERCLE 4 (blog public)
  0116_compartimentage_epistemique.adoc  ← publié sur cheroliv.com
       ↓
  ./gradlew deploy (bakery-gradle → JBake → JGit → GitHub Pages)
       ↓
  https://cheroliv.com/blog/2026/0116/  ← live
----

นักพัฒนาไม่ได้เขียนบทความ เขาตั้งคำถาม อ่านทบทวน และตรวจรับ LLM เป็นผู้เขียน วงจรคือ:

1. ระบายความคิดแบบอิสระ → ไม่มีการเซ็นเซอร์
2. การจำแนกเชิงญาณวิทยาโดย LLM → ไม่มีการรั่วไหล
3. การเขียนโดย LLM → ไม่ผัดวันประกันพรุ่ง
4. การตรวจทานโดยมนุษย์ → ไม่มีข้อผิดพลาด

คอขวดในอดีต — «ฉันไม่มีเวลาเขียน» — ถูกขจัดออกไปแล้ว LLM ทำงานส่วนใหญ่ มนุษย์ทำสิ่งที่มนุษย์เท่านั้นทำได้: ตัดสิน

== บทสรุป: เสรีภาพในการคิดโดยปราศจากความกลัวในการเผยแพร่

การแบ่งแยกองค์ความรู้อัตโนมัติไม่ใช่เครื่องมือเซ็นเซอร์ มันเป็น**ผู้ปลดปล่อย**. มันช่วยให้คิดได้อย่างอิสระ คาดเดาได้โดยไม่มีตัวกรอง ระบายทุกสิ่งที่ผ่านเข้ามาในหัวออกมาให้หมด — โดยไม่ต้องกลัวเลยว่าความคิดที่ยังไม่เป็นรูปเป็นร่างจะหลุดไปอยู่บนบล็อก

LLM คือผู้พิทักษ์พรมแดนนี้ มันอ่านทุกสิ่ง มันจำแนกประเภท มันเจือจางสิ่งที่สมควรอยู่รอด มันกักเก็บสิ่งที่ต้องคงเป็นส่วนตัว มันเขียนสิ่งที่เผยแพร่ได้

และนักพัฒนาก็เป็นผู้มีคำพูดสุดท้าย: อ่านทบทวน ท้าทาย ตรวจสอบยืนยัน ตัดสิน

นี่คือการแบ่งงานที่นักพัฒนาที่ทำงานคนเดียวขาดไป: พนักงานสังเคราะห์ที่จัดการงานเอกสารในหัวให้ เพื่อให้มนุษย์โฟกัสกับสิ่งที่ทำได้ดีที่สุด — การออกแบบ การวางสถาปัตยกรรม การตัดสินใจ
