ปรับปรุงการจัดการงานของ Gradle ด้วย Kotlin DSL และ buildSrc

การทำให้งานสร้างอัตโนมัติเป็นสิ่งสำคัญสำหรับทุกโครงการซอฟต์แวร์ และ Gradle ด้วย DSL ของ Kotlin ให้ความยืดหยุ่นที่ยอดเยี่ยม ระหว่างการพูดคุยของเรา เราได้สำรวจวิธีการรวมและใช้ตรรกะการสร้างซ้ำ ๆ โดยเฉพาะสำหรับรายงานการทดสอบโดยการใช้ประโยชน์จากทุกโครงการ, buildSrc, และงานที่กำหนดเองใน Kotlin

รวมศูนย์การตั้งค่าด้วย allprojects และ `subprojects

บล็อก`allprojects` et `subprojects`ในของคุณ`build.gradle.kts`รากของโครงการมีความสำคัญอย่างยิ่งต่อการนำการตั้งค่าทั่วไปมาใช้กับโครงการแบบหลายโมดูลของคุณ

*allprojects { …​ }: นำการตั้งค่าไปใช้กับโครงการรากและโครงการย่อยทั้งหมดของมัน. เหมาะสำหรับการกำหนดหนึ่ง`group`, หนึ่ง`version`, หรือ บาง`repositories`ทั่วไป. *subprojects { …​ }`ใช้การตั้งค่าเฉพาะกับโครงการย่อย, ไม่รวมโครงการราก. เหมาะสมสำหรับนำไปใช้ปลั๊กอินเฉพาะของโมดูล (เช่น`java ou kotlin-jvm) หรือการพึ่งพาที่ใช้ร่วมกันในไลบรารีของคุณ.

ต่อไปนี้คือตัวอย่างที่แสดงเป็นอุทาหรณ์ :

// build.gradle.kts (projet racine)
plugins {
    base // Appliqué au projet racine
}

allprojects {
    group = "com.example"
    version = "1.0.0"

    repositories {
        mavenCentral()
    }

    tasks.withType<org.gradle.api.tasks.testing.Test> {
        useJUnitPlatform() // Configuration commune des tests pour tous les projets
    }
}

subprojects {
    apply(plugin = "java")
    apply(plugin = "org.jetbrains.kotlin.jvm")

    dependencies {
        implementation("org.jetbrains.kotlin:kotlin-stdlib-jdk8")
    }

}

\==buildSrc: มีดพกสวิสของตรรกะการบิลด์

เมื่อตรรกะของงานของคุณซับซ้อนหรือต้องใช้ซ้ำ,buildSrcเป็นตัวเลือกที่ให้ความสำคัญสูงสุด. มันเป็นโมดูล Gradle พิเศษที่ถูกคอมไพล์ก่อนสคริปต์บิลด์หลัก ทำให้คลาสของมันพร้อมใช้งานใน classpath ของทั้งบิลด์ของคุณ

ทำไมต้องใช้`buildSrc`สำหรับงาน ?

  • การนำกลับมาใช้ใหม่: งานที่กำหนดใน`buildSrc`สามารถนำไปใช้กับทุกโครงการในขั้นตอนการสร้างได้.

  • องค์กร: รวมโค้ดการสร้างให้เป็นที่เดียว ทำให้สะอาดและบำรุงรักษาได้ง่าย.

  • ความปลอดภัยของชนิดและการเติมอัตโนมัติ: โค้ด Kotlin ใน`buildSrc`ถูกคอมไพล์แล้ว, ซึ่งให้การตรวจสอบข้อผิดพลาดและการเติมโค้ดอัตโนมัติจาก IDE ของคุณ, ปรับปรุงประสบการณ์ในการพัฒนา.

\==การสร้างงานรายงานนามธรรม

เพื่อจัดการรายงานทดสอบ เราได้ออกแบบวิธีการที่เป็นโมดูลโดยใช้คลาสงานเชิงนามธรรมใน`buildSrc`. ตามความต้องการของคุณ คลาสนี้อาจสืบทอดจาก`DefaultTask` ou de Exec.

\=== งานนามธรรม`OpenTestReportTask`(รับมาจาก`DefaultTask`)

วิธีนี้แนะนำให้ใช้เมื่อคุณต้องการตรรกะ Kotlin ที่ปรับแต่งเองซึ่งทำงานร่วมกับระบบไฟล์หรือ API อื่น ๆ ของ Gradle แล้วจึงเรียกคำสั่งภายนอก

[source,kotlin]

แพ็คเกจ com.yourpackage

นำเข้า org.gradle.api.DefaultTask import org.gradle.api.tasks.Input นำเข้า org.gradle.api.tasks.TaskAction import java.io.File

นามธรรม คลาส OpenTestReportTask : DefaultTask()

----
init {
    group = "verification"
    description = "Opens a test report in Firefox."
    dependsOn("check") // Assure que les rapports sont générés
}

@get:Input
abstract var reportPath: String

@TaskAction
fun openReport() {
    val separator = File.separator
    val reportFile = project.layout.projectDirectory.asFile.toPath()
        .resolve(reportPath.replace("/", separator))
        .toAbsolutePath()
        .toFile()

    if (!reportFile.exists()) {
        logger.warn("Report file does not exist: $reportFile. Ensure 'check' ran.")
        return
    }

    project.exec {
        commandLine("firefox", "--new-tab", reportFile.absolutePath)
    }
    logger.lifecycle("Opened test report: ${reportFile.absolutePath}")
}
----

\== งานนามธรรม`AbstractJbakeExecTask`(ที่สืบทอดจาก`Exec`)

หากงานของคุณเป็นเพียงการเรียกใช้คำสั่งภายนอกที่มีอาร์กิวเมนต์แปรผัน ให้สืบทอดโดยตรงจาก**Exec**เป็นทางที่ตรงกว่า。

## [source,kotlin]

package com.yourpackage

import org.gradle.api.tasks.Exec import org.gradle.api.tasks.Input import java.io.File

abstract class AbstractJbakeExecTask : Exec()
init {
    group = "verification"
    description = "Opens a Jbake project report in Firefox."
    dependsOn("check")
}

@get:Input
abstract var reportRelativePath: String

override fun exec() {
    val separator = File.separator
    val reportFile = project.layout.projectDirectory.asFile.toPath()
        .resolve(reportRelativePath.replace("/", separator))
        .toAbsolutePath()
        .toFile()

    if (!reportFile.exists()) {
        logger.warn("Report file does not exist: $reportFile. Ensure 'check' ran.")
        return
    }

    commandLine("firefox", "--new-tab", reportFile.absolutePath)
    logger.lifecycle("Attempting to open report: ${reportFile.absolutePath}")
    super.exec() // Appelle la méthode exec() de la super-classe Exec
}

}
