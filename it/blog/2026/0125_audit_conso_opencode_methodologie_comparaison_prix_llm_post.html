OpenCode non è un fornitore di modelli.È un CLI open source (github.com/anomalyco/opencode) che orchestra agenti IA. Non vende abbonamenti, non fornisce inferenza. È l’equivalente di`git`per il versionamento: uno strumento, non un servizio Ollama Cloud è il fornitore d’inferenza.La mia installazione locale di Ollama agisce come client — si autentica presso i server di Ollama tramite una chiave SSH unica (Device Key) e delega loro l’esecuzione dei modelli taggati.:cloud. L’abbonamento Pro (20€/mese) sblocca quote superiori e consente di accumulare più account su una stessa macchina tramite Docker.

Introduzione : Perché un audit ?

Due mesi fa, utilizzavo i modelli gratuitamente sulla mia installazione locale di Ollama. Poi ho sottoscritto un primo abbonamento Ollama Cloud Pro a 20€ al mese, che mi permette di utilizzare i modelli cloud (quelli con il tag`:cloud`) via il provider`ollama-cloud`. Un secondo abbonamento è seguito un mese più tardi, su un’istanza Docker separata con il proprio account e la propria chiave SSH — il metodo di cumulo descritto in il mio articolo sul cumulo degli abbonamenti

sono giustificati questi 20€ al mese ? Non a caso. Con dei numeri.

Per rispondere, avevo bisogno di dati precisi. Non delle stime. Non delle medie. Il mio consumo reale, token per token, modello per modello, sessione per sessione.

E OpenCode — la CLI — lo memorizza in un database SQLite.

Il tavolo`session`è perfetta per un audit globale : ogni sessione ha il suo conteggio aggregato di token, il modello utilizzato, e il suo costo. Il campo`model`è del JSON grezzo :

{
  "id": "deepseek-v4-pro:cloud",
  "providerID": "ollama-cloud",
  "variant": "default"
}

Il campo`cost`nel database OpenCode riflette solo le spese API esterne pagate a consumo tramite API key (Google Gemini, OpenAI, ecc.). Le chiamate tramite Ollama — sia in locale che tramite Ollama Cloud Pro — sono marcate`cost=0`perché il costo è forfettario (abbonamento), non per-token. Il vero costo di queste chiamate è l’abbonamento mensile.

Il Codice di Estrazione

Non è necessario installare nulla. Node.js 22+ incorpora un modulo SQLite sperimentale (node:sqlite) che funziona perfettamente. Ecco lo script che mi ha dato tutto :

const { DatabaseSync } = require('node:sqlite');
const db = new DatabaseSync(
  `${process.env.HOME}/.local/share/opencode/opencode.db`,
  { readonly: true }
);

// 1. Statistiques globales
const global = db.prepare(`
  SELECT
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(tokens_reasoning) as total_reasoning,
    SUM(tokens_cache_read) as total_cache_read,
    SUM(cost) as total_cost
  FROM session
`).get();

// 2. Ventilation par modèle et fournisseur
const byModel = db.prepare(`
  SELECT
    json_extract(model, '$.id') as model_id,
    json_extract(model, '$.providerID') as provider,
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(cost) as total_cost
  FROM session
  WHERE model IS NOT NULL
  GROUP BY model_id, provider
  ORDER BY SUM(tokens_input) DESC
`).all();

// 3. Par mois
const monthly = db.prepare(`
  SELECT
    strftime('%Y-%m', datetime(time_created/1000, 'unixepoch')) as month,
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(cost) as total_cost
  FROM session
  WHERE time_created IS NOT NULL
  GROUP BY month
  ORDER BY month
`).all();

// 4. Messages par modèle (détection des changements intra-session)
const msgByModel = db.prepare(`
  SELECT
    json_extract(m.data, '$.model.providerID') as provider,
    json_extract(m.data, '$.model.modelID') as model_id,
    COUNT(*) as messages
  FROM message m
  WHERE json_extract(m.data, '$.model') IS NOT NULL
  GROUP BY provider, model_id
  ORDER BY COUNT(*) DESC
`).all();

console.log({ global, byModel, monthly, msgByModel });
db.close();

Il flag`--experimental-sqlite`è necessario su Node.js 22.x. Con Node.js 24+, il modulo è stabile e non richiede più il flag.

Il Costo Nascosto : Prompt Engineering e Iterazioni

Il costo token è solo una parte dell’equazione. Il vero costo è il tempo dello sviluppatore.

Con OpenCode + Ollama Cloud Pro + il mio agente di governance (EAGER/LAZY/Hot/Warm/Cold, descritto in l’articolo sulla governance), ottengo:

  • 0 prompt engineering ripetitivo: il contesto viene iniettato automaticamente

  • oltre il 90% di precisione al primo colpo: il codice compila al primo colpo

  • Zero allucinazioni deepseek su 8 sessioni consecutive(documentato in la comparazione Kimi/GLM/DeepSeek)

Con Claude o GPT senza fine-tune né governance :

  • 2-3 iterazioni per attività in media

  • Ingegneria del prompt sistematica

  • Allucinazioni sulle API Kotlin/Gradle non appena il contesto supera i 30K token

Il costo « effettivo » mensile — token × iterazioni × tempo di correzione — è da 27× a 54× quello della mia soluzione, come ho dimostrato in l’articolo sul rapporto di efficienza.

_ Non è solo una questione di prezzo per token. Un Claude Opus al prezzo 57× che richiede 3× più iterazioni ha un costo effettivo ~170× superiore. Per dirla brutalmente: pagare uno stagista lo stipendio di un partner McKinsey. _

Cumulare gli abbonamenti Ollama Cloud Pro: Il metodo Docker

Se un solo abbonamento non basta, li accumuliamo. Il principio consiste nell’isolare ogni abbonamento nella propria installazione Ollama, con la propria chiave SSH di autenticazione. Docker lo rende banale.

Il metodo completo è dettagliato in l’articolo sul cumulo Docker, ecco il principio :

skinparam backgroundColor #FEFEFE

node "La mia macchina fisica" {
  frame "Ollama Instance A (nativa)
porta :11434" as Native {
    database "Identità A
/usr/share/ollama/.ollama/id_ed25519"
  }
  frame "Ollama istanza B (Docker)
porta :11435" as Docker {
    database "Identità B
~/ollama-b-data/id_ed25519"
  }
}

cloud "Ollama Cloud" {
  actor "Conto Pro A\n(email 1)" as A
  actor "Conto Pro B\n(email 2)" as B
}

Native --> A : "Chiave del dispositivo A"
Docker --> B : "Dispositivo Chiave B"

note bottom of Docker
  Conteneur Docker isolé :
  - Clé SSH distincte
  - Port réseau distinct (11435)
  - Volume persistant (~/ollama-b-data)
  - restart: always
end note
@enduml

Il pattern è semplice :

  1. Creare un volume`~/ollama-b-data`

  2. Avvia un contenitore Docker`ollama/ollama:0.20.2`mappato su`11435:11434`

  3. Recuperare la chiave SSH del contenitore → salvarlo su ollama.com

  4. fare`ollama signin`con una seconda email

  5. Configurare OpenCode con due provider (`ollama`su :11434,`ollama-b`su :11435)

Due conti, una carta blu, zero conflitto.

Ciò che l’audit non misura

angolo cieco impatto

Qualità del codice prodotto

2,6 miliardi di token non dicono se il codice compila. Le mie 8 sessioni DeepSeek V4 Pro hanno un tasso di first-shot >90%.

Ecosistema OpenCode

La CLI è gratuita, ma il suo valore (agenti, sandbox, cronologia, caching dei prompt) è enorme. Non è incluso nel prezzo dell’abbonamento — è uno strumento separato.

Costo opportunità

Passare 2h/giorno a fare il debug delle allucinazioni di un modello inferiore costa più di 20€/mese.

Tranquillità d’animo

Forfait fisso = nessuna sorpresa. Con il pagamento per-token, un pic di attività può far molto male.

I prezzi citati sono quelli di maggio 2026. Tra sei mesi, tutto sarà diminuito. Ma il rapporto di forza strutturale — abbonamento fisso vs pagamento a consumo — rimarrà favorevole all’abbonamento per i grandi consumatori.
