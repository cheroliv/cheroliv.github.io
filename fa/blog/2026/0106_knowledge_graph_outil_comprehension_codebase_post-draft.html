زمان مطالعه : 15 minutes

شما به یک پروژه با ۱۰۰٬۰۰۰ خط می‌رسید. بیست ماژول، صد کلاس، وابستگی‌های نامرئی، تاریخچهٔ ريفکتورینگ‌های فراموش‌شده. README از معماری «microservices» خبر می‌دهد اما کد چیز دیگری می‌گوید. چقدر زمان لازم است تا بتوانید کارآمد شوید؟سه ماه— اگر شانس داشته باشید. و اگر یک نقشه تعاملی از کد، به‌طور خودکار تولید شده، می‌تواند این را به سه روز کاهش دهد؟

دیوار او‌نبورдинگ

هر توسعه‌دهنده این صحنه را تجربه کرده است:

  1. روز ۱ : ما به شما README را نشان می‌دهیم (آخرین به‌روزرسانی : ۱۸ ماه پیش)

  2. روز 3 : متوجه می‌شوید که ماژول`billing`به صورت مخفی ماژول را صدا می‌زند`notification`

  3. روز ۷: یک کارمند ارشد به شما می‌گوید: "آه بله، این کلاس در واقع دو کار می‌کند، ما قصد داشتیم آن را تقسیم کنیم

  4. روز ۱۴: متوجه می‌شوید که تمام هوش تجاری در`utils/LegacyHelper.java`— یک فایلی که در هیچ جای دیگری ارجاع داده نشده است

@startuml
skinparam backgroundColor #FEFEFE
skinparam ActivityBackgroundColor #FDEDEC
skinparam ActivityDiamondBackgroundColor #FFF3CD

start

:Arrivée sur le projet;
note right: 100k lignes, 20 modules

:Lit le README;
note right: Obsolète depuis 18 mois

:Découvre les dépendances au fur et à mesure;
note right: Par erreur, en production

:Demande au senior;
note right: "آه بله، این یک ارث..."

:Génère une documentation mentale;
note right: Incomplète, subjective

:Productif ?;
note right: ~3 mois plus tard

stop

@enduml

مشکل عدم اسناد نیست — بلکهنقص کارت. نقشه‌ای که قلمرو واقعی را نشان می‌دهد، نه قلمرو تخیلی از آخرین redesign.

یک Knowledge Graph چیست؟

یک Knowledge Graph یک نمایش ساختاریافته ازدانستنمحتوا در پایگاه کد شما :

وجود نمونه در کد نقش در گراف

گره

کلاس, تابع, مفهوم

رأس گراف

استخوان ماهی

تماس, ارث, واردات

ارتباط بین دو گره

جامعه

گروه کلاس‌های مرتبط

خوشه بصری

نوع لبه

استخراج شده, استنتاج شده, مبهم

امتیاز اعتماد

0.0 à 1.0

حفره‌ی هیپر

پیچیدگی معماری

 
@startuml
skinparam backgroundColor #FEFEFE
skinparam classAttributeIconSize 0

package "جامعه 0 : لایه سرویس" #Ede8f8 {
  class "LlmService" as n0 {
    type = class
  }
  class "معالِج نمودار" as n1 {
    type = class
  }
}

package "مجتمع 1 : پیکربندی" #D5f5e3 {
  class "بارگیر پیکربندی" as n2 {
    type = class
  }
  class "ApiKeyPool" as n3 {
    type = class
  }
}

n0 --> n1 : calls\nEXTRACTED
n2 ..> n3 : creates\nINFERRED (0.75)
n0 --> n2 : configures\nEXTRACTED

note right of n0
  **Hyperedge possible :**
  LlmService + DiagramProcessor + ConfigLoader
  partagent un contexte RAG
end note

@enduml

تفاوت با یک دیاگرام UML ساده چیست؟یک نمودار UML نشان می‌دهد توسعه‌دهنده تصمیم گرفته است چه چیزی را نشان دهد. یک Knowledge Graph چه چیزی در واقع وجود دارد را نشان می‌دهد، از جمله وابستگی‌های پنهان و مفاهیم پدیدار.

چahar سطح درک

یک Knowledge Graph به navegation اجازه می‌دهدچهار مقیاس :

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

node "سطح 1 : کلاس" as n1 #D6eaf8 {
  [KnowledgeGraphParser]
  [KnowledgeGraphRenderer]
}

node "سطح 2 : ماژول" as n2 #Ede8f8 {
  package "سرویس" {
    [LlmService]
    [ConfigLoader]
  }
}

node "سطح 3 : جامعه" as n3 #D5f5e3 {
  package "لایه سرویس" #D5f5e3 {
    [LlmService]
    [DiagramProcessor]
  }
  package "لایه پیکربندی" #Fdedec {
    [ConfigLoader]
    [ApiKeyPool]
  }
}

node "سطح ۴: سیستم" as n4 #Fef9e7 {
  [PlantUML Plugin] --> [graphify]
  [GraphifyPromptAdapter] ..> [KnowledgeGraph]
}

n1 --> n2 : agrège
n2 --> n3 : découvre
n3 --> n4 : intègre

@enduml

خط کد

فایل‌های این ماژول چه هستند؟

پرونده

tree, ls

3 — جامعه

کدام مفاهیم با هم کار می‌کنند؟

گروه مرتبط

گراف دانش

4 — système

همه چیز چطور به هم می‌خورد؟

معماری کلی

دیاگرام KG کامل

بدون Knowledge Graph، سطوح ۳ و ۴ هستندنا dorsرس— یا حداقل، ذاتی و منسوخ.

به‌منزلهٔ گم‌شده: یک سناریو ملموس

یک توسعه‌دهنده تازه‌کار به نام آنا را تصور کنید که به پروژه پیوسته است. باید یک ویژگی به نام «quota tracking» برای تماس‌های LLM اضافه کند.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

actor "Anaïs (جدید)" as ana

rectangle "چیزی که او دنبال می‌کند" {
  [QuotaTracker] as qt
  [ApiKeyPool] as akp
  [RateLimiter] as rl
}

rectangle "چیزی که او می‌یابد" {
  [LlmService] as ls
  [ConfigLoader] as cl
}

ana --> ls : "جستجو 'quota'\nدر IDE"
ls --> cl : "یاب ConfigLoader
(نام برد 'quota' در یک کامنت)"
cl --> qt : "۳ هفته بعد :
QuotaTracker را کشف کن
قبلاً موجود است"

note right of qt
  **Contexte perdu :**
  QuotaTracker était dans
  un module non-référencé
  dans le README
end note

@enduml

با یک Knowledge Graph، آنیس می‌دیده بود در۵ دقیقه :

  • QuotaTracker`مرتبط با`ApiKeyPool(رشتهاستخراج شده)

  • RateLimiter`связан با`QuotaTracker(دمهاستنتاج شده, اعتماد 0.82)

  • این سه گره یک را تشکیل می‌دهندجامعهمدیریت سهمیه

  • یک هیپرإدج نیز متصل می‌شود`LlmService`— نقطه ورود

پایپ‌لاین: کد سفارشی در یک دستور

پایپلاین Graphify + پلاگین Gradle پایگاه کد شما را به نمودار PlantUML دردو دستور:

@startuml
skinparam backgroundColor #FEFEFE
skinparam sequenceArrowThickness 2

actor "توسعه‌دهنده" as dev
participant "گرافیک‌سازی" as gfy
participant "graphify-out/graph.json" as json
participant "پلاگین Gradle" as plg
participant "KnowledgeGraphParser" as kgp
participant "KnowledgeGraphRenderer" as kgr
participant "دیایگرام‌ها/گراف دانش/" as out

dev -> gfy : graphify update . --no-viz
gfy -> json : extrait nœuds, arêtes,\ncommunautés, confiances

dev -> plg : ./gradlew generateKnowledgeGraphDiagram
plg -> kgp : parse graph.json
kgp -> kgr : nodes + edges + communities
kgr -> out : génère .puml + .png

out --> dev : diagramme interactif

@enduml

صفر LLM.همه چیز Deterministیک است: همان کد، همان گراف، همان نمودار. قابل بازتولید، قابل نسخه‌بندی، قابل مشاهده آفلاین.

انواع لبه‌ها: چه می‌گوید اعتماد

@startuml
skinparam backgroundColor #FEFEFE

node "سرویس LLM" as ls
node "نمودار پردازشگر" as dp
node "بارگذاری_پیکربندی" as cl
node "ApiKeyPool" as akp
node "LegacyHelper" as lh #F1948a

ls --> dp : EXTRACTED\n(calls, direct)
cl ..> akp : INFERRED 0.75\n(creates, probable)
ls -[#FF5722]-> lh : AMBIGUOUS\n(legacy, douteux)

legend right
  |= Type |= Symbole |= Signification |
  | EXTRACTED | <b>--></b> | Relation visible dans le code |
  | INFERRED | <b>..></b> | Relation déduite (score de confiance) |
  | AMBIGUOUS | <b>--x</b> | Relation incertaine, à vérifier |
endlegend

@enduml

نوع‌های لبه برای بوردینگ ضروری هستند:

  • استخراج شده: می‌توانی به‌آرامی ناوبری کنی — این در کد است

  • استنتاج شده(0.6-0.8) : احتمالاً درست است، اما پیش از ریفکتورینگ بررسی کن

  • نتیجه‌گیری‌شده(0.8+) : بسیار قابل اعتماد — از آن به عنوان مرجع استفاده کن

  • مبهم: احتیاط، نقطه حساس. از یک ارشد بخواه.

5 دقیقه برای تولید Knowledge Graph خودtan

@startuml
skinparam backgroundColor #FEFEFE
skinparam ActivityBackgroundColor #D5f5e3

start

:pip install graphify==0.4.29;

:graphify update . --no-viz;
note right: Génère graphify-out/graph.json

:Ajouter le plugin Gradle;
note right: plugins { id("com.cheroliv.plantuml") }

:./gradlew generateKnowledgeGraphDiagram;
note right: Génère .puml + .png

:Vérifier diagrams/knowledge-graph/;
note right: knowledge-graph-full.puml\nknowledge-graph-full.png

stop

@enduml
دستورالعمل‌های عملی
# 1. Installer graphify
pip install graphify==0.4.29

# 2. Générer le Knowledge Graph
graphify update . --no-viz

# 3. Vérifier le JSON
cat graphify-out/graph.json | jq '.nodes | length'
# → 47 nœuds

# 4. Générer le diagramme
./gradlew generateKnowledgeGraphDiagram

# 5. Filtrer par communauté
./gradlew generateKnowledgeGraphDiagram -Pplantuml.kg.community="service layer"

# 6. Limiter la taille
./gradlew generateKnowledgeGraphDiagram -Pplantuml.kg.maxNodes=20

مقدار برای onboarding : سناریو Anaïs بازنگری شده

با Knowledge Graph، سناریو آنweis به‌طور اساسی تغییر می‌کند :

@startuml
skinparam backgroundColor #FEFEFE
skinparam ActivityBackgroundColor #D5f5e3
skinparam ActivityDiamondBackgroundColor #FFF3CD

start

:Jour 0 : reçoit le lien\nvers le diagramme KG;
note right: PNG intégré\ndans le README

:Découvre la communauté\n"مدیریت سهمیه";
note right: 3 noeuds, 2 arêtes\nINFERRED + EXTRACTED

:Clic sur QuotaTracker\ndans le diagramme;
note right: Liens vers LlmService\net RateLimiter visibles

:Ouvre le code avec\ncontexte complet;
note right: Sait où chercher\navant de chercher

:Premier commit\nproductif;
note right: Jour 3, pas jour 30

stop

@enduml

Knowledge Graph جایگزین IDE نیست— او آن را تکمیل می‌کند. IDE کجا را نشان می‌دهد ; KG چرا و چگونه این کار انجام می‌شود

مقدار برای ناوبری روزانه

Onboarding تنها یک مورد استفاده نیست. برای یک توسعه‌دهندهٔ ارشد، Knowledge Graph برای :

@startuml
skinparam backgroundColor #FEFEFE
skinparam usecaseStyle roundrectangle

left to right direction

actor "توسعه‌دهنده" as dev

usecase "بازسازی" as ref
usecase "مرور
معماری" as rev
usecase "Debug
وابستگی‌ها" as dbg
usecase "فرآیند بکارگیری" as onb
usecase "مستندات
به‌صورت خودکار تولیدشده" as doc

dev --> ref
dev --> rev
dev --> dbg
dev --> onb
dev --> doc

ref --> ("شناسایی
نقاط داغ") : hyperedges\ndensité d'arêtes
rev --> ("بررسی\nمرزها") : AMBIGUOUS\naux limites
dbg --> ("ریدیابی\nتماس‌ها") : EXTRACTED\nchaîne de calls
onb --> ("کاوش کنید
کمونیتی‌ها") : filtres\npar cluster
doc --> ("ایجاد
نمودارها") : ./gradlew\ngenerateKnowledgeGraphDiagram

@enduml
مورد استفاده چگونه KG کمک می‌کند مثال واقعی

بازنویسی

هایپر_edges را نمایش دهید (لینک‌های 3+)

این ۵ کلاس همیشه مرتبط هستند — یک ماژول استخراج می-conduct

بررسی معماری

AMBIGUOUS را در مرزها تشخیص بده

تماس بین billing و notification نامطمئن است

اشکال‌زدایی

رشته‌ی EXTRACTED را دنبال کنید

چرا LlmService LegacyHelper را صدا می‌زند؟

ادغام

انجمن‌ها را با فیلتر کاوش کن

لایه سرویس چیست؟

مستندات

دیاگرام‌ها را در CI تولید کن

حدود و چشم‌اندازها

یک Knowledge Graph یک چنگک جادویی :

محدودیت توضیح راه دور

فقط کد استاتیک

هیچ زمان اجرا نیست، هیچ جریان داده‌ای

به دنباله‌های APM تکمیل کنید

INFERRED می‌تواند نادرست باشد

لبه‌های استنتاجی نیاز به تأیید دارند

امتیاز اعتماد + بازبینی انسانی

هیچ سِمانتیک کسب‌وکاری

KG می‌داند "LlmService ConfigLoader را فراخوانی می‌کند"، نه "این نقطه ورود/auth است

یادداشت‌های دستی یا پست‌پردازش LLM

بدون زمانی

یک عکس لحظه‌ای از کد، نه توسعه آن

ایجاد منظم + مقایسهٔ نسخه‌ها

منظره‌ا:

  • تفاوت کیلوگرم: مقایسهٔ دو نسخه برای دیدن جابجایی‌های جامعه‌ها

  • KG تعاملی: کلیک بر روی یک گره → باز کردن IDE در خط متناظر

  • KG تاریخی: نمایش تحولجامعات در زمان (بده فنی که مهاجرت می‌کند)

نتیجه

Knowledge Graph یک عمل را تبدیل می‌کندتنها و طولانی(درک یک پایهٔ کد) در یک عملبه اشتراک گذاشته و سریع(نقشه را ببین).

این مستندات نیست — این استنقشه‌سازی. یک نقشه که به صورت خودکار به‌روز می‌شود، که سرزمین واقعی را نشان می‌دهد و به هر توسعه‌دهنده‌ای، جدید یا ارشد، اجازه می‌دهد تا با اعتماد حرکت کند.

pip install graphify==0.4.29
graphify update . --no-viz
./gradlew generateKnowledgeGraphDiagram

3 دستورات. 5 دقیقه. یک نقشه از پایهٔ کد شما.
