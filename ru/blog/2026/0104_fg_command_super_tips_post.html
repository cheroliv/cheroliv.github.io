Вы бросаете`./gradlew build`, терминал заблокирован на 3 минуты, и вам нужно сделать что-то другое пока ждёте ? Не нужно открывать новую вкладку.`Ctrl+Z`приостанови процесс,`fg`Он возвращает его именно туда, где вы его оставили. Это самый недооценённый совет Unix в повседневной жизни разработчика.

Проблема: занятый терминал

Каждый разработчик сталкивался с такой ситуацией:

$ ./gradlew build
> Building...

Терминал заблокирован. Вы больше не можете вводить никакие команды. И вам нужно открыть файл, запустить`git status`, или проверить занятый порт.

@startuml
skinparam backgroundColor #FEFEFE

actor Développeur as dev
participant "Терминал" as term
participant "Gradle
( процесс )" as gradle

dev -> term : ./gradlew build
term -> gradle : Lance le build
gradle -> term : Occupe le terminal\n(pas de prompt)
dev -> term : veut taper une commande
term --> dev : ❌ Terminal bloqué

note right of dev
  Le développeur est
  paralysé pendant
  toute la durée du build
end note
@enduml

Большинство разработчиков открывают новый терминал. Но есть более элегантное, быстрое и нативное решение: управление задачами.

три незаменимые команды

Ctrl+Z — приостановить (SIGTSTP)

`Ctrl+Z`отправляет сигнал`SIGTSTP`в фоновый процесс. Процесс естьприостановлен— не убит — и терминал снова показывает приглашение.

$ ./gradlew build
> Building...
^Z
[1]+  Stoppé    ./gradlew build
$

Число в квадратных скобках`[1]`(two spaces)номер задания. Le `+`указывает задание по умолчанию.

fg — Вернуть на передний план

`fg`Переместить приостановленную задачу на передний план. Процесс возобновляется точно там, где он остановился.

$ fg
./gradlew build
> Building... (reprend où il en était)

С конкретным номером задания:

$ fg %2

bg — Возобновить в фоновом режиме

`bg`Возобновляет процесс без блокировки терминала. Идеально для длительных сборок.

$ bg
[1]+ ./gradlew build &
$

Le `&`В конце означает, что процесс работает в фоновом режиме.

jobs — Перечислить задания оболочки

$ jobs
[1]-  Stoppé    vim README.md
[2]+  En cours   ./gradlew build
@startuml
skinparam backgroundColor #FEFEFE
skinparam defaultFontName sans-serif

state "Передний план\n(терминал заблокирован)" as fg #LightCoral
state "Приостановлен
(Ctrl+Z)" as stopped #LightYellow

(bg)" as bg_ #LightGreen

  Le terminal est libre
  le build continue
end note
@enduml

Сценарий 1 : Длинная сборка

Это самый распространённый вариант использования. Вы запускаете сборку Gradle, терминал заблокирован, и вам нужно сделать что-то другое.

@startuml
skinparam backgroundColor #FEFEFE
autonumber

actor Développeur as dev
participant "Терминал" as term
participant "Gradle" as gradle
database "Состояние
процесс" as state

dev -> term : ./gradlew build
term -> gradle : Lance le build
gradle -> state : En cours (FG)
dev -> term : Ctrl+Z
term -> state : Suspendu (job [1])
term --> dev : Prompt libre $

dev -> term : git status
term --> dev : working tree clean

dev -> term : fg
term -> state : Reprend (FG)
gradle --> dev : Build réussi ✓

note right of state
  Le processus Gradle
  n'a jamais été tué
  Il reprend exactement
  où il s'était arrêté
end note
@enduml

Сценарий 2: Забытый редактор

Вы находитесь в`vim`, вам нужно обратиться к другому файлу, не выходя`vim`.

# Dans vim, en mode commande :
:shell
$ cat /path/to/other/file.txt
$ exit
# Retour dans vim

Но это тяжело. С`Ctrl+Z`, это мгновенно :

# Dans vim, n'importe quel moment :
Ctrl+Z
[1]+  Stoppé    vim README.md

$ cat /path/to/other/file.txt
# ... lire le fichier ...

$ fg
vim README.md
# Retour exact là où on en était, curseur en place
@startuml
skinparam backgroundColor #FEFEFE
autonumber

actor Développeur as dev
participant "vim" as vim
participant "шелл" as shell

dev -> vim : édition en cours
dev -> vim : Ctrl+Z
vim -> shell : Suspendu (job [1])
dev -> shell : cat autre_fichier.txt
shell --> dev : contenu du fichier
dev -> shell : fg
shell -> vim : Reprend (job [1])
vim --> dev : Curseur exactement\nà la même position

note right of vim
  vim restaure
  intégralement l'état :
  position du curseur,
  buffer, undo stack
end note
@enduml
vim`восстанавливает идеально его состояние после`fg: положение курсора, содержимое буфера, история отмены — всё сохранено.

Сценарий 3 : приостановленный процесс opencode

Это сценарий, который послужил основой для этой статьи. Вы используете`opencode`(CLI‑инструмент pour piloter un LLM sur votre code), и процесс приостановлен.

@startuml
skinparam backgroundColor #FEFEFE
skinparam defaultFontName sans-serif
skinparam componentStyle rectangle

actor Développeur as dev
participant "opencode\n(LLM agent)" as agent
participant "Шелл" as shell
participant "git" as git

dev -> agent : Session active
agent -> agent : Tour de parole\ndu LLM en cours

note over agent
  Ctrl+Z arrive
  en plein milieu
  d'une analyse de code
end note

dev -> agent : Ctrl+Z
agent -> shell : Suspendu (job [1])
dev -> git : git diff
git --> dev : changements visibles
dev -> shell : fg
shell -> agent : Reprend (job [1])
agent --> dev : Reprend exactement\nl'analyse en cours

note right of agent
  Aucune perte de contexte
  Le LLM reprend sa réponse
  exactement où il en était
end note
@enduml
$ opencode
# ... session en cours, LLM analyse le code ...
^Z
[1]+  Stoppé    opencode

$ git diff HEAD~1
# vérifier les changements récents

$ fg
opencode
# Le LLM reprend là où il s'était arrêté

Преимущество двойное:

  1. Нет потери контекста: сессия LLM, история диалога, открытые файлы — всё сохранено

  2. Нет перезагрузки: не нужно перезапускать opencode, перезагружать контекст, повторно объяснять проблему LLM

Сценарий 4: Управлять несколькими задачами одновременно

fg et `bg`принимают номер задачи, чтобы нацелиться на конкретный процесс, когда несколько из них приостановлены.

$ vim config.yml
^Z
[1]+  Stoppé    vim config.yml

$ ./gradlew test
^Z
[2]+  Stoppé    ./gradlew test

$ htop
^Z
[3]+  Stoppé    htop

$ jobs
[1]   Stoppé    vim config.yml
[2]-  Stoppé    ./gradlew test
[3]+  Stoppé    htop

$ fg %2
./gradlew test
# Le build reprend en avant-plan

$ bg %3
[3] htop &
# htop reprend en arrière-plan
@startuml
skinparam backgroundColor #FEFEFE

rectangle "Приостановленные задания" as jobs #LightYellow {
  card "[1] vim config.yml" as j1
  card "[2] ./gradlew test" as j2
  card "[3] htop" as j3
}

rectangle "действия" as actions #LightGreen {
  card "fg %2\n→ передний план" as a1
  card "bg %3\n→ фон" as a2
  card "fg %1\n→ передний план" as a3
}

jobs --> actions : fg/bg + numéro de job
actions --> j2 : Reprend
actions --> j3 : En arrière-plan

note bottom of jobs
  Chaque job conserve
  son état exact
  entre les suspend/resume
end note
@enduml

Различия между fg, bg, Ctrl+Z, Ctrl+C и &

Многие разработчики путают эти механизмы. Вот решительное уточнение.

@startuml
skinparam backgroundColor #FEFEFE
skinparam defaultFontName sans-serif

rectangle "**Ctrl+Z**\nSIGTSTP" as ctrlz #LightYellow {
  card "Приостановить процесс
(он всё ещё находится в памяти)
Можно использовать с fg/bg" as c1
}

rectangle "**Ctrl+C**\nSIGINT" as ctrlc #LightCoral {
  card "Убей процесс
(возврат невозможен)
Потеря всего состояния" as c2
}

rectangle "** & **\n(фон)" as ampersand #LightGreen {
  card "Запусти напрямую
в фоновом режиме
Терминал свободен немедленно" as c3
}

rectangle "**fg**\n(передний план)" as fg_ #SkyBlue {
  card "Привести задачу
приостановленную на передний план
Занят терминал" as c4
}

rectangle "**bg**\n(фон)" as bg_ #Lavender {
  card "Продолжает задачу\nПриостановлено в фоне\nТерминал свободен" as c5
}

ctrlz -right-> fg_ : fg pour reprendre
ctrlz -right-> bg_ : bg pour continuer\nen arrière-plan
ctrlc -right-> c2 : Pas de retour\nprocessus tué

note bottom of ctrlz
  Le processus est **figé**
  mais **pas tué**
end note

note bottom of ampersand
  Alternative : lancer
  ./gradlew build &
  directement en arrière-plan
end note
@enduml
Сочетание клавиш/Команда сигнал Эффект Вернуться назад?

Ctrl+Z

SIGTSTP

Приостановить процесс (замороженный, в памяти)

Да:`fg` ou bg

Ctrl+C

SIGINT

Убей процесс (завершённый)

Нет: процесс уничтожен

Ctrl+\

SIGQUIT

Убей процесс + дамп ядра

Нет: процесс уничтожен

commande &

—

Запусти напрямую в фоновом режиме

`fg`чтобы вернуть его на передний план
`Ctrl+Z`естьнеразрушающий. Процесс заморожен как есть, в памяти. Вы можете немедленно продолжить с`fg`Это пауза, не стоп.

Полный жизненный цикл задания

@startuml
skinparam backgroundColor #FEFEFE
skinparam defaultFontName sans-serif

title Полный жизненный цикл задания оболочки
state "несуществующий" as none
state "Передний план
(занимает терминал)" as foreground #LightCoral
state "Приостановлен
(Ctrl+Z / SIGTSTP)" as suspended #LightYellow
state "Фон
(bg ou &)" as background #LightGreen
state "Завершено\n(exit code 0)" as done #LightGray

[*] --> none
none --> foreground : tape une commande
foreground --> suspended : Ctrl+Z
foreground --> done : fin normale

suspended --> foreground : fg
suspended --> background : bg
suspended --> done : kill %n

background --> foreground : fg
background --> done : fin normale\n(en arrière-plan)
background --> suspended : Ctrl+Z\n(si fg puis Ctrl+Z)

done --> [*]

note right of suspended
  L'état suspendu est
  le pivot de tout le
  système de jobs
end note
@enduml

Продвинутые советы

fg с последней работой и чередованием

fg`без аргумента возвращает помеченную задачу+(самый последний). Но вы можете также использовать%-`pour нацеливания на предыдущую работу :

$ vim file1.txt
^Z
[1]+  Stoppé    vim file1.txt

$ vim file2.txt
^Z
[2]+  Stoppé    vim file2.txt

$ fg      # ramène job [2] (le plus récent)
$ fg %-   # ramène job [1] (le précédent)

убить работу правильно

$ jobs
[1]-  Stoppé    vim config.yml
[2]+  Stoppé    ./gradlew test

$ kill %2       # envoie SIGTERM au job 2
$ kill -9 %1    # envoie SIGKILL au job 1 (force)

disown : отсоединить от оболочки

disown`Удаляет задание из таблицы заданий оболочки. Процесс продолжает работать, но его нельзя более вернуть с`fg:

$ ./gradlew build &
[1] 12345

$ disown %1
# Le processus continue mais n'est plus lié au shell
# Ça survives à la fermeture du terminal

Сочетать с nohup для длительных процессов

Чтобы процесс продолжал работать после закрытия терминала:

$ nohup ./gradlew build &
[1] 12345
$ disown %1
# Le build continue même si vous fermez le terminal
@startuml
skinparam backgroundColor #FEFEFE
skinparam defaultFontName sans-serif

rectangle "fg" as fg_ #SkyBlue {

самое последнее (+)" as f1
  card "Нацель одно задание\nконкретное : fg %n" as f2

}

  card "SIGTERM (корректный)" as k1
  card "SIGKILL -9 (принудительно)" as k2
}

rectangle "отречься" as disown #Lavender {
  card "Отсоединить от оболочки\n(переживает отключение)" as d1
}

  card "Иммунизированный процесс

nohup_ -left-> fg_ : fg ramène en\navant-plan

  Après disown, fg ne peut
  plus ramener le job
end note
@enduml

Ловушки и типичные ошибки

Перепутать Ctrl+Z и Ctrl+C

Это самая частая ошибка.`Ctrl+C`убивает процесс.`Ctrl+Z`его приостанавливает. Если вы нажимаете на`Ctrl+C`рефлекторно всё состояние потеряно — открытые файлы, сеансы LLM, текущие сборки

@startuml
skinparam backgroundColor #FEFEFE

rectangle "Ctrl+Z (SIGTSTP)" as z #LightGreen {
  card "Процесс, замороженный в памяти" as z1
  card "fg возвращает его нетронутым" as z2
  card "Нет потерь" as z3
}

rectangle "Ctrl+C (SIGINT)" as c #LightCoral {
  card "Процесс завершён" as c1
  card "Состояние утеряно окончательно" as c2
  card "Возврата нет" as c3
}

note bottom of z
  Pause → Reprendre
end note

note bottom of c
  Kill → Perdu
end note
@enduml

Задания локальны для оболочки

jobs, fg et `bg`работают только в оболочке, которая запустила процессы. Если вы откроете новый терминал, вы не увидите заданий другого.

# Terminal 1
$ vim file.txt
^Z
[1]+  Stoppé    vim file.txt

# Terminal 2 (nouveau)
$ jobs
# (rien — les jobs sont locaux au shell)

Для просмотра системных процессов используйте`ps` ou htop:

ps aux | grep vim

Задания не сохраняются при закрытии оболочки

Если вы закроете терминал, все приостановленные и фоновые задания будут удалены. Чтобы процесс остался живым, используйте`nohup`+disown:

$ nohup ./gradlew build &
[1] 12345
$ disown %1
# Fermer le terminal → le build continue

Интерактивные процессы и fg

Некоторые интерактивные программы не работают хорошо после одного`Ctrl+Z`+fg. Это редко, но случается :

  • Некоторые программы, которые используют сигналы (vim, htop, less хорошо справляются`Ctrl+Z`)

  • Долгие сетевые программы (ssh, opencode) обычно корректно получают

  • Программы, которые изменяют терминал (ncurses), могут иногда оставлять терминал в неожиданном состоянии

В случае повреждённого терминала после`fg`, введите :

reset

Почему fg недооценён

Большинство современных разработчиков открывают`fg`поздно, или даже никогда. Несколько причин :

  1. IDE скрывают терминал: VS Code предлагает встроенный терминал, но множественные вкладки делают`fg`внешне менее необходимо

  2. Графические инструменты заменяют CLI: файловые менеджеры, системные мониторы, графические клиенты Git

  3. tmux и screen: эти мультиплексоры решают одну и ту же проблему по-разному, но`fg`проще и всегда доступен

Однако,`fg`есть :

  1. Универсальный: присутствует во всех POSIX-оболочках (bash, zsh, fish…​)

  2. Без зависимости: не нужно устанавливать tmux или screen

  3. Снимок: два удара (Ctrl+Z`потом`fg) для приостановки и возобновления
