Ваша кодовая база растёт. Зависимости между модулями множатся. Архитектурная документация устаревает ещё до того, как будет написана. А что, если ваша сборка Gradle могла бы автоматически генерировать актуальные диаграммы на основе реальной структуры кода? Вот что делает пайплайн Graphify + PlantUML Gradle Plugin :`graphify . --no-viz`извлекает Knowledge Graph,`./gradlew generateKnowledgeGraphDiagram`Он преобразует его в диаграммы PlantUML. Ноль LLM, ноль руководства, 100% детерминированный.

Проблема: диаграммы всегда отстают от кода

Любой проект, превышающий несколько тысяч строк, сталкивается с этим синдромом:

  1. В начале проекта рисуется архитектурная диаграмма

  2. Код меняется, зависимости меняются

  3. Диаграмма становится декоративной ложью

  4. Никто не обновляет его, потому что это утомительно

  5. Новые прибывающие полагаются на это и совершают ошибки

@startuml
skinparam backgroundColor #FEFEFE
skinparam ActivityBackgroundColor #FDEDEC
skinparam ActivityDiamondBackgroundColor #FFF3CD

start

:Diagramme d'architecture créé\n(manuellement, à la main);

:Le code évolue\n(nouvelles classes, nouvelles dépendances);

:Diagramme obsolète\n(ne reflète plus le code);

if (Qui met à jour ?) then (Personne)
    :Documentation mensongère;
    note right: Les nouveaux développeurs\nse basent dessus... et font des erreurs
else (Quelqu'un)
    :Mise à jour manuelle\n(2-3 heures de travail);
    note right: Déjà obsolète\nà la prochaine PR
endif

stop

@enduml

Вопрос не в нужны ли диаграммы? — все знают, что да. Вопрос в том, что:Кто поддерживает их в актуальном состоянии?

Ответ: никто. За исключением случая, когда это автоматическое.

Решение: детерминированный pipeline Knowledge Graph → PlantUML

Принцип прост: вместо того чтобы рисовать диаграммы от руки, мы ихгенерирует из реальной структуры кода.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

actor Développeur
component "Graphify
(pip install graphifyy)" as Graphify
collections "graphify-out/graph.json
(Граф знаний)" as KGJSON
component "Плагин PlantUML Gradle\n(generateKnowledgeGraphDiagram)" as Plugin
component "KnowledgeGraphParser" as Parser
component "KnowledgeGraphRenderer" as Renderer
component "PlantumlService\n(валидация + отрисовка PNG)" as PS
collections "diagrams/knowledge-graph/\n(.puml + .png)" as Output

Développeur --> Graphify : graphify . --no-viz
Graphify --> KGJSON : extrait la structure\ndu code source
Développeur --> Plugin : ./gradlew generateKnowledgeGraphDiagram
Plugin --> Parser : parse(graph.json)
Parser --> Plugin : KnowledgeGraph\n(noeuds + arêtes + communautés)
Plugin --> Renderer : render(graph, filters)
Renderer --> Plugin : code PlantUML\ndéterministe
Plugin --> PS : validateSyntax + generateImage
PS --> Output : .puml + .png

note bottom of Plugin
  Pipeline DÉTERMINISTE
  Aucun appel LLM
  Résultat reproductible
end note

@enduml

Две команды. Вот и всё.

# Étape 1 : extraire le Knowledge Graph
graphify . --no-viz

# Étape 2 : générer les diagrammes PlantUML
./gradlew generateKnowledgeGraphDiagram

Результат ? Файлы`.puml` et .png`в`diagrams/knowledge-graph/, версиированные в Git, всегда актуальны вместе с кодом.

Шаг 1: Установить Graphify и извлечь граф знаний

Установка

Graphify — это инструмент Python, который анализирует вашу кодовую базу и строит структурированный граф знаний:

# Méthode recommandée
uv tool install graphifyy && graphify install --platform opencode

# Alternative avec pip
pip install graphifyy && graphify install --platform opencode

Настроить исключения

Создать файл`.graphifyignore`в корне проекта для исключения файлов, которые не являются частью бизнес-логики :

# Secrets — JAMAIS dans le graphe
*-context.yml
*.env

# Fichiers générés
build/
.gradle/

# Tests fonctionnels
src/functionalTest/

Извлечь граф знаний

graphify . --no-viz

Флаг`--no-viz`пропускает генерацию HTML (бесполезно в конвейере Gradle). Результат — файл`graphify-out/graph.json`содержит :

  • Узлы: классы, функции, файлы — с их типом и сообществом

  • кромки: отношения между узлами (EXTRACTED из кода, INFERRED LLM)

  • Сообщества: автоматические группировки связанных узлов

Пример структуры`graph.json`
{
  "nodes": [
    {"id": "0", "label": "LlmService", "file_type": "code", "community": 0},
    {"id": "1", "label": "ApiKeyPool", "file_type": "code", "community": 0},
    {"id": "2", "label": "PlantumlService", "file_type": "code", "community": 1}
  ],
  "links": [
    {"source": "1", "target": "0", "relation": "uses", "confidence": "EXTRACTED", "weight": 0.9},
    {"source": "0", "target": "2", "relation": "calls", "confidence": "INFERRED", "weight": 0.7}
  ]
}

Исходный код (.kt, .java) анализируется локально с помощью tree-sitter,без апелляции LLM. Только файлы документации (.adoc, .md) требуют вызова LLM для семантического извлечения. Поэтому`--update`код Kotlin почти мгновенный

Шаг 2: Плагин Gradle преобразует Knowledge Graph в PlantUML

Архитектура пайплайна

Плагин`com.cheroliv.plantuml`включает задачу`generateKnowledgeGraphDiagram`который преобразует`graph.json`в диаграммах PlantUML способомполностью детерминированный :

@startuml
skinparam backgroundColor #FEFEFE

participant "Грейдл" as G
participant "GenerateKnowledgeGraphDiagramTask" as Task
participant "KnowledgeGraphParser" as Parser
participant "KnowledgeGraphRenderer" as Renderer
participant "PlantumlService" as PS

collections "graphify-out/graph.json" as JSON

G -> Task : execute
Task -> JSON : read
Task -> Parser : parse(graph.json)
Parser --> Task : KnowledgeGraph\n(noeuds + arêtes + communautés)
Task -> Renderer : render(graph, filters)
Renderer --> Task : code PlantUML\n(déterministe)
Task -> PS : validateSyntax(plantumlCode)
alt syntaxe valide
    Task -> PS : generateImage → .png
else syntaxe invalide
    Task -> Task : save .puml avec warning
end

@enduml

Внутренние компоненты

Компонент Роль

KnowledgeGraphParser

Разбор`graph.json`— поддерживает 3 формата: graphify natif (nodes+links), legacy (communities), плоский. Преобразует числовые ID в метки.

KnowledgeGraphRenderer

Детерминированно преобразует`KnowledgeGraph`в коде PlantUML. Группы по типу, сообщества в пакетах, автоматическая легенда.

GenerateKnowledgeGraphDiagramTask

Задача Gradle, которая оркестрирует: parse → render → validate → PNG. Настраивается через свойства Gradle.

kgmodels.kt

Модели данных:`KnowledgeGraph`, KnowledgeGraphNode, KnowledgeGraphEdge, KnowledgeGraphCommunity, EdgeType.

PlantumlService

Синтаксическая проверка + рендеринг PNG (повторно используется всеми задачами плагина).

Правила рендеринга

Рендерер применяет детерминированные визуальные соглашения :

Тип ребра Нотация PlantUML Значение

извлечённый

-→(сплошная линия, чёрный)

Связь, извлечённая из исходного кода (достоверность)

выведен

..>(пунктирная линия)

Связь, выведенная LLM (оценка уверенности)

неоднозначный

--x(красная пунктирная линия)

Неоднозначное отношение (требует проверки)

Сообщества отображаются как пакеты PlantUML с автоматической палитрой цветов.

Шаг 3: Ежедневное использование

Полная диаграмма

# Générer le diagramme du Knowledge Graph complet
./gradlew generateKnowledgeGraphDiagram

Выход:`diagrams/knowledge-graph/knowledge-graph-full.puml`+.png

Фильтровать по сообществу

# Une seule communauté
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.community=community_0

# Limiter le nombre de noeuds (lisibilité)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.community=community_0 \
  -Pplantuml.kg.maxNodes=15

Фильтровать по типу ребра

# Uniquement les relations certaines (EXTRACTED)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.edgeTypes=EXTRACTED

# Relations certaines + inférées
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.edgeTypes=EXTRACTED,INFERRED

Фильтровать по типу узла и уверенности

# Uniquement les classes de code
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.nodeTypes=code

# Seuil de confiance minimum (pour les INFERRED)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.minConfidence=0.7

Пользовательский каталог вывода

./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.outputDir=docs/architecture

Полный справочник свойств

собственность дефект Описание

plantuml.kg.community

(все)

Фильтровать сообщества по имени (совпадение подстроки)

plantuml.kg.edgeTypes

(все)

Типы рёбер, разделённые запятыми:`EXTRACTED`, INFERRED, AMBIGUOUS

plantuml.kg.minConfidence

Минимальный порог доверия для рёбер

plantuml.kg.maxNodes

(без ограничений)

Максимальное количество узлов для отображения

plantuml.kg.nodeTypes

(все)

Типы узлов, разделенные запятыми (пример`class`, code)

plantuml.kg.outputDir

Полный конвейер в рабочем процессе Gradle

Тип рабочего процесса

@startuml
skinparam backgroundColor #FEFEFE
skinparam ActivityBackgroundColor #E8F4FD
skinparam ActivityDiamondBackgroundColor #FFF3CD
skinparam ActivityBorderColor #2C3E50

start

partition "извлечение" {
    :graphify . --no-viz;
    note right: Analyse le code source\ntree-sitter (local, pas de LLM)

    :graphify-out/graph.json;
    note right: Noeuds + arêtes\n+ communautés
}

partition "ГЕНЕРАЦИЯ" {
    :./gradlew generateKnowledgeGraphDiagram;
    note right: Pipeline déterministe\nparse → render → validate → PNG

    if (Filtres actifs ?) then (Oui)
        :Appliquer filtres\n(community, edgeTypes,\nmaxNodes, nodeTypes);
    else (Non)
        :Diagramme complet;
    endif

    :diagrams/knowledge-graph/\nknowledge-graph-full.puml\nknowledge-graph-full.png;
}

partition "ИНТЕГРАЦИЯ" {
    :git add diagrams/knowledge-graph/;
    :git commit;
    note right: Diagrammes versionnés\ntoujours à jour avec le code
}

stop

@enduml

Интеграция в цикл разработки

Конвейер естественно вписывается в ключевые этапы разработки :

@startuml
skinparam backgroundColor #FEFEFE

state "Разработка" as dev
state "Извлечение
graphify . --no-viz" as extract
state "Генерация
./gradlew generateKnowledgeGraphDiagram" as generate
state "Commit
версионированные диаграммы" as commit

[*] --> dev
dev --> extract : Code modifié
extract --> generate : graph.json à jour
generate --> commit : .puml + .png générés
commit --> dev : Diagrammes dans le repo

note right of extract
  Quasi instantané sur du code Kotlin
  (tree-sitter, pas de LLM)
end note

note right of generate
  Déterministe
  Pas de LLM
  Résultat reproductible
end note

@enduml

Инкрементальное обновление

Когда код меняется, мы не перестраиваем весь граф с нуля :

# Mise à jour incrémentale (fichiers modifiés uniquement)
graphify . --update

# Puis régénérer les diagrammes
./gradlew generateKnowledgeGraphDiagram

--update`извлекает заново только изменённые файлы (обнаруженные по SHA256 в`graphify-out/cache/). Для кода Kotlin это почти мгновенно потому что tree-sitter работает локально без обращения к LLM.

Dogfooding: плагин сам документирует себя

Плагин PlantUML существует для преобразования запросов в диаграммы. Он также может преобразовать Knowledge Graph своей собственной кодовой базы в диаграммы документации. Это dogfooding : плагин использует свой собственный сервис.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

package "Нормальный конвейер
(пользователь → диаграммы)" as normal {
    [Fichier .prompt] as prompt
    [LlmService\n+ ApiKeyPool] as llm1
    [ProcessPlantumlPromptsTask] as task1
    [Diagramme PNG] as out1

    prompt --> task1
    task1 --> llm1
    llm1 --> out1
}

package "Pipeline Knowledge Graph\n(детерминированный, без LLM)" as kg {
    [graphify-out/graph.json] as kgjson
    [KnowledgeGraphParser] as parser
    [KnowledgeGraphRenderer] as renderer
    [PlantumlService] as ps
    [Diagramme PNG\n(documentation du plugin)] as out2

    kgjson --> parser
    parser --> renderer
    renderer --> ps
    ps --> out2
}

package "Pipeline Dogfooding
(LLM → документация плагина)" as dogfood {
    [GraphifyPromptAdapter] as gpa
    [Fichiers .prompt\nauto-générés] as auto_prompt
    [LlmService\n+ ApiKeyPool] as llm2
    [ProcessPlantumlPromptsTask] as task2
    [Diagramme PNG\n(documentation LLM)] as out3

    kgjson --> gpa
    gpa --> auto_prompt
    auto_prompt --> task2
    task2 --> llm2
    llm2 --> out3
}

note "Тот же LlmService, тот же ApiKeyPool,
тот же PlantumlService
— НУЛЬ дублирования" as N

@enduml

Связанные задачи Gradle :

Задача LLM ? Описание

generateKnowledgeGraphDiagram

Нет

Преобразуй`graph.json`в PlantUML (детерминированный)

generateDiagramDocs

Да

генерируй некоторые`.prompt`из графа обрабатывает их через LLM (dogfooding)

 
# Documentation déterministe (rapide, pas de LLM)
./gradlew generateKnowledgeGraphDiagram

# Documentation LLM (plus riche, consomme des tokens)
./gradlew generateDiagramDocs

Почему это детерминировано (и почему это важно)

Ключевой момент конвейера`generateKnowledgeGraphDiagram`:Он не вызывает никакой LLM. Трансформация`graph.json`→ PlantUML — чистая функция.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

rectangle "Конвейер ДЕТЕРМИНИСТИЧНЫЙ
(generateKnowledgeGraphDiagram)" as det {
    [graph.json] as json
    [KnowledgeGraphParser] as parser
    [KnowledgeGraphRenderer] as renderer
    [PlantUML code] as puml

    json --> parser : parse
    parser --> renderer : KnowledgeGraph
    renderer --> puml : render (fonction pure)
}

rectangle "Pipeline LLM\n(processPlantumlPrompts)" as llm {
    [.prompt] as prompt
    [LlmService] as llmSvc
    [ChatModel] as model
    [PlantUML code] as puml2

    prompt --> llmSvc
    llmSvc --> model : API call
    model --> puml2 : réponse non-déterministe
}

note bottom of det
  Même entrée → même sortie
  Pas de latence réseau
  Pas de coût en tokens
  Reproductible en CI
end note

note bottom of llm
  Même entrée → sortie variable
  Latence réseau (1-5s)
  Coût en tokens
  Nécessite une clave API
end note

@enduml

Конкретные преимущества:

преимущество Влияние

воспроизводимость

даже`graph.json`→ тот же график. Точно. Каждый раз.

Нулевая стоимость

Без вызова LLM = без токенов = без счёта за API

Нулевая задержка

Разбор + рендеринг занимает ~100 мс, а не 1-5 секунд.

Совместимая CI

API-ключ не нужен. Нет неустойчивого теста из‑за переменного ответа LLM.

версионный

Le .puml`Сгенерировано — это текст. Его можно`diff, ревьюер в PR, версионировать в Git.

Интеграция в управление проектом

В нашем проекте этот конвейер интегрируется в стратегию управления контекстом EAGER/LAZY для ИИ-агента. Knowledge Graph заменяет ручную архитектурную документацию структурированным, запрашиваемым и автоматически обновляемым графом.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

package "EAGER\n(всегда заряжен)" as eager {
    [PROMPT_REPRISE.adoc\n(contexte session)] as pr
    [INDEX.adoc\n(vue d'ensemble)] as idx
    [GRAPH_REPORT.adoc\n(~50 lignes)] as gr
}

package "LAZY — Стратегия\n(по запросу)" as lazy_strat {
    [Méthodologies] as meth
    [Archives sessions] as sessions
}

package "LAZY — Graphify
(целевые запросы)" as lazy_graph {
    [graph.json] as gj
    [Queries\n(query/path/explain)] as queries
}

package "Конвейер PlantUML
(автоматически сгенерирован)" as puml {
    [generateKnowledgeGraphDiagram] as kgTask
    [generateDiagramDocs] as ddTask
    [Diagrammes PNG] as diagrams
}

Agent --> eager : Lit en début de session
Agent ..> lazy_strat : Charge si type détecté
Agent ..> lazy_graph : Query si besoin structurel
kgTask --> diagrams : Déterministe
ddTask --> diagrams : Via LLM

note right of gr
  Condensé du Knowledge Graph
  God nodes + communautés
  Remplace ECOSYSTEM_OVERVIEW
  (225 lignes → 50 lignes)
end note

@enduml

Сочетание двух систем является дополнительным:

  • Стратегия управляет когда и как— управление, рабочий процесс, архивация

  • Graphify управляет ЧТОМ и ГДЕ— структура кода, связи, целевые запросы

Подводные камни и меры по смягчению

Ловушка Описание Смягчение

Слишком плотный граф

Большой проект генерирует сотни нечитаемых узлов

Использовать`-Pplantuml.kg.maxNodes=30`и фильтровать по сообществу

Слишком широкие исключения

Слишком много файлов в`.graphifyignore`уменьшает значение графика

Начать с исключения только credentials и build

Направление стрелок

Ребра INFERRED могут иметь неоднозначное направление

Фильтровать по`-Pplantuml.kg.edgeTypes=EXTRACTED`только для определённых отношений

устаревший граф

Код меняется, но граф не перестраивается

Использовать`graphify . --update`регулярно или git-хук`graphify hook install`

Обновленная стоимость

Инкрементальные обновления практически бесплатны (tree-sitter local)

Только документы (.adoc) потребляют токены LLM
