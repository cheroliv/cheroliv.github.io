OpenCode не является поставщиком моделей.Это CLI с открытым исходным кодом (github.com/anomalyco/opencode) который оркеструет агентов ИИ. Он не продает подписку, он не предоставляет вывод. Это эквивалент`git`для версионирования: инструмент, а не сервис. Ollama Cloud — поставщик инференса.Локальная установка Ollama действует как client — она аутентифицируется у серверов Ollama через уникальный SSH-ключ (Device Key) и делегирует им выполнение помеченных моделей`:cloud`. Подписка Pro (20€/мес) разблокирует более высокие квоты и позволяет объединять несколько учетных записей на одной машине через Docker.

Введение: Почему аудит?

Два месяца назад я использовал модели бесплатно на моей локальной установке Ollama. Затем я оформил первую подписку Ollama Cloud Pro за 20 евро в месяц, которая позволяет мне использовать облачные модели (те, у которых есть тег`:cloud`) через провайдера`ollama-cloud`. Второй абонемент последовал через месяц на отдельном Docker-экземпляре с собственным аккаунтом и собственным ключом SSH — метод накопления, описанный в моя статья о накоплении подписок.

Вопрос, который меня терзал: оправданы ли эти 20 евро в месяц? Не наугад. С цифрами.

Чтобы ответить, мне нужны были точные данные. Никаких оценок. Никаких средних. Моё потребление реальное, токен за токеном, модель за моделью, сессия за сессией.

И OpenCode — CLI — хранит всё это в базе данных SQLite.

База данных OpenCode: золотой рудник

OpenCode сохраняет полную историю своих сессий в файле SQLite, расположенном по адресу`~/.local/share/opencode/opencode.db`. La mienne pèse 660 Mo pour 73 jours d’utilisation — une base de données de production tout à fait respectable.

$ ls -lh ~/.local/share/opencode/opencode.db
-rw-r--r-- 1 cheroliv cheroliv 660M mai 18 12:25 opencode.db

Схема

База содержит около двадцати таблиц, но три из них имеют решающее значение для нашего аудита:

  * cost : REAL
  * tokens_input : INTEGER
  * tokens_output : INTEGER
  * tokens_reasoning : INTEGER
  * tokens_cache_read : INTEGER

  * time_created : INTEGER
  * project_id : TEXT
}

  * id : TEXT
  --
  * session_id : TEXT <<FK>>
  * data : TEXT (JSON)
  * time_created : INTEGER
}

  * id : TEXT
  --
  * worktree : TEXT
  * name : TEXT
}

S ||--o{ M : "session_id"
S }o--|| P : "project_id"

note right of S
  La table session agrège
  tokens + coût + modèle.
  C'est notre point d'entrée
  principal.
end note

  Les messages individuels.
  Le champ data contient
  le modèle utilisé (format JSON)
  même si la session change
  de modèle en cours de route.

@enduml

Стол`session`идеально подходит для глобального аудита: каждая сессия имеет свой агрегированный подсчёт токенов, используемую модель и её стоимость. Поле`model`является необработанным JSON:

{
  "id": "deepseek-v4-pro:cloud",
  "providerID": "ollama-cloud",
  "variant": "default"
}

Поле`cost`в базе OpenCode отражает только внешние расходы на API, оплачиваемые по мере использования через API-ключ (Google Gemini, OpenAI и т.д.). Вызовы через Ollama — будь то локально или через Ollama Cloud Pro — помечены`cost=0`потому что стоимость фиксированная (подписка), а не за токен. Истинная стоимость этих вызовов — это ежемесячная подписка.

код экстракции

Не нужно устанавливать что-либо. Node.js 22+ включает экспериментальный модуль SQLite (node:sqlite) работает безупречно. Вот скрипт, который дал мне всё:

const { DatabaseSync } = require('node:sqlite');
const db = new DatabaseSync(
  `${process.env.HOME}/.local/share/opencode/opencode.db`,
  { readonly: true }
);

// 1. Statistiques globales
const global = db.prepare(`
  SELECT
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(tokens_reasoning) as total_reasoning,
    SUM(tokens_cache_read) as total_cache_read,
    SUM(cost) as total_cost
  FROM session
`).get();

// 2. Ventilation par modèle et fournisseur
const byModel = db.prepare(`
  SELECT
    json_extract(model, '$.id') as model_id,
    json_extract(model, '$.providerID') as provider,
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(cost) as total_cost
  FROM session
  WHERE model IS NOT NULL
  GROUP BY model_id, provider
  ORDER BY SUM(tokens_input) DESC
`).all();

// 3. Par mois
const monthly = db.prepare(`
  SELECT
    strftime('%Y-%m', datetime(time_created/1000, 'unixepoch')) as month,
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(cost) as total_cost
  FROM session
  WHERE time_created IS NOT NULL
  GROUP BY month
  ORDER BY month
`).all();

// 4. Messages par modèle (détection des changements intra-session)
const msgByModel = db.prepare(`
  SELECT
    json_extract(m.data, '$.model.providerID') as provider,
    json_extract(m.data, '$.model.modelID') as model_id,
    COUNT(*) as messages
  FROM message m
  WHERE json_extract(m.data, '$.model') IS NOT NULL
  GROUP BY provider, model_id
  ORDER BY COUNT(*) DESC
`).all();

console.log({ global, byModel, monthly, msgByModel });
db.close();

Флаг`--experimental-sqlite`Требуется на Node.js 22.x. На Node.js 24+ модуль стабилен и больше не требует флага.

Накопление подписок Ollama Cloud Pro: Метод Docker

Если одной подписки недостаточно, их накапливают. Принцип заключается в изоляции каждой подписки в собственной установке Ollama с собственным SSH‑ключом аутентификации. Docker делает это тривиальным.

Полный метод подробно описан в статья о накоплении Docker, вот принцип :

@startuml
skinparam backgroundColor #FEFEFE
skinparam defaultFontSize 12

title Архитектура — Два подписки Ollama Cloud Pro на одной машине
left to right direction

node "Моя физическая машина" {
  frame "Экземпляр Ollama A (родной)
порт :11434" as Native {
    database "Identity A\n/usr/share/ollama/.ollama/id_ed25519"
  }
  frame "Ollama Instance B (Docker)
порт :11435" as Docker {
    database "Идентичность B
~/ollama-b-data/id_ed25519"
  }
}

cloud "Ооллама Клауд" {
  actor "Профессиональный аккаунт A
(почта 1)" as A
  actor "Профессиональный аккаунт B
(электронная почта 2)" as B
}

Native --> A : "Device Key A"
Docker --> B : "Устройство Ключ B"

note bottom of Docker
  Conteneur Docker isolé :
  - Clé SSH distincte
  - Port réseau distinct (11435)
  - Volume persistant (~/ollama-b-data)
  - restart: always
end note
@enduml

Шаблон прост:

  1. Создать том`~/ollama-b-data`

  2. Запустить контейнер Docker`ollama/ollama:0.20.2`сопоставлен с`11435:11434`

  3. Получить SSH-ключ контейнера → сохранить его на ollama.com

  4. делать`ollama signin`с вторым email

  5. Настроить OpenCode с двумя поставщиками (`ollama`на :11434,`ollama-b`на :11435)

Два счета, одна синяя карта, ноль конфликтов.

Тратить 2 часа в день на отладку галлюцинаций модели низшего качества обходится дороже, чем 20 евро в месяц.

Спокойствие ума

Фиксированный тариф = без сюрпризов. При оплате за токен всплеск активности может очень больно ударить.

Цены, указанные выше, относятся к маю 2026 года. Через шесть месяцев всё снизится. Но структурное соотношение сил — фиксированная подписка против оплаты по использованию — останется благоприятным для подписки для крупных потребителей.
