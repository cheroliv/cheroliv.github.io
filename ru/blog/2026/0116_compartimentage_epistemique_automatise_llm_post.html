Автоматизированная эпистемологическая компартментация — Как LLM защищает мой ментальный сад

Мой LLM не ограничивается выполнением моих задач Gradle. Он — страж границы между моей частной мыслью и моим публичным выражением. Каждая идея классифицируется — Видение, Мнение, Стратегия — прежде чем будет направлена. Вот как эта автоматизированная эпистемологическая изоляция защищает мой умственный сад, не заставляя меня молчать.

Проблема : думать свободно, не публикуя ничего

Когда соло‑разработчик документирует свой мыслительный процесс с помощью LLM, он сталкивается с парадоксом:

CAPTURE TOUT (Cercle 0, jardin secret)
  ├→ Brain dump libre, pas de censure
  ├→ Idées brutes, spéculations, intuitions non vérifiées
  ├→ Allers-retours LLM : challenger, itérer, raffiner
  └→ Le LLM voit TOUT — le bon, le flou, l'embryonnaire

PUBLICATION SÉLECTIVE (Cercle 4, blog public)
  ├→ Uniquement les décisions actées
  ├→ Uniquement les patterns testés (>100 tests PASS)
  ├→ Uniquement ce qui a de la valeur pour le lecteur
  └→ JAMAIS une spéculation présentée comme une vérité

Между этими двумя крайностями, естьфильтр. Вопрос: кто это делает? Усталый человек в конце сеанса? Неопытный скрипт с регулярными выражениями? Или сам LLM, который уже всё прочитал?

Мой ответ: LLM.

Паттерн STIMULUS — Родиться, Зафиксировать, Разбавить, Умереть

СТИМУЛУС - это файл`.adoc`временный в корне рабочего пространства (Круг 0). Его имя следует выразительному соглашению —PICTURE_ME_ROLLIN.adoc, HOLD_MY_BEER.adoc, ONCE_UPON_A_TIME.adoc— который отражает исследовательское намерение момента.

Его жизненный цикл беспощаден:

CRÉATION (Cercle 0)
  ├→ Fichier vide, brain dump libre
  ├→ Allers-retours LLM ← → développeur
  └→ Aucune pression de structure ou de publication

MATURATION
  ├→ Le contenu se densifie
  ├→ Des sections émergent naturellement
  └→ Le fichier devient une référence informelle de session

CLASSIFICATION ÉPISTÉMIQUE ← FAIT PAR LE LLM
  ├→ VISION    → publiable, diluer dans les docs publics + blog
  ├→ OPINION   → confiner au Cercle 0, pas de dilution externe
  └→ STRATÉGIE → dilution restreinte (docs racine, PAS de blog)

DILUTION (Cascade vers Cercles légitimes)
  ├→ VISION → WORKSPACE_AS_PRODUCT.adoc + WHAT_THE_GAMES.adoc + blog
  ├→ STRATÉGIE → WORKSPACE_AS_PRODUCT.adoc (section business)
  └→ OPINION → reste dans le stimulus, ne bouge pas

ARCHIVAGE + SUPPRESSION
  ├→ Snapshot dans configuration/vision-archive/ (trace historique)
  └→ rm du stimulus — il a fini son travail

Стимул, который сохраняется более 2 сеансов без разбавления, является антипаттерном. Либо информация слишком важна, чтобы гнить во временном файле (→ разбавлять), либо она слишком неопределённа, чтобы заслуживать существования (→ удалять).

Делегирование LLM : Почему именно LLM выполняет фильтрацию

Я не хардкожу классификацию Vision/Opinion в Kotlin. Я внедряю его в leсистемный промптLLM через`AGENT_GOVERNANCE.adoc` :

----
----
Pour chaque dilution de stimulus ou session, tu es responsable de classifier
le contenu :
- VISION : décision architecturale actée, pattern testé en production (>100 tests PASS),
  décision documentée dans BACKLOG ou ROADMAP
- OPINION : spéculation, hypothèse non validée par des tests, intuition
  sans ancrage expérimental
- STRATEGIE : positionnement business, pricing, marché cible

Règles :
- Si OPINION, le contenu reste confiné dans son cercle d'origine
- Si VISION, tu procèdes à la dilution dans les documents racine
- Si STRATEGIE, dilution restreinte (docs racine, pas de blog public)
- Cette classification détermine aussi si un article de blog est publiable
  sur cheroliv.com
----

LLM читает эту директиву**раньше**для обработки сессии. Она находится в своём непосредственном контексте, а не в отдельном файле. Это *детерминированный инжиниринг промптов* : поведение возникает из внедрённого текста, а не из внешнего классификатора.

=== Почему это работает — и почему это контр-интуитивно

Стандартная реакция: « Ты доверяешь классификацию ИИ? А если она ошибается?

Ответ: человек не справляется лучше в 2 часа ночи. Разница в том, что LLM, он, читает ВСЁ. У него полный контекст сессии и целевых документов. Он знает что`VPS ECO-16 12€ HT`является инфраструктурным решением (VISION) в то время как`« le TTS ElevenLabs sonne plus naturel que Coqui »`это непроверенное мнение, не подтверждённое бенчмарком.

Человек в конце сеанса читает по диагонали и делает всё, что может. LLM читает исчерпывающе и применяет систематическую сетку. Результат**более надежный**, не менее.

И для 20% неоднозначных случаев — серая зона, где даже LLM колеблется — ответ не «добавить кода». Ответ**LangGraph4j**(EPIC 13): граф состояния, который для неоднозначных случаев активирует узел Human-in-the-Loop и передаёт решение человеку. Но для 80% ясных случаев достаточно LLM.

== Полный трубопровод: от Brain Dump до блог-поста

Вот полный поток — от сырых идей до опубликованной статьи — с LLM как единственным фильтр :

[source]
----
CERCLE 0 (jardin secret)
  PICTURE_ME_ROLLIN.adoc   ← brain dump, allers-retours LLM
       ↓
  [LLM classifie] → VISION / OPINION / STRATÉGIE
       ↓
  VISION → dilution dans WORKSPACE_AS_PRODUCT.adoc
         → dilution dans WHAT_THE_GAMES_BEEN_MISSING.adoc
         → dilution dans WORKSPACE_VISION.adoc (session context)
         → RÉDACTION ARTICLE BLOG ← le LLM écrit, pas le dev
       ↓
CERCLE 4 (blog public)
  0116_compartimentage_epistemique.adoc  ← publié sur cheroliv.com
       ↓
  ./gradlew deploy (bakery-gradle → JBake → JGit → GitHub Pages)
       ↓
  https://cheroliv.com/blog/2026/0116/  ← live
----

Разработчик не пишет статью. Он бросает вызов, перечитывает, подтверждает. LLM пишет. Цикл :

1. Свободный дамп мозга → без цензуры
2. Эпистемическая классификация LLM → нет утечки
3. Написание LLM → без прокрастинации
4. Проверка человеком → без ошибки

Историческое узкое место — « у меня нет времени писать » — устранено. LLM выполняет основную работу. Человек делает то, что может сделать только человек: судит.

== Три корневых документа — Как информация находит своё место

Каждый целевой документ имеет точную роль в каскаде разведения :

[cols="1,3,2"]
|===
|Документ |Что он получает |Тип контента |`WORKSPACE_AS_PRODUCT.adoc` |Архитектурные решения, технический стек, дорожная карта, бизнес-модель |ВИДЕНИЕ + СТРАТЕГИЯ |`WHAT_THE_GAMES_BEEN_MISSING.adoc` |Шаблоны, уроки, антипаттерны, онтология, формальные правила |ВИДЕНИЕ (проверенные шаблоны) |`WORKSPACE_VISION.adoc` |Контекст сессии, история решений, точки инфраструктуры |ВИДЕНИЕ + СТРАТЕГИЯ (контекст) |`AGENT_GOVERNANCE.adoc` |Правила управления, портфель проектов, процедуры |ВИДЕНИЕ (управление) |**Блог cheroliv.com** |Публичные статьи, ценность для внешнего читателя |VISION только
|===

Один и тот же стимул может поддерживать четыре документа + блог — каждое назначение получает соответствующую ему часть, без избыточности, без противоречий.

Это то, что произошло для`PICTURE_ME_ROLLIN.adoc`(3 мая 2026) :

| Информация | Классификация | Назначения | | Перечень 13+ проектов foundry/ | VISION | WORKSPACE_AS_PRODUCT | | VPS-2 OVH, edster.cloud, 8.49€/мес | VISION | WORKSPACE_AS_PRODUCT + WORKSPACE_VISION |  Африканский рынок готов для мобильных денег » | СТРАТЕГИЯ | WORKSPACE_AS_PRODUCT (section business)  DeepSeek > Kimi > GLM для длинного контекста » | МНЕНИЕ → ВИДЕНИЕ | Ограничен, затем повышен после бенчмарка (статья 0112) | Синтетический сотрудник как конечный продукт | СТРАТЕГИЯ | WORKSPACE_AS_PRODUCT (без блога) |

== Шаблон Baby-Step + TestContainer + Doc Vivante — код, который тестирует сам себя

Паттерн `STIMULUS/Dilution` управляет мышлением. Его аналог для кода — это паттерн `Baby-Step/TestContainer/Doc Vivante`, подтверждённый `plantuml-gradle` (380/380 тестов PASS, 137 сессий без утечки Docker) :

[cols="1,3"]
|===
|принцип |Правило |**маленький шаг** |Никогда не более 3 баллов на УС. Если УС вызывает страх, разрезать. УС в 1 балл, который проходит > УС в 8 баллов, который отстаёт. |**TestContainer сначала** |Перед бизнес-кодом, контейнер. Тест инфраструктуры проходит → гарантирована стабильная среда. |**Набор данных комитета** |Минимальное, но представительное подмножество в`src/test/resources/`, без ПИИ. Клонируемый, запускаемый. |**Живая документация** |Каждый тест Cucumber = предложение на естественном языке. Исходный код — это исполняемая спецификация. Никакой документации Markdown для поддержания. |**Автоматическая очистка** |Нулевая утечка ресурсов. Контейнеры-сироты,`/tmp/gradle-test-*`: всё убрано.
|===

Этот шаблон — причина, по которой plantuml-gradle никогда не имел регрессий Docker в 138 сессий. Он гарантирует, что код, взаимодействующий с внешней инфраструктурой (PostgreSQL, Redis, Kafka), всегда тестируется в среде, идентичной продакшену — версионированной, воспроизводимой и запускаемой одной командой.

== Вывод: свобода мысли без страха публикации

Автоматизированная эпистемическая сегрегация не является инструментом цензуры. Это**освободитель**. Он позволяет мыслить свободно, спекулировать без фильтров, вываливать всё, что приходит в голову — никогда не боясь, что зародыш идеи окажется в блоге.

LLM — хранитель этой границы. Он читает всё. Он классифицирует. Он размывает то, что заслуживает выжить. Он изолирует то, что должно оставаться приватным. Он пишет то, что подлежит публикации.

И разработчик, он, сохраняет за собой последнее слово: перечитать, оспорить, утвердить. Судить.

Это разделение труда, которого не хватало одиночному разработчику: синтетический сотрудник, занимающийся ментальными формальностями, чтобы человек мог сосредоточиться на том, что он делает лучше всего — проектировать, архитектурировать, принимать решения.
