Часть 1: Настроить простой CI/CD пайплайн для Python и PyPI

Введение

Цель : Сопроводить читателя в создании минималистичного, но функционального CI/CD-пайплайна для Python-приложения с автоматическим развертыванием на PyPI.

Автоматизация процессов разработки стала неизбежной в современных проектах. Хорошо спроектированный CI/CD‑pipeline позволяет не только выявлять регрессии на ранних этапах цикла разработки, но и полностью автоматизировать процесс развёртывания.

В этой статье мы рассмотрим, как настроить полный пайплайн с GitHub Actions для приложения Python: от непрерывной интеграции (CI) до непрерывного развертывания (CD) на PyPI.

Архитектура конвейера

Наш конвейер состоит из двух отдельных рабочих процессов:

  1. конвейер CI: Выполняется при каждом push и pull request

  2. Конвейер CD: Срабатывает только во время релизов GitHub

Настройка конвейера непрерывной интеграции (CI)

Структура CI Workflow

CI-рабочий процесс разработан для проверки каждого вклада в код. Вот его полная конфигурация:

name: CI/CD Pipeline

on:
  push:
    branches:
      - main
  pull_request:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
    - name: Checkout code
      uses: actions/checkout@v4

    - name: Set up Python
      uses: actions/setup-python@v5
      with:
        python-version: '3.x'

    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install -r requirements.txt
        pip install ruff pytest pytest-mock

    - name: Run Linting (Ruff)
      run: ruff check .

    - name: Run Tests (Pytest)
      run: pytest

Анализ этапов CI

Триггеры (on)

----
----
on:
  push:
    branches:
      - main
  pull_request:
    branches:
      - main
----

Конвейер запускается при: - Каждый push в ветку`main` - Каждый pull request к`main`

Этот подход гарантирует, что основной код остаётся стабильным и что любой вклад одобрен перед интеграцией.

==== 2. Среда выполнения

----

runs-on: ubuntu-latest

Ubuntu Latest предлагает хороший компромисс между производительностью, стоимостью и совместимостью для большинства проектов на Python.

==== 3. Выдача кода

```yaml
----
----
- name: Checkout code
  uses: actions/checkout@v4
----

действие`checkout@v4`Получает исходный код репозитория. Версия v4 приносит улучшения производительности и безопасности.

==== 4. Конфигурация Python

----

- name: Set up Python uses: actions/setup-python@v5 with: python-version: '3.x'

Использование`'3.x'`позволяет автоматически использовать последнюю стабильную версию Python 3, упрощая обслуживание.

==== 5. Установка зависимостей

```yaml
----
----
- name: Install dependencies
  run: |
    python -m pip install --upgrade pip
    pip install -r requirements.txt
    pip install ruff pytest pytest-mock
----

Этап: - Обновить pip до последней версии - Установите зависимости проекта - Добавьте инструменты разработки (линтинг и тесты)

==== 6. Линтинг с Ruff

----

- name: Run Linting (Ruff) run: ruff check .

**Ruff**является сверхбыстрым линтером Python, написанным на Rust. Он объединяет функции нескольких инструментов (Flake8, Black, isort) в один мощный инструмент.

==== 7. Выполнение тестов

```yaml
----
----
- name: Run Tests (Pytest)
  run: pytest
----

Pytest запускает весь набор тестов, гарантируя, что изменения не вызывают регрессий.

== Конфигурация пайплайна развертывания (CD)

=== Структура рабочего процесса CD

CD workflow запускается только при релизах GitHub и автоматизирует публикацию на PyPI :

[source,yaml]
----
name: Publish to PyPI

on:
  release:
    types:
      - published

jobs:
  deploy:
    runs-on: ubuntu-latest

    steps:
    - name: Checkout code
      uses: actions/checkout@v4

    - name: Set up Python
      uses: actions/setup-python@v5
      with:
        python-version: '3.x'

    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install setuptools wheel twine

    - name: Build and publish
      env:
        TWINE_USERNAME: __token__
        TWINE_PASSWORD: ${{ secrets.PYPI_API_TOKEN }}
      run: |
        python setup.py sdist bdist_wheel
        twine upload dist/*
----

=== Анализ этапов CD

==== 1. Срабатывание Release

----

on: release: types: - published

Pipeline CD срабатывает только при публикации релиза GitHub. Такой подход обеспечивает точный контроль над развертываниями.

==== 2. Установка средств сборки

```yaml
----
----
pip install setuptools wheel twine
----

- **setuptools**: Инструменты упаковки Python - **колесо**: Формат дистрибутива современного Питона - **шпагат**: Безопасный инструмент для загрузки в PyPI

==== 3. Настройка аутентификации

----

env: TWINE_USERNAME: __token__ TWINE_PASSWORD: ${{ secrets.PYPI_API_TOKEN }}

Аутентификация использует токен API PyPI, хранящийся как секрет GitHub, который более безопасен, чем классические учётные данные.

==== 4. Сборка и публикация

```yaml
----
----
run: |
  python setup.py sdist bdist_wheel
  twine upload dist/*
----

- `sdist`Создаёт исходный дистрибутив - `bdist_wheel`: Создаёт wheel (бинарное распределение) - `twine upload`Опубликуй дистрибутивы на PyPI

== Настройка пакета Python

=== Структура setup.py

Чтобы пайплайн работал, ваш проект должен включать файл`setup.py`:

[source,python]
----
from setuptools import setup, find_packages

with open("README.adoc", "r", encoding="utf-8") as fh:
    long_description = fh.read()

setup(
    name="playlist-downloader",
    version="1.0.0",
    author="Votre Nom",
    author_email="votre.email@example.com",
    description="CLI tool for managing YouTube playlists",
    long_description=long_description,
    long_description_content_type="text/plain",
    url="https://github.com/cheroliv/playlist-downloader",
    packages=find_packages(),
    classifiers=[
        "Development Status :: 4 - Beta",
        "Intended Audience :: Developers",
        "License :: OSI Approved :: MIT License",
        "Operating System :: OS Independent",
        "Programming Language :: Python :: 3",
        "Programming Language :: Python :: 3.8",
        "Programming Language :: Python :: 3.9",
        "Programming Language :: Python :: 3.10",
        "Programming Language :: Python :: 3.11",
    ],
    python_requires=">=3.8",
    install_requires=[
        "typer>=0.9.0",
        "yt-dlp>=2023.1.6",
        "google-api-python-client>=2.70.0",
        "google-auth-oauthlib>=0.7.1",
        "pymonad>=2.4.0",
        "pyyaml>=6.0",
    ],
    entry_points={
        "console_scripts": [
            "playlist-downloader=cli:app",
        ],
    },
)
----

=== Ключевые моменты setup.py

1. **Метаданные**: Название, версия, автор, описание
2. **Зависимости**Список требуемых пакетов
3. **Точки входа**: Открытые команды CLI
4. **Классификаторы**: Метаданные для PyPI

== Безопасность с использованием секретов GitHub

=== Настройка токена PyPI

1. **Создать токен API на PyPI**:

- Войдите в PyPI - Перейдите в Account Settings > API tokens - Создайте новый токен с соответствующими разрешениями

1. **Добавить секрет в GitHub** :

- Настройки репозитория > Секреты и переменные > Действия - Создайте новый секрет с именем`PYPI_API_TOKEN` Вставьте ваш токен PyPI

== Мониторинг и отладка

=== Логи и мониторинг

GitHub Actions предоставляет подробные журналы для каждого шага. Для отладки:

1. **Проверьте логи**де каждого шага
2. **Активируйте отладку**с`ACTIONS_STEP_DEBUG`
3. **Используйте артефакты**для сохранения файлов сборки

----

- name: Upload build artifacts uses: actions/upload-artifact@v3 if: failure() with: name: build-logs path: build/

=== Уведомления

Добавьте уведомления Slack или email :

```yaml
----
----
- name: Notify on failure
  if: failure()
  uses: 8398a7/action-slack@v3
  with:
    status: ${{ job.status }}
    webhook_url: ${{ secrets.SLACK_WEBHOOK }}
----

== Заключение

Внедрение надёжного CI/CD-пайплайна с использованием GitHub Actions кардинально преобразует опыт разработки. Автоматизируя линтинг, тесты и развёртывание, вы :

- **Сократите ошибки**в производстве - **Ускорьте циклы**разработки - **Улучшите доверие**в ваших релизах - **Упростите сотрудничество**в команде

Этот пайплайн можно адаптировать к различным типам проектов Python, настраивая инструменты линтинга, фреймворки тестирования или места развертывания.

Первоначальные инвестиции в настройку этих рабочих процессов быстро окупаются за счёт экономии времени и снижения количества ручных ошибок при развертывании.
