Lesezeit: 15 minutes

Du landest bei einem Projekt mit 100 000 Zeilen. Zwanzig Module, hundert Klassen, unsichtbare Abhängigkeiten, eine Geschichte vergessener Refactorings. Das README verspricht eine Architektur „microservices“, doch der Code erzählt etwas anderes. Wie lange dauert es, produktiv zu sein?Drei Monate— wenn Sie Glück haben. Und wenn eine automatisch generierte interaktive Karte des Codes dies auf drei Tage reduzieren könnte?

Die Onboarding-Wand

Jeder Entwickler hat diese Szene erlebt:

  1. Tag 1: Wir zeigen dir das README (letzte Aktualisierung: vor 18 Monaten)

  2. Tag 3: Sie entdecken, dass das Modul`billing`ruft das Modul heimlich`notification`

  3. Tag 7: Ein Senior sagt dir: "Ach ja, diese Klasse macht in Wirklichkeit zwei Dinge, wir hatten vorgesehen, sie aufzuteilen

  4. Tag 14 : Sie erkennen, dass die gesamte Geschäftsintelligenz in`utils/LegacyHelper.java`— eine Datei, die nirgendwo referenziert wird

skinparam backgroundColor #FEFEFE

:Arrivée sur le projet;

note right: "Ah ja, es ist ein Legacy..."

:Génère une documentation mentale;
note right: Incomplète, subjective

:Productif ?;

@enduml

Das Problem ist nicht der Mangel an Dokumentation — es ist dasEs fehlt eine KarteEine Karte, die das wirkliche Gebiet zeigt, nicht das imaginäre Gebiet des letzten Redesigns.

Was ist ein Knowledge Graph?

Ein Knowledge Graph ist eine strukturierte Darstellung deswissenenthalten in deiner Codebasis:

Entität Beispiel im Code Rolle im Graphen

Knoten

Klasse, Funktion, Konzept

Knoten des Graphen

Kante

Aufruf, Erbe, Import

Verbindung zwischen zwei Knoten

Gemeinschaft

Gruppe verwandter Klassen

visueller Cluster

Kantentyp

EXTRAHIERT, GESCHLOSSEN, MEHRDEUTIG

Vertrauen in die Beziehung

Vertrauensscore

0.0 à 1.0

Zuverlässigkeit einer Kante INFERRED

Hyperkante

Relation 3+ Knoten

Architektonische Komplexität

Der Unterschied zu einem einfachen UML‑Diagramm?Ein UML-Diagramm zeigt, was der Entwickler entschieden hat zu zeigen. Ein Knowledge Graph zeigt was tatsächlich dort ist, einschließlich der versteckten Abhängigkeiten und der emergenten Konzepte.

Der verlorene Kontext: ein konkretes Szenario

Stellen Sie sich eine neue Entwicklerin, Anaïs, vor, die zum Projekt stößt. Sie muss eine Funktionalität zum "quota tracking" für LLM-Aufrufe hinzufügen.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

actor "Anaïs (neu)" as ana

rectangle "Was sie sucht" {
  [QuotaTracker] as qt
  [ApiKeyPool] as akp
  [RateLimiter] as rl
}

rectangle "Was sie findet" {
  [LlmService] as ls
  [ConfigLoader] as cl
}

ana --> ls : "Suche 'quota'
in der IDE"
ls --> cl : "Finde ConfigLoader
(erwähne 'quota'
in einem Kommentar)"
cl --> qt : "3 Wochen später :
entdecke QuotaTracker
existiert bereits"

note right of qt
  **Contexte perdu :**
  QuotaTracker était dans
  un module non-référencé
  dans le README
end note

@enduml

Mit einem Wissensgraph, hätte Anaïs gesehen in5 Minuten:

  • QuotaTracker`ist damit verbunden`ApiKeyPool(KanteEXTRACTED)

  • RateLimiter`ist verbunden mit`QuotaTracker(KanteINFERRED, Vertrauen 0.82)

  • Diese drei Knoten bilden eineGemeinschaftKontingentverwaltung

  • Ein hyperedge verbindet auch`LlmService`— der Einstiegspunkt

Pipeline : individuell zusammengestellter Code in einem Befehl

Das Graphify‑Pipeline + Gradle‑Plugin verwandelt deine Codebasis in ein PlantUML‑Diagramm.zwei Befehle(empty)

@startuml
skinparam backgroundColor #FEFEFE
skinparam sequenceArrowThickness 2

actor "Entwickler" as dev
participant "graphifizieren" as gfy
participant "graphify-out/graph.json" as json
participant "Gradle-Plug-in" as plg
participant "KnowledgeGraphParser" as kgp
participant "KnowledgeGraphRenderer" as kgr
participant "Diagramme/Wissen-Graph/" as out

dev -> gfy : graphify update . --no-viz
gfy -> json : extrait nœuds, arêtes,\ncommunautés, confiances

dev -> plg : ./gradlew generateKnowledgeGraphDiagram
plg -> kgp : parse graph.json
kgp -> kgr : nodes + edges + communities
kgr -> out : génère .puml + .png

out --> dev : diagramme interactif

@enduml

Null LLM.Alles ist deterministisch: gleicher Code, gleicher Graph, gleiches Diagramm. Reproduzierbar, versionierbar, offline abrufbar.

Kantentypen: Was das Vertrauen sagt

@startuml
skinparam backgroundColor #FEFEFE

node "LlmService" as ls
node "Diagrammprozessor" as dp
node "ConfigLoader" as cl
node "ApiKeyPool" as akp
node "LegacyHelper" as lh #F1948a

ls --> dp : EXTRACTED\n(calls, direct)
cl ..> akp : INFERRED 0.75\n(creates, probable)
ls -[#FF5722]-> lh : AMBIGUOUS\n(legacy, douteux)

legend right
  |= Type |= Symbole |= Signification |
  | EXTRACTED | <b>--></b> | Relation visible dans le code |
  | INFERRED | <b>..></b> | Relation déduite (score de confiance) |
  | AMBIGUOUS | <b>--x</b> | Relation incertaine, à vérifier |
endlegend

@enduml

Die Kantenarten sind entscheidend für das Onboarding:

  • EXTRACTED: du kannst ruhig navigieren — das ist im Code

  • abgeleitet(0.6-0.8) : wahrscheinlich richtig, aber prüfe bevor du refaktorierst

  • INFERRED(0.8+) : sehr zuverlässig — verwende es als Referenz

  • mehrdeutig: Achtung, empfindlicher Punkt. Frag einen Senior.

Konkrete Befehle

# 1. Installer graphify
pip install graphify==0.4.29

# 2. Générer le Knowledge Graph
graphify update . --no-viz

# 3. Vérifier le JSON
cat graphify-out/graph.json | jq '.nodes | length'
# → 47 nœuds

# 4. Générer le diagramme
./gradlew generateKnowledgeGraphDiagram

# 5. Filtrer par communauté
./gradlew generateKnowledgeGraphDiagram -Pplantuml.kg.community="service layer"

# 6. Limiter la taille
./gradlew generateKnowledgeGraphDiagram -Pplantuml.kg.maxNodes=20

Mit dem Knowledge Graph ändert sich das Szenario von Anaïs radikal:

@startuml
skinparam backgroundColor #FEFEFE
skinparam ActivityBackgroundColor #D5f5e3
skinparam ActivityDiamondBackgroundColor #FFF3CD

start

:Jour 0 : reçoit le lien\nvers le diagramme KG;
note right: PNG intégré\ndans le README

:Découvre la communauté\n"Quotenverwaltung";
note right: 3 noeuds, 2 arêtes\nINFERRED + EXTRACTED

:Clic sur QuotaTracker\ndans le diagramme;
note right: Liens vers LlmService\net RateLimiter visibles

:Ouvre le code avec\ncontexte complet;
note right: Sait où chercher\navant de chercher

@enduml

Der Knowledge Graph ersetzt die IDE nicht— er ergänzt es. Die IDE zeigt wo ; der KG führt warum und wie das zusammenpasst an.

Grenzen und Perspektiven

Ein Knowledge Graph ist kein Zauberstab:

Grenze Erklärung Umgehung

Nur statischer Code

Keine Laufzeit, kein Datenfluss

Mit APM-Traces ergänzen

INFERRED kann falsch sein

Die abgeleiteten Kanten erfordern Validierung

Vertrauensscore + menschliche Überprüfung

Keine Fachsemantik

Der KG weiß, dass "LlmService ConfigLoader aufruft", nicht "es ist der Authentifizierungs-Einstiegspunkt

Manuelle Annotationen oder LLM-Nachbearbeitung

Keine Temporalität

Ein Snapshot des Codes, nicht seiner Entwicklung

Regelmäßig generieren + Versionen vergleichen

Perspektiven(no response)

  • Diff KG: zwei Versionen vergleichen, um die Bewegungen der Gemeinschaften zu sehen

  • KG interaktiv: Klick auf einen Knoten → IDE öffnen an der entsprechenden Zeile

  • KG historischEntwicklung der Gemeinschaften im Zeitverlauf visualisieren (technische Schulden, die migrieren)

Fazit

Der Knowledge Graph verwandelt einen Akteinsam und lang(ein Codebase verstehen) in einem Aktgeteilt und schnell(eine Karte konsultieren).

Es ist keine Dokumentation — es ist dieKartographie. Eine Karte, die sich automatisch aktualisiert, die das reale Gebiet zeigt und es jedem Entwickler, neu oder erfahren, ermöglicht, mit Vertrauen zu navigieren.

pip install graphify==0.4.29
graphify update . --no-viz
./gradlew generateKnowledgeGraphDiagram

3 Befehle. 5 Minuten. Eine Karte Ihres Codebases.
