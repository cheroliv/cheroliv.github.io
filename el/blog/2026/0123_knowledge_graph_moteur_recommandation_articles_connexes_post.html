Αυτό δεν είναι bug του JBake. Είναι η προεπιλεγμένη συμπεριφορά του παντός γεννητής στατικού ιστοτόπου : η λίστα των αναρτήσεων είναι επίπεδη και ταξινομείται κατά ημερομηνία. Το πρότυπο κάνει ό, τι μπορεί με ό, τι έχει.

Αλλά αυτό δεν είναι λόγος για να το αποδεχτεί.

Η διάγνωση : Τρεις τύποι σχέσεων που κανένα πρότυπο δεν βλέπτη

Το σώμα άρθρων μου — 23 δημοσιεύσεις σε 4 μήνες — έχει μια πλούσια δομή που Το χρονολογικό πρότυπο καταστρέφει εντελώς :

Η Λύση: Ένα Pipeline Gradle, όχι ένας ζεστός κλήσος LLM

Η πρώτη πρόκληση θα ήταν να καλέσεις ένα LLM κατά τη διάρκεια του bake: «Για αυτό το άρθρο, βρίσκει τα τρία πιο παρόμοια άρθρα στο σώμα κειμένου. Μην κάνετε αυτό.

Μια κλήση LLM σε κάθε`./gradlew bake`χρόνο, χρήματα, και Η απάντηση του LLM μπορεί να αλλάξετε μεταξύ δύο builds χωρίς να αλλάξει το περιεχόμενο. Η CI σας γίνεται μη επαναληπτο, τα τεστ σας γίνονται ασταθή.

Η λύση είναι determinist: μια Gradle pipeline που προ-υπολογίζει το γράφημα της ομοιότητας και το αποθηκεύει στο`graph.json`. Το πρόtotype διαβάζει το αποτέλεσμα — ποτέ δεν εκκινεί έναν υπολογισμό.

Η αρχιτεκτονική: Το Bakery εισάγει το Graphify, όχι το Engine

Αυτό είναι το σημαντικότερο σημείο αρχιτεκτονικής. Η πειρασμός θα ήταν να συνδέστε τη συνεργασία στο`engine/build.gradle.kts`engine εφαρμοσμένο graphify για το scan, bakery για το bake, και engine δημιουργεί τη γέφυρα μεταξύ και τα δύο.

Αυτό είναι ένα anti‑pattern. Το Engine είναι ένα terminal consommateur — αυτό εφαρμόζει των plugins, δεν υλοποιεί λογική επιχείρησης. Ο κανόνας είναι : η ευθύνη της απόδειξης είναι στο ιδιοκτησιακό πρόσθετο.

Το Pipeline: Σάρωση → Γράφος → Πρότυπο

Εδώ είναι το πλήρες pipeline σε τρία βήματα:

  1. Σάρωση (γραφικοποίηση) :`graphify-plugin`σαρώνει το workspace. Στην του

το τρέχον μορφότυπο, ήδη ανιχνεύει τα`xref:`μεταξύ`.adoc`και τα εμφανίζει σε`graph.json`ως ακμές τύπου`reference`.
Το εμπλουτίζουμε για το επεξεργαστικό περιεχόμενο: * Ανάλυσε τα μεταδεδομένα του JBake (:jbake-tags:, :jbake-description:) κάθε`.adoc`του blog * Υπολογίσε τις συμπιπτώσεις ετικετών → ακμές`tag_cooccurrence`με βάρος * Αποκοπή των ονομαστικών οντοτήτων από τις περιγραφές με TF-IDF → ακμές`entity_overlap` * Εισάγει μια ενότητα`blog_articles`στο`graph.json`Υπάρχον

// Extrait de l'enrichissement graphify pour le blog
fun enrichBlogSection(graphJson: File, blogDir: File): GraphJson {
    val articles = blogDir.listFiles { f -> f.extension == "adoc" }
        .map { parseJbakeMetadata(it) }

    val nodes = articles.map { ArticleNode(it.slug, it.title, it.tags) }
    val edges = mutableListOf<GraphEdge>()

    // Couche 1 : xref (déjà fait par scanWorkspace)

    // Couche 2 : co-occurrences de tags
    for (a in articles) {
        for (b in articles) {
            if (a.slug == b.slug) continue
            val common = a.tags.intersect(b.tags)
            if (common.isNotEmpty()) {
                edges.add(GraphEdge(
                    source = a.slug,
                    target = b.slug,
                    type = "tag_cooccurrence",
                    weight = common.size.toDouble() / (a.tags.size + b.tags.size)
                ))
            }
        }
    }

    return graphJson.copy(
        blogArticles = BlogSection(nodes, edges)
    )
}

  1. Bake (bakery) : στη στιγμή του`./gradlew bake`, `BakeryPlugin`διαβάζει

`graph.json`και επιλύει τα σχετικά άρθρα για κάθε άρθρο.

// BakeryPlugin — résolution des articles connexes
fun resolveRelatedPosts(
    currentSlug: String,
    graph: GraphJson,
    maxResults: Int = 4
): List<RelatedPost> {
    val edges = graph.blogArticles.edges
        .filter { it.source == currentSlug || it.target == currentSlug }

    return edges
        .sortedByDescending { it.weight }
        .take(maxResults)
        .map { edge ->
            val relatedSlug = if (edge.source == currentSlug) edge.target else edge.source
            graph.blogArticles.nodes.first { it.slug == relatedSlug }
        }
}

Εναλλακτική χρονολογική

Si `graph.json`είναι απουσιάζει (τοπική κατασκευή χωρίς προηγούμενο scan, πρώτος) διανομή, CI που δεν έχει εšte ενσωματώσει το σαρωτικό graphify), το προτύπο πρέπει να υποβιβάζεται ευχάριστα:

fun resolveRelatedPosts(currentSlug: String, graph: GraphJson?): List<RelatedPost> {
    if (graph != null && graph.blogArticles != null) {
        return resolveFromGraph(currentSlug, graph)
    }
    // Fallback chronologique — même comportement qu'aujourd'hui
    logger.warn("[bakery] graph.json absent — fallback chronologique")
    return resolveFromChronology(currentSlug)
}

filtering, δεν υπάρχει A/B testing, δεν υπάρχει feedback loop)

  • Η ποιότητα εξαρτάται από το πλουτότητα των μεταδεδομένων JBake — αν τα

Οι περιγραφές είναι κενές, το TF-IDF δεν βλέπει τίποτα

  • Το NLP είναι εκτός σύνδεσης — τα νέα άρθρα δεν είναι ομαδοποιημένα μόνο στο

το επόμενο σάρωμα (είναι καλό: η κατασκευή παραμένει determinist)

Προοπτικές: Το Blog ως Δημόσιο Γνωσιακό Γράφημα

Αυτή η λειτουργία ανοίγει μια ευρύτερη προοπτική : και αν`cheroliv.com` γίνονταν αυτός ένα knowledge graph navigable ?

Τα άρθρα είναι κόμβοι. Τα tags είναι κοινότητες. Τα xref είναι πλευρές. Ο αναγνώστης δεν διαβάζει πλέον ένα απομονωμένο άρθρο—περιηγείται σε ένα graphe de connaissance` οπου το τρέχον άρθρο είναι το σημείο εισόδου.

Φανταστείτε μια αρχική σελίδα που δεν εμφανίζει τη χρονολογική λίστα των τελευταίων αναρτήσεων, αλλά μία χάρτης του κόρπουσ : οντλογικά σύστατα, κύρια άρθρα (τα οποία έχουν το περισσότερο άκρα), διαδρομές ανάγνωσης προτεινόμενα (« Αν σας άρεσε το άρθρο για το Graphify, διαβάστε εξής αυτό στο Knowledge Graph ως εργαλείο κατανόησης » )

Δεν είναι πλέον ένα blog. Είναι ένα συμαντικός άτλας.

Και αυτό δεν είναι επιστημονική φαντασία. Ο`graph.json`υπάρχει ήδη. Μόνον το περιβάλλο της πλοήγυσης του λείπει.

Συμπέρασμα: Το σύστημα αρχείων ξέρει αυτό που το πρότυπο αγνοεί

Τι σχεδιάσα αυτό το Τρίτη βράδυ, είναι η αντικατάσταση μιας ευρετικής. αβαρής (η χρονολογική σειρά) από μια πιστή αναπαράσταση της η δομή του κόρπους μου (του Knowledge Graph).

Το template`post.thyme`δεν αλλάζει. Το που αλλάζει, είναι αυτό που αυτό του δίνει φαγητό. Πριν: μια λίστα Java ταξινομημένη από`date`. Μετά : ένας βαρυφορτισμένος γράφος που προκύπτει από τρεις στρώματα ανάλυσης — xrefs, co-occurrences ετικετών, και αναδυόμενη οντολογία με NLP

Ο βρόχος είναι κλειστός. graphify σαρώνει το workspace. Bakery διαβάζει το Γράφημα και τροφοδοτεί το πρότυπο. Ο αναγνώστης βλέπει προτάσεις. σχετικές. Και μηχανή — ο δι-ρι-γε-υ-τής — δεν ξέρει ακόμα και ότι Όλα αυτά υπάρχουν.

Αυτό είναι η σωστή αρχιτεκτονική. Κάθε πρόσθετο κάνει ένα πράγμα. Και ο τερματικός καταναλωτή δεν χρειάζεται να ξέρει πώς.
