τικ

[]

Το πρόβλημα : ένα απασχολισμένο τερματικό

Κάθε προγραμματιστής έχει γνωρίσει αυτή την κατάσταση:

$ ./gradlew build
> Building...

Το τερματικό είναι μπλοκαρμένο. Δεν μπορείτε πλέον να πληκτρολογήσετε καμία εντολή. Και χρειάζεστε να δείτε ένα αρχείο, να εκκινήσετε ένα`git status`, ή ελέγξτε μια πόρτα που είναι κατειλημμένη.

@startuml
skinparam backgroundColor #FEFEFE

actor Développeur as dev
participant "Τερματικό" as term
participant "Gradle
( διαδικασία )" as gradle

dev -> term : ./gradlew build
term -> gradle : Lance le build
gradle -> term : Occupe le terminal\n(pas de prompt)
dev -> term : veut taper une commande
term --> dev : ❌ Terminal bloqué

note right of dev
  Le développeur est
  paralysé pendant
  toute la durée du build
end note
@enduml

Οι περισσότεροι προγραμματιστές ανοίγουν ένα νέο τερματικό. Υπάρχει όμως μια πιο ελκυστική, πιο γρήγορη, και εγγενής λύση: η διαχείριση των εργασιών.

Οι τρεις απαραίτητες εντολές

Ctrl+Z — Παύση (SIGTSTP)

`Ctrl+Z`στείλε το σήγμα`SIGTSTP`στη διαδικασία στο προσκήνιο. Η διαδικασία είναιαναστέλλετος— δεν σκοτώθηκε — και το τερματικό επιστρέφει στη προτροπή του.

$ ./gradlew build
> Building...
^Z
[1]+  Stoppé    ./gradlew build
$

Ο αριθμός μεταξύ των αγκυλών`[1]`είναι τοαριθμός εργασίας. Le `+`δηλώνει την προεπιλεγμένη εργασία.

fg — Επαναφορά στο προσκήνιο

`fg`Φέρνει το suspensed job στο προσκήνιο. Η διαδικασία συνεχίζει ακριβώς εκεί जहां είχε σταματήσει.

$ fg
./gradlew build
> Building... (reprend où il en était)

Με έναν συγκεκριμένο αριθμό εργασίας:

$ fg %2

bg — Επαναλαμβάνω στο παρασκήνιο

`bg`Συνεχίστε τη διαδικασία χωρίς να μπλοκάρετε το τερματικό. Ιδανικό για τα μεγάλα builds.

$ bg
[1]+ ./gradlew build &
$

Le `&`στο τέλος σημαίνει ότι η διαδικασία τρέχει στο παρασκήνιο.

jobs — Λίστα των jobs του shell

$ jobs
[1]-  Stoppé    vim README.md
[2]+  En cours   ./gradlew build

Σενάριο 1 : Η μακρή σύνθεση

Αυτή είναι η πιο συνήθης περίπτωση χρήσης. Εκτελείτε μια Gradle build, το τερματικό είναι κολλημένο, και χρειάζεστε να κάνετε κάτι άλλο.

@startuml

autonumber

participant "Τερματικό" as term
participant "Gradle" as gradle
database "Κατάσταση
διαδικασία" as state

dev -> term : ./gradlew build
term -> gradle : Lance le build
gradle -> state : En cours (FG)
dev -> term : Ctrl+Z
term -> state : Suspendu (job [1])
term --> dev : Prompt libre $

dev -> term : git status
term --> dev : working tree clean

dev -> term : fg
term -> state : Reprend (FG)
gradle --> dev : Build réussi ✓

note right of state
  Le processus Gradle
  n'a jamais été tué
  Il reprend exactement
  où il s'était arrêté
end note
@enduml

βήμα-βήμα

$ ./gradlew build
> Building...
^Z
[1]+  Stoppé    ./gradlew build

$ git status

nothing to commit, working tree clean

$ fg

Σενάριο 2: Ο ξεχασμένος επεκτυπωτής

Είστε σε`vim`, χρειάζεστε να διαβάζετε άλλο αρχείο χωρίς να φύγετε`vim`.

# Dans vim, en mode commande :
:shell
$ cat /path/to/other/file.txt
$ exit
# Retour dans vim

Αλλά είναι βαρύ. Με`Ctrl+Z`, είναι άμεσα :

# Dans vim, n'importe quel moment :
Ctrl+Z
[1]+  Stoppé    vim README.md

$ cat /path/to/other/file.txt
# ... lire le fichier ...

$ fg
vim README.md
# Retour exact là où on en était, curseur en place
@startuml
skinparam backgroundColor #FEFEFE
autonumber

actor Développeur as dev
participant "vim" as vim
participant "Shell" as shell

dev -> vim : édition en cours
dev -> vim : Ctrl+Z
vim -> shell : Suspendu (job [1])
dev -> shell : cat autre_fichier.txt
shell --> dev : contenu du fichier
dev -> shell : fg
shell -> vim : Reprend (job [1])
vim --> dev : Curseur exactement\nà la même position

note right of vim
  vim restaure
  intégralement l'état :
  position du curseur,
  buffer, undo stack
end note
@enduml
vim`επαναφέρει τέλεια την κατάσταση του μετά ένα`fg: θέση του κέρσορα, περιεχόμενο του buffer, ιστορικό αναιρέσεων — όλο είναι διατηρημένο.

Σενάριο 3 : Η διαδικασία opencode είναι ανασταλμένη

Αυτό είναι το σενάριο που έθαρρεν αυτό το άρθρο. Χρησιμοποιείτε`opencode`(CLI εργαλείο για να ελέγξετε ένα LLM στον κώδικά σας), και η διαδικασία είναι σε αναμονή.

@startuml
skinparam backgroundColor #FEFEFE
skinparam defaultFontName sans-serif
skinparam componentStyle rectangle

actor Développeur as dev
participant "opencode
(πρόκτορας LLM)" as agent
participant "Shell" as shell
participant "γκιτ" as git

dev -> agent : Session active
agent -> agent : Tour de parole\ndu LLM en cours

note over agent
  Ctrl+Z arrive
  en plein milieu
  d'une analyse de code
end note

dev -> agent : Ctrl+Z
agent -> shell : Suspendu (job [1])
dev -> git : git diff
git --> dev : changements visibles
dev -> shell : fg
shell -> agent : Reprend (job [1])
agent --> dev : Reprend exactement\nl'analyse en cours

note right of agent
  Aucune perte de contexte
  Le LLM reprend sa réponse
  exactement où il en était
end note
@enduml
$ opencode
# ... session en cours, LLM analyse le code ...
^Z
[1]+  Stoppé    opencode

$ git diff HEAD~1
# vérifier les changements récents

$ fg
opencode
# Le LLM reprend là où il s'était arrêté

Το πλεονέκτημα είναι διπλό:

  1. Χωρίς απώλεια πλαισίου: η συνεδρία LLM, το ιστορικό της συζήτησης, τα ανοιχτά αρχεία — όλα διατηρούνται

  2. Χωρίς επανεκκίνηση: Δεν χρειάζεται να ξανατρέξετε το opencode, να φορτώσετε ξανά το πλαίσιο, να εξηγήσετε ξανά το πρόβλημα στο LLM

Σενάριο 4 : Διαχείριση πολλαπλών εργασιών ταυτόχρονα

σύντομη/εντολή Σήμα Επίδραση Πίσω;

Ctrl+Z

SIGTSTP

Υποβάλε τη διαδικασία (καταγεμμένη, στη μνήμη)

Ναι :`fg` ou bg

Ctrl+C

SIGINT

Κτάνε τη διαδικασία (ολοκληρωμένη)

Όχι : διαδικασία καταστραμμένη

Ctrl+\

SIGQUIT

Στονέστε τη διαδικασία + core dump

Όχι: η διαδικασία έχει καταστραφεί

commande &

—

Εκκίνησε στο παρασκήνιο άμεσα

`fg`για να το φέρνω στο προσκήνιο
Ctrl+Z`είναιμη-καταστροφικό. Η διαδικασία είναι παγωμένη ως είναι, στη μνήμη. Μπορείτε να συνεχίσετε άμεσα με`fg. Είναι ένα pause, όχι ένα stop.

Ο πλήρης κύκλος ζωής ενός job

@startuml

skinparam defaultFontName sans-serif

title Πλήρης κύκλος ζωής μιας εργασίας shell
state "μη ύπαρκτος" as none
state "προσκήνιο\n(καταλαμβάνει το τερματικό)" as foreground #LightCoral

state "Φόντο
(bg ή &)" as background #LightGreen

[*] --> none
none --> foreground : tape une commande
foreground --> suspended : Ctrl+Z
foreground --> done : fin normale

suspended --> foreground : fg
suspended --> background : bg
suspended --> done : kill %n

background --> foreground : fg
background --> done : fin normale\n(en arrière-plan)
background --> suspended : Ctrl+Z\n(si fg puis Ctrl+Z)

done --> [*]

note right of suspended
  L'état suspendu est
  le pivot de tout le
  système de jobs
end note
@enduml

Προχωρημένα συμβουλές

fg με η πιο πρόσφατη δουλειά και η εναλλαγή

fg`χωρίς όρισμα επιστρέφει τη σηματισμένη εργασία+(ο πιο πρόσφατο). Μπορείτε επίσης να το χρησιμοποιήσετε%-`για στοχεύση στην προηγούμενη δουλειά :

$ vim file1.txt
^Z
[1]+  Stoppé    vim file1.txt

$ vim file2.txt
^Z
[2]+  Stoppé    vim file2.txt

$ fg      # ramène job [2] (le plus récent)
$ fg %-   # ramène job [1] (le précédent)

να τελειώσετε μια δουλειά σωστά

$ jobs
[1]-  Stoppé    vim config.yml
[2]+  Stoppé    ./gradlew test

$ kill %2       # envoie SIGTERM au job 2
$ kill -9 %1    # envoie SIGKILL au job 1 (force)

désown : αποσπορά από το shell

disown`Supprime un travail de la table des travaux du shell. Le processus continue de tourner mais ne peut plus être ramené avec`fg :

$ ./gradlew build &
[1] 12345

$ disown %1
# Le processus continue mais n'est plus lié au shell
# Ça survives à la fermeture du terminal

Συνδυάστε με το nohup για τα μακροχρόνια διεργασίες

Για να επιβιώσει μια διεργασία την κλείσιμο του τερματικού:

$ nohup ./gradlew build &
[1] 12345
$ disown %1
# Le build continue même si vous fermez le terminal

Παγίδες και συνηθισμένα λάθη

Συγχέω το Ctrl+Z και το `Ctrl+C

Αυτό είναι το πιο συχνό λάθος.`Ctrl+C`κτείνει τη διαδικασία.`Ctrl+Z`τον αναβαλλει. Αν πατήσετε`Ctrl+C`Από ανταπόκριση, όλοκληρος ο κατάσταση χάθηκε — ανοιχτά αρχεία, συνεδρίες LLM, δημιουργίες σε εξέλιξη.

@startuml
skinparam backgroundColor #FEFEFE

  card "διαδικασία παγωμένη στη μνήμη" as z1
  card "fg τον επαναφέρει άκαμψη" as z2
  card "Κενένη απώλεια" as z3
}

rectangle "Ctrl+C (SIGINT)" as c #LightCoral {
  card "Διαδικασία ολοκληρωμένη" as c1
  card "Κατάσταση χαμένη για πάντα" as c2
  card "Δεν είναι δυνατή η επιστροφή" as c3
}

note bottom of z
  Pause → Reprendre
end note

note bottom of c
  Kill → Perdu
end note
@enduml

Οι εργασίες είναι τοπικές στο κελύφος

jobs, fg et `bg`Λειτουργούν μόνο στο shell που ξεκίνησε τις διαδικασίες. Αν ανοίξετε ένα νέο τερματικό, δεν θα δείτε τα jobs του άλλου.

# Terminal 1
$ vim file.txt
^Z
[1]+  Stoppé    vim file.txt

# Terminal 2 (nouveau)
$ jobs
# (rien — les jobs sont locaux au shell)

Για να δείτε τις διεργασίες στο επίπεδο συστήματος, χρησιμοποιήστε`ps` ou htop:

ps aux | grep vim

Οι εργασίες δεν επιβιώνουν μετά την κλείσιμο του shell

Εάν κλείσετε το τερματικό, όλες οι παγιευμένες εργασίες ή οι εργασίες στο φόντο καταστρέφονται. Για να παραμείνει ενεργή μια διαδικασία, χρησιμοποιήστε`nohup`+disown(Empty output)

$ nohup ./gradlew build &
[1] 12345
$ disown %1
# Fermer le terminal → le build continue

Οι διαλογιστικές διαδικασίες και fg

μερικά διαλογικά προγράμματα δεν λειτουργούν καλά μετά ένα`Ctrl+Z`+fg. Είναι σπάνιο αλλά συμβαίνει :

  • Μερικά προγράμματα που χρησιμοποιούν σήματα (vim, htop, less διαχειρίζονται καλά`Ctrl+Z`)

  • Τα μακροχρόνια προγράμματα δικτύου (ssh, opencode) συνήθως αποκαθιστούν σωστά.

  • Τα προγράμματα που τροποποιούν το τερματικό (ncurses) μπορούν μερικές φορές να αφήσουν το τερματικό σε ένα απρόσμενο κατάσταση

Συμπέρασμα

`fg`δεν είναι ένα άγνωστο tip — είναι ένας θεμελιώδης μηχανισμός του Unix shell, διαθέσιμο από τα έτη του '70. Το γεγονός ότι η πλειοψηφία των προγραμματιστών αγνοούν αυτό είναι ένα σύμπτωμα της εποχής μας: τα IDE και τα multiplexers μας έχουν απομακρύνει από τις βάσεις.

Αλλά όταν είστε σε έναν διακομιστή SSH, σε ένα ελάχιστο τερματικό, ή απλώς χρησιμοποιείτε`opencode`και ότι το LLM είναι πλήρως απασχολημένο —Ctrl+Z, fg, bg, `jobs`Είναι οι καλύτεροι φίλοι σας.

_ Ctrl+Z παύει, fg συνεχίζει. Αυτό είναι η pause-play του τερματικού. _
