Πριν δύο εβδομάδες, έχω εκκινήσει`capsule-gradle`— ένα plugin που μετατρέπει ένα deck reveal.js σε καψέλα βίντεο WebM με TTS. Σήμερα, προσθέτω ένα νέο plugin : hyperframes-gradle. Κάνει κάτι που το capsule-gradle δεν κάνει : να μετατρέψετε το AsciiDoc ευθύς σε βίντεο MP4, χωρίς να περάσετε μέσω του reveal.js.

Εδώ είναι γιατί αυτό το plugin υπάρχει, πώς ενσωματώνεται με το υπάρχον, και το που η μηχανή HyperFrames του HeyGen προσφέρει στη ροή παραγωγής περιεχομένου.

Η τρύπα σε ο αγωγός βίντεο

Το documentary pipeline μου παράγει δύο τύπους βίντεο:

  1. κάψουλα επανάληψης (capsule-gradle) — ένας δέκας reveal.js συλλημμένο σε WebM με

αφήγγιση TTS. Ιδέαλ για να επαναλάβετε ένα ενότητα.

  1. Ανιματισμένες διαφάνειες (slider-gradle) — ένας διαδραστικός deck reveal.js HTML για

ο εκπαιδευτής πρόσωπο.

Αλλά λείπει ένας τρίτος τύπος : το standalone video

Το Capsule-gradle δεν μπορεί να απαντήσει: του χρειάζεται ήδη ένα deck reveal.js. ο slider-gradle παράγει καλά αυτό το deck, αλλά δεν έχει σχεδιαστεί για την απόδοση βίντεο. Πρέπει να υπήρχε ένα ευθύγραμμο pipeline : AsciiDoc → βίντεο.

HyperFrames : Ο Μηχανισμός

Εξέφυλαhttps://github.com/heygen-com/hyperframes[HyperFrames] il y a μερές μέρες. Είναι ένα πλαίσιο open-source (Apache 2.0) που δημιουργήθηκε από το HeyGen, το μονοκέρωτο του βίντεο ΤΕ. 22 700 αστέρια στο GitHub. Το pitch κρατάει στο μια πρόταση :

Γράψτε HTML. Αποδίδει βίντεο. Χτισμένο για πράκτορες

Η αρχή: γράφετε HTML με`data-*`ιδιότητες, αναφέρετε Μια κίνηση GSAP (ή CSS, Lottie, Three.js…), και ο μηχανός αποδίδει όλο το σε MP4 μέσω Puppeteer (headless Chrome) + FFmpeg. Αποτέλεσμα determinιστικό: ίσα εισαγωγή, ίδιες frames, ίδιο βίντεο.

Τι κάνει το HyperFrames διαφορετικό από το Remotion ; Χωρίς React, χωρίς bundler, χωρίς JSX. Ακατέργαστο HTML που οι παράγοντες AI ξέρουν να γράφουν φυσικά. Το είναι προσαρμοσμένο ακριβώς για το pipeline μου : planner-gradle με deepseek μπορεί να δημιουργήσει αυτό το HTML από ένα σχέδιο SPG/SPD, και ένα plugin Gradle μπορεί να το μετατρέψει σε MP4.

Το DSL AsciiDoc

Η πραγματική αξία που προσθέτει το plugin, είναι το DSL AsciiDoc. Ο χρήστης Δεν γράφει ποτέ HTML. Σημειώνει το υπάρχον του εγγράφου AsciiDoc:

= Formation Docker & Kubernetes
:hyperframes-width: 1920
:hyperframes-height: 1080
:hyperframes-fps: 30

[hyperframes-composition, id="intro"]
== Introduction

Le titre apparaît avec un fondu GSAP sur fond vidéo.

[hyperframes-track, index=0, start=0, duration=6]
video::assets/background.mp4[muted, playsinline]

[hyperframes-track, index=1, start=1, duration=4]
Formation Docker & Kubernetes

[hyperframes-animation, type=gsap]

const tl = gsap.timeline({ paused: true }); tl.from("#title", { opacity: 0, y: 40, duration: 0.8 }, 1); window.timelines = window.timelines || {}; window.__timelines.intro = tl;

Τα χαρακτηριστικά docinfo (:hyperframes-width:) ρυθμίζουν τις διαστάσεις. Τα προσαρμοσμένα μπλοκ ορίζουν τα συνθέματα και τις pistes. Το μπλοκ `[hyperframes-animation]`περιέχει τον ακατέργαστο κώδικα GSAP — που ο πράκτορας ΤΝ μπορεί να δημιουργήσει από μια περιγραφή σε φυσική γλώσσα.

Η Γέφυρα Node.js

Το único τεχνικό σημείο εμπόδια: Το HyperFrames είναι σε Node.js/TypeScript, και τα plugins μου είναι σε Kotlin/JVM. Η λύση είναι ένα`ProcessBuilder`:

(three spaces after newline)

class RenderHyperframesTask : DefaultTask() {

    @TaskAction
    fun render() {
        val process = ProcessBuilder(
            "npx", "hyperframes", "render",
            "--input", inputHtml.absolutePath,
            "--output", outputMp4.absolutePath
        )
            .inheritIO()
            .start()

        val exitCode = process.waitFor()
        require(exitCode == 0) {
            "HyperFrames render failed with exit code $exitCode"
        }
    }
}

Με μηδενική συνεζυγία κώδικα JVM ↔ Node.js. Το συμβόλαιο είναι μέσω γραμμής εντολών. και αρχεία σε δίσκο. Είναι το ίδιο μοτίβο που`plantuml-gradle` (καλεί την CLI PlantUML) ή`slider-gradle`(που καλεί το AsciidoctorJ). Κανένα νέο στον ήλιο — απλώς εφαρμοσμένο σε ένα πιο νέο εργαλείο.

Δεν ανταλλάσσονται. Συμπληρώνονται. Η πλήρης αλυσίδα αξίας:

AsciiDoc ──→ slider-gradle ──→ deck reveal.js ──→ capsule-gradle ──→ WebM (καψούλα αναθεώρησης)

AsciiDoc ──→ hyperframes-gradle ──→ MP4 (αυτόνομο βίντεο)

Ο χρήστης γράφει ένα μόνο αρχείο AsciiDoc. slider-gradle παράγει τις διαφάνειες. capsule-gradle παραγεύει την καψίδα ανθεώρησης. hyperframes-gradle παραγεύει το βίντεο teaser και τα τεχνικά demos

Γιατί λειτουργεί;

Τρεις λόγοι :

  1. HyperFrames είναι "built for agents". Ο αγωγός μου βασίζεται σε agents AI

(planner-gradle + deepseek) που δημιουργούν περιεχόμενο. HyperFrames δέχεται HTML ακατέργαστο — το format που τα LLMs το διαχειρίζονται καλύτερα. Χωρίς React, χωρίς για το JSX, δεν υπάρχει καμπύλη μάθησης για τον παράγοντα.

  1. Το DSL AsciiDoc είναι φυσικό. Το ολόκληρο μου οικοσύστημα μιλά AsciiDoc.

slider-gradle, codex-gradle, training-gradle — όλοι καταναλώνουν το`.adoc`. προσθέστε μπλοκ customs`[hyperframes-composition]`είναι μια επέκταση λογικό, όχι μια διακοπή.

  1. Η γέφυρα Node.js είναι ένα αποδεδειγμένο μοτίβο. ProcessBuilder εκτός της JVM,

Αυτό είναι αυτό που κάνω ήδη για το PlantUML, το Graphviz, το Piper. Προσθέστε το HyperFrames Δεν αλλάζει τίποτα στην αρχιτεκτονική — είναι απλώς ένα εξωτερικό εργαλείο περισσότερο, ελεγχόμενο από το Gradle.

Η αληθινή δύναμη του pattern, είναι ότι δεν υπάρχει καθόλου εξάρτηση npm στο το Gradle build. Το πρόσθετο δεν εισάγει κώδικα Node.js. Εκτελεί ένα εντολή shell. Αν το HyperFrames εξελιχθεί ή καταστραφεί, το πρόσθετο δεν είναι συνδεδεμένο — Αρκεί να ενημερώσετε την εντολή.

Conclusion : Το ληστέρον που λείπεται

Με το hyperframes-gradle, το pipeline βίντεό μου είναι ολοκληρωμένο. Έχω :

  • Οι διαλογικές διαφάνειες (slider-gradle)

  • Τα καψούλες επαναλήψεως (capsule-gradle)

  • Οι βίντεο standalone (hyperframes-gradle)

Τρεις μορφές. Ένας μόνο αρχείο πηγής: το AsciiDoc.

Ο επόμενος στόχος είναι HF-1: να μεταγλωτίσουμε το πρόσθετο και να δημιουργήσουμε ένα πρώτο HTML HyperFrames από ένα έγγραφο AsciiDoc σχολιασμένο. Η συνεδρία 001 είναι ήτοι πλαϊσμένο.

hyperframes-gradle υπάρχει. Η διακυβέρνηση είναι εφαρμοσμένη. Το backlog γράφεται. Η αρχιτεκτονική είναι τεκμηριωμένη. Το plugin είναι γεννημένο.
