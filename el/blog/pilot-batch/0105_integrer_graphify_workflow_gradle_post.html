Και εάν η Gradle build σας μπορούσε να αυτοματικά δημιουργεί ενημερωμένα διαγράμματα από την πραγματική δομή του κώδικα; Αυτό είναι ακριβώς αυτό που κάνει το pipeline Graphify + PlantUML Gradle Plugin :`graphify . --no-viz`εξάγει το Knowledge Graph,`./gradlew generateKnowledgeGraphDiagram`τον μετατρέπει σε διαγράμματα PlantUML. μηδέν LLM, μηδέν χειροκίνητο, 100% καθορισμένος.

Το πρόβλημα: διάγραμματα που είναι πάντα πίσω από τον κώδικα

Κάθε έργο που υπερβαίνει τις μερικές χιλιές γραμμές γνωρίζει αυτό το σύνδρομο:

  1. Σχεδιάζουμε ένα αρχιτεκτονικό διάγραμμα στην έναρξη του έργου.

  2. Ο εξελίσσεται, οι εξαρτήσεις αλλάζουν

  3. Το διάγραμμα γίνεται ένα διακοσμητικό ψέμα

  4. Κανείς το ενημερώνει επειδή είναι βαρετό.

  5. Οι πρόσφατα φθάνοντες βασίζονται σε αυτό και κάνουν λάθη

@startuml

Ο αρχός είναι απλός: αντί να ζωγραφίζουμε τα διαγράμματα χειροκίνητα, ταπαράγει από την πραγματική δομή του κώδικα.

Δύο εντολές. Αυτό είναι όλο.

# Étape 1 : extraire le Knowledge Graph
graphify . --no-viz

# Étape 2 : générer les diagrammes PlantUML
./gradlew generateKnowledgeGraphDiagram

Το αποτέλεσμα; Αρχεία`.puml` et .png`σε`diagrams/knowledge-graph/, υποβάλλονται στο Git, πάντα ενημερωμένοι με τον κώδικα.

Βήμα 1: Εγκατάσταση του Graphify και εξαγωγή του Knowledge Graph

Εγκατάσταση

Το Graphify είναι ένα εργαλείο Python που αναλύει τη βάση κώδικά σας και κατασκευάζει ένα δομημένο γράφο γνώσης :

# Méthode recommandée
uv tool install graphifyy && graphify install --platform opencode

# Alternative avec pip
pip install graphifyy && graphify install --platform opencode

Ρυθμίστε τις εξαιρέσεις

Δημιουργήστε ένα αρχείο`.graphifyignore`στη ρίζα του έργου για να εξαιρέσει τα αρχεία που δεν ανήκουν στην επιχειρηματική λογική :

# Secrets — JAMAIS dans le graphe
*-context.yml
*.env

# Fichiers générés
build/
.gradle/

# Tests fonctionnels
src/functionalTest/

Εξαγωγή του Knowledge Graph

graphify . --no-viz

Το flag`--no-viz`παραλείπει την παραγωγή HTML (αχρειωστο σε έναν pipeline Gradle). Το αποτέλεσμα είναι ένα αρχείο.`graphify-out/graph.json`περιέχει :

  • κόμβοι: κλάσεις, συναρτήσεις, αρχεία — με τον τύπο τους και την κοινότητα

  • ακμές: σχέσεις μεταξύ κόμβων (EXTRACTED από τον κώδικα, INFERRED από το LLM)

  • κοινότητες: αυτοματοποιημένα ομαδοποιήματα συνδεδεμένων κόμβων

Παράδειγμα δομής`graph.json`
{
  "nodes": [
    {"id": "0", "label": "LlmService", "file_type": "code", "community": 0},
    {"id": "1", "label": "ApiKeyPool", "file_type": "code", "community": 0},
    {"id": "2", "label": "PlantumlService", "file_type": "code", "community": 1}
  ],
  "links": [
    {"source": "1", "target": "0", "relation": "uses", "confidence": "EXTRACTED", "weight": 0.9},
    {"source": "0", "target": "2", "relation": "calls", "confidence": "INFERRED", "weight": 0.7}
  ]
}

Ο πηγαίος κώδικας (.kt, .java) αναλύεται τοπικά από το tree-sitter,χωρίς κλήση LLM. Μόνο τα αρχεία τεκμηρίωσης (.adoc, .md) απαιτούν μια κλήση LLM για σεμαντική εξαγωγή. Έτσι`--update`Η μεταγλώττιση κώδικα Kotlin είναι σχεδόν άμεσα.

Βήμα 2 : Το πρόσθετο Gradle μετατρέπει το Knowledge Graph σε PlantUML

αρχιτεκτονική του pipeline

Το πρόσθετο`com.cheroliv.plantuml`ενσωματώνει μια εργασία`generateKnowledgeGraphDiagram`qui μετατρέπει`graph.json`σε διαγράμματα PlantUML με τρόποπλήρως δεтерμινinistικός:

(Note: The output preserves the leading space, colon, and trailing space exactly as in the input.)

@startuml
skinparam backgroundColor #FEFEFE

participant "Gradle" as G
participant "GenerateKnowledgeGraphDiagramTask" as Task
participant "KnowledgeGraphParser" as Parser
participant "KnowledgeGraphRenderer" as Renderer
participant "PlantumlService" as PS

collections "graphify-out/graph.json" as JSON

G -> Task : execute
Task -> JSON : read
Task -> Parser : parse(graph.json)
Parser --> Task : KnowledgeGraph\n(noeuds + arêtes + communautés)
Task -> Renderer : render(graph, filters)
Renderer --> Task : code PlantUML\n(déterministe)
Task -> PS : validateSyntax(plantumlCode)
alt syntaxe valide
    Task -> PS : generateImage → .png
else syntaxe invalide
    Task -> Task : save .puml avec warning
end

@enduml

τα εσωτερικά εξαρτήματα

συστατικό Ρόλος

KnowledgeGraphParser

αναλύστε`graph.json`— υποστηρίζει 3 μορφές : graphify εγγενής (nodes+links), legacy (communities), flat. Λύει τα αριθμητικά IDs σε ετικέτες.

KnowledgeGraphRenderer

Μετατρέπει determinιστίκα ένα`KnowledgeGraph`σε κώδικα PlantUML. Ομάδες ανά τύπο, κοινότητες σε πακέτα, αυτόματη λεγέντα.

GenerateKnowledgeGraphDiagramTask

Gradle εργασία που οργανώνει: parse → render → validate → PNG. Ρυθμίσιμη μέσω ιδιοτήτων Gradle.

kgmodels.kt

Μοντέλα δεδομένων:`KnowledgeGraph`, KnowledgeGraphNode, KnowledgeGraphEdge, KnowledgeGraphCommunity, EdgeType.

PlantumlService

Συντακτικός έλεγχος + αποδόμηση PNG (επαναχρησιμοποιούμενος από όλες τις εργασίες του προσθέτου).

Κανόνες απόδοσης

Ο renderer εφαρμόζει οπτικές καθορισμένες συνήθειες :

Τύπος άκμης Σημείωση PlantUML σημαινόμενο

Οι κοινότητες αποδίδονται ως πακέτα PlantUML με αυτόματη χρωματική παλέτα.

Βήμα 3 : Καθημερινή χρήση

Πλήρες διάγραμμα

# Générer le diagramme du Knowledge Graph complet
./gradlew generateKnowledgeGraphDiagram

Έξοδος:`diagrams/knowledge-graph/knowledge-graph-full.puml` + .png

Φιλτράρισμα ανά κοινότητα

# Une seule communauté
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.community=community_0

# Limiter le nombre de noeuds (lisibilité)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.community=community_0 \
  -Pplantuml.kg.maxNodes=15

Φιλτράριση κατά τύπο ακμής

# Uniquement les relations certaines (EXTRACTED)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.edgeTypes=EXTRACTED

# Relations certaines + inférées
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.edgeTypes=EXTRACTED,INFERRED

Φίλτρο ανά τύπο κόμβου και εμπιστοσύνης

# Uniquement les classes de code
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.nodeTypes=code

# Seuil de confiance minimum (pour les INFERRED)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.minConfidence=0.7

προσαρμοσμένος φάκελος εξόδου

./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.outputDir=docs/architecture

Το πλήρες pipeline σε ένα workflow Gradle

τύπος workflow

@startuml
skinparam backgroundColor #FEFEFE
skinparam ActivityBackgroundColor #E8F4FD
skinparam ActivityDiamondBackgroundColor #FFF3CD
skinparam ActivityBorderColor #2C3E50

start

partition "Εξαγωγή" {
    :graphify . --no-viz;
    note right: Analyse le code source\ntree-sitter (local, pas de LLM)

    :graphify-out/graph.json;
    note right: Noeuds + arêtes\n+ communautés
}

partition "ΓΕΝΝΗΣΗ" {
    :./gradlew generateKnowledgeGraphDiagram;
    note right: Pipeline déterministe\nparse → render → validate → PNG

    if (Filtres actifs ?) then (Oui)
        :Appliquer filtres\n(community, edgeTypes,\nmaxNodes, nodeTypes);
    else (Non)
        :Diagramme complet;
    endif

    :diagrams/knowledge-graph/\nknowledge-graph-full.puml\nknowledge-graph-full.png;
}

partition "ΕΝΤΕΓΡΩΣΗ" {
    :git add diagrams/knowledge-graph/;
    :git commit;
    note right: Diagrammes versionnés\ntoujours à jour avec le code
}

stop

@enduml

  Quasi instantané sur du code Kotlin
  (tree-sitter, pas de LLM)
end note

  Déterministe
  Pas de LLM
  Résultat reproductible
end note

@enduml

πρακτική ενημέρωση

Όταν ο κώδικας αλλάζει, δεν ξαναχτίζουμε όλο τον γράφο από το μηδέν:

# Mise à jour incrémentale (fichiers modifiés uniquement)
graphify . --update

# Puis régénérer les diagrammes
./gradlew generateKnowledgeGraphDiagram

--update`εξάγει ξανά μόνο τα τροποποιημένα αρχεία (ανιχνευμένα με SHA256 σε`graphify-out/cache/). Στον κώδικα Kotlin, είναι σχεδόν άμεσα επειδή το tree-sitter λειτουργεί τοπικά χωρίς κλήση LLM.

Το dogfooding : το plugin τεκμηριώνει τον εαυτό του

Το plugin PlantUML υπάρχει για να μετατρέπει τα prompts σε διάγραμμα. Μπορεί επίσης να μετατρέπει τον Knowledge Graph της δικό του codebase σε διάγραμμα τεκμηριώσεων. Αυτό είναι dogfooding : ο plugin καταναλώνει την δική του υπηρεσία.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

package "Κανονικό pipeline
(χρήστης → διαγράμματα)" as normal {
    [Fichier .prompt] as prompt
    [LlmService\n+ ApiKeyPool] as llm1
    [ProcessPlantumlPromptsTask] as task1
    [Diagramme PNG] as out1

    prompt --> task1
    task1 --> llm1
    llm1 --> out1
}

package "Pipeline Knowledge Graph
(determinist, χωρίς LLM)" as kg {
    [graphify-out/graph.json] as kgjson
    [KnowledgeGraphParser] as parser
    [KnowledgeGraphRenderer] as renderer
    [PlantumlService] as ps
    [Diagramme PNG\n(documentation du plugin)] as out2

    kgjson --> parser
    parser --> renderer
    renderer --> ps
    ps --> out2
}

package "Pipeline Dogfooding
(LLM → τεκμηρίωση του πρόσθετου)" as dogfood {
    [GraphifyPromptAdapter] as gpa
    [Fichiers .prompt\nauto-générés] as auto_prompt
    [LlmService\n+ ApiKeyPool] as llm2
    [ProcessPlantumlPromptsTask] as task2
    [Diagramme PNG\n(documentation LLM)] as out3

    kgjson --> gpa
    gpa --> auto_prompt
    auto_prompt --> task2
    task2 --> llm2
    llm2 --> out3
}

note "Το ίδιο LlmService, το ίδιο ApiKeyPool,
Το ίδιο PlantumlService
— Μηδενική διπλοποίηση" as N

@enduml

Συνδεδεμένες εργασίες Gradle:

Εργασια LLM ? Περιγραφή

generateKnowledgeGraphDiagram

Όχι

Μετατρέψε`graph.json`στο PlantUML (δετερμινίστικός)

generateDiagramDocs

Ναι

Δημιούργησε μερικά`.prompt`από τον γράφο, τα επεξεργάζεται μέσω LLM (dogfooding)

 
# Documentation déterministe (rapide, pas de LLM)
./gradlew generateKnowledgeGraphDiagram

# Documentation LLM (plus riche, consomme des tokens)
./gradlew generateDiagramDocs

Γιατί είναι ορισμένο (και γιατί έχει σημασία)

Το κρίσιμο σημείο του pipeline`generateKnowledgeGraphDiagram`:Δεν καλεί καμία LLM. Η μετασχέδωση`graph.json`→ Το PlantUML είναι μια καθαρή συνάρτηση.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

rectangle "Pipeline deterministiko
(generateKnowledgeGraphDiagram)" as det {
    [graph.json] as json
    [KnowledgeGraphParser] as parser
    [KnowledgeGraphRenderer] as renderer
    [PlantUML code] as puml

    json --> parser : parse
    parser --> renderer : KnowledgeGraph
    renderer --> puml : render (fonction pure)
}

rectangle "Σωλήνας ΜΓΜ
(επεξεργασίαPlantumlπροτάσεις)" as llm {
    [.prompt] as prompt
    [LlmService] as llmSvc
    [ChatModel] as model
    [PlantUML code] as puml2

    prompt --> llmSvc
    llmSvc --> model : API call
    model --> puml2 : réponse non-déterministe
}

note bottom of det
  Même entrée → même sortie
  Pas de latence réseau
  Pas de coût en tokens
  Reproductible en CI
end note

note bottom of llm
  Même entrée → sortie variable
  Latence réseau (1-5s)
  Coût en tokens
  Nécessite une clave API
end note

@enduml

Ταυτοπρακτικά οφέλη :

πλεονέκτημα επίπτωση

αναπαραγωγιμότητα

ακόμη`graph.json`→ ίδιο διάγραμμα. Ακριβώς. Κάθε φορά.

μηδενικό κόστος

Δεν υπάρχει κλήση LLM = δεν υπάρχουν tokens = δεν υπάρχει τιμολόγιο API.

μηδενική καθυστέρηση

Η ανάλυση + απόδοση παίρνει ~100ms, όχι 1-5 δευτερόλεπτα.

Συμβατό CI

Δεν απαιτείται κλειδί API. Δεν υπάρχει τεστ ακαμάτως λόγω μεταβλητής απάντησης LLM.

υποverseible

Le .puml`γεννημένο είναι μερικό κείμενο. Μπορούμε το`diff, ο αναθεωρητής στη PR, να το βάλουμε υπό έλεγχο έκδοσης στο Git.

Ενσωμάτωση στην διαχείριση του έργου

Στον σχεδιασμό μας, αυτό το pipeline ενσωματώνεται σε μια στρατηγική διαχείρισης περιβάλλοντος EAGER/LAZY για τον AI agent. Ο Γνώστος Γράφος αντικαθιστά το εγχειρίδιο αρχιτεκτονικής χειροκίνητο με ένα δομημένο, ερωτήσιμο και αυτόματα ενημερωμένο γράφος.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

package "EAGER\n(πάντα φορτισμένο)" as eager {

πάγος Περιγραφή Μείωση

Γράφημα πολύ πυκνό

Ένα μεγάλο έργο παράγει εκατοντάδες μη αναγνώσιους κόμβους

Χρησιμοποιεί`-Pplantuml.kg.maxNodes=30`και φιλτράρετε κατά κοινότητα

Υπερογκές εξαιρέσεις

Παρα πολλά αρχεία στον`.graphifyignore`μειώνει την τιμή του γράφου

Ξεκινήστε αποκλείοντας μόνο τα credentials και το build

Κατεύθυνση των βελών

Οι άκρες INFERRED μπορούν να έχουν αβσασή κατεύθυνση

Φιλτράρετε κατά`-Pplantuml.kg.edgeTypes=EXTRACTED`για τις βεβαίες σχέσεις μόνο

παλαιός γράφος

Χρησιμοποιήστε`graphify . --update`δια τακτικά ή το git hook`graphify hook install`

Τα πραγματικά όφελη:

Κέρδος Λεπτομέρεια

Η τεκμηρίωση είναι πάντα ενημερωμένη

Τα διαγράμματα αντικατοπτρίζουν τον τρέχοντα κώδικα, όχι ένα χειροκίνητο στιγμιότυπο

Μηδενική προσπάθεια συντήρησης

Τα διαγράμματα ανακτιούνται σε κάθε build

μείωση του τεχνικού χρέους

Δεν χρειάζεται πλέον να διατηρείτε τα διαγράμματα χειροκίνητα

Οπτικό πλαίσιο για τους νέους

Ένας νέος προγραμματιστής κατανοεί την αρχιτεκτονική βλέποντας τα διαγράμματα.

Fine-tuning πιθανό

Τα ζεύγη (υπογράφημα → διάγραμμα) είναι παραδείγματα εκπαίδευσης τεχνητής νοημοσύνης

αυτόματη επικύρωση

`PlantumlService.validateSyntax()`ελέγζει κάθε παραγόμενο διάγραμμα

Γρήγορη ενσωμάτωση

5 διαγράμματα = ολοκληρωμένη θέα της αρχιτεκτονικής

_ Οποιος έχει ένα _pourquoi μπορεί να αντέχει όλους τους comment. __

Το pourquoi : διαγράμματα πάντα ενημερωμένα. Το comment : δύο εντολές σε ένα pipeline Gradle.
