Ο Πρώτος Νεοαπασχολημένος μας: Ο Ανωνυμοποιητής Δεδομένων — MVP0 κατά τη δοκιμαστική περίοδος

Δημοσιεύτηκε 01 May 2026

Table des matières
  • Το πρόβλημα που κάνει όλοι να φύγουν
χρόνος ανάγνωσης : 12 minutes

Δεν προσλαμβάνω ένα LLM. Προσλαμβάνω έναν ανωνυμοποιητή. Πριν από να κάνω RAG pgvector, πριν από να fine-tune ειδικούς CDA/FPA, πριν από τη παροχή χώρων εργασίας για πελάτες — κάποιος πρέπει να καθαρίσει τα ωηελετρίνα των δεδομένων. Αυτό το υπεύθυνος είναι ο ειδικός στην ανωνυμοποίηση (MVP0, EPIC 2 του codebase-gradle). Και είναι αυτός που κάνει το προϊόν αγοραρό.

Το πρόβλημα που κάνει όλοι να φύγουν

Κάθε startup IA που χειρίζεται δεδομένα εκπαίδευσης βλέπει τον ίδιο τοίχο :

----
----
Données brutes client (SPG, cours, évaluations)
  ├→ Noms de stagiaires en clair dans les PDF
  ├→ Emails dans les métadonnées JSON
  ├→ IP de connexion dans les logs pgvector
  ├→ Identifiants dans les nœuds Graphify
  └→ Références OF pilote dans les schémas SQL
----

Αποτέλεσμα: είτε κάνεις RAG σε βρωμικά δεδομένα (hallucinations PII, μη συμμόρφωση GDPR, νομικός κίνδυνος), είτε δεν κάνεις τίποτα (δεν υπάρχει προϊόν). Ο τρίτος τρόπος — καθαρισμός με το χέρι — δεν είναι κλιμακώσιμος.

Η απάντησή μου: μην αγνοείτε το πρόβλημα. L'**αυτοματοποιώ**.

== MVP0 : Ο ανωνυμοποιητής, πρώτος προσλαμβανός κατά τη δοκιμαστική περίοδο

Το MVP0 δεν είναι μια λειτουργία. Είναι**ειδáticos στηνευ_colία**— ένας υπάλληλος που κάνει την άσχιστη, ανόητη και κακόπροσώπεια δουλειά, και που κανείς δεν θέλει να μιλήσει στα pitch decks.

Τι κάνει :

[source]
----
ENTRÉE : Données brutes multi-sources
  ├→ AsciiDoc (SPG_A2SP.adoc) → noms, dates, OF pilote
  ├→ JSON (catalogue formations) → emails, téléphones
  ├→ YAML (config workspace) → tokens OAuth2
  ├→ SQL (schémas DDL) → IP, adresses
  ├→ pgvector (métadonnées embeddings) → identifiants
  ├→ ONNX (outputs classification) → noms propres
  └→ Graphify (graph.json) → nœuds avec PII

SORTIE : Datasets propres, format standardisé
  ├→ [ANONYMIZED] remplace les PII détectées
  ├→ Classification RGPD (niveau 0→4)
  ├→ Rapport d'audit (quoi a été nettoyé)
  └→ Dataset prêt pour RAG ET fine-tuning
----

Ανιχνεύει πρώτα τα πιο φανερά πρότυπα (emails`.*@.*`, τοκενς`sk-*`, `ghp_*`, IPs), τότε μαθαίνει. Η περίοδος δοκιμής, αυτό είναι: επαληθεύουμε ότι δεν επιτρέπει την παράλειψη ψευδών αρνητικών πριν τον οριστικοποιήσουμε.

== Τι ξεκλείδωσε αυτό το MVP (και δεν είναι μόνο η συμμόρφωση)

Η ανωνυμοποίηση ως MVP0 δεν είναι το τελώνιο του GDPR πριν τον αυτοκινητόδρομο. Είναι ο ίδιος ο αυτοκινητόδρομος. Αυτό είναι το τι ανοίγει:

=== Παρόν: Επαυξημένη Πραγματικότητα στο Prompt

[source]
----
DONNÉES BRUTES CLIENT
    ↓
Anonymiseur MVP0 → datasets propres
    ↓
RAG pgvector (MVP1) → top-K documents similaires (filtrés, anonymisés)
    ↓
LLM (deepseek-v4-pro) → réponse augmentée, zéro PII
----

Το RAG δεν ψάχνει σε λημένα δεδομένα — ψάχνει σε ένα χώρο**καθαρός από κατασκευή**. Αυτό αλλάζει όλα για την ποιότητα των απαντήσεων: το LLM δεν αφιώνει τον χρόνο του προσπαθώντας να αποφύγει τα PII που αναγνωρίζει αλλά δεν πρέπει να αναφέρει.

=== Μέλλον: Fine-Tuning σε καθαρά δεδομένα

[source]
----
MVP0 → datasets propres accumulés (session après session)
    ↓
Fine-tuning expert métier (CDA, FPA) sur données zéro PII
    ↓
Modèle fine-tuné exposé via Ollama (sans fuite de données)
----

Η ρυθμιζasyon (fine-tuning) σε απυκαίστα δεδομένα είναι μια πιθανή νομική καταστροφή. Σε καθαρά δεδομένα, είναι μια**αναπαραγώγιμη μέθοδος**. Κάθε πελάτης συσσωρεί τα καθαρισμένα datasets του, κάθε πελάτης μπορεί να ρυθμίσει τους ειδικούς του επιχειρηματικού τομέα στα δεδομένα του — χωρίς ποτέ να εκθέσει δεδομένα προσωπικού χαρακτήρα.

== Γιατί είναι εμπορικά ελκυστικό

Δεν είναι « ένα εργαλείο συμμόρφωσης GDPR ». Είναι μια**επαναλήψιμη μέθοδος που μετατρέπει ένα παγκόσμιο πρόβλημα σε περιουσιακό στοιχείο**:

1. *Κάθε επιχείρηση κατάρτισης έχει δεδομένα βρώμικα* — είναι το πρόβλημα
2. *Κανένα δεν έχει αυτόματο πολυπηγές pipeline καθαρισμού* — αυτή είναι η αγορά
3. *Ο βρόχος: ανωνυμοποίηση → RAG → fine-tuning είναι ιδιοκτησιακός* — αυτό είναι η εμπόδιο

Το SaaS Edster (MVP3) δεν θα πουλάει « un workspace Gradle ». Θα πουλάει αυτό τον κλειστόν βρόχο. Και το MVP0 είναι η εισόδου.

== Η μορφή SQL ως τρίτος τρόπος του περιβάλλοντος

Η εισαγωγή δομημένων δεδομένων δεν είναι απλώς μια μορφή ανταλλαγής. Το σχήμα SQL (DDL) φέρει το**μοντέλο ουσίας-σχέσης του τομέα** :

[source]
----
CREATE TABLE formation (
  id UUID PRIMARY KEY,
  titre VARCHAR NOT NULL,
  referentiel RNCP REFERENCES rncp(id),
  organisme OF REFERENCES of_pilote(id)  -- ← va être anonymisé
);
----

Αυτός ο DDL, μια φορά ανωνυμοποιημένος (γραμμή 4), γίνεται μια πηγή περιβάλλοντος για τον LLM. Δεν είναι κείμενο — du**επιχειρηματικό μοντέλο**. Το RAG παρέχει το περιεχόμενο (διανυσματική ομοιότητα), το Graphify παρέχει τις σχέσεις (ακριβής δομή), και το σχήμα SQL παρέχει το**Domain-Driven Design emphanís**: bounded contexts, agrégats, value objects. Ο LLM καταλαβαίνει το επιχείρημα επειδή διαβάζει το σχήμα του.

== Ο χάρτης δρόμου: από το MVP0 έως το SaaS

[source]
----
MVP0 — Anonymiseur (ce que cet article décrit)
  Sortie : datasets propres, reproductible

MVP1 — RAG pgvector (dépend de MVP0)
  Realité augmentée en prompt sur données nettoyées

MVP2 — Graphify + ONNX + SQL DDD (dépend de MVP1)
  Vecteur composite de contexte (règles + similarité + relations exactes)

MVP3 — SaaS Edster (dépend de MVP0-2)
  Provisionnement workspace client complet
----

Κάθε MVP εξαρτάται από το προηγούμενο. Κανένας δεν μπορεί να παραδοθεί χωρίς το MVP0. Αυτό είναι ο λόγος για τον οποίο ο Ανωνυμοποιητής δεν είναι « P0 » στο backlog — είναι**MVP0**. Αυτό είναι το πρώτο εμπορικό προϊόν, και όλο το υπόλοιπο εξαρτάται από την επιτυχία του.

== Συμπέρασμα: Το αόρατο έργο που κάνει όλα δυνατά

Σε μια παραδοσιακή startup, το καθαρισμό των δεδομένων εξαρκείται εξωτερικά, είναι χειροκίνητο ή αγνοείται. Σε αυτήν την αρχιτεκτονική, είναι το**καρδιά του προϊόντος**. Ο ανωνυμιστής είναι ο πρώτος υπάλληλος επειδή χωρίς αυτόν, τίποτα δεν λειτουργεί:

* Χωρίς MVP0 → δεν υπάρχει νομικό RAG (MVP1)
* Χωρίς MVP0 → δεν υπάρχει fine-tuning χωρίς διάρροια δεδομένων (EPIC 5)
* Χωρίς MVP0 → χωρίς πιστό SaaS (MVP3)
* Χωρίς MVP0 → χωρίς αύξητη πραγματικότητα στο πρόσκαμμα
* Χωρίς MVP0 → δεν υπάρχει τρίτος δρόμος περιβάλλοντος (SQL DDD)

Κάνει τη βρώμικη δουλειά. Θα μην αναφέρεται ποτέ στις παρουσιάσεις. Αλλά αυτός είναι ο οποίος κάνει τη βιομηχανία να λειτουργεί.

Και γιαυτό τον προσλαμβάνουν πρώτο.
