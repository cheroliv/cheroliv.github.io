OpenCode is NIET een leverancier van modellen.Dit is een open source CLI (github.com/anomalyco/opencode) die AI-agents orchestreert. Hij verkoopt geen abonnement en levert geen inferentie. Dit is het equivalent van`git`voor versiebeheer: een hulpmiddel, geen dienst. Ollama Cloud is de inferentieprovider.Mijn lokale Ollama-installatie fungeert als client — ze authenticeren bij de Ollama-servers via een unieke SSH-sleutel (Device Key) en delegeert de uitvoering van de gelabelde modellen aan hen.:cloud. Pro-abonnement (20 €/maand) ontgrendelt hogere quoteringen en maakt het mogelijk om meerdere accounts op één machine te combineren via Docker.

Inleiding: Waarom een audit?

Twee maanden geleden gebruikte ik gratis modellen op mijn lokale Ollama-installatie. Daarna sloot ik een eerste abonnement af op Ollama Cloud Pro van 20 euro per maand, waardoor ik de cloudmodellen kan gebruiken (die met de tag`:cloud`) via de provider`ollama-cloud`. Een tweede abonnement volgde een maand later op een gescheiden Docker-instantie met zijn eigen account en eigen SSH-sleutel — de cumulatieve methode beschreven in mijn artikel over het stapelen van abonnementen

De vraag die me bezighield : Zijn deze 20 € per maand gerechtvaardigd? Niet op gevoel. Met cijfers.

Om te antwoorden, had ik precieze gegevens nodig. Geen schattingen. Geen gemiddelden. Mijn echte consumptie, token per token, model per model, sessie per sessie.

En OpenCode — de CLI — slaat dit alles op in een SQLite-database.

De OpenCode-database: Een goudmijn

OpenCode slaat de volledige geschiedenis van zijn sessies op in een SQLite-bestand dat zich bevindt op`~/.local/share/opencode/opencode.db`. La mienne pèse 660 Mo pour 73 jours d’utilisation — une base de données de production tout à fait respectable.

De tafel`session`is perfect voor een globale audit: elke sessie heeft zijn geaggregeerde aantal tokens, zijn gebruikte model en zijn kosten. Het veld`model`is ruwe JSON :

{
  "id": "deepseek-v4-pro:cloud",
  "providerID": "ollama-cloud",
  "variant": "default"
}

Het veld`cost`in de OpenCode-database weerspiegelt alleen de externe API-kosten betaald per gebruik via API-sleutel (Google Gemini, OpenAI, enz.). De aanroepen via Ollama — zowel lokaal als via Ollama Cloud Pro — zijn gemarkeerd`cost=0`omdat de kosten vastliggen (abonnement), niet per-token. De echte kosten van deze gesprekken zijn het maandelijkse abonnement.

De extractiecode

Je hoeft niets te installeren. Node.js 22+ bevat een experimenteel SQLite-module (node:sqlite) die perfect werkt. Dit is het script dat mij alles heeft gegeven:

const { DatabaseSync } = require('node:sqlite');
const db = new DatabaseSync(
  `${process.env.HOME}/.local/share/opencode/opencode.db`,
  { readonly: true }
);

// 1. Statistiques globales
const global = db.prepare(`
  SELECT
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(tokens_reasoning) as total_reasoning,
    SUM(tokens_cache_read) as total_cache_read,
    SUM(cost) as total_cost
  FROM session
`).get();

// 2. Ventilation par modèle et fournisseur
const byModel = db.prepare(`
  SELECT
    json_extract(model, '$.id') as model_id,
    json_extract(model, '$.providerID') as provider,
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(cost) as total_cost
  FROM session
  WHERE model IS NOT NULL
  GROUP BY model_id, provider
  ORDER BY SUM(tokens_input) DESC
`).all();

// 3. Par mois
const monthly = db.prepare(`
  SELECT
    strftime('%Y-%m', datetime(time_created/1000, 'unixepoch')) as month,
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(cost) as total_cost
  FROM session
  WHERE time_created IS NOT NULL
  GROUP BY month
  ORDER BY month
`).all();

// 4. Messages par modèle (détection des changements intra-session)
const msgByModel = db.prepare(`
  SELECT
    json_extract(m.data, '$.model.providerID') as provider,
    json_extract(m.data, '$.model.modelID') as model_id,
    COUNT(*) as messages
  FROM message m
  WHERE json_extract(m.data, '$.model') IS NOT NULL
  GROUP BY provider, model_id
  ORDER BY COUNT(*) DESC
`).all();

console.log({ global, byModel, monthly, msgByModel });
db.close();

De vlag`--experimental-sqlite`Op Node.js 22.x is vereist. Op Node.js 24+ is het module stabiel en vereist geen vlag meer.

De Verborgen Kosten : Prompt Engineering en Iteraties

De tokenkosten zijn slechts een deel van de vergelijking. De echte kosten zijn de ontwikkelertijd.

Met OpenCode + Ollama Cloud Pro + mijn bestuur agent (EAGER/LAZY/Hot/Warm/Cold, beschreven in het artikel over de bestuur), ik krijg :

  • 0 prompt engineering repetitief: de context wordt automatisch geïnjecteerd

  • 90%+ correct bij eerste pogingde code compileert in één keer

  • Nul hallucinatie deepseek bij 8 opeenvolgende sessies(gedocumenteerd in de vergelijking Kimi/GLM/DeepSeek)

Met Claude of GPT zonder fine-tuning of governance :

  • 2-3 iteraties per taak gemiddeld

  • Systematisch prompt engineering

  • Hallucinaties over de Kotlin/Gradle API’s zodra de context 30K tokens overschrijdt

De effectieve maandelijkse kosten — tokens × iteraties × correctietijd — zijn 27× tot 54× die van mijn oplossing, zoals ik heb aangetoond in het artikel over de efficiëntieratio.

_ Het is niet alleen een kwestie van prijs per token. Een Claude Opus die 57× duurder is en 3× meer iteraties vereist, heeft een effectieve kosten die ~170× hoger is. Om het ronduit te zeggen: een stagiaire betalen met het salaris van een McKinsey-partner. _

De Ollama Cloud Pro-abonnementen combineren: de Docker-methode

Als één abonnement niet voldoende is, combineren we ze. Het principe is om elk abonnement te isoleren in zijn eigen Ollama-installatie, met zijn eigen SSH-authenticatiesleutel. Docker maakt het triviaal.

De volledige methode wordt gedetailleerd beschreven in het artikel over het combineren van Docker, hier is het principe :

@startuml
skinparam backgroundColor #FEFEFE
skinparam defaultFontSize 12

title Architectuur — twee Ollama Cloud Pro-abonnementen op één machine
left to right direction

node "Mijn fysieke machine" {
  frame "Ollama instantie A (natief)
poort :11434" as Native {
    database "Identiteit A
/usr/share/ollama/.ollama/id_ed25519"
  }
  frame "Ollama Instance B (Docker)
poort :11435" as Docker {
    database "Identity B\n~/ollama-b-data/id_ed25519"
  }
}

cloud "Ollama Cloud" {
  actor "Pro A-account
(e-mail 1)" as A
  actor "Account Pro B\n(email 2)" as B
}

Native --> A : "Device Key A"
Docker --> B : "Apparaatsleutel B"

note bottom of Docker
  Conteneur Docker isolé :
  - Clé SSH distincte
  - Port réseau distinct (11435)
  - Volume persistant (~/ollama-b-data)
  - restart: always
end note
@enduml

Het patroon is simpel:

  1. Een volume maken`~/ollama-b-data`

  2. Een Docker-container starten`ollama/ollama:0.20.2`gemapt op`11435:11434`

  3. Ophalen van de SSH-sleutel van de container → opslaan op ollama.com

  4. doen`ollama signin`met een tweede e-mail

  5. OpenCode configureren met twee providers (`ollama`op :11434,`ollama-b`op :11435)

Twee rekeningen, één blauwe kaart, geen conflicten.

Wat de audit niet meet

dode hoek impact

Kwaliteit van de geproduceerde code

ecosysteem OpenCode

De CLI is gratis, maar de waarde (agents, sandboxes, geschiedenis, prompt caching) is enorm. Het is niet inbegrepen in de prijs van het abonnement — het is een apart hulpmiddel.

alternatieve kosten

2 uur per dag besteden aan het debuggen van hallucinaties van een inferieur model kost meer dan €20 per maand.

Gemoedsrust

Vast tarief = geen verrassing. Met per-token kan een piek in activiteit ernstig pijn doen.

De genoemde prijzen zijn die van mei 2026. Over zes maanden zal alles zijn gedaald. Maar de structurele krachtverhouding — vast abonnement versus betalen naar gebruik — blijft gunstig voor het abonnement voor grote verbruikers.
