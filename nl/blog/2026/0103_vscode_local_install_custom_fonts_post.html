De waarom: VS Code in de Home

Het probleem met de systeeminstallatie

VS Code geïnstalleerd via`apt`, dnf`of in/opt`Vergrendelt de toepassingsbestanden achter root-rechten. Elke wijziging van de native CSS, van`product.json`of de installatiemap vereist`sudo`.

Echter, wanneer men gebruiktopencode(tool CLI om een LLM op zijn code te besturen), de agent heeft de mogelijkheid nodig om :

  • Schrijven in de configuratiebestanden (~/.config/Code/User/settings.json) — dat is al thuis

  • Wijzig de assets van de IDE (CSS van de workbench,product.json) voor de geavanceerde aanpassingen — dat, is geblokkeerd zonder sudo

De oplossing: een lokale installatie

We downloaden de officiële tarball-archief en pakken het direct uit in`~/apps/`:

mkdir -p ~/apps
cd ~/apps
wget "https://code.visualstudio.com/sha/download?build=stable&os=linux-x64" -O vscode.tar.gz
tar -xzf vscode.tar.gz
rm vscode.tar.gz

De binaire bevindt zich dan in`~/apps/VSCode-linux-x64/bin/code`. Geen`sudo`is niet nodig om een bestand te lezen, te bewerken of te vervangen onder`~/apps/VSCode-linux-x64/`.

Aanpassen van het lettertype van het hoofdmenu

De bevinding

Het standaardlettertype van het hoofdmenu (File, Edit, View…​) en van de vervolgkeuzelijsten is te klein. VS Code biedt geen parameter om het te wijzigen.

De techniek: directe CSS-patch

We voegen CSS toe aan het einde van het bestand`workbench.desktop.main.css` :

@startuml

dev -> vscode : Redémarrer VS Code

  Deux fichiers dans ~/apps/

@enduml
CSS_FILE="$HOME/apps/VSCode-linux-x64/resources/app/out/vs/workbench/workbench.desktop.main.css"

cat >> "$CSS_FILE" << 'EOF'
.menubar-menu-title{font-size:23px!important}
.menubar>.menubar-menu-button{font-size:23px!important}
.monaco-menu-option{font-size:22px!important;line-height:34px!important}
.monaco-menu .action-label:not(.codicon){font-size:22px!important}
.menubar-menu-items-holder .monaco-menu .action-item .action-label{font-size:22px!important}
EOF

Verwijder de integriteitswaarschuwing

VS Code detecteert de wijzigingen in zijn bestanden en toont een banner "Your installation is corrupt". Om dit te voorkomen, verwijderen we de checksums van`product.json`:

import json
product_json = "$HOME/apps/VSCode-linux-x64/resources/app/product.json"
with open(product_json, 'r') as f:
    data = json.load(f)
data.pop('checksums', None)
with open(product_json, 'w') as f:
    json.dump(data, f, indent=2)

Na het opnieuw opstarten zijn er geen waarschuwingen meer en zijn de menu’s eindelijk leesbaar.

Het lettertype van het Explorer-venster aanpassen — de strijd

Tentative 1 : een parameter die niet bestaat

We proberen eerst de native parameter`workbench.tree.fontSize`in`settings.json`:

{
    "workbench.tree.fontSize": 20
}

Resultaat :geen effect. Deze instelling bestaat niet in VS Code. Het bewijs dat niet-herkende instellingen stilzwijgend worden genegeerd.

Tentative 2: de extensie Custom CSS and JS Loader

We installeren de extensie`be5invis.vscode-custom-css`:

~/apps/VSCode-linux-x64/bin/code --install-extension be5invis.vscode-custom-css

We maken een CSS-bestand in`~/.vscode-custom-css/custom.css`met selectors gericht op de elementen van de verkenner :

.monaco-tree-rows .monaco-tree-row,
.sidebar .monaco-list-row,
.explorer-viewlet .monaco-list-row,
.monaco-list-row .monaco-icon-label {
    font-size: 22px !important;
    line-height: 36px !important;
}

En we verwijzen naar dit bestand in de instellingen:

{
    "vscode_custom_css.imports": [
        "file:///home/user/.vscode-custom-css/custom.css"
    ]
}

Resultaat :De wijzigingen worden niet toegepast.

De valkuil: je moet de extensie elke keer activeren

De documentatie van de extensie is discreet over dit cruciale punt: na elke wijziging van de custom CSS, moetabsoluutvoer de opdracht uit vanuit het palet :

  1. Ctrl+Shift+P→ typenAangepaste CSS en JS inschakelen

  2. VS Code vraagt een herstart → accepteren

Zonder deze stap wordt de CSS nooit in de IDE geïnjecteerd.

Poging 3: de lijnen overlappen

Zelfs met`font-size: 22px` et line-height: 36px, de letters met een staaf (g, p, f, b) steken uit op de naastgelegen lijnen. We proberen toe te voegen`height` et min-height :

.monaco-list-row {
    height: 36px !important;
    min-height: 36px !important;
}

Resultaat :geen wijziging. VS Code berekent de regelhoogtes in JavaScript en overschrijft de CSS-waarden.

In plaats van te vechten tegen de JavaScript-layout, wordt de eigenschap gebruikt.`zoom`op de container van de lijnen :

.explorer-viewlet .monaco-list-rows,
.sidebar .monaco-list-rows {
    zoom: 1.25;
}

`zoom`vergroot uniform de rendering van de container — tekst EN spatie — zonder het door JavaScript van VS Code berekende layout te verbreken. De factor 1.25 komt ongeveer overeen met een overgang van 13px naar 16px.

Resultaat :de bestandsnamen zijn eindelijk leesbaar, de regels zijn correct gespatieerd.

Het probleem

Wanneer VS Code wordt bijgewerkt, vervangt het de installatiemap enWis alle CSS-patches. U moet de wijzigingen elke keer handmatig opnieuw toepassen.

Het script `vscode-update.sh

We maken`~/apps/vscode-update.sh`:

#!/bin/bash
set -e

VSCODE_DIR="$HOME/apps/VSCode-linux-x64"
BACKUP_DIR="$HOME/apps/vscode-backup"
TEMP_DIR="/tmp/vscode-update"

MENUBAR_FONT_SIZE="23px"
DROPDOWN_FONT_SIZE="22px"

echo "=== VS Code Local Updater ==="

CURRENT_VERSION=$("$VSCODE_DIR/bin/code" --version 2>/dev/null | head -1)
echo "Current version: $CURRENT_VERSION"

echo "Downloading latest VS Code..."
mkdir -p "$TEMP_DIR"
wget -q "https://code.visualstudio.com/sha/download?build=stable&os=linux-x64" \
    -O "$TEMP_DIR/vscode.tar.gz"

echo "Extracting..."
mkdir -p "$TEMP_DIR/extracted"
tar -xzf "$TEMP_DIR/vscode.tar.gz" -C "$TEMP_DIR/extracted"

NEW_VERSION=$("$TEMP_DIR/extracted/VSCode-linux-x64/bin/code" \
    --version 2>/dev/null | head -1)
echo "New version: $NEW_VERSION"

if [ "$CURRENT_VERSION" = "$NEW_VERSION" ]; then
    echo "Already up to date!"
    rm -rf "$TEMP_DIR"
    exit 0
fi

echo "Backing up current installation..."
mkdir -p "$BACKUP_DIR"
cp -r "$VSCODE_DIR" "$BACKUP_DIR/VSCode-linux-x64-$(date +%Y%m%d-%H%M%S)"

echo "Updating..."
rm -rf "$VSCODE_DIR"
mv "$TEMP_DIR/extracted/VSCode-linux-x64" "$VSCODE_DIR"
rm -rf "$TEMP_DIR"

CSS_FILE="$VSCODE_DIR/resources/app/out/vs/workbench/workbench.desktop.main.css"
echo "Re-applying custom CSS patch \
    (menubar=${MENUBAR_FONT_SIZE}, dropdown=${DROPDOWN_FONT_SIZE})..."
cat >> "$CSS_FILE" << CSSEOF
.menubar-menu-title{font-size:${MENUBAR_FONT_SIZE}!important}\
.menubar>.menubar-menu-button{font-size:${MENUBAR_FONT_SIZE}!important}\
.monaco-menu-option{font-size:${DROPDOWN_FONT_SIZE}!important;\
line-height:34px!important}\
.monaco-menu .action-label:not(.codicon)\
{font-size:${DROPDOWN_FONT_SIZE}!important}\
.menubar-menu-items-holder .monaco-menu .action-item .action-label\
{font-size:${DROPDOWN_FONT_SIZE}!important}
CSSEOF

PRODUCT_JSON="$VSCODE_DIR/resources/app/product.json"
if [ -f "$PRODUCT_JSON" ]; then
    echo "Removing checksums to prevent integrity warning..."
    python3 -c "
import json
with open('$PRODUCT_JSON','r') as f: data=json.load(f)
data.pop('checksums', None)
with open('$PRODUCT_JSON','w') as f: json.dump(data,f,indent=2)
print('Done.')
"
fi

echo "=== Update complete: $CURRENT_VERSION -> $NEW_VERSION ==="

Het script :

  1. Download de nieuwste stabiele versie

  2. Controleer of de versie verschilt van de huidige

  3. Bewaar de huidige installatie (getimestamp) in`~/apps/vscode-backup/`

  4. Vervang de installatiemap

  5. Opnieuw aanbrengende CSS-patch van het hoofdmenu

  6. Verwijder de checksums de `product.json`om de integriteitswaarschuwing te voorkomen

Aanpassingen van het Verkenner via de Custom CSS-extensie en het bestand`~/.vscode-custom-css/custom.css`Ze overleven updates omdat ze buiten de installatiemap leven.

Installeren in de home geeft alles vrij

Een lokale installatie in`~/apps`geeft volledige controle over VS Code:

  • Geen`sudo`om de CSS of de configuratie aan te passen

  • De opencode+LLM-agent kan schrijven naar de configuratiebestanden en de assets van de IDE

  • Triviale rollback: terugzetten de getijdgestempelde backup

zoom` > font-size voor de lijstcomponenten

VS Code controleert de regelhoogte via JavaScript. Wijzigen`font-size`Niet kunnen aanpassen aan de door de layout-engine toegewezen hoogte levert teksten die overlopen. De eigenschap`zoom`Op de oudercontainer vergroot alles evenredig en omzeilt dit probleem.

De Custom CSS-extensie vereist een expliciete activering.

Dit is geen "set and forget"-parameter. Elke wijziging aan het aangepaste CSS-bestand vereist het opnieuw uitvoeren van "Enable Custom CSS and JS" vanaf de opdrachtpalet (Ctrl+Shift+P).

Een script voor update is onmisbaar

Zonder script verwijdert elke update van VS Code de CSS-patches van het workbench. Het script`vscode-update.sh`automatiseert het downloaden, vervangen, herpatchen en opruimen van checksums
