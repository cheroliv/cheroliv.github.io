Hybride architectuur: Het beste van twee werelden met Supabase en Spring Boot

Gepubliceerd op 14 January 2026

leestijd : 12 minutes

In plaats van te kiezen tussen de eenvoud van Supabase en de kracht van Spring Boot, waarom zou je de twee niet combineren? Ontdek een hybride architectuur die het beste van elke technologie benut.

Het valse dilemma van de moderne architectuur

Wanneer we een moderne applicatie bouwen met een statisch frontend, komen we vaak voor een binaire keuze te staan:

  • Alles inzetten op een Backend-as-a-Service oplossing(Supabase, Firebase) - eenvoudig maar beperkt

  • Bouw een volledige backend(Spring Boot, Node.js) - krachtig maar complex

Deze keuze is een valse dilemma. De hybride architectuur biedt een derde weg: gebruik elke technologie daar waar ze uitblinkt

Architecturale visie

De traditionele architectuur: monolithisch

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

package "Traditionele architectuur" {
  actor Utilisateur as user
  component "frontend" as frontend #LightBlue
  component "Monolithisch backend" as backend #LightCoral {
    [Authentification]
    [CRUD]
    [Logique Métier]
    [Jobs]
    [APIs Tierces]
  }
  database "Database" as db #LightGray

  user --> frontend
  frontend --> backend : Toutes les requêtes
  backend --> db
}

note right of backend
  Tout passe par le backend
  même les opérations simples

  ⚠️ Point de congestion unique
  ⚠️ Complexité dès le départ
  ⚠️ Couplage fort
end note
@enduml

In deze aanpak moeten zelfs de eenvoudigste operaties (het lezen van een artikel, het aanmaken van een reactie) via uw backend verlopen. U betaalt de kost van de complexiteit vanaf de eerste dag.

De BaaS-architectuur : Elke afgevaardigde

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

package "Zuivere BaaS-architectuur" {
  actor Utilisateur as user
  component "frontend" as frontend #LightBlue
  cloud "Supabase / Firebase" as baas #LightGreen {
    [Auth]
    [Database]
    [Storage]
    [Edge Functions]
  }

  user --> frontend
  frontend --> baas : Toutes les opérations
}

note right of baas
  Développement rapide
  Pas de serveur à gérer

  ⚠️ Limité pour logique complexe
  ⚠️ Vendor lock-in
  ⚠️ Edge Functions contraintes
end note
@enduml

Aan de andere kant is het volledig uitbesteden aan een BaaS in het begin aantrekkelijk, maar het toont al snel zijn grenzen zodra de bedrijfslogica complexer wordt.

De hybride architectuur: Scheiding van verantwoordelijkheden

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

actor Utilisateur as user #LightBlue

package "frontendlaag" {
  component "Statische site JBake" as frontend #SkyBlue
}

package "Eenvoudige laag (Supabase)" #LightGreen {
  component "authenticatie" as auth
  component "CRUD Basis" as crud
  component "Bestandsopslag" as storage
  component "real-time" as realtime
}

package "Zakelijke laag (Spring Boot)" #Coral {
  component "complexe logica" as logic
  component "Orchestratie" as orchestration
  component "Geplande taken" as jobs
  component "Integraties" as integrations
}

database "PostgreSQL Gedeeld" as db #LightGray

user --> frontend

frontend --> auth : OAuth2, JWT
frontend --> crud : Articles, Profils
frontend --> storage : Images, Fichiers
frontend --> realtime : Notifications

frontend --> logic : Calculs, Rapports
frontend --> orchestration : Workflows
logic --> integrations : Stripe, APIs
orchestration --> db
jobs --> db

crud --> db
auth --> db

note bottom of db
  **Une seule source de vérité**
  Partagée entre Supabase et Spring Boot
end note

note right of auth
  **Gratuit jusqu'à 50k users**
  Configuration en quelques clics
  OAuth2 multi-providers
end note

note right of logic
  **Activé seulement si nécessaire**
  Kotlin + Coroutines
  Transactions complexes
end note
@enduml

De hybride architectuur scheidt duidelijk de verantwoordelijkheden op basis van de complexiteit en de aard van de bewerkingen.

Orkestratie van de fluxen

Flux 1 : Gecentraliseerde authenticatie

@startuml
skinparam backgroundColor #FEFEFE
autonumber

actor "Gebruiker" as user
participant "JBake" as jbake
participant "Supabase Auth" as auth
participant "Spring Boot" as spring
database "PostgreSQL" as db

== Authentification ==
user -> jbake : Clique "Inloggen"
jbake -> auth : Redirect OAuth2 (Google/GitHub)
auth -> user : Consent screen
user -> auth : Autorise
auth -> auth : Génère JWT
auth -> jbake : Retourne JWT + Refresh Token
jbake -> jbake : Stocke tokens (sessionStorage)

== Accès aux Ressources ==
group Opération Simple (CRUD)
  user -> jbake : Crée un article
  jbake -> db : POST avec JWT
  note right: Supabase Row Level Security\nvérifie le JWT automatiquement
  db -> jbake : Article créé
end

group Opération Complexe (Métier)
  user -> jbake : Génère un rapport
  jbake -> spring : POST /api/reports\navec JWT
  spring -> spring : Valide JWT Supabase
  spring -> spring : Extrait claims (user_id, roles)
  spring -> db : Requêtes complexes
  spring -> jbake : Rapport généré
end

note over auth, spring
  **Le JWT est universel**
  Valide par Supabase ET Spring Boot
  Pas de double authentification
end note
@enduml

Belangrijk puntEén authenticatieproces, één JWT, overal bruikbaar.

Flux 2 : Orchestration van een complex zakelijk proces

@startuml
skinparam backgroundColor #FEFEFE
autonumber

actor "klant" as user
participant "JBake" as jbake
participant "Spring Boot" as spring
participant "Supabase DB" as supadb
participant "Stripe API" as stripe
participant "Voorraadservice" as inventory
participant "e-mailservice" as email
database "PostgreSQL" as db

user -> jbake : Passe commande
jbake -> spring : POST /api/orders/create

== Orchestration Spring Boot ==
spring -> db : BEGIN TRANSACTION

par Vérifications Parallèles
  spring -> inventory : Vérifier stock
  inventory -> spring : Stock OK
else
  spring -> db : Vérifier profil client
  db -> spring : Client vérifié
end

spring -> stripe : Créer Payment Intent
stripe -> spring : Intent créé (ID: pi_xxx)

spring -> db : Créer Order (status: PENDING)
db -> spring : Order créé

spring -> stripe : Confirmer paiement
stripe -> spring : Paiement confirmé

spring -> db : Update Order (status: PAID)
spring -> inventory : Décrémenter stock
spring -> db : COMMIT TRANSACTION

par Notifications Asynchrones
  spring -> email : Email confirmation
else
  spring -> supadb : Insert notification
  note right: Notification temps réel\nvia Supabase Realtime
end

spring -> jbake : Order confirmé
jbake -> user : Affiche confirmation

note over spring
  **Responsabilités Spring Boot :**
  • Transaction ACID
  • Orchestration multi-services
  • Rollback automatique si erreur
  • Gestion des cas limites
end note
@enduml

Wat Spring Boot brengtBetrouwbare orchestratie van complexe processen die meerdere systemen omvatten, met transactiegarantie.

Flux 3 : Geplande taken en synchronisaties

@startuml
skinparam backgroundColor #FEFEFE

participant "Scheduler\n(Spring Boot)" as scheduler
participant "Rapport Service" as report
participant "PostgreSQL" as db
participant "externe API" as api
participant "e-mailservice" as email
participant "Supabase Opslag" as storage

== Job Quotidien : 2h00 ==
activate scheduler
scheduler -> report : Déclenche génération rapport

activate report
report -> db : Récupère données\ndes dernières 24h
db -> report : Dataset

report -> report : Calculs & Agrégations
report -> report : Génération PDF

report -> storage : Upload PDF
storage -> report : URL publique

report -> email : Envoie aux admins\navec lien PDF
deactivate report

== Job Hebdomadaire : Dimanche 3h00 ==
scheduler -> report : Synchronisation externe

activate report
report -> api : Fetch données externes
api -> report : Nouvelles données

report -> db : Mise à jour tables
report -> db : Nettoyage données obsolètes
deactivate report

== Job Mensuel : 1er du mois ==
scheduler -> report : Facturation

activate report
report -> db : Liste clients actifs
report -> report : Calcul montants
report -> api : Génération factures (Stripe)
report -> email : Envoi factures
deactivate report

deactivate scheduler

note right of scheduler
  **Impossible avec Supabase seul**
  Edge Functions non adaptées
  pour jobs longs et récurrents
end note
@enduml

Wat Spring Boot brengt: Betrouwbare geplande taken met statusbeheer, automatische nieuwe poging, en gegarandeerde uitvoering.

Wanneer kies je deze architectuur?

✅ Deze architectuur is ideaal als :

  • Je wilt snel starten (MVP in dagen, niet in maanden)

  • U verwacht een groei van de bedrijfscomplexiteit

  • U wilt de initiële kosten minimaliseren

  • U houdt van PostgreSQL en u wilt een enkele bron van waarheid

  • Je waardeert Kotlin en de Coroutines voor de zakelijke code

  • U wilt volledige vendor lock-in vermijden

Deze architectuur is NIET geschikt als :

  • Uw project is eenvoudig en zal dat blijven (persoonlijke blog → 100% Supabase is voldoende)

  • Je hebt al een gevestigde backend-stack die je beheerst

  • Je prefereert een traditionele monoliet

  • Je hebt .NET, Python of een andere backendtaal nodig.

Anti-Patterns om te vermijden

❌ Niet doen:

  • Dupliceren de gegevens tussen Supabase en Spring Boot

  • Maak twee aparte PostgreSQL-databases

  • Codeer de authenticatie zelf

  • Gebruik Spring Boot voor eenvoudige CRUD

  • Vanaf het begin over-architectureren

  • Negeer Row Level Security van Supabase

✅ Doe liever :

  • Een PostgreSQL-database delen

  • Laat Supabase de authenticatie regelen

  • Gebruik Spring Boot alleen voor de complexiteit

  • Begin eenvoudig, evolueer geleidelijk

  • Benut de sterke punten van elke technologie

  • Beveiligen met RLS op database-niveau

Architecturale getuigenissen

Startup SaaS (50k gebruikers)

_ We zijn begonnen met 100% Supabase. Bij 5k gebruikers hebben we Spring Boot alleen toegevoegd voor Stripe-facturatie en maandelijkse rapporten. Een jaar later zijn 80% van onze bewerkingen nog steeds via Supabase. Spring Boot behandelt alleen het kritieke deel. Deze scheiding heeft ons in staat gesteld om te schalen zonder herontwerp. _

E-learningplatform (10k gebruikers)

_ De OAuth2-authenticatie van Supabase heeft ons drie weken ontwikkeltijd bespaard. De automatisch gegenereerde API’s beheren ons volledige cursuscatalogus. Spring Boot wordt alleen gebruikt voor PDF-certificaten en voortgangs-e-mails. Eenvoudige, onderhoudbare, schaalbare architectuur. _

Marketplace B2B (3k gebruikers)

__ Spring Boot beheert de transacties tussen kopers en verkopers (kritiek). Supabase beheert alles andere: profielen, realtime berichten, documenten. Het feit dat ze dezelfde PostgreSQL-database delen, bespaart ons complexe synchronisatie. De beste architecturale keuze die we ooit hebben gemaakt. (Empty)
