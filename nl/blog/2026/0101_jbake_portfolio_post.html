Architectonisch visioen

leidend principe

De architectuur is gebaseerd op het principe van scheiding van zorgen :

  • Inhoud : gestructureerde AsciiDoc-bestanden met rijke metadata

  • Presentatie : herbruikbare Thymeleaf-sjablonen

  • Gegevens : sjabloon automatisch geëxtraheerd door JBake vanaf de AsciiDoc-attributen

  • Stijl : Bootstrap 5 voor visuele consistentie

Strategische keuze: AsciiDoc voor het portfolio

Waarom AsciiDoc?

Criterium voordeel

Coherentie

Zelfde formaat als de blogartikelen

metadata

Gestructureerde en uitbreidbare attributen (project-*)

onderhoudbaarheid

Simpele tekstbewerking, versiebaar met Git

Flexibiliteit

Kan rijke inhoud bevatten (tabellen, code, afbeeldingen)

Sjabloon

JBake extraheert automatisch de attributen voor Thymeleaf

gegevensmodel

Elk portfolio-project is een AsciiDoc-document met:

  • Koptekstmetadata : gestructureerde informatie (klant, duur, technologieën, enz.)

  • Lichaam van het document : narratieve beschrijving, uitdagingen, oplossingen, resultaten

  • Aangepaste attributen: voorgefixeerd`project-*`voor de automatische extractie

@startuml
skinparam backgroundColor #FEFEFE
skinparam handwritten false

class ProjetAsciiDoc {
  +titre: String
  +jbake-type: "project"
  +jbake-status: published|draft
  +jbake-date: Date
  +jbake-tags: List<String>
  --
  +project-category: String
  +project-client: String
  +project-duration: String
  +project-role: String
  +project-thumbnail: String
  +project-gallery: List<String>
  +project-tech-stack: String
  +project-highlights: List<String>
  +project-demo-url: String
  +project-github-url: String
  --
  +body: HTML (converti)
}

class JBakeEngine {
  +parse(asciidoc)
  +extractMetadata()
  +convertToHTML()
}

class ThymeleafTemplate {
  +portfolio.html
  +project.html
  +partials/project-card.html
}

class PortfolioPage {
  +published_projects: List
  +filtres: categories
}

ProjetAsciiDoc --> JBakeEngine : parse
JBakeEngine --> ThymeleafTemplate : fournit données
ThymeleafTemplate --> PortfolioPage : génère
@enduml

Gedetailleerde use cases

UC1 : Voeg een element toe aan de portfolio

nominaal flux

@startuml
skinparam backgroundColor #FEFEFE
actor Développeur as dev
participant "Editor
Tekst" as editor
participant "Bestand
AsciiDoc" as file
participant "JBake\nMotor" as jbake
participant "Site\nStatisch" as site

dev -> editor : Créer nouveau fichier
activate editor
editor -> file : portfolio/nouveau-projet.adoc
activate file

dev -> editor : Rédiger en-tête avec métadonnées\n(titre, type=project, status=published,\nattributs project-*)
dev -> editor : Rédiger contenu narratif\n(contexte, défis, solutions)
dev -> editor : Ajouter images dans assets/img/portfolio/

editor -> file : Sauvegarder
deactivate editor

dev -> jbake : Lancer build (jbake -b)
activate jbake
jbake -> file : Lire et parser
jbake -> jbake : Extraire métadonnées
jbake -> jbake : Convertir AsciiDoc → HTML
jbake -> jbake : Appliquer template project.html
jbake -> jbake : Ajouter à la liste portfolio.html
jbake -> site : Générer pages statiques
deactivate jbake

dev -> site : Vérifier résultat
activate site
site --> dev : Afficher projet
deactivate site
@enduml

Sjabloon van het bestand dat moet worden gemaakt

De ontwikkelaar maakt`content/portfolio/nom-projet.adoc`met een gestandaardiseerde structuur :

  • Kop met alle vereiste attributen

  • Genormaliseerde secties (Context, Uitdagingen, Oplossingen, Resultaten)

  • Coherente nomenclatuur van afbeeldingen

Validatiepunten

  • De vereiste attributen zijn aanwezig (jbake-type, jbake-status, project-thumbnail)

  • De verwezen afbeeldingen bestaan in`assets/img/portfolio/`

  • De JBake-build slaagt zonder fout

  • Het project verschijnt op de portfolio-pagina

  • De individuele projectpagina wordt correct weergegeven

UC2 : Verwijder een item uit het portefeuille

nominale flux

@startuml

participant "Systeem
Bestanden" as fs
participant "JBake
motor" as jbake

Statisch" as site

dev -> fs : (Optionnel) Supprimer images associées\nassets/img/portfolio/projet-ancien-*
activate fs
fs --> dev : Images supprimées
deactivate fs

dev -> cache : Nettoyer cache JBake
activate cache
cache --> dev : Cache vidé
deactivate cache

dev -> jbake : Rebuild complet (jbake -b)
activate jbake
jbake -> jbake : Scanner content/portfolio/
jbake -> jbake : Projet absent → non généré
jbake -> jbake : Régénérer portfolio.html\n(sans le projet supprimé)
jbake -> site : Déployer nouveau build
deactivate jbake

dev -> site : Vérifier
activate site
site --> dev : Projet absent de la liste
deactivate site
@enduml

Alternatieve strategie : archivering

In plaats van definitief te verwijderen, mogelijkheid om een map aan te maken`content/portfolio/archive/` :

  • Verplaats het bestand in plaats van het te verwijderen

  • Maakt het mogelijk om gemakkelijk te herstellen

  • Houd de Git-geschiedenis duidelijker

bronopschoning

  • Controleer de weesafbeeldingen in`assets/img/portfolio/`

  • Verwijder de afbeeldingen die niet door andere projecten worden gerefererd

  • Maak de JBake-cache schoon om spookverwijzingen te voorkomen

UC3: Zet als niet gepubliceerd (concept)

nominale flux

@startuml
skinparam backgroundColor #FEFEFE
actor Développeur as dev
participant "Bestand
AsciiDoc" as file
participant "JBake
Motor" as jbake
participant "Site\nStatisch" as site

dev -> file : Ouvrir portfolio/projet.adoc
activate file

dev -> file : Modifier attribut\n:jbake-status: published\n↓\n:jbake-status: draft

file --> dev : Sauvegardé
deactivate file

dev -> jbake : Rebuild (jbake -b)
activate jbake
jbake -> file : Parser le fichier
jbake -> jbake : Détecter status=draft
jbake -> jbake : Exclure de published_projects
jbake -> jbake : Ne pas créer page publique
note right
  Le projet existe toujours
  mais n'est pas publié
end note
jbake -> site : Générer site (sans ce projet)
deactivate jbake

dev -> site : Vérifier portfolio
activate site
site --> dev : Projet absent de la liste publique
deactivate site
@enduml

Mogelijke staten

@startuml
skinparam backgroundColor #FEFEFE

[*] --> Draft : Création initiale
Draft --> Published : Validation et publication
Published --> Draft : Retrait temporaire
Draft --> Archived : Projet abandonné
Published --> Archived : Projet obsolète
Archived --> [*] : Suppression définitive
Published --> Published : Mises à jour

note right of Draft
  :jbake-status: draft
  Non visible publiquement
  Utile pour projets en cours
end note

note right of Published
  :jbake-status: published
  Visible sur le portfolio
  Indexé par JBake
end note

note right of Archived
  Déplacé dans archive/
  ou jbake-status: archived
  Non publié mais conservé
end note
@enduml

Typische gebruiksscenario’s

  • Project in concept : maak een concept, publiceer wanneer klaar

  • Tijdelijk vertrouwelijk project : overschakelen naar concept totdat de klant akkoord gaat

  • Belangrijke update: overgaan naar draft, wijzigen, opnieuw publiceren

  • A/B testing : dupliceren in concept, testen, publiceer de beste versie

Patroon van gegevensextractie

JBake converteert automatisch de AsciiDoc-attributen naar toegankelijke eigenschappen in Thymeleaf :

@startuml
skinparam backgroundColor #FEFEFE

rectangle "Document AsciiDoc" {
  (":project-client: Acme Corp") as attr1
  (":project-duration: 6 maanden") as attr2
  (":project-tags: java, react") as attr3
}

rectangle "Model JBake" {
  (content['project-client']) as prop1
  (content['project-duration']) as prop2
  (content.tags) as prop3
}

rectangle "Sjabloon Thymeleaf" {
  (th:text="${project['projectklant']}") as tmpl1
  (th:text="${project['project-duration']}") as tmpl2
  (th:each="tag : ${project.tags}") as tmpl3
}

attr1 --> prop1 : parsing
attr2 --> prop2 : parsing
attr3 --> prop3 : parsing

prop1 --> tmpl1 : binding
prop2 --> tmpl2 : binding
prop3 --> tmpl3 : binding
@enduml

Naamgevingsconventies

  • Projectattributen : voorvoegsel`project-*` (ex: project-client, project-tech-stack)

  • Bestanden : kebab-case (bijv:`ecommerce-platform.adoc`)

  • Afbeeldingen : voorvoegsel projectnaam (bijv:`ecommerce-platform-thumb.jpg`)

  • Sjablonen : functionele naam (voorbeeld:`project-card.html`, tech-badge.html)

Extensibiliteit

Toevoeging van nieuwe attributen

Om het gegevensmodel te verrijken, voeg eenvoudig nieuwe voorvoegsel-attributen toe.project-*</think> (empty)

  • `project-awards`Prijzen en erkenningen

  • project-testimonial: klantcitatie

  • project-team-size: Teamgrootte

  • `project-budget-range`Begrotingsmarge

Deze attributen worden automatisch beschikbaar in de sjablonen zonder wijziging van de JBake-motor.

Beste Praktijken

Organisatie van bestanden

  • Een bestand = een project: Vermeng meerdere projecten niet

  • Afbeeldingen in speciale map :`assets/img/portfolio/nom-projet/`

  • Consistente nomenclatuur : vergemakkelijkt zoeken en onderhoud

  • Versioning Git : volledige bijhouding van wijzigingen

Inhoudsbeheer

  • Standaardconceptstatus : publiceren alleen wanneer gereed

  • Review voor publicatie : validatie van kwaliteit en vertrouwelijkheid

  • Volledige metadata : vul alle relevante velden

  • Rijk narratieve inhoud : niet beperken tot metadata

prestatie

  • Afbeeldingen optimaliseren : compressie voor commit

  • Paginering indien nodig : als >20 projecten

  • Laden op aanvraag : afbeeldingen van galeries worden geladen op aanvraag

  • browsercache : geschikte headers voor assets

Conclusie

Deze architectuur maakt het mogelijk :

  • Gebruiksgemak : een project toevoegen = een tekstdocument maken

  • Flexibiliteit : extensible via nieuwe attributen

  • Onderhoudbaarheid : scheiding inhoud/presentatie

  • Traceerbaarheid : volledige Git-versiebeheer

  • Automatisering : build en continu implementatie mogelijk

De keuze voor AsciiDoc zorgt voor consistentie met de rest van de site en biedt tegelijkertijd de rijkdom aan benodigde metadata voor een professioneel portfolio.
