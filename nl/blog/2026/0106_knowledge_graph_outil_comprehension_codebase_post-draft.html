leestijd: 15 minutes

Je komt terecht bij een project van 100.000 regels. Twintig modules, honderd classes, onzichtbare afhankelijkheden, een vergeten geschiedenis van refactorings. Het README belooft een architectuur "microservices" maar de code vertelt iets anders. Hoe lang om productief te zijn?Drie maanden— als je geluk hebt. En wat als een automatisch gegenereerde interactieve codekaart dit zou kunnen terugbrengen tot drie dagen?

[]

De muur van de onboarding

Elke ontwikkelaar heeft deze scène meegemaakt:

  1. Dag 1: we laten je de README zien (laatste update: 18 maanden geleden)

  2. Dag 3: je ontdekt dat het module`billing`roept het module in het geheim`notification`

  3. Dag 7 : een senior zegt "Ja, deze klasse doet in feite twee dingen, we hadden gepland om het op te splitsen

  4. Dag 14 : je realiseert dat alle bedrijfsinformatie zit in`utils/LegacyHelper.java`— een bestand dat nergens verwezen wordt

@startuml
skinparam backgroundColor #FEFEFE
skinparam ActivityBackgroundColor #FDEDEC
skinparam ActivityDiamondBackgroundColor #FFF3CD

start

:Arrivée sur le projet;
note right: 100k lignes, 20 modules

:Lit le README;
note right: Obsolète depuis 18 mois

:Découvre les dépendances au fur et à mesure;
note right: Par erreur, en production

:Demande au senior;
note right: "Ach ja, dat is een legacy..."

:Génère une documentation mentale;
note right: Incomplète, subjective

:Productif ?;
note right: ~3 mois plus tard

stop

@enduml

Het probleem is niet het gebrek aan documentatie — het istekort aan kaart. Een kaart die het echte grondgebied toont, niet het denkbeeldige grondgebied van de laatste redesign.

Wat is een Knowledge Graph?

Een Knowledge Graph is een gestructureerde representatie van dewetenInhoud in uw codebase:

Entiteit Voorbeeld in de code Rol in de graf

knoop

Klasse, functie, concept

Top van de graaf

Rand

aanroep, erfenis, import

Verbinding tussen twee knooppunten

Gemeenschap

Groep van gerelateerde klassen

Cluster visueel

Type van rand

GEEËXTRAHEERD, AFGLEID, ONDUIDELIJK

Vertrouwen in de relatie

Betrouwbaarheidsscore

0.0 à 1.0

Betrouwbaarheid van een rand INFERRED

hyperzijde

Relatie 3+ knopen

architectonische complexiteit

 
@startuml
skinparam backgroundColor #FEFEFE
skinparam classAttributeIconSize 0

package "Gemeenschap 0 : Service Layer" #Ede8f8 {
  class "LlmService" as n0 {
    type = class
  }
  class "DiagramProcessor" as n1 {
    type = class
  }
}

package "Gemeenschap 1: Config" #D5f5e3 {
  class "ConfigLader" as n2 {
    type = class
  }
  class "ApiKeyPool" as n3 {
    type = class
  }
}

n0 --> n1 : calls\nEXTRACTED
n2 ..> n3 : creates\nINFERRED (0.75)
n0 --> n2 : configures\nEXTRACTED

note right of n0
  **Hyperedge possible :**
  LlmService + DiagramProcessor + ConfigLoader
  partagent un contexte RAG
end note

@enduml

Wat is het verschil met een eenvoudig UML-diagram?Een UML-diagram toont wat de ontwikkelaar heeft besloten te tonen. Een Knowledge Graph toont wat er echt is, inclusief de verborgen afhankelijkheden en de opkomende concepten.

De verloren context: een concreet scenario

Stel je voor een nieuwe ontwikkelaar, Anaïs, die op het project begint. Ze moet een functionaliteit voor 'quota tracking' toevoegen voor LLM-aanroepen.

skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

actor "Anaïs (nieuw)" as ana

rectangle "wat zij zoekt" {
  [QuotaTracker] as qt
  [ApiKeyPool] as akp
  [RateLimiter] as rl
}

rectangle "Wat zij vindt" {
  [LlmService] as ls
  [ConfigLoader] as cl
}

ana --> ls : "Zoek 'quota'
in de IDE"
ls --> cl : "Vind ConfigLoader
(vermeld 'quota'
in een commentaar)"
cl --> qt : "3 weeks later :
ontdek QuotaTracker
bestaat al"

note right of qt
  **Contexte perdu :**
  QuotaTracker était dans
  un module non-référencé
  dans le README
end note

@enduml

Met een Knowledge Graph zou Anaïs erin hebben gezien5 minuten:

  • QuotaTracker`is verbonden met`ApiKeyPool(randEXTRACTED)

  • RateLimiter`is gerelateerd aan`QuotaTracker(kamafgeleid, vertrouwen 0.82)

  • Deze drie knopen vormen eengemeenschapquota beheer

  • Een hyperedge verbindt ook`LlmService`— het toegangspunt

Pipeline : code op maat in één opdracht

De Graphify-pipeline + Gradle-plugin transformeert uw codebase naar een PlantUML-diagram intwee commando’s:

@startuml
skinparam backgroundColor #FEFEFE
skinparam sequenceArrowThickness 2

actor "ontwikkelaar" as dev
participant "graphify" as gfy
participant "graphify-out/graph.json" as json
participant "Gradle-plugin" as plg
participant "KnowledgeGraphParser" as kgp
participant "KennisgrafRenderer" as kgr
participant "diagrams/knowledge-graph/" as out

dev -> gfy : graphify update . --no-viz
gfy -> json : extrait nœuds, arêtes,\ncommunautés, confiances

dev -> plg : ./gradlew generateKnowledgeGraphDiagram
plg -> kgp : parse graph.json
kgp -> kgr : nodes + edges + communities
kgr -> out : génère .puml + .png

out --> dev : diagramme interactif

@enduml

Nul LLM.Alles is deterministisch: dezelfde code, dezelfde grafiek, hetzelfde diagram. Reproduceerbaar, versieerbaar, offline raadpleegbaar.

Randtypen: wat vertrouwen zegt

@startuml
skinparam backgroundColor #FEFEFE

node "LlmService" as ls
node "DiagramProcessor" as dp
node "ConfigLoader" as cl
node "api-sleutelpool" as akp
node "LegacyHelper" as lh #F1948a

ls --> dp : EXTRACTED\n(calls, direct)
cl ..> akp : INFERRED 0.75\n(creates, probable)
ls -[#FF5722]-> lh : AMBIGUOUS\n(legacy, douteux)

legend right
  |= Type |= Symbole |= Signification |
  | EXTRACTED | <b>--></b> | Relation visible dans le code |
  | INFERRED | <b>..></b> | Relation déduite (score de confiance) |
  | AMBIGUOUS | <b>--x</b> | Relation incertaine, à vérifier |
endlegend

@enduml

Soorten randen zijn cruciaal voor onboarding:

  • extract: jij kunt rustig navigeren — Het zit in de code

  • AFGELEID(0.6-0.8): waarschijnlijk correct, maar controleer voordat je refactort

  • afgeleid(0.8+) : zeer betrouwbaar — gebruik het als referentie

  • onduidelijk: let op, gevoelig punt. Vraag het aan een senior.

Concrete opdrachten

# 1. Installer graphify
pip install graphify==0.4.29

# 2. Générer le Knowledge Graph
graphify update . --no-viz

# 3. Vérifier le JSON
cat graphify-out/graph.json | jq '.nodes | length'
# → 47 nœuds

# 4. Générer le diagramme
./gradlew generateKnowledgeGraphDiagram

# 5. Filtrer par communauté
./gradlew generateKnowledgeGraphDiagram -Pplantuml.kg.community="service layer"

# 6. Limiter la taille
./gradlew generateKnowledgeGraphDiagram -Pplantuml.kg.maxNodes=20

Limieten en perspectieven

Een Knowledge Graph is geen toverstok:

Limiet Uitleg Omweg

Alleen statische code

Geen runtime, geen gegevensstroom

Aanvullen met APM-traces

INFERRED kan fout zijn

Afgeleide randen vereisen validatie

Vertrouwensscore + menselijke beoordeling

Geen zakelijke semantiek

De KG weet "LlmService roept ConfigLoader aan", niet "dit is het auth-invoerpunt

Handmatige annotaties of LLM-postverwerking

Geen temporaliteit

Een snapshot van de code, niet zijn evolutie

Regelmatig genereren + de versies vergelijken

Perspectieven:

  • Verschil KG: twee versies vergelijken om de verplaatsingen van gemeenschappen te zien

  • interactieve KG: klik op een knooppunt → opening IDE op de corresponderende regel

  • KG historisch: visualiseer de evolutie van gemeenschappen in de tijd (technische schuld die migreert)

Conclusie

De Knowledge Graph transformeert een handelingeenzaam en lang(een codebase begrijpen) in één actegedeeld en snel(kaart raadplegen).

Het is geen documentatie — het is van decartografie. Een kaart die automatisch wordt bijgewerkt, die het echte grondgebied toont, en die elke ontwikkelaar, nieuw of senior, in staat stelt om met vertrouwen te navigeren.

pip install graphify==0.4.29
graphify update . --no-viz
./gradlew generateKnowledgeGraphDiagram

3 opdrachten. 5 minuten. Een kaart van uw codebase.
