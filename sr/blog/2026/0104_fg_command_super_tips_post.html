vreme čitanja : 10 minutes

Vi bacate`./gradlew build`, terminal je blokiran za 3 minute, i vi trebate da uradite nešto drugo čekajući? Ne treba da otvorite novu karticu.`Ctrl+Z`zaustavljuje proces,`fg`Vraća vas tačno na mesto gde ste ga ostavili. To je najmanje cenjen Unix savet u svakodnevnom životu programera.

так

[]

Problem: zauzet terminal

Svaki programer je doživio ovu situaciju:

$ ./gradlew build
> Building...

Терминал је блокиран. Више не можете укуцати ниједну команду. И вам је потребно прегледати датотеку, покренути`git status`, или проверити заузети порт.

@startuml
skinparam backgroundColor #FEFEFE

actor Développeur as dev
participant "Терминал" as term
participant "Gradle
( proces )" as gradle

dev -> term : ./gradlew build
term -> gradle : Lance le build
gradle -> term : Occupe le terminal\n(pas de prompt)
dev -> term : veut taper une commande
term --> dev : ❌ Terminal bloqué

note right of dev
  Le développeur est
  paralysé pendant
  toute la durée du build
end note
@enduml

Većina programera otvara novi terminal. Ipak postoji rešenje koje je elegantnija, brža i prirodna: upravljanje poslovima.

Tri neophodne komande

Ctrl+Z — Zaustavi (SIGTSTP)

`Ctrl+Z`Šalje signal`SIGTSTP`процесу у передњем плану. Процес јеsuspendovan— ne ubijen — i terminal vraća svoj prompt.

$ ./gradlew build
> Building...
^Z
[1]+  Stoppé    ./gradlew build
$

Број између заграда`[1]`јеbroj posla. Le `+`ukazuje na podrazumevani posao

fg — Врати на предњи план

`fg`vraća zaustavljen posao u primarni plan. Proces se nastavlja tačno gde se je zaustavio.

$ fg
./gradlew build
> Building... (reprend où il en était)

Sa specifičnim brojem posla :

$ fg %2

bg — Nastavi u pozadini

`bg`Uzima proces bez blokiranja terminala. Idealno za dugograjde gradnje.

$ bg
[1]+ ./gradlew build &
$

Le `&`Na kraju znači da se proces izvršava u pozadini.

jobs — Lista poslova u shellu

$ jobs
[1]-  Stoppé    vim README.md
[2]+  En cours   ./gradlew build
@startuml
skinparam backgroundColor #FEFEFE
skinparam defaultFontName sans-serif

state "prednji plan\n(blokiran terminal)" as fg #LightCoral
state "Заустavljen\n(Ctrl+Z)" as stopped #LightYellow
state "Фон\n(bg)" as bg_ #LightGreen

[*] --> fg : Lance une commande
fg --> stopped : Ctrl+Z\n(SIGTSTP)
stopped --> fg : fg\nreprend en avant-plan
stopped --> bg_ : bg\nreprend en arrière-plan
bg_ --> fg : fg\nramène en avant-plan
fg --> [*] : Commande terminée

note right of stopped
  Le processus est figé
  mais _pas_ tué
end note

note left of bg_
  Le terminal est libre
  le build continue
end note
@enduml

Scenario 2: Zaboravljeni urednik

Vi ste u`vim`, trebate da pogledate drugi fajl bez napuštanja`vim`.

# Dans vim, en mode commande :
:shell
$ cat /path/to/other/file.txt
$ exit
# Retour dans vim

Ali je teško. Sa`Ctrl+Z`, to je odmah :

# Dans vim, n'importe quel moment :
Ctrl+Z
[1]+  Stoppé    vim README.md

$ cat /path/to/other/file.txt
# ... lire le fichier ...

$ fg
vim README.md
# Retour exact là où on en était, curseur en place
@startuml
skinparam backgroundColor #FEFEFE
autonumber

actor Développeur as dev
participant "vim" as vim
participant "lupija" as shell

dev -> vim : édition en cours
dev -> vim : Ctrl+Z
vim -> shell : Suspendu (job [1])
dev -> shell : cat autre_fichier.txt
shell --> dev : contenu du fichier
dev -> shell : fg
shell -> vim : Reprend (job [1])
vim --> dev : Curseur exactement\nà la même position

note right of vim
  vim restaure
  intégralement l'état :
  position du curseur,
  buffer, undo stack
end note
@enduml

Белешка:`vim`savršeno vraća svoje stanje nakon`fg`: pozicija kurzora, sadržaj bafera, istorija poništavanja — sve je sačuvano.

Сценарио 3: Процесс opencode приостановљен

Ово је сценариј који је мотивао ovaj чланак. Ви користите`opencode`(CLI alat za pokretanje LLM na vašem kodu), a proces je zaustavljen.

@startuml
skinparam backgroundColor #FEFEFE
skinparam defaultFontName sans-serif
skinparam componentStyle rectangle

actor Développeur as dev
participant "opencode
(агент LLM)" as agent
participant "Shell" as shell
participant "git" as git

dev -> agent : Session active
agent -> agent : Tour de parole\ndu LLM en cours

note over agent
  Ctrl+Z arrive
  en plein milieu
  d'une analyse de code
end note

dev -> agent : Ctrl+Z
agent -> shell : Suspendu (job [1])
dev -> git : git diff
git --> dev : changements visibles
dev -> shell : fg
shell -> agent : Reprend (job [1])
agent --> dev : Reprend exactement\nl'analyse en cours

note right of agent
  Aucune perte de contexte
  Le LLM reprend sa réponse
  exactement où il en était
end note
@enduml
$ opencode
# ... session en cours, LLM analyse le code ...
^Z
[1]+  Stoppé    opencode

$ git diff HEAD~1
# vérifier les changements récents

$ fg
opencode
# Le LLM reprend là où il s'était arrêté

Предност је двострука :

  1. Нет губитка контекста: сесија LLM, историја разговора, отварені датотеке — све је сачувано

  2. Никаког рестартане треба покретати опенкоде, не треба поновити контекст, не треба поново обяснити проблематицу LLM-у

Свод наредби за poslove

narudžba efekat primer

Ctrl+Z

Suspendiraj proces u prvom planu

Slanje`SIGTSTP`

fg

Ponovo preuzima podrazumevani posao u primarnom planu

fg ou fg %1

fg %n

Навести посао n у передњи план

fg %2

bg

Продовити подразумевани задатак у позадини

bg ou bg %1

bg %n

Врати посао n у позадни план

bg %2

jobs

Покажи радње текуће шелле

jobs -l(sa PID)

kill %n

Završi posao n

kill %2

Пречица/Команда Signal Efekat Vratiti se nazad?

Ctrl+Z

SIGTSTP

Zaustavi proces (zamrznut, u memoriji)

Да :`fg` ou bg

Ctrl+C

SIGINT

Ubij proces (završen)

Не : уништожен процес

Ctrl+\

SIGQUIT

Zabij proces + core dump

Ne: proces uništen

commande &

—

Pokreni u pozadini direktno

`fg`da ga vrati u prednji plan
Ctrl+Z`jeнедеструктиван. Proces je zaklepčen kako jest, u memoriji. Možete nastaviti odmah sa`fg. To je pauza, ne zaustavak.

[1] 12345

$ disown %1
# Le processus continue mais n'est plus lié au shell
# Ça survives à la fermeture du terminal

ловушке и честе грешке

Мешати Ctrl+Z и Ctrl+C

Ovo je najčešća greška.`Ctrl+C`ubija proces.`Ctrl+Z`Ga zaustavlja. Ako pritisnete na`Ctrl+C`iz refleksa, sve stanje je izgubljeno — otvoreni fajlovi, sesije LLM, gradnje u toku.

Poslovi su lokalni u shellu

jobs, fg et `bg`ne funkcionišu samo u shellu koji je pokrenuo procese. Ako otvorite novi terminal, nećete videti jobove drugog.

# Terminal 1
$ vim file.txt
^Z
[1]+  Stoppé    vim file.txt

# Terminal 2 (nouveau)
$ jobs
# (rien — les jobs sont locaux au shell)

Da biste videli sistemski procesi, koristite`ps` ou htop:

ps aux | grep vim

Poslovi ne preživljavaju zatvaranje shell-a

Ako zatvorite terminal, svi suspenirani ili pozadinski poslovi su uništeni. Da biste proces preživi, koristite`nohup`+disown :

$ nohup ./gradlew build &
[1] 12345
$ disown %1
# Fermer le terminal → le build continue

Interaktivni procesi i fg

Neki interaktivni programi nisu u dobrom stanju nakon jednog`Ctrl+Z`+fg. Ретко је, но дешава се :

  • Neki programi koji koriste signale (vim, htop, less) dobro upravljaju`Ctrl+Z`)

  • Дуготрајни мрежни програми (ssh, opencode) обично исправно опорављају

  • Programi koji modifikuju terminal (ncurses) mogu ponekad ostaviti terminal u neočekivanom stanju.

U slučaju oštećenog terminala nakon`fg`, ukucaj :

reset

Zašto fg je podocenjen

Većina modernih programera otkriva`fg`kasno, ili čak nikada. Neki razlozi :

  1. IDE sakrivaju terminal: VS Code nudi ugrađeni terminal, ali više kartica prave`fg`manje potrebno na prvi pogled

  2. Grafički alati zamjenjuju CLI: управљачи фајловима, системски монитори, графички кlijenti Git

  3. tmux i screen: ovi multipleskseri rešavaju isti problem na drugačiji način, ali`fg`je jednostavniji i uvek dostupan

Ipak,`fg`je :

  1. универзалниprisutan u svim POSIX shell-ovima (bash, zsh, fish…​)

  2. Bez zavisnosti: нема потребе да инсталирате tmux или screen

  3. Snimak: dva udara (Ctrl+Z`zatim`fg) za zaustavljanje i nastavak

  4. Čuvac konteksta: stanje procesa je neporušeno

Tehnička memorija: signali

Za zainteresovane, voici signali koji su uključeni :

Сигнал Име Poslao Efekat

Ctrl+C

Prekid — završava proces

3

SIGQUIT

Ctrl+\

Napusti sa core dump

18

SIGTSTP

Ctrl+Z

Interaktivni stop — poništava proces

19

SIGCONT

fg / bg

Nastavi — ponovo pokreće suspendovan proces

15

SIGTERM

kill %n

Правилан завршатак

9

note right of proc : Processus figé\nen mémoire

user -> shell : fg
shell -> proc : SIGCONT (signal 19)
note right of proc : Processus reprend\nen avant-plan

user -> shell : bg
shell -> proc : SIGCONT (signal 19)
note right of proc : Processus reprend\nen arrière-plan

user -> shell : Ctrl+C
shell -> proc : SIGINT (signal 2)
note right of proc : Processus terminé\nétat perdu
@enduml

Zaključak

`fg`Nije sakriven savet — to je fundamentalni mehanizam Unix shella, dostupan od 70-h godina. Činjenica da većina razvojara to ignoriše je simptom našeg doba: IDE i multiplexeri nas su udaljiti od osnova.

Pero kada ste na SSH serveru, u minimalnom terminalu, ili jednostavno koristite`opencode`и да LLM је у полној раду —Ctrl+Z, fg, bg, `jobs`су ваши најбољи пријатели.
