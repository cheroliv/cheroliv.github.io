Greška 1 : fantomska promenljiva `reportsDir

Скрипта`jhipster.cucumber-conventions.gradle`sadrži :

tasks.register('consoleLauncherTest', JavaExec) {
    dependsOn(testClasses)
    String cucumberReportsDir = file("$buildDir/reports/tests")
    outputs.dir(reportsDir)           // <-- reportsDir n'existe PAS
    classpath = sourceSets["test"].runtimeClasspath
    main = "org.junit.platform.console.ConsoleLauncher"
    // ...
}

Definisana promenljiva je`cucumberReportsDir`. Korišćena je`reportsDir`— која није дефинисана нигде.

Корекција : outputs.dir(cucumberReportsDir)

Greška 2 : main = "…​" više ne postoji u Gradle 9

Hitno ponovno pokretanje :

Could not set unknown property 'main' for task ':consoleLauncherTest' of type org.gradle.api.tasks.JavaExec.

Gradle 9 uklanja svojstvo`main`u korist`mainClass`о задацима`JavaExec`.

Корекција:`mainClass = "org.junit.platform.console.ConsoleLauncher"`

Greška 3 : sourceCompatibility više nije svojstvo projekta

Nova greška:

Could not set unknown property 'sourceCompatibility' for root project 'edster' of type org.gradle.api.Project.

Коренијски скрипт је imao :

sourceCompatibility=17
targetCompatibility=17

Gradle 9 uklanja ove svojstva na korenom nivou. Oni moraju da budu unutar bloka.java.

Корекција:

java {
    sourceCompatibility = JavaVersion.VERSION_21
    targetCompatibility = JavaVersion.VERSION_21
}

Greška 4: Groovy tvrdenje sa tri operanda

Stari skript je sadržavao:

assert System.properties["java.specification.version"] == "17" || "21" || "24"

У Грови,"21" et "24"`су truthy низове. Izraz se rešava u(…​ == "17") || true || true`, što je uvek tačno — ali sintaksa nije validna za zahtevanu strogu tvrdnju.

Ispravka :

assert System.properties["java.specification.version"] in ["17", "21", "23", "24"]

Greška 5: implicitna zavisnost compileKotlin → `openApiGenerate

Build napreduje. Kompajliranje Kotlin-a je uspelo. Zatim:

Task ':compileKotlin' uses this output of task ':openApiGenerate'
without declaring an explicit or implicit dependency.

Gradle 9 odbija implicitne zavisnosti između zadataka. Jer`compileKotlin`чита генерисане изворове од`openApiGenerate`, Треба јавити везу.

Исправкаu`build.gradle`:

afterEvaluate {
    tasks.named("compileKotlin").configure {
        dependsOn(tasks.named("openApiGenerate"))
    }
}

Le `afterEvaluate`jer je potrebno`openApiGenerate`је додатак (OpenAPI Generator plugin) и није задатак који је директно доступан током фазе конфигурације.

Грешка 6 : generateGitProperties се срушава на `FilterOutputStream.write()

Kompajliranje Jave prolazi. Resursi se obrađuju. Zatim :

> Task :generateGitProperties FAILED

No signature of method: java.io.FilterOutputStream.write() is applicable for argument types: (Integer) values: [103]

Плагин`gradle-git-properties`version 2.5.0 nije kompatibilna sa Java 21 / Gradle 9. Unutrašnji greška pokušava da pozove`write(int)`preko Groovy na toku koji ga je zatvorio

Ispravkau`gradle.properties`:

gitPropertiesPluginVersion=2.5.7

Faza 1 : docker-java staza

Prvi refleks : Docker Java klijent korišćen od Testcontainers šalje verziju API`1.32`u njegovom HTTP handshake-u, ali Docker Engine 29.4.1 zahteva najmanje`1.40`. Проблем је на нивоу клијента, не демона.

Провера верзије docker-java решена од стране Testcontainers 1.20.6:

$ ./gradlew dependencies --configuration testRuntimeClasspath | grep docker-java

+--- com.github.docker-java:docker-java-api:3.4.1
+--- com.github.docker-java:docker-java-transport:3.4.1

docker-java 3.4.1, datira iz Testcontainers 1.20.6. Najnovija javna verzija docker-jave je 3.5.1. Pokušamo da prisilimo na nadogradnju verzije kroz`resolutionStrategy`у блоку`configurations` de build.gradle:

configurations {
    all {
        resolutionStrategy.eachDependency { details ->
            if (details.requested.group == "com.github.docker-java"
                && details.requested.name.startsWith("docker-java")) {
                details.useVersion("3.5.1")
            }
        }
    }
}

Ponovno pokretanje izgradnje. Ista greška:`client version 1.32 is too old`.

Провера Gradle кеша: JAR-ови су успешно поново преузети, али грешка остаје. docker-java 3.5.1 увек шаље`1.32`. Ova verzija nije dovoljna za Docker Engine 29.4.1.

Акција чишћењаOčisti potpuno keš Gradle, radi slučaja

rm -rf ~/.gradle/caches
rm -rf /path/to/project/.gradle

Ponovni pokret nakon čišćenja. Ista greška.

Faza 2: web pretraga i GitHub krumplin

docker-java 3.5.1 je nedovoljan. Ostaje samo da se proveri da li je neko susrešao ovaj tačan problem.

Ciljana pretraga na problemima testcontainers-java i docker-java :

site:github.com/testcontainers "client version 1.32 is too old"
site:github.com/docker-java "client version 1.32" Docker Engine 29

Prvi neposredni rezultati :

  • testcontainers-java#11210—[Bug]: client version 1.32 is too old. Minimum supported API version is 1.44

  • testcontainers-java#11212—[Bug]: Docker 29.0.0 could not find a valid Docker environment

  • testcontainers-java#11491—[Bug]: Incompatibility in Ubuntu Github runners with Docker Engine 29.1.*

Нита Ариадне је јасна: Docker Engine 29.x је повео свој минималан API на`1.24`(стари дефект) у`1.40`. Testcontainers 1.20.x koristi docker-java 3.4.x koji pregovara verziju API-ja slanjem`1.32`. Daemon ljubazno ali tvrdohladno odbija.

У проблему #11491, одржавач одговара:

Ovaj odgovor sadržidve kritične informacije:

  1. Testcontainers 2.0.3+ rešava problem

  2. Moduli su bilipreimenovani sa prefiksom `testcontainers-

Коначна исправкау`build.gradle`:

configurations {
    all {
        resolutionStrategy.eachDependency { details ->
            if (details.requested.group == "com.github.docker-java"
                && details.requested.name.startsWith("docker-java")) {
                details.useVersion("3.7.1")
            }
            if (details.requested.group == "org.testcontainers"
                && details.requested.name == "testcontainers") {
                details.useVersion("2.0.5")
            }
        }
    }
}

dependencies {
    testImplementation platform("org.testcontainers:testcontainers-bom:2.0.5")
    testImplementation "org.testcontainers:testcontainers-jdbc"
    testImplementation "org.testcontainers:testcontainers-junit-jupiter"
    testImplementation "org.testcontainers:testcontainers-postgresql"
    testImplementation "org.testcontainers:testcontainers"
    // ... autres dépendances Spring Boot
}

Le `resolutionStrategy.eachDependency`једин начин за обилазак BOM`spring-boot-dependencies`upravljeno pluginom Spring Boot. Test jednakosti na`details.requested.name == "testcontainers"`Namerno je ograničeno: prisiljujemo samo core modul. Module`testcontainers-*`Sledeju BOM Testcontainers 2.0.5 koji smo eksplicitno naveli.

Zaključak

Ако ваш JHipster/Gradle build падне nakon подијања верзије на Gradle 9 + Docker Engine 29, грешке се подељују на две категорије :

Greške u skripti za gradnju(prvih 6) : Gradle 9 uklanja svojstva i sintakse koje su radile veoma godinama (sourceCompatibility=, main =, reportsDir). Ovo su mehaničke migracije jednom kada upoznamo novi API.

Greške u izvršavanju Docker(последње две) : Docker Engine 29.4.1 odbacuje klijente API < 1.40. Testcontainers 1.20.6 (impozovan od strane Spring Boot 3.4.5) koristi docker-java 3.4.1 koji šalje 1.32. Jedino Testcontainers 2.0.5 + docker-java 3.7.1 rešava problem, sa preimenovanjem artefakata i prisilivanjem verzije via`resolutionStrategy.eachDependency`kao jedini način da se obiđe implicitni BOM u Spring Boot-u.

Gradle build skript u korenu projekta je sada čist.`./gradlew build`користи Java 21, Gradle 9.4.1, Spring Boot 3.4.5 и Docker Engine 29.4.1.
