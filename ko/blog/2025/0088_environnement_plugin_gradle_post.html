소개

대상 고객 : Gradle 플러그인 개발에 도전하고자 하는 개발자.

그레이들 플러그인을 효과적으로 개발하려면 잘 구성된 개발 환경이 필수적입니다. 좋은 설정은 시간을 절약해 주고, 불만을 줄이며, 빌드의 일관성을 보장합니다.

이 가이드는 네 가지 필수 기둥에 초점을 맞춥니다 :

  1. Le JDK(Java Development Kit), Gradle과 JBake가 JVM에서 실행되기 때문에.

  2. Un 통합 개발 환경현대적인 (IntelliJ IDEA) Kotlin과 Gradle에 대한 좋은 지원

  3. 그레이들스스로, 프로젝트를 초기화하기 위해

  4. 제이베이크, 우리 정적 사이트의 엔진.

1. JDK: Gradle 엔진

Gradle는 Java Virtual Machine (JVM)에서 실행되는 애플리케이션입니다. 따라서 JDK 설치는 절대적인 필수 조건입니다.

어떤 버전을 선택해야 할까요?

자바의 Long-Term Support (LTS) 버전을 사용하는 것이 권장됩니다. 현재로서는,JDK 17 ou JDK 21훌륭한 선택입니다.

SDKMAN!을 통한 설치 (권장)

SDKMAN! 은 Java와 Gradle을 포함한 많은 SDK의 버전을 관리하기에 훌륭한 도구입니다.

SDKMAN! 설치

curl -s "https://get.sdkman.io" | bash source "$HOME/.sdkman/bin/sdkman-init.sh"

JDK 버전 설치

# Pour lister les versions de Java disponibles sdk list java

# Pour installer Java 17 (par exemple, la distribution Temurin)
sdk install java 17.0.8-tem

설치 확인

java -version

방금 설치한 버전이 표시되는 것을 보셔야 합니다.

2. IDE : IntelliJ IDEA

Gradle 플러그인 개발에 Kotlin DSL을 사용할 때,인텔리J IDEA는 선호되는 도구입니다. 그의 Gradle 및 Kotlin과의 통합은 비교할 수 없습니다.

  • Community Edition :무료이며 시작하기에 충분합니다.

  • 얼티밋 에디션 :유료이며, 웹 및 데이터베이스 개발을 위한 고급 기능을 제공합니다.

JetBrains 사이트에서 당신에게 맞는 버전을 다운로드하세요 : https://www.jetbrains.com/idea/download/

IDE가 자동으로 파일을 감지합니다.build.gradle.kts et settings.gradle.kts, 강력한 자동 완성, 코드 내비게이션, 그리고 통합 디버깅 도구를 제공합니다.

3. Gradle : 빌드 도구

각 프로젝트가 Gradle Wrapper를 통해 자체 Gradle 버전을 사용하더라도, 새 프로젝트 초기화와 같은 작업에는 전역 Gradle 설치를 해두는 것이 유용합니다 (gradle init)

SDKMAN!을 통한 설치!

JDK와 마찬가지로, SDKMAN!은 Gradle 설치를 간소화합니다.

Gradle 설치

sdk install gradle

설치 확인

gradle -v

이 명령은 사용되는 Gradle, Kotlin, Groovy 및 JDK의 버전을 표시합니다.

4. JBake : 정적 사이트 생성기

JBake는 우리가 소스 파일(예: 이 파일)을 정적 웹사이트로 변환하는 데 사용할 도구입니다. 로컬 설치를 갖는 것은 변경 사항을 미리 보는 데 편리합니다.

SDKMAN!을 통한 설치

다른 도구들과 마찬가지로, SDKMAN!이 가장 간단한 방법입니다.

JBake 설치

sdk install jbake

설치 확인

jbake -v

이 명령은 JBake 버전과 이를 사용하는 Java 환경 정보를 표시합니다.

5. Gradle Wrapper: 절대적인 모범 사례

프로젝트가 생성된 후(다음 문서에서 다룰 내용과 같이), 더 이상 전역 명령어를 사용해서는 안 됩니다.gradle. 대신에, 당신은 그것을 사용할 것입니다.그레이들 래퍼 (./gradlew), 프로젝트에 포함된 스크립트.

왜?

  • 재현성:Wrapper는 프로젝트에서 작업하는 모든 사람(CI/CD 서버 포함)이 정확히 라를 사용하도록 보장합니다.같은 버전의 Gradle, 이로 인해 다른 환경으로 인한 빌드 오류가 제거됩니다.

  • 단순함 :프로젝트에 기여하기 위해 Gradle을 수동으로 설치할 필요가 없습니다.

저장소를 클론하고 실행하기만 하면 됩니다../gradlew.

일반적인 명령은 다음과 같이 보일 것입니다 :

# Ne pas faire : gradle build
# À faire :
./gradlew build

6. Docker와 Portainer : 재현 가능한 빌드 (선택 사항)

플러그인을 작성하는 데 엄격히 필요한 것은 아니지만, Docker와 Portainer는 재현 가능한 빌드 생성을 크게 용이하게 하고 환경을 관리하는 데 도움을 주는 현대적인 DevOps 도구입니다.

Docker Engine 설치

Docker을 사용하면 애플리케이션과 그 종속성을 컨테이너에 패키징할 수 있습니다.

Docker을 공식 스크립트로 설치하기 :

curl -fsSL https://get.docker.com -o get-docker.sh sudo sh get-docker.sh

Docker 관리 sudo 없이 (권장) :

사용자를 그룹에 추가하세요.docker.

sudo usod -aG docker $USER
docker run hello-world

Portainer (GUI)로 Docker 관리하기

Portainer는 Docker 컨테이너를 관리하기 위한 가벼운 웹 인터페이스입니다.

Portainer 데이터용 볼륨을 생성하세요:

docker volume create portainer_data

Portainer 컨테이너 실행 :

docker run -d -p 8000:8000 -p 9443:9443 --name portainer --restart=always -v /var/run/docker.sock:/var/run/docker.sock -v portainer_data:/data portainer/portainer-ce:latest

이제 Portainer 인터페이스에 접근할 수 있습니다`https://localhost:9443`.

결론

당신의 환경이 이제 준비되었습니다! JDK, 가장 적합한 IDE, Gradle 및 JBake가 있습니다. Docker을 추가하면 컨테이너화되고 재현 가능한 빌드를 만들 수 있도록 준비됩니다. 이 견고한 기반은 여러분이 핵심에 집중할 수 있게 해 줄 것입니다: 강력하고 유용한 플러그인 개발.
