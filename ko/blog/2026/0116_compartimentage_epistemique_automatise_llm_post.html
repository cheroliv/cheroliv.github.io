자동화된 인식론적 구분 — LLM이 내 마음의 정원을 어떻게 보호하는가

게시: 02 May 2026

Table des matières
  • 문제 : 자유롭게 생각하기, 아무것도 게시하지 않기
  • STIMULUS 패턴 — 태어나다, 고정하다, 희석하다, 죽다
  • LLM에 위임: 왜 LLM이 필터링을 하는가
읽기 시간 : 10 minutes

내 LLM은 단순히 내 Gradle 작업을 실행하는 것에 만족하지 않는다. 그것은 내 비공개 생각과 공개 표현 사이의 경계를 지키는 수호자이다. 모든 아이디어는 라우팅되기 전에 — 비전, 의견, 전략 — 으로 분류된다. 이것이 자동화된 인지론적 구분이 나의 정신 정원을 침묵시키지 않으면서 보호하는 방식이다.

틱

[]

문제 : 자유롭게 생각하기, 아무것도 게시하지 않기

혼자 일하는 개발자가 LLM과 함께 자신의 사고 과정을 문서화할 때, 그는 하나의 역설에 직면한다 :

CAPTURE TOUT (Cercle 0, jardin secret)
  ├→ Brain dump libre, pas de censure
  ├→ Idées brutes, spéculations, intuitions non vérifiées
  ├→ Allers-retours LLM : challenger, itérer, raffiner
  └→ Le LLM voit TOUT — le bon, le flou, l'embryonnaire

PUBLICATION SÉLECTIVE (Cercle 4, blog public)
  ├→ Uniquement les décisions actées
  ├→ Uniquement les patterns testés (>100 tests PASS)
  ├→ Uniquement ce qui a de la valeur pour le lecteur
  └→ JAMAIS une spéculation présentée comme une vérité

이 두 극단 사이에 하나가필터. 이 질문은 : 누가 이것을 하는가? 피곤한 인간(세션 끝에)? 순진한 regex 스크립트? 아니면 LLM 자신이, 이미 모든 것을 읽은 것인가?

내 답변: LLM.

STIMULUS 패턴 — 태어나다, 고정하다, 희석하다, 죽다

STIMULUS는 파일입니다..adoc`워크스페이스 루트(서클 0)에 임시로 위치하고, 그 이름은 느낌을 주는 명명 규칙을 따릅니다 —`PICTURE_ME_ROLLIN.adoc, HOLD_MY_BEER.adoc, ONCE_UPON_A_TIME.adoc— 현재의 탐색적 의도를 포착하는.

그의 삶의 주기는 냉혹합니다:

CRÉATION (Cercle 0)
  ├→ Fichier vide, brain dump libre
  ├→ Allers-retours LLM ← → développeur
  └→ Aucune pression de structure ou de publication

MATURATION
  ├→ Le contenu se densifie
  ├→ Des sections émergent naturellement
  └→ Le fichier devient une référence informelle de session

CLASSIFICATION ÉPISTÉMIQUE ← FAIT PAR LE LLM
  ├→ VISION    → publiable, diluer dans les docs publics + blog
  ├→ OPINION   → confiner au Cercle 0, pas de dilution externe
  └→ STRATÉGIE → dilution restreinte (docs racine, PAS de blog)

DILUTION (Cascade vers Cercles légitimes)
  ├→ VISION → WORKSPACE_AS_PRODUCT.adoc + WHAT_THE_GAMES.adoc + blog
  ├→ STRATÉGIE → WORKSPACE_AS_PRODUCT.adoc (section business)
  └→ OPINION → reste dans le stimulus, ne bouge pas

ARCHIVAGE + SUPPRESSION
  ├→ Snapshot dans configuration/vision-archive/ (trace historique)
  └→ rm du stimulus — il a fini son travail

2회 이상의 세션을 거치지 않고 살아남는 자극은 안티-패턴입니다. 정보가 임시 파일에서 썩히기엔 너무 중요하다면(→ 희석), 존재할 가치가 있을 만큼 명확하지 않다면(→ 삭제).

LLM에 위임: 왜 LLM이 필터링을 하는가

나는 Kotlin에서 Vision/Opinion 분류를 하드코딩하지 않습니다. 나는 그것을 안에 주입한다.시스템 프롬프트LLM을 통해`AGENT_GOVERNANCE.adoc` :

----
----
Pour chaque dilution de stimulus ou session, tu es responsable de classifier
le contenu :
- VISION : décision architecturale actée, pattern testé en production (>100 tests PASS),
  décision documentée dans BACKLOG ou ROADMAP
- OPINION : spéculation, hypothèse non validée par des tests, intuition
  sans ancrage expérimental
- STRATEGIE : positionnement business, pricing, marché cible

Règles :
- Si OPINION, le contenu reste confiné dans son cercle d'origine
- Si VISION, tu procèdes à la dilution dans les documents racine
- Si STRATEGIE, dilution restreinte (docs racine, pas de blog public)
- Cette classification détermine aussi si un article de blog est publiable
  sur cheroliv.com
----

LLM은 이 지시를 읽는다**이전**세션을 처리하는 것. 그것은 별도의 파일이 아닌 즉시적인 컨텍스트에 있습니다. *결정적 프롬프트 엔지니어링* : 행동은 외부 분류자가 아닌 주입된 텍스트에서 발생합니다.

=== 왜 작동하는가 — 그리고 왜 직관과 반대되는가

표준 반응 : « AI에게 분류를 맡기나요? 실수하면 어쩌려고?

답변: 인간은 새벽 2시에 더 잘하지 못한다. 차이점은 LLM이 모든 것을 읽는다는 점이다. 세션과 대상 문서의 전체 맥락을 가지고 있다. 그것은 알고 있다`VPS ECO-16 12€ HT`이는 인프라 의사결정(VISION)이며`« le TTS ElevenLabs sonne plus naturel que Coqui »`이는 벤치마크에 의해 검증되지 않은 의견입니다.

인간은 세션이 끝날 무렵 대각선으로 읽으며 최선을 다한다. LLM은 모든 것을 읽고 체계적인 격자를 적용한다. 결과는**더 신뢰할 수 있는**, 적어도.

그리고 20%의 애매한 경우 — 심지어 LLM조차 주저하는 회색 지대 — 에 대한 답은 '코드를 더 추가하는 것'이 아니다. 답은**LangGraph4j**(EPIC 13) : 모호한 경우에 Human-in-the-Loop 노드를 활성화하고 인간에게 결정을 맡기는 상태 그래프이지만, 명확한 경우의 80%에서는 LLM만으로 충분합니다.

== 완전한 파이프: 브레인 덤프에서 블로그 게시물까지

다음은 아이디어 초안에서 게시된 기사까지 전체 흐름 — LLM만이 유일한 필터인 — :

[source]
----
CERCLE 0 (jardin secret)
  PICTURE_ME_ROLLIN.adoc   ← brain dump, allers-retours LLM
       ↓
  [LLM classifie] → VISION / OPINION / STRATÉGIE
       ↓
  VISION → dilution dans WORKSPACE_AS_PRODUCT.adoc
         → dilution dans WHAT_THE_GAMES_BEEN_MISSING.adoc
         → dilution dans WORKSPACE_VISION.adoc (session context)
         → RÉDACTION ARTICLE BLOG ← le LLM écrit, pas le dev
       ↓
CERCLE 4 (blog public)
  0116_compartimentage_epistemique.adoc  ← publié sur cheroliv.com
       ↓
  ./gradlew deploy (bakery-gradle → JBake → JGit → GitHub Pages)
       ↓
  https://cheroliv.com/blog/2026/0116/  ← live
----

개발자는 기사를 작성하지 않는다. 그는 도전하고, 검토하고, 검증한다. LLM이 작성한다. 루프는 :

1. 브레인 덤프 자유 → 검열 없음
2. LLM에 의한 인식론적 분류 → 누수 없음
3. LLM에 의한 작성 → 미루지 않기
4. 인간 검토 → 오류 없음

역사적인 병목 현상 — « 시간을 낼 수 없다 » — 은 해소되었다. LLM이 대부분의 작업을 수행한다. 인간은 오직 인간만이 할 수 있는 일, 즉 판단한다.

== 세 가지 루트 문서 — 정보가 제자리를 찾는 방법

각 대상 문서는 희석 캐스케이드에서 정확한 역할을 수행합니다:

[cols="1,3,2"]
|===
|문서 |그가 받는 것 |콘텐츠 유형 |`WORKSPACE_AS_PRODUCT.adoc` |아키텍처 결정, 기술 스택, 로드맵, 비즈니스 모델 |비전 + 전략 |`WHAT_THE_GAMES_BEEN_MISSING.adoc` |패턴, 수업, 안티패턴, 온톨로지, 형식적인 규칙 |비전 (테스트된 패턴) |`WORKSPACE_VISION.adoc` |세션 컨텍스트, 결정 기록, 인프라 포인트 |비전 + 전략 (맥락) |`AGENT_GOVERNANCE.adoc` |거버넌스 규정, 프로젝트 포트폴리오, 절차 |비전 (지배구조) |**블로그 cheroliv.com** |공개된 기사, 외부 독자를 위한 가치 |비전만
|===

같은 자극이 4개의 문서와 블로그에 영양을 공급할 수 있다 — 각 목적지는 자신에게 해당하는 부분을 받으며, 중복도 모순도 없다.

이게 일어난 일`PICTURE_ME_ROLLIN.adoc`(2026년 5월 3일) :

| Information | Classification | Destinations | | 인벤토리의 13+ 프로젝트 파운드리/ | 비전 | WORKSPACE_AS_PRODUCT | | VPS-2 OVH, edster.cloud, 월 8.49유로 | VISION | WORKSPACE_AS_PRODUCT + WORKSPACE_VISION |  아프리카 시장은 모바일 머니를 위해 준비되어 있다 » | STRATÉGIE | WORKSPACE_AS_PRODUCT (section business) | « DeepSeek > Kimi > GLM 장기 컨텍스트 » | OPINION → VISION | 제한되었다가 벤치마크 후 승진됨 (문서 0112) | | 합성 직원을 최종 제품으로 | 전략 | WORKSPACE_AS_PRODUCT (블로그 없음) |

== Baby-Step 패턴 + TestContainer + 살아있는 문서 — 스스로 테스트하는 코드

이 패턴 `STIMULUS/Dilution`은 생각을 관리한다. 코드에서의 대응은 패턴 `Baby-Step/TestContainer/Doc Vivante`, 검증된 `plantuml-gradle (380/380 tests PASS, 137 sessions sans fuite Docker)` :

[cols="1,3"]
|===
|원칙 |규칙 |**아기 발걸음** |US당 3점을 초과하지 마시오. US가 두렵다면 나누시오. 통과하는 1점 US가 지연되는 8점 US보다 낫다. |**TestContainer 먼저** |비즈니스 코드 이전에 컨테이너. 인프라 테스트 통과 → 안정적인 환경 보장 |**커밋된 데이터셋** |최소한이면서도 대표적인 부분집합에서`src/test/resources/`, PII 없이. 복제 가능, 실행 가능. |**살아있는 문서** |각 Cucumber 테스트는 자연어 문장입니다. 소스 코드가 실행 가능한 명세입니다. 마크다운 문서를 유지할 필요가 없습니다. |**자동 정리** |자원 누수 없음. 고아 컨테이너,`/tmp/gradle-test-*`: 모든 것이 청소되었습니다.
|===

이 패턴이 138회 세션 동안 plantuml-gradle이 Docker 회귀를 한 번도 겪지 않은 이유입니다. 이것은 외부 인프라(PostgreSQL, Redis, Kafka)와 통신하는 코드가 항상 프로덕션과 동일한 환경에서 버전 관리되고, 재현 가능하며, 한 명령으로 실행 가능한 상태로 테스트된다는 것을 보장합니다.

== 결론:출판에 대한 두려움 없이 생각의 자유

자동화된 인식론적 분할은 검열 도구가 아닙니다. 그것은**해방자**. 자유롭게 생각하고, 필터 없이 추측하며, 머리 속에 떠오르는 모든 것을 뇌 덤프한다 — 언제든 미성숙한 아이디어가 블로그에 올라올까 봐 두려워하지 않는다.

LLM은 이 경계의 수호자이다. 그것은 모든 것을 읽는다. 그것은 분류한다. 그것은 생존할 가치가 있는 것을 희석시킨다. 그것은 비공개로 남아 있어야 할 것을 가두어 놓는다. 그것은 공개 가능한 것을 작성한다.

그리고 개발자는 마지막 말을 가진다 : 다시 읽고, 도전하고, 검증한다. 판단한다.

혼자 일하는 개발자에게 부족했던 것은 업무 분업이었습니다. 정신적인 paperwork을 처리하는 합성 직원이 있다면, 인간은 자신이 가장 잘하는 일—설계하고, 아키텍처를 구성하고, 결정을 내리는 것—에 집중할 수 있습니다.
