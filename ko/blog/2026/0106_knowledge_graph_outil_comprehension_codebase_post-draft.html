  3. 7일차 : 선배가 말합니다 "아 네, 이 클래스는 실제로 두 가지 일을 있어요. 우리는 그것을 나누려고 계획했어요.

  4. 14일차: 비즈니스 인텔리전스의 모든 것이 거기에 있음을 깨닫습니다`utils/LegacyHelper.java`— 어디에도 참조되지 않는 파일

지식 그래프는 무엇입니까?

Knowledge Graph는 구조화된 표현의알다코드베이스에 있는 내용 :

개체 코드 안의 예시 그래프에서의 역할

매듭

클래스, 함수, 개념

그래프의 정점

가장자리

호출, 유산, 가져오기

두 노드 사이의 링크

커뮤니티

관련 클래스 그룹

시각 클러스터

모서리 유형

추출된, 추정된, 모호한

관계에 대한 신뢰

신뢰도 점수

0.0 à 1.0

엣지의 신뢰성 INFERRED

하이퍼엣지

관계 3+ 노드

파이프라인 : 하나의 명령으로 맞춤형 코드

Graphify 파이프라인 + Gradle 플러그인은 코드베이스를 PlantUML 다이어그램으로두 명령:

@startuml
skinparam backgroundColor #FEFEFE
skinparam sequenceArrowThickness 2

actor "개발자" as dev
participant "그래프화" as gfy
participant "graphify-out/graph.json" as json
participant "Gradle 플러그인" as plg
participant "지식 그래프 파서" as kgp
participant "지식 그래프 렌더러" as kgr
participant "diagrams/knowledge-graph/" as out

dev -> gfy : graphify update . --no-viz
gfy -> json : extrait nœuds, arêtes,\ncommunautés, confiances

dev -> plg : ./gradlew generateKnowledgeGraphDiagram
plg -> kgp : parse graph.json
kgp -> kgr : nodes + edges + communities
kgr -> out : génère .puml + .png

out --> dev : diagramme interactif

@enduml

0 LLM.모든 것이 결정론적입니다: 동일한 코드, 동일한 그래프, 동일한 다이어그램. 재현 가능하고, 버전 관리 가능하며, 오프라인에서도 조회할 수 있습니다.

엣지 유형: 신뢰가 말하는 것

@startuml
skinparam backgroundColor #FEFEFE

node "LLM 서비스" as ls
node "다이어그램 프로세서" as dp
node "구성 로더" as cl
node "API 키 풀" as akp
node "LegacyHelper" as lh #F1948a

ls --> dp : EXTRACTED\n(calls, direct)
cl ..> akp : INFERRED 0.75\n(creates, probable)
ls -[#FF5722]-> lh : AMBIGUOUS\n(legacy, douteux)

legend right
  |= Type |= Symbole |= Signification |
  | EXTRACTED | <b>--></b> | Relation visible dans le code |
  | INFERRED | <b>..></b> | Relation déduite (score de confiance) |
  | AMBIGUOUS | <b>--x</b> | Relation incertaine, à vérifier |
endlegend

@enduml

엣지 유형은 온보딩에 매우 중요합니다 :

  • 추출된: 편안하게 탐색할 수 있습니다 — 그것은 코드에 있습니다

  • 추론된(0.6-0.8) : 아마도 정확하지만, 리팩터링하기 전에 확인해.

  • 추론된(0.8+) : 매우 신뢰할 수 있음 — 이를 참조로 사용해

  • 애매한: 주의, 중요한 점. 선배에게 물어보세요.

구체적인 명령
# 1. Installer graphify
pip install graphify==0.4.29

# 2. Générer le Knowledge Graph
graphify update . --no-viz

# 3. Vérifier le JSON
cat graphify-out/graph.json | jq '.nodes | length'
# → 47 nœuds

# 4. Générer le diagramme
./gradlew generateKnowledgeGraphDiagram

# 5. Filtrer par communauté
./gradlew generateKnowledgeGraphDiagram -Pplantuml.kg.community="service layer"

# 6. Limiter la taille
./gradlew generateKnowledgeGraphDiagram -Pplantuml.kg.maxNodes=20

Knowledge Graph는 IDE를 대체하지 않습니다.— 그것을 완성시킨다. IDE는 *어디*를 보여준다; KG는 *왜*와 *어떻게 연결되는지*를 제시한다.

일상 항해의 가치

온보딩이 유일한 사용 사례는 아닙니다. 시니어 개발자를 위해 Knowledge Graph는 다음과 같이 사용됩니다:

@startuml

건축" as rev

제한과 전망

지식 그래프는 마법의 지팡이가 아닙니다:

한계 설명 우회

정적 코드만

런타임 없음, 데이터 흐름 없음

APM 트레이스로 완성

INFERRED 거짓일 수 있다

추론된 에지는 검증이 필요합니다.

신뢰 점수 + 인간 검토

비즈니스 의미 없음

KG는 "`LlmService appelle ConfigLoader`"을 알고 있지만, "`c’est le point d’entrée auth`"은 아니다.

수동 주석 또는 LLM 후처리

시간성 없음

코드의 스냅샷, 진화가 아닌

정기적으로 생성 + 버전 비교

전망 :

  • 차이 KG: 두 버전을 비교하여 커뮤니티의 이동을 확인하다

  • KG 대화형: 노드 클릭 → 해당 라인에서 IDE 열기

  • 역사적 KG: 시간에 따른 커뮤니티의 변화를 시각화하다 (마이그레이션되는 기술 부채)

결론

Knowledge Graph는 행위를 바꾼다외롭고 긴(코드베이스 이해하기) 한 가지 행위로공유되고 빠른(지도를 보세요).

이것은 설명서가 아닙니다 — 이건지도 제작. 자동으로 업데이트되는 지도, 실제 영토를 보여주며, 신입이든 senior이든 모든 개발자가 자신 있게 항해할 수 있도록 해주는 지도.
