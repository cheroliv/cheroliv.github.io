What is a Knowledge Graph?

A Knowledge Graph is a structured representation of theto knowcontent in your codebase :

Entity Example in the code Role in the graph

Knot

Class, function, concept

Vertex of the graph

Ridge

call, inheritance, import

Link between two nodes

Community

Group of related classes

Visual cluster

Edge type

EXTRACTED, INFERRED, AMBIGUOUS

Trust in the relationship

Confidence score

0.0 à 1.0

Reliability of an edge INFERRED

Hyperedge

Relation 3+ nodes

Architectural complexity

The difference with a simple UML diagram?A UML diagram shows what the developer decided to show. A Knowledge Graph shows what is actually there, including hidden dependencies and emergent concepts.

Pipeline: à la carte code in one command

The Graphify + Gradle plugin pipeline transforms your codebase into a PlantUML diagram intwo commands</think>

Zero LLM.Everything is deterministic: same code, same graph, same diagram. Reproducible, versionable, consultable offline.

Edge types: what confidence says

Edge types are crucial for onboarding:

  • EXTRACTED: you can navigate calmly — it’s in the code

  • INFERRED(0.6-0.8) : probably correct, but check before refactoring

  • INFERRED(0.8+) : very reliable — use it as reference

  • AMBIGUOUS: attention, sensitive point. Ask a senior.

5 minutes to generate your own Knowledge Graph

Concrete commands
# 1. Installer graphify
pip install graphify==0.4.29

# 2. Générer le Knowledge Graph
graphify update . --no-viz

# 3. Vérifier le JSON
cat graphify-out/graph.json | jq '.nodes | length'
# → 47 nœuds

# 4. Générer le diagramme
./gradlew generateKnowledgeGraphDiagram

# 5. Filtrer par communauté
./gradlew generateKnowledgeGraphDiagram -Pplantuml.kg.community="service layer"

# 6. Limiter la taille
./gradlew generateKnowledgeGraphDiagram -Pplantuml.kg.maxNodes=20

Limits and perspectives

A Knowledge Graph is not a magic wand:

Limit Explanation Workaround

Static code only

No runtime, no data flow

Complete with APM traces

INFERRED may be false

The deduced edges require validation

Confidence score + human review

No business semantics

The KG knows "LlmService calls ConfigLoader", not "it’s the auth entry point

Manual annotations or LLM post-processing

No temporality

A snapshot of the code, not its evolution

Generate regularly + compare the versions

Perspectives:

  • Diff KG: compare two versions to see community movements

  • Interactive KGclick on a node → opening IDE at the corresponding line

  • historical KG: visualize the evolution of communities over time (technical debt that migrates)

Conclusion

It’s not documentation — it’scartography. A map that updates automatically, that shows the real territory, and that allows every developer, new or senior, to navigate with confidence.
