وقت پڑھنا : 10 minutes

میری LLM صرف میرے Gradle ٹاسکس کو انجام دینے پر محتوط نہیں ہے۔ یہ خصوصی خیالات اور عمومی اظہار کے درمیانحد سے قافیہ کا محافظ ہے۔ ہر خیال راوٹ ہونے سے پہلے — نظریہ، رائے، حکمت عملی — درج بندی کر دیا جاتا ہے۔ خودکار معرفت کی تقسیم کیسے میری ذہنی باغ کو محفوظ رکھتی ہے مجھے خاموش کرنے کے بغیر۔

مشکل : آزادانہ سوچنا اور کِسی چیز کی اشاعت کئے بغیر

ایک سولو ڈویلپر جب اپنے سوچ کے عمل کو ایک LLM کے ساتھ ڈاکیومنٹ کرتا ہے، تو اس کے مقابلے میں ایک متناقضت :

CAPTURE TOUT (Cercle 0, jardin secret)
  ├→ Brain dump libre, pas de censure
  ├→ Idées brutes, spéculations, intuitions non vérifiées
  ├→ Allers-retours LLM : challenger, itérer, raffiner
  └→ Le LLM voit TOUT — le bon, le flou, l'embryonnaire

PUBLICATION SÉLECTIVE (Cercle 4, blog public)
  ├→ Uniquement les décisions actées
  ├→ Uniquement les patterns testés (>100 tests PASS)
  ├→ Uniquement ce qui a de la valeur pour le lecteur
  └→ JAMAIS une spéculation présentée comme une vérité

یہ دونوں کے درمیان ایک ہےفلٹر. سوال یہ ہے: یہ کس کر رہا ہے؟ تھکایا ہوا انسان سیشن کے آخر میں؟ naïve regex اسکرپت؟ یا خود LLM، جو پہلے سے سب کچھ پڑھ چکا ہے؟

میرا جواب : LLM.

پیٹرن STIMULUS — پیدا ہونا، ثابت کرنا، تخفیف کرنا، مرنا

STIMULUS ایک فائل ہے`.adoc`مؤقت workspace کی جڑ پر (دائرہ 0). اس نام ایک suggestive convention پر مشتمل ہے —PICTURE_ME_ROLLIN.adoc, HOLD_MY_BEER.adoc, ONCE_UPON_A_TIME.adoc— جس کا تجسّسی نیت لحظة کو پکڑتا ہے

اس کی زندگی کا دور بے رحمانہ ہے:

CRÉATION (Cercle 0)
  ├→ Fichier vide, brain dump libre
  ├→ Allers-retours LLM ← → développeur
  └→ Aucune pression de structure ou de publication

MATURATION
  ├→ Le contenu se densifie
  ├→ Des sections émergent naturellement
  └→ Le fichier devient une référence informelle de session

CLASSIFICATION ÉPISTÉMIQUE ← FAIT PAR LE LLM
  ├→ VISION    → publiable, diluer dans les docs publics + blog
  ├→ OPINION   → confiner au Cercle 0, pas de dilution externe
  └→ STRATÉGIE → dilution restreinte (docs racine, PAS de blog)

DILUTION (Cascade vers Cercles légitimes)
  ├→ VISION → WORKSPACE_AS_PRODUCT.adoc + WHAT_THE_GAMES.adoc + blog
  ├→ STRATÉGIE → WORKSPACE_AS_PRODUCT.adoc (section business)
  └→ OPINION → reste dans le stimulus, ne bouge pas

ARCHIVAGE + SUPPRESSION
  ├→ Snapshot dans configuration/vision-archive/ (trace historique)
  └→ rm du stimulus — il a fini son travail

ایک سٹیمولوس جو 2 سیشنز سے زیادہ تکخفف (dilution) کے بغیر بقی رہتا ہے، anti-pattern ہوتا ہے۔ یا تو معلومات بہت اہم ہے جسے ایک موقت فائل میں سڑنے نہ دیا جائے (→ ہلکا کرنا/ dilute)، یا یہ بہت مبہم ہے جس کی وجود کے لئے Worth نہیں (→ حذف کرنا)۔

ال ای ل ام کی وفد : کیونکہ یہ ای ل ام ہی فیلٹر کرتا ہے

میں Kotlin میں Vision/Opinion درج بندی کو hardcode نہیں کرتا۔ میں اسے …​ کے اندر انجرکت کرتا ہوںسیسٹم پرامپٹLLM کے ذریعے`AGENT_GOVERNANCE.adoc`:

----
----
Pour chaque dilution de stimulus ou session, tu es responsable de classifier
le contenu :
- VISION : décision architecturale actée, pattern testé en production (>100 tests PASS),
  décision documentée dans BACKLOG ou ROADMAP
- OPINION : spéculation, hypothèse non validée par des tests, intuition
  sans ancrage expérimental
- STRATEGIE : positionnement business, pricing, marché cible

Règles :
- Si OPINION, le contenu reste confiné dans son cercle d'origine
- Si VISION, tu procèdes à la dilution dans les documents racine
- Si STRATEGIE, dilution restreinte (docs racine, pas de blog public)
- Cette classification détermine aussi si un article de blog est publiable
  sur cheroliv.com
----

LLM یہ ہدایت پڑھ رہا ہے**پہلے**یہ اپنا فوری context میں ہے، الگ فائل میں نہیں. *محدودیت والا پرومپٹ انجینئرنگ* : سلوک injector کردہ متن سے ظاہر ہوتا ہے، بیرونی کلاس فائل سے نہیں۔

=== کیوں یہ کام کرتا ہے — اور کیوں یہ خلافِ intuitive ہے؟

معمولی ردعمل : « آپ طبقہ بندی کو AI پر اعتماد کر رہے ہیں؟ اور اگر وہ غلط ہو؟

جواب : انسان 2 بجے صبح بہتر نہیں کرتا۔ فرق یہ ہے کہ LLM، وہ، سب کچھ پڑھتا ہے۔ اس کے پاس سیشن اورہدف دستاویزات کا مکمل سیاق و سباق ہے۔ وہ جانتا ہے`VPS ECO-16 12€ HT`یہ انفراسٹرکچر کا فیصلہ (VISION) جبکہ`« le TTS ElevenLabs sonne plus naturel que Coqui »`یہ ایک غیر تصدیق شدہ رائے ہے جو بنچمارک سے تصدیق نہیں کی گئی۔

انسان، سیشن کے آخر میں، قطری طور سے پڑھتا ہے اور اپنی سب سے بہترین کوشش کرتا ہے۔ LLM مکمل طور سے پڑھتا ہے اور نظامیک گرید لاگو کرتا ہے۔ نتیجہ یہ ہے**زیادہ اعتبار**, کم نہیں.

اور 20% مبہم حالات — سرمئی حلقہ جس میں LLM بھیجھجتا ہے — جواب یہ نہیں ہے « کوڈ شامل کرنا » جواب یہ ہے**LangGraph4j**(EPIC 13) : ایک ستيٹ گرף جو ambiguous cases کے لیے Human-in-the-Loop node کو activate کرتا ہے اور فیصلے کے لیے انسان کے پاس واپس جاتا ہے۔ لیکن واضح 80% cases کے لیے LLM کافی ہے۔

== مکمل نل : برین ڈامپ سے بلاگ پوسٹ تک

یہ مکمل فلو — خام خیال سے شائع مضامین تک — LLM صرف فیلٹر کے طور پر :

[source]
----
CERCLE 0 (jardin secret)
  PICTURE_ME_ROLLIN.adoc   ← brain dump, allers-retours LLM
       ↓
  [LLM classifie] → VISION / OPINION / STRATÉGIE
       ↓
  VISION → dilution dans WORKSPACE_AS_PRODUCT.adoc
         → dilution dans WHAT_THE_GAMES_BEEN_MISSING.adoc
         → dilution dans WORKSPACE_VISION.adoc (session context)
         → RÉDACTION ARTICLE BLOG ← le LLM écrit, pas le dev
       ↓
CERCLE 4 (blog public)
  0116_compartimentage_epistemique.adoc  ← publié sur cheroliv.com
       ↓
  ./gradlew deploy (bakery-gradle → JBake → JGit → GitHub Pages)
       ↓
  https://cheroliv.com/blog/2026/0116/  ← live
----

ڈویلپر مضمون نہیں لکھتا۔ وہ چیلنج کرتا ہے، دوبارہ پڑھتا ہے، تصدیق کرتا ہے۔ LLM لکھتا ہے۔ لوپ ہے:

1. برین ڈمپ آزاد → سنسور نہیں
2. LLM کے ذریعے معرفتِ درجہ بندی → کوئی فری نہیں
3. LLM کی طرف سے تحریر → procrastination nahi
4. انسانی پڑھنے → غلطی نہیں

تاریخی رکاوٹ — « مجھے لکھنے کا وقت نہیں ہے » — دور ہو گیا۔ LLM زیادہ کام کرتا ہے۔ انسان وہ کرتا ہے جو صرف انسان کر سکتا ہے : فیصلہ کرنا۔

ہر ہدف شدہ دستاویز کا تخفیف کی سلسِلہ میں ایک معین کردہ کردار ہوتا ہے:

|===

== Baby-Step پیٹرن + ٹیسٹ کینٹر + زندہ ڈاک — یہ کوڈ جو خود خود ٹیسٹ کرتا ہے

STIMULUS/Dilution pattern سوچ کو منظم کرتا ہے۔ کوڈ کے لیے اس کا معادل Baby-Step/TestContainer/Doc Vivante pattern ہے جو plantuml-gradle سے تصدیق شدہ ہے (380/380 tests PASS, 137 sessions بغير ڈاکر لیک) :

[cols="1,3"]
|===
|مبدا |قاعدہ |**چھوٹا قدم** |Kabhi bhi US ke liye 3 points se zyada nahi honi chahiye. Agar ek US dar de, to us ko kaat dein. Ek 1-point wali US jo guzar jati hai > ek 8-point wali US jo halki chal rahi ho. |**TestContainer پہلے** |کاروباری کوڈ سے پہلے، کنٹینر۔ انسارت ڈ ٹیسٹ پاس → مستحکم ماحول کی ضمانت۔ |**ملتزم ڈیٹا سٹ** |خفیفی سے کم لیکن نمائندہ زیرجموعہ میں`src/test/resources/`, بے PII. کلونبل، لانچبل |**زندہ ڈاکیومینٹیشن** |ہر کیوکمبر ٹیسٹ = Natural language کی ایک جملہ۔ Source code executable spec ہے۔ صفر Marckdown دستاویزات رکھنے کی ضرورت نہیں۔ |**خودکار صفائی** |صفر ریکورسز لیک۔ اُٹھلے ہوے کنٹینرز،`/tmp/gradle-test-*`: سب چیز صاف ہے۔
|===

یہ پیٹرن اس وجہ سے ہے کہ plantuml-gradle نے کبھی 138 سیشنوں میں ڈوکر رگریشن نہیں کی۔ یہ یقین دلاتا ہے کہ بیرونی انفراسٹرکچر (PostgreSQL, Redis, Kafka) سے بات کرنے والا کوڈ ہمیشہ production کے مماثل ماحول میں ٹیسٹ کیا جاتا ہے — ورژن شدہ، قابلِ بازپیدا کرنے، اور ایک کوامند سے چلانے کے قابل۔

== نتیجہ : سوچ کی آزادی، نشر کرنے کے خوف کے بغیر

خودکار علمی تقسیم سنسور کے ٹول نہیں ہے۔ یہ ایک**آزاد کرنے والا**. یہ آزاد سوچنے، بغیر کسی فیلٹر کے speculation کرنے، اور برین‑덤پر (brain-dumper) کی اجازت دیتا ہے — کبھی نہیں خوف کرتا کہ کوئی ابتدائی ایڈیا بلگ پر آ جائے۔

LLM اس حدود کا محافظ ہے۔ اس سے سب کچھ پڑھتا ہے۔ اس سے درجہ بندی کرتا ہے۔ اس سے وہ چیزیں کمزور کرتا ہے جو رہنے کے لائق ہیں۔ اس سے وہ چیزیں محدود کرتا ہے جو خفی رہنے چاہئیں۔ اس سے وہ چیزیں تیار کرتا ہے جو شائع ہونے کے قابل ہیں۔

اور ڈویلپر، وہ، آخری بولی کرتا ہے: جائزہ لینا، چیلنج کرنا، تصدیق کرنا۔ فیصلہ کرنا۔

یہ solitary developer کے لئے کام کی تقسیم جو کمی تھی: ایک مصنوع ملازم جو ذہنی کاغذاتات کا انتظام کرتا ہے تاکہ انسان وہ کرے جس میں وہ بہترین ہو — ڈیزائن بنانا، معماريت بنانا، فیصلہ کرنا۔
