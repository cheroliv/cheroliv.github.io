پڑھنے کا وقت : 14 minutes

ماہوں تک، میں نے ایجنٹ گورنسنس کے قواعد کو ڈال رکھا ہے۔ فائلیں EAGER, LAZY cheklist, sassion khatam karne ke chhe qadam wale protokool و تاہم، ایک سوال masih unresolved تھا: LLM konsay janta hai k us کیا اس کے پاس ایک فائل کے ساتھ کرنے کا حق ہے ?

جواب پرامپٹ میں نہیں ہے۔ یہ فائل سسٹم میں ہے۔

یہ معماروں کی تفصیلات ہے جو جواب کو usable بناتی ہے — la LLM حکمرانی میٹرکس.

مسئولہ: پرومپٹ انجینیرینگ سینڈ کا قلعہ ہے

جب آپ ایک فائل LLM کو دیتے ہیں، آپ اسے سب کچھ دیتے ہیں۔ مضمون، ہاں — اس کے علاوہ حفاظتی تدابیر کی کمی۔ LLM نہیں جانتا کہ یہ فائل مشتمل ہے یک راز، ایک تخمینی رائے، یا بند سورس کوڈ۔ وہ اسے انڈیکس کرے گا، اس کا خلاصہ کرنا، اس کا حوالہ دینا، اسے دیگر ڈیٹ کے ساتھ ملانا — اور ممکن اس کو عمومی امبیڈنگ یا صارف کے جواب میں شائع کرنا۔

کلاسیک پرِیڈ، یہ پرومپٹ ہے :

"Tu es un assistant sécurisé. Ne divulgue jamais d'informations confidentielles.
Si tu détectes un secret, ignore-le. Si tu détectes une opinion, ne la répète pas."

یہ پرامپٹ میں تین مسائل ہیں :

  1. یہ LLM کیخیرخواہ پر مبنی ہے۔ کافی بڑا مودیل کے لئے

کمپلیکس بغس حل کرنا ایک ہدایت کو دور کرنے کے لیے کافی بڑا ہے 200k توکن کے سیاق ومقع میں ڈوبی ہوئی سیکورٹی۔

  1. یہ سیاق و سباق پر مبنی ہے، ساخت پر مبنی نہیں. промپٹ بدلیں، LLM بدلیں

سیشن تبدیل کریں — اور כלל مٹ جاتی ہے۔

  1. اس کا سکیلنگ نہیں ہوتا۔ ہر نئی فائل کی قسم، ہر نئی سطح

رازداری ایک نئی شرط طلب کرتی ہے۔ آپ کا پرامپٹ ایک مقرراتی متن جو کوئی بھی مکمل نہیں پڑتا

نظام کی حفاظت کبھی بھی ایک ہدایت جس پر منحصر نہیں ہونی چاہیے یہ بھول سکتا ہے، باپس کر سکتا ہے، یا نہیں لوڈ کر سکتا ہے۔ اس کو ایک پر منحصر ہونا چاہیے مانع جسے بgré واضح طور پر چاہنا پار نہیں کیا جا سکتا

LLM اس میٹرکس کو کیسے استعمال کرتا ہے؟

مائٹرکس ایک دستاویز نہیں ہے جو LLM پڑھتا ہے۔ یہ ایک محدودیت ضمین ایンキڈ سیاقِ مرکب وكتور (EPIC 9 — جاری ہے نفاذ کا)

یہ ہے جو ہر سیشن میں LLM ملتا ہے:

VECTEUR COMPOSITE DE CONTEXTE
├── RAG pgvector → OSS/ + office/Vision
│   (similarité sémantique sur contenu publiable)
├── Knowledge Graph graphify → OSS/
│   (relations exactes entre artéfacts publics)
├── Knowledge Graph privé → CSS/
│   (relations entre code closed source — jamais exporté)
├── Métadonnées de zone → chaque fichier taggé par zone physique
│   (le LLM sait s'il est dans office/ ou OSS/)
└── Historique des décisions → WORKSPACE_VISION.adoc
    (contexte temporel des arbitrages)

خالص طور پر، جب LLM می کہے:

Je vais indexer le contenu de edster/ pour enrichir le knowledge graph...

منطقہ میٹا ڈیٹا LLM کی جملہ مکمل ہونے سے پہلے جواب دیتا ہے: edster/`میں ہے`CSS/, سطح 3 →عوامی knowledge graph کے لئے رسائی ممنوع. راج اسے نہیں دیکھتا۔ گراف اسے نہیں چھوتا۔ صارف کا جواب نہیں وہ اس کاحوالہ نہیں دیتا

فضائی آنٹولوجيا جسے ایک کام کرتی ہےیونیکس اجازتLLM کے لئے آپ ایک پروسیس سے محتاط ہونے کا طلب نہیں کرتے۔/etc/shadow— آپ اس کے لیے پڑھنے کی اجازت منکر کرتے ہیں۔ وہی اصول۔

تنفیذ : ٹائپڈ گرڈیل ٹاسک

مٹرکس философия نہیں ہے۔ یہ کوڈ ہے۔ یہ کام کا معاہدہ ہے۔ Gradle جو یہ اجرا کرتا ہے:

abstract class ZoneAwareIndexer @Inject constructor(
    private val rootDir: DirectoryProperty,
    private val configServer: ConfigServerProperty  // → configuration/
) : DefaultTask() {

    @Input
    val zoneFilter: SetProperty<Zone> = project.objects.setProperty(Zone::class.java)

    @OutputFile
    val ragIndex: RegularFileProperty = project.objects.fileProperty()

    @TaskAction
    fun index() {
        val allowedPaths = zoneFilter.get().flatMap { it.resolve(rootDir.get()) }
        val forbiddenPaths = Zone.RESTRICTED.resolve(rootDir.get())
                            + Zone.INTIMATE.resolve(rootDir.get())
        // Le RAG ne voit jamais configuration/ ni la racine
        // CSS/ alimente un index privé, pas celui-ci
        // office/ est filtré par le classifieur Vision/Opinion
    }
}

enum class Zone {
    INTIMATE,      // Cercle 0 — racine
    RESTRICTED,    // Cercle 1 — configuration/
    EDITORIAL,     // Cercle 2 — office/
    CLOSED_SOURCE, // Cercle 3 — foundry/private/
    OPEN_SOURCE    // Cercle 3 — foundry/public/
}

ٹاسک testable ہے۔ آپ ایک ٹیسٹ لکھ سکتے ہیں جو جانچتا ہے :

@Test
fun `le RAG n'indexe jamais configuration`() {
    val index = ZoneAwareIndexer(rootDir, configServer)
    index.zoneFilter.set(setOf(Zone.OPEN_SOURCE, Zone.EDITORIAL))
    index.index()

    assertThat(index.ragIndex).doesNotContain("configuration/")
}

@Test
fun `le code closed source est exclu du RAG public`() {
    val index = ZoneAwareIndexer(rootDir, configServer)
    index.zoneFilter.set(setOf(Zone.OPEN_SOURCE))  // OSS only

    assertThat(index.ragIndex).doesNotContain("edster")
}

کیوں یہ ایک مانیفیسٹو ہے، صرف ایک Spec نہیں

یہ دستاویز معمارتی specification ہے کیونکہ یہ تعریف کرتا ہے:

  • کچابعاد(فضائی، اعلمی)

  • کچھحتمی قواعد(منطقه → رسائی کا حق)

  • Un ٹاسک کا عقد(Gradle ٹائپ کردہ، قابل ٹیسٹ)

  • ایکحوالہ نفاذ(میرا کام کرنے کی جگہ)

لیکن یہ بھی ایکمنفیستکونکہ وہ بحث میں اپنی موقف واضح کر رہا ہے بڑا : کیسے ایک LLM کی ڈیٹا تک رسائی کو منظم کیا جا سکتا ہے ؟

صنعے کا جواب پرامپٹ انجینیئنگ + گارڈ ریلز ہے
post-hoc کلاسifiers. میرا جواب یہ ہے: آپ کی فائلوں کو میں بہتر فائلیں. باقی خودکار ہے۔

یہ منفیست نہیں کہتا ہے "LLMs کو ہم آہنگ بنانا چاہیے". یہ کہتا ہے: "ہم آہنگی ایک LLM کا آپ کے قوانین امنیتی پر ایک نتیجہ آپ کے نظام کا ہے فائلز، آپ کے پرومپٹ سے نہیں.
