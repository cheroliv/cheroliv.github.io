مسئلہ: ڈائگرăm کوڈ سے ہمیشہ پیچھے رہے ہیں

جس پروژه میں چند ہزار لائنوں سے زیادہ ہوتی ہے، اس سينڈروم سے واقف ہوتا ہے :

  1. ہم پراجیکٹ کے ابتداء میں معمارتی ڈائگرام بناتے ہیں

  2. کوڈ بدل رہا ہے، وابستگیں بھی بدل رہی ہیں

  3. ڈائگرام زینتی جھوٹ بن جاتا ہے

  4. کسی نے اسے اپ ڈیٹ نہیں کیا کیونکہ یہ تنگ کرنے والا ہے

  5. نئے آنے وال لوگ اس پر اعتماد کرتے ہیں اور غلطیاں کرتے ہیں

@startuml

سوال یہ نہیں ہے کیا diagram درکار ہیں؟ — سب جانتے ہیں کہ ہاں۔ سوال یہ ہے :کس انہیں اپ ڈیٹ رکھتا ہے؟

جواب : کوئی نہیں مگر اگر یہ خودکار نہیں ہے

حل: Knowledge Graph → PlantUML کا ضباطی پائپ لائن

مفهوم سادہ ہے: ہاتھ سے diagram بنانے کی جگہ ہم ان کوحقیقی کوڈ کی ساخت سے بناتا ہے.

@startuml

skinparam componentStyle rectangle

Graphify --> KGJSON : extrait la structure\ndu code source
Développeur --> Plugin : ./gradlew generateKnowledgeGraphDiagram

Parser --> Plugin : KnowledgeGraph\n(noeuds + arêtes + communautés)

Renderer --> Plugin : code PlantUML\ndéterministe
Plugin --> PS : validateSyntax + generateImage

  Pipeline DÉTERMINISTE
  Aucun appel LLM

دو کمانڈ۔ یہ سب ہے۔

# Étape 1 : extraire le Knowledge Graph

مرحلہ 1: Graphify کو انسٹال کریں اور Knowledge Graph کو نکالیں

انсталاشين

Graphify ایک Python ٹول ہے جو آپ کے کوڈبیس کا تجزیہ کرتا ہے اور ایک منظم علم کا گراف بناتا ہے :

# Méthode recommandée
uv tool install graphifyy && graphify install --platform opencode

# Alternative avec pip
pip install graphifyy && graphify install --platform opencode

استثنائیاں کنفیگر کریں

ایک فائل بنائیں`.graphifyignore`پروجیکٹ کی جڑ پر، وہ فائلیں внеш کرنے کے لیے جو کاروباری منطق کا حصہ نہیں ہیں:

# Secrets — JAMAIS dans le graphe
*-context.yml
*.env

# Fichiers générés
build/
.gradle/

# Tests fonctionnels
src/functionalTest/

Knowledge Graph کو نکالیں

graphify . --no-viz

فلگ`--no-viz`HTML کی جنریٹ.skip (Gradle پائلائن میں لا فائدہ). نتیجہ ایک فائل ہے`graphify-out/graph.json`مشتمل :

  • گرہیں: کلاس، فائنکشنز، فائلز — ان کے نوع اور کمیونٹی کے ساتھ

  • کنارے: نودز کے درمیان تعلقات (EXTRACTED کوڈ سے، INFERRED par l’LLM)

  • مجتمعات: مربوط نودز کے خودکار گروپنگ

سٹرکچر کی مثال`graph.json`
{
  "nodes": [
    {"id": "0", "label": "LlmService", "file_type": "code", "community": 0},
    {"id": "1", "label": "ApiKeyPool", "file_type": "code", "community": 0},
    {"id": "2", "label": "PlantumlService", "file_type": "code", "community": 1}
  ],
  "links": [
    {"source": "1", "target": "0", "relation": "uses", "confidence": "EXTRACTED", "weight": 0.9},
    {"source": "0", "target": "2", "relation": "calls", "confidence": "INFERRED", "weight": 0.7}
  ]
}

سورس کوڈ ().kt, .java) tree-sitter کے ذریعے مقامی طور پر تحلیل کیا جاتا ہے,قطعی LLM. صرف دستاویز فائلوں (.adoc, .md) ضرورت ہوتی ہیں ایک LLM کال سمانتی استخراج کے لیے. اس لئے`--update` sur du code Kotlin est quasi instantané.

مرحلہ 2 : گریڈیل پلاگین نالیج گراف کو PlantUML میں بدل دیتا ہے

پائپ لائن کی معماریت

یہ پلاگین`com.cheroliv.plantuml`ایک کام شامل کرتا ہے`generateKnowledgeGraphDiagram`جو تبدیل کرتا ہے`graph.json`PlantUML ڈیاگراموں میںtarīḥ seبالکل محدد:

@startuml
skinparam backgroundColor #FEFEFE

participant "Gradle" as G
participant "نॉलج گراف ڈائیگرامٹاسک بنائیں" as Task
participant "KnowledgeGraphParser" as Parser
participant "KnowledgeGraphRenderer" as Renderer
participant "PlantumlService" as PS

collections "graphify-out/graph.json" as JSON

G -> Task : execute
Task -> JSON : read
Task -> Parser : parse(graph.json)
Parser --> Task : KnowledgeGraph\n(noeuds + arêtes + communautés)
Task -> Renderer : render(graph, filters)
Renderer --> Task : code PlantUML\n(déterministe)
Task -> PS : validateSyntax(plantumlCode)
alt syntaxe valide
    Task -> PS : generateImage → .png
else syntaxe invalide
    Task -> Task : save .puml avec warning
end

@enduml

اندرونی اجزاء

جز کردار

KnowledgeGraphParser

پارس کرنا`graph.json`— 3 فارمٹ سپورٹ کرتا ہے: اسلی graphify (nodes+links), legacy (communities), flat. عدد IDs کو لیبلز میں حل کرتا ہے۔

KnowledgeGraphRenderer

حتمی طور پر ایک کو بدل دیتا ہے`KnowledgeGraph`PlantUML کوڈ میں. قسم کے مطابق گروپ، پیکجوں میں کمیونٹیز، خودکار ليجند.

GenerateKnowledgeGraphDiagramTask

گریڈل ٹاسک جو منظم کرتا ہے: parse → render → validate → PNG.gradlePrivacySettings کےziiے可调

kgmodels.kt

ڈیٹا ماڈلز :`KnowledgeGraph`, KnowledgeGraphNode, KnowledgeGraphEdge, KnowledgeGraphCommunity, EdgeType.

PlantumlService

نحوی تصدیق + PNG کا رندرنگ (پلاگین کے تمام کاموں کے لیے dubarah istemal).

مرحلہ 3 : روزمرہ استعمال

مکمل ڈائاگرام

# Générer le diagramme du Knowledge Graph complet
./gradlew generateKnowledgeGraphDiagram

نتيجہ :`diagrams/knowledge-graph/knowledge-graph-full.puml`+.png

کامیونٹی کے حسب فیلٹر

# Une seule communauté
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.community=community_0

# Limiter le nombre de noeuds (lisibilité)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.community=community_0 \
  -Pplantuml.kg.maxNodes=15

کناارے کی قسم کے مطابق فیلٹر

# Uniquement les relations certaines (EXTRACTED)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.edgeTypes=EXTRACTED

# Relations certaines + inférées
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.edgeTypes=EXTRACTED,INFERRED

نود کے قسم اور اعتماد کے مبنی پر فیلٹر

# Uniquement les classes de code
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.nodeTypes=code

# Seuil de confiance minimum (pour les INFERRED)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.minConfidence=0.7

اختیاری آؤٹ پٹ ڈائریکٹری

./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.outputDir=docs/architecture

انکمنٹل اپ ڈیٹ

جب کوڈ بدل جاتا ہے، تو ہم پوری گراف کو صفر سے دوبارہ نہیں بناتے ہیں :

# Mise à jour incrémentale (fichiers modifiés uniquement)
graphify . --update

# Puis régénérer les diagrammes
./gradlew generateKnowledgeGraphDiagram

--update`صرف مبدل شدہ فائلیں نکال دیتا ہے (SHA256 کے ذریعے`graphify-out/cache/)". Kotlin کوڈ پر یہ تقریباً فوری ہے کیونکہ tree-sitter مقامی طور پر کام کرتا ہے LLM کے بغیر۔

ڈگFOODING : پلاگین خود خود کو دستاویز کرتا ہے

پلاگ ان PlantUML مطالبات کو ڈائاگراموں میں تبدیل کرنے کے لیے موجود ہے۔ یہ اپنی codebase کا Knowledge Graph بھی documentation کے ڈائاگراموں میں بدل سکتا ہے۔ یہ dogfooding ہے: پلاگ ان اپنی خدمت خود کرتا ہے۔

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

package "عام پائپ لائن
(صارف → ڈائگرام)" as normal {
    [Fichier .prompt] as prompt
    [LlmService\n+ ApiKeyPool] as llm1
    [ProcessPlantumlPromptsTask] as task1
    [Diagramme PNG] as out1

    prompt --> task1
    task1 --> llm1
    llm1 --> out1
}

package "Pipeline Knowledge Graph
(معین کردہ، LLM نہیں)" as kg {
    [graphify-out/graph.json] as kgjson
    [KnowledgeGraphParser] as parser
    [KnowledgeGraphRenderer] as renderer
    [PlantumlService] as ps
    [Diagramme PNG\n(documentation du plugin)] as out2

    kgjson --> parser
    parser --> renderer
    renderer --> ps
    ps --> out2
}

package "Pipeline Dogfooding
(LLM → plugin کے dutawaziāt)" as dogfood {
    [GraphifyPromptAdapter] as gpa
    [Fichiers .prompt\nauto-générés] as auto_prompt
    [LlmService\n+ ApiKeyPool] as llm2
    [ProcessPlantumlPromptsTask] as task2
    [Diagramme PNG\n(documentation LLM)] as out3

    kgjson --> gpa
    gpa --> auto_prompt
    auto_prompt --> task2
    task2 --> llm2
    llm2 --> out3
}

note "ایسے ہی LlmService، اسی ApiKeyPool،
ایسے ہی PlantumlService
— صفر تکثیر" as N

@enduml

@startuml

    llmSvc --> model : API call
    model --> puml2 : réponse non-déterministe
}

  Même entrée → même sortie
  Pas de latence réseau
  Pas de coût en tokens
  Reproductible en CI
end note

note bottom of llm
  Même entrée → sortie variable

  Coût en tokens
  Nécessite une clave API
end note

@enduml

@startuml
skinparam backgroundColor #FEFEFE

participant "ڈویلپر" as Dev
participant "Gradle" as G
participant "نالッジ گراف ڈایگرام ٹاسک پیدا کریں" as Task
participant "KnowledgeGraphParser" as Parser
participant "KnowledgeGraphRenderer" as Renderer
participant "PlantumlService" as PS
collections "graphify-out/graph.json" as JSON
collections "ڈائاگرامز/نالیدگی گراف/" as Out

Dev -> G : ./gradlew generateKnowledgeGraphDiagram
G -> Task : execute
Task -> JSON : read
Task -> Parser : parse(graph.json)
Parser --> Task : KnowledgeGraph

alt filtres actifs
    Task -> Task : appliquer filtres\n(community, edgeTypes, maxNodes…)
end

Task -> Renderer : render(graph, filters)
Renderer --> Task : code PlantUML

Task -> PS : validateSyntax()
alt valide
    Task -> PS : generateImage()
    PS --> Out : .puml + .png
else invalide
    Task -> Out : .puml (avec warning)
end

@enduml
