آپ لنگچین 4J کے ساتھ pgvector کی انٹیگریشن پر ایک مضامین پڑھ رہے ہیں۔ صفحے کے نیچے، JBake آپ کی تجویز «مربوط مضامین»۔ آپ کلک کرتے ہیں۔ یہ ایک مضامین ہے …​configuration کے بارے میں کٹی ٹرمنل سے. دوں کے درمیان ایک ہی مشترکہ نقطہ؟ ان کو کم سے کم پندرہ دنوں کا فاصلہ. یہ مشورہ نہیں. یہ ایک تقویم جسے ڈکھایا گیا ہے محرر کا مضمون.

سين: منگل 12 مئی، 17:30

میں اپنی ایک مضامین کی دوبارہ پڑھ رہا ہوں — واس پر Knowledge Graph، codebase سمجھنے کا اوزار محتوا گہرا ہے: نودز, ایجس, کمیونٹی, PlantUML, آن بورڈ۔ ایک مضبوط 15 منٹ کی پڑھنے کی ٹیکنیک جو متحرک کرتی ہے`graphify-gradle`, plantuml-gradle, اور گراف ٹاپولوجی کے مفاهیم.

صفحے کے نیچے، « مضمرات متعلقہ » مجھے تجویز دیتے ہیں :

  1. فائر بیس کنٹیکٹ فارم (0113) پر ایک مضمون

  2. ایجر/لےزی میكانزم پر ایک مضبوط (0108)

  3. Gradle سکرپٹ سے پلاگائن تک کی migration پر ایک مضمون (0102)

  4. Ollama Pro (0120) کے اشتراکوں کے مجموع پر ایک مضامین

ان چار مضامین میں سے تین کا کوئی تعلق Knowledge Graph سے نہیں ہے. وہ یہاں موجود ہیں کیونکہ وہ سب سے آخر میں شائع ہیں — زمانہ کا پڑوسی، نہیں معنیاتی ہمسایگی.

میں ٹیمپلیٹ دیکھ رہا ہوں`post.thyme`:

<!-- Articles connexes (liens internes SEO) -->
<th:block th:each="post,postStat : ${published_posts}">
    <th:block th:if="${!post.uri.equals(content.uri) and postStat.index lt 4}">
        ...
    </th:block>
</th:block>

`published_posts`یہ ایک تاریخی فہرست ہے۔`postStat.index lt 4`لتا ہے موجودہ پوسٹ سے مختلف پہلاچار (پہلے چار). یہ سب ہے۔ کوئی منطق نہیں۔ مشابہت کا۔ مضمون کا کوئی تصور نہیں۔ صرف ایک لوپ`for`نقاب زد توصیہ.

JBake کا بگ نہیں ہے۔ یہ سب کا ڈیفالٹ سلوک ہے۔ اسٹاٹک سائٹ جينریٹر: پوسٹوں کی فہرست سادہ اور تاریخ کے مطابق ترتیب دی گئی ہے۔ ٹیمپلیٹ وہ کر سکتا ہے جو اس کے پاس ہے۔

حل: ایک Gradle پائپ لائن، گرم LLM کال نہیں

پہلی وسوسہ یہ ہوگا کہ بیک کے وقت ایک LLM کو بلایا جائے: « لیے یہ مضامین corpus میں سب سے زیادہ مماثل تین مضامین ڈھونڈتا ہے۔ یہ مت کریں

ہر ایک کے لیے LLM کا ایک کال`./gradlew bake`وقت، پیسے اور آپ کی بنڈ میں غیر‑تعیناتی انداز شامل ہوتی ہے۔ LLM کا جواب دو بینڈز کے درمیان بدلنا، جو کہ مضمون تبدیل نہ ہوا ہو۔ آپ کی سسٹمر نمائندگی بن جاتی ہے غ़یر قابلِ تجدید، آپ کے ٹیسٹس فلیکی بن جاتے ہیں۔

حل مخصوص ہے: گرینڈل ایک پائلائن ہے جو گراف پیش سے حساب لگاتا ہے مشابہت کا اور اسے سٹور کرتا ہے میں`graph.json`. ٹیمپلیٹ نتیجہ پڑھتا ہے — وہ کبھی بھی حساب چلاتا نہیں.

معمار: باکری Graphify importe karti hai، Engine nahi

یہ معماریہ کا سب سے اہم نقطہ ہے۔ وسوسہ یہ ہوگا کہ تعاون میں تار لگانا`engine/build.gradle.kts`: انجن لاگو کرتا ہے graphify اسکن کے لیے, bakery بیک کے لیے, اور engine درمیان پل بناتا ہے دونوں.

یہ ایک انٹی-پryn ہے. Engine ایک صارف ٹرمینل ہے — یہ لاگو کرتا ہے پلاگ انز، بزنس لاجیک کو لاگو نہیں کرتا۔ قانون ہے: ثبوت کا بوجھ مالک پلاگ پر ہے۔

  1. سکن (گرافائی) :`graphify-plugin`یہ workspace کو اسکین کرتا ہے۔ اس کے

موجودہ شکل، وہ پہلے سے ہی ان`xref:`بیچ`.adoc`اور وہ داخل ظاہر کرتا ہے`graph.json`جéisے edges ki kisam`reference`.
اسے اداری مواد کے لیے محسّن کیا جاتا ہے : * JBake کے میتا ڈیٹا پارس کریں (:jbake-tags:, :jbake-description:) ہر کا`.adoc`بلوگ کا * ٹیگز کے مشترک واقعات کی حساب لگائیں → edges`tag_cooccurrence`وزن کے ساتھ * ٹی ایف آئی ڈی ایف کے ذریعے وضاحات سے نام رکھنے والی موجودات نکالیں → edges`entity_overlap` ایک حصہ انجیکشن کریں`blog_articles`کے اندر`graph.json`موجود

// Extrait de l'enrichissement graphify pour le blog
fun enrichBlogSection(graphJson: File, blogDir: File): GraphJson {
    val articles = blogDir.listFiles { f -> f.extension == "adoc" }
        .map { parseJbakeMetadata(it) }

    val nodes = articles.map { ArticleNode(it.slug, it.title, it.tags) }
    val edges = mutableListOf<GraphEdge>()

    // Couche 1 : xref (déjà fait par scanWorkspace)

    // Couche 2 : co-occurrences de tags
    for (a in articles) {
        for (b in articles) {
            if (a.slug == b.slug) continue
            val common = a.tags.intersect(b.tags)
            if (common.isNotEmpty()) {
                edges.add(GraphEdge(
                    source = a.slug,
                    target = b.slug,
                    type = "tag_cooccurrence",
                    weight = common.size.toDouble() / (a.tags.size + b.tags.size)
                ))
            }
        }
    }

    return graphJson.copy(
        blogArticles = BlogSection(nodes, edges)
    )
}

`graph.json`اور ہر پست کے لئے منسلک مضامین حل کرتا ہے۔

// BakeryPlugin — résolution des articles connexes
fun resolveRelatedPosts(
    currentSlug: String,
    graph: GraphJson,
    maxResults: Int = 4
): List<RelatedPost> {
    val edges = graph.blogArticles.edges
        .filter { it.source == currentSlug || it.target == currentSlug }

    return edges
        .sortedByDescending { it.weight }
        .take(maxResults)
        .map { edge ->
            val relatedSlug = if (edge.source == currentSlug) edge.target else edge.source
            graph.blogArticles.nodes.first { it.slug == relatedSlug }
        }
}
