واقعہ: پرامپٹ انżynئرنگ ریتی کا قلعہ ہے

Teen haftay tak, maine Opencode ke saath Gradle plugins develop kiye, teen mukhtalif LLMs istemaal karte hue — Kimi K2.6, GLM-5.1, aur DeepSeek-V4-Pro (wahid bachta, lekin yeh ek doosri kahani Déjà couverte ici.) Mere governance ka tarika agentJe l’ai documentée en détail dans un précédent article. AsciiDoc files ke mutabiq —AGENT.adoc, INDEX.adoc, PROMPT_REPRISE.adoc— ہر سیشن کے شروع میں تقریباً 30,000 ٹوکن قواعد، بیکلاگ اور تاریخ لوڈ کرتے ہیں۔

اس کے باوجود اس دستاویزی ڈھانچے کے، دو چیزیں مجھ پر اثر ڈالی :

  1. LLM بھول جاتا ہے۔ ہر EAGER فائل کے سربراہ پر مطلق قواعد کے ساتھ، 60 000 ٹوکنز کے مجموعی بعد ( ابتدائی سیاق + مکالمہ )، Kimi K2.6 پیشکش کرنے لگ گیا ہے`Write`کونفیگریشن فائلوں پر زائد بار. GLM-5.1 نے ایک Firebase ٹوکن کو جسے بدلنا ہو، ایک placeholder کے ساتھ گھلا دیا. قواعد likhī gayī تھیں — LLM انہیں بعد یہ نہیں دیکھتا۔

  2. حکمرانی خود ایک مسئلے میں تبدیل ہوتی ہے۔ بعد از Hot/Warm/ColdArticle sur la rotation de backup. کو لاگو کرنے کے بعد، سیاق کے پھٹنے سے بچنے کے لیے، میرے EAGER فائلیں ابھی بھی 1414 لائنوں کا وزن تھاJ’ai documenté cet audit ici.۔ حکمرانی — LLM کی saturation سے حفاظت کرنے کے لیے بنائی گئی — LLM کو saturation کر دی گئی۔

مجھے ایک آ لائنمنٹ میکانزم درکار تھا جو پرامپٹ میں ٹوکنز کی تعداد پر مبنی نہ ہو۔

جواب: متن کے مطابق ہيئنگ کرنا بند کریں، اور ہيئنگ شروع کرنے کے لیےجگہ.

سرگُوں باغ : خارج-CVS فضا

یہ سب سے اہم مفهوم — اور سب سے مخالفِ حسی۔

جڑ`workspace/نہیں ہے.git/. وہ دستاویزات جو وہاں رہتے ہیں (`WORKSPACE_VISION.adoc, WORKSPACE_AS_PRODUCT.adoc, WORKSPACE_ORGANIZATION.adoc— اور آپ ابھی جو پڑھ رہے ہیں، جو اس سے نازل ہے) ان کو ورژن بنانے، شیر کرنے، یا دوبارہ پڑھنے کے لیے نہیں بنایا گیا، صرف میرا خود کے سوا کسی اور کے لیے. یہ ہیںنیکشانی خیالات.

خفی باغ out-of-CVS کی فطرت سے ہے۔ نسخہ سازی کی عدم موجودگی سوچ کی آزادی کی شرط ہے۔ وہاں لکھا نہیں جاتا تاکہ پڑھا جا سکے — وہاں لکھا جاتا ہے تاکہ اپنی اپنی تصورات کو واضح کیا جا sake۔

مگر یہ آزادی کی ایک قیمت ہے: ایک`rm`اتفاقی طور پر، یہ استراتژیکی سوچ کے ماہین غاب ہو جاتے ہیں۔ حل باغ کا ورژننگ کرنے کا نہیں ہے (یہ اسے تباہ کر دے گا) — یہ اس کاعکس کرناسب سے محدود دائرے میں.

جڑ پر`workspace/, ایک فائل.gitignore`کم سے کم ظاہر کرتا ہے وہسیاست تاریخ سازیرازہ باغ کے فائلز :

Ce .gitignore`اس میں کلاسیک Git کا کوئی عمل نہیں ہے (کسی چیز نہیں.git/`jar par) woh ek jesa act karta haiحکمرانی کنفیگری فائلیہ ایک مخصوص سوال کا جواب دیتا ہے: راز کے باغ کی کunse اشیا تاریخی لائق ہیں، اور کunse صرف provisional ہیں؟

  • فہرست شدہ فائلیں میں`.gitignore`(Empty output).goosehints, .goose— ایجنٹس کے ذریعے پیدا کیے گئے عارضی اشیاء. کوئی استراتژیک قدر نہیں. کوئی تاریخ نگاری نہیں.

  • فائلز`.adoc`جڑ کا —WORKSPACE_VISION.adoc, WORKSPACE_ORGANIZATION.adoc, WORKSPACE_AS_PRODUCT.adoc, WHAT_THE_GAMES_BEEN_MISSING.adoc, depots_implementes_strategie.adoc, synthese-LLMs-long-contexte.adoc— نہیں ہیںنہیںمیں`.gitignore`۔ یہ تاریخی بنانے کے لئے artefacts ہیں۔

Le `.gitignore`ہےحکمرانی کا ڈھانچہ: جس چیز کو یہاں فہرست نہیں کی گئی، وہ سنیپ شاپ کے لیے מועמד ہے۔ اور LLM اس فائل کو پڑھ کر بات جانتا ہے کہ کیا محفوظ رکھنا چاہیے اور کیا نادیده کیا جا سکتا ہے — промپٹ میں اسے یاد دلانے کی ضرورت نہیں۔

سنیپ شاپٹ میکانیزم

میں نے بنایا`configuration/vision-archive/: تمام کے تاریخ شدہ سnapshot.adoc`جڑ سے، خفیہ ذخیرہ میں کامٹس`configuration/`. ہر برین سٹورمینگ سیشن ایک سناپ شٹ پیدا کرتا ہے :

DATE=$(date +%Y-%m-%d)
mkdir -p /home/cheroliv/workspace/configuration/vision-archive/$DATE
cp /home/cheroliv/workspace/*.adoc /home/cheroliv/workspace/configuration/vision-archive/$DATE/
cd /home/cheroliv/workspace/configuration && git add vision-archive/ && \
  git commit -m "vision-archive: snapshot $DATE"

یہ عمل سیشن کے آخر میں LLM خود شروع کرتا ہے، جو یہ عالمی راؤٹنگ کا کام انجام دیتا ہے۔ ہر سنیپشٹ ایک مخصوص وقت T پر استراتیجی سوچ کی مکمل حالت راکارد کرتا ہے۔

گِٹ کی تاریخ`configuration/`بنتی ہےمیری استراتیقی سوچ کی بیوگرافی. میں ایک بن سکتا ہوں`git log — vision-archive/`اور اپنی نظر کی ترقی کو دیکھیں، سیشن بار سیشن، تاریخ بار tarih۔

ایک واقعی مثال تاریخچے کے بعد ایک کام کرنے کے دن:

$ git -C configuration log --oneline -- vision-archive/

ایک دن میں پانچ سناپ شاٹس۔ ہر ایک بازیابی کا نقطہ ہے۔ ہر ایک حکمت عملی کی پیدائش میں ایک مرحلہ ہے۔

فائل`configuration/vision-archive/latest/`ہمیشہ ایک شامل ہےکام کرنے والی کاپیآخری سنیپ شٹ، فوری رجعان کے طور پر استعمال ہونے والا، جس سے گِٹ کی تاریخ میں ناوози کرنے کی ضرورت نہیں پڑتی۔

اور LLM کے لیے، یہ ایکاتساق کا پیشگوی: جب وہ موجودہ پیاده سازی اور محفوظ نظر کے درمیان تعارض دیکھتا ہے، وہ اسے گزارش کر سکتا ہے۔

سیف: configuration/ Spring Cloud Config کی طرح

`configuration/`یہ صرف وژن کے آرکائیو کا صرف یہ نہیں شامل ہوتا۔ اس کی بنیادی (اور مستقبلی) funksiya aik haiسپرنگ کلاؤڈ کنفیگ سرور. تمام راز، ٹوکن، credentials، اور انفراسٹرکچر کے वर्णن یہان موجود ہیں، ایک خفیہ گِٹ ریپوزٹری میں جو صرف مالک تک رسائی رکھتا ہے۔

کyon ایک الگ ریپازِٹوری، ایک فائل کے بجائے؟`.env`ہر پروجیکٹ میں؟

  • غلط سے پُش راز : ناممکن. رازوں کو ایک خفیہ ذخیرہ میں رکھا جاتا ہے جو عمومیProjects کی غلط اشارے سے ارجاع نہیں کیا جا سکتا.

  • Audit: Git کا تاریخچہ ہر ترتیب کے بدل کا ریکارڈ دیتا ہے۔ کون نے کیا بدلایا، کب، اور کس SHA hash کے ساتھ۔

  • رول بیک :`git revert`ایک خراب کنفیگری پر. اچانک، دستی بیکاپ بنا.

کِتاب خانہ: office/ جیسے ڈیٹا قابلِ مصرف

`office/`یہ بلاغ کے مضامین، ٹیکنیکی مواصفات، تربیت کے مواد (38 کورس ڈائریکٹری FPA, SPG/SPD, JSON اسکیما، بلوم/هارو/krathwohl taksonomies) — سب چیز جو یہ تشکیل دیتا ہےتعلیمی مواد.

لیکن`office/`یہ صرف ایک ڈاکس ڈروور نہیں ہے۔ یہ ایکسٹرکچرڈ ڈیٹا کا ذریعہکہ گریڈیل پلاگینوں کا`foundry/`وہ استعمال کرتے ہیں. ایک بلاگ کا مضمون میں`office/`یہ ایک انٹری ہے جسے پلاگین HTML میں تبدیل کر دے گا۔ ایسکی ڈاک کے SPG میں`office/metiers/FPA/`یہ ایک آرٹیفیکٹ ہے جسے ایک اورکیسٹریٹر پارس کر کے سلیڈز، کویز، اور ویڈیو کیپسولز بنانے کے لیے استعمال کرے گا۔

Et le `build.gradle.kts`جڑ میں`office/`یہ کاروباری کوڈ نہیں — یہ ایکپلاگین ایکوسیстем کی استعمال کا سکرپٹ۔ وہ کہتا ہے: "یہ گریڈل پلاگ‑inz ہیں جو میں استعمال کرتا ہوں،یہ میرے وورک سпыس کا سیاق ہے

اس کا بنیادی فائدہ دُفاعی (سکیورٹی، وِزِبیلیٹی) نہیں — یہ ہےخلاق. جب LLM ایک онтولوجی کے تحت منظم شدہ فضاء میں کام کرتا ہے، تو وہ اس کر سکتا ہے جسے کوئی پرامپٹ اجازت نہیں دیتا: دیلتا کا مشاہدہ کرنا

WorkSpace ka rabita al-jabr aur mushahidda delta

جب LLM گزر رہا ہے`foundry/, اس کے پاس ایکمنظم شدہ ڈیٹا کا جالی: نوڈز (پلاگائنز، فائلز، ٹیسٹس، انحصارات)، ٹائپڈ ایجس (`import, depends_on, generates, tests), relations de composition et d’ordre (`training-gradle`ریپازٹری نکالیں →`slider-gradle`اسلائڈز بناتا ہے →`capsule-gradle`ویدیو چلاو).

یہ الجبر کدھر بھی واضح طور پر لکھا نہیں گیا — لیکن یہ معلوم ہے۔ ہر`build.gradle.kts`یہ انحصارات کو دکھاتا ہے۔ ہر`INDEX.adoc`یہ متقابل اشارے پیش کرتا ہے۔

LLM یہ الجبر ملاحظہ کرتا ہے اور اسے پتہ لگاتا ہےڈیلٹا: فاصلہ بین یہ سسٹم پہلے سے پیدا کرنے والا ہے اور جو vision بیان کرتی ہے۔

اس ڈیلٹے سے، وہ کچھ تعریف کر سکتا ہےکاروبار کے ماہرین کی نقشات— CDA (ایپلیکیشن کے ڈیزائنر اور ڈویلپر، Kotlin/Gradle/JHipster) اور FPA (حرفے کے افراد کے براۓ تربیت کا ماہر، تدریس/Qualiopi/Bloom) — اور ہر ماہر کے لیے جس کمی ہے، اسے شناخت کریں

LLM کو بتانے کی ضرورت نہیں ہے کہ اسے کیا کرنا ہے۔ ڈیلٹہ ساخت سے ظاہر ہوتا ہے۔

مکمل سیاق و سباق ویکٹر: RAG + pgvector + Graphify

رابطی الجبر ایک نظریاتی بناؤ نہیں ہے۔ یہ ہے مادی شکل میں تین اجزاء سے جو ایک بنائے ہیںسیاق و سباق کا مرکب ویکٹرکے لیے LLM.

حصہ 1 — RAG LangChain4j + PostgreSQL pgvector

میں نے پہلے سے LangChain4j دو پلیگنز میں پروڈکشن میں deploy کر چکا ہے :`slider-gradle`(4 LLM پرووائڈرز) اور`plantuml-gradle`(7 فراہم کرنے والے). ONNX امبیڈنگز (AllMiniLmL6V2) انڈیکس کرتی ہیں ڈیٹا کا`office/`اور مzholi kod کا`foundry/`PostgreSQL + pgvector میں

یہ RAG دو بعدوں پر کام کرتا ہے:

  • بعدی ڈیٹا : دستاویزات`office/`(SPG, مضامین، تربیاں، JSON کے سکیما)

  • Dimension code : کوڈ بیسز`foundry/`(مصادر Kotlin، ٹیسٹس Cucumber، AGENT.adoc)

تقاطع دونوں کیا (کاروباری ڈومین) اور کیسے (تنفاذ) کوغطا کرتی ہے۔

جزء 2 — Knowledge Graph Graphify

Graphify میں شامل ہے`plantuml-gradle`(109 tests, 380/380 PASS) aur ek paida karta hai`graph.json`— ایک ساخت یافتہ دانش گراف نڈ، किनارے اور خودکاراً entdeckٹی ہوئی کامیونٹیز کے ساتھ۔

RAG کے برعکس جو ویکٹرSimilarity (فزع) سے عمل کرتا ہے، knowledge graph عمل کرتا ہےدقیق تعلقات(محدد)`graphify query`semantiki sawalat (~50 tokens) ke liye,`graphify path`ناویگیشن کرنے کے لیے,`graphify explain`وضاحت کرنے کے لیے.

حصہ 3 — Graphify افزائشی : پھیلے ہوئے، جمع کرنے کے قابل، استعمال ہونے والا

یہ کلیدی معمارتی فیصلہ ہے۔

Graphify ko ek hi repository mein jeena nahi chahiye. Isay ek tarah se jeena chahiye.متفرقہہر پلاگین میں :

  1. ہر ایک پلاگین Gradle ایک تاپم شامل کرتا ہے`updateKnowledgeGraph`جو Graphify کو بلاتا ہےاپنا scope پراور پیدا کرتا ہے ایک`graph.json`مقامی.

  2. بیلڈ اسکرپٹ کا`office/ استعمال کرتا ہے`graphify-gradle`مع`rootDir = /home/cheroliv/workspace`اور پیدا کرتا ہے ایک`graph.json عالمیجس میں مقامی گرافز کو جمع کیا جاتا ہے

  3. ہر پلاگین کا RAG یہ داخل کرتا ہے`graph.json`عالمی جیسےسیاق کا فِلٹرLLM کی طلبات کے لئے.

فضائی أنتولوجيا سب چیزوں کو کولٹی نہیں کرتی۔ کُڈ اسٹائل کی اصطلاحات، نام رکھنے کے طریقے، میمارانہ ڈیزائن کے选定 — یہ سب پرامپٹ میں رہتا ہے۔ جِس کا حل فضائی أنتولوجيا کرتا ہے، وہسキュورٹی اور ظاہریت کا طبقہ: جہاں ہر بائٹ کو رہنا ضروری ہے، اور جو اس دیکھ سکتا ہے۔

نتیجہ: معماريت، ایک گفتگو کے طور پر

میں اپنی ویب سائیٹ کے فوٹر میں کوئی سیاسی مانیفیسٹ نہیں ڈالتا۔ میں اپنے پرامپٹس میں کوئی اخلاقی قواعد نہیں ڈالتا۔ تنظیم متن میں نہیں ہے — یہ …​ میں ہےفائل سسٹم.

جب یک LLM اس فضلے میں کام کر رہا ہوتا ہے، تو وہ ایک راز نہیں لیک سکتا (راستہ اسے روک دیتا ہے). وہ تعلیمی ڈیٹا کو سورس کوڈ کے ساتھ نہیں گھلتا سکتا (فصلی حصہ مختلف ہے). وہ 80,000 ٹوکنز کی ایک سیکیورٹی رول نہیں بھول سکتا — کیونکہ رول پرامپٹ میں نہیں ہے، یہ … میں`workspace/→`configuration/→office/→`foundry/`کہ ہر فائل کی پڑھنے سے دوبارہ فعال ہو جاتا ہے

یہ secure by design کا اصول ہے-agent alignment پر لاگو: LLM سے قواعد کو یاد کرنے کے لیے نہیں پوچھنا۔ معماری اس طرح بنائیں کہ غلطی ساختاً ناممکن بن جائے۔

براہ راست، یہ LLM کو وہ دیتا ہے جو کوئی پرامپٹ نہیں دے سکتا: اپنی صلاحیت کومحسوس کرناجہاں وہ ہے، موجودہ چیزیں، کمی — اور اس سے نتیجہ نکال کر فیصلہ کرنا کہ اسے کیا کرنا چاہیے۔
