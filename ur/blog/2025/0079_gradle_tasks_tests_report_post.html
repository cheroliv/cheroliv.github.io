Kotlin DSL اور buildSrc کے ساتھ Gradle کاموں کی مینیجمنٹ کو بہتر بنائیں

شائع شدہ: 11 July 2025

Sommaire
  • تنظیمات کو مرکزی بنائیں allprojects اور subprojects کے ساتھ
  • [source,plantuml]
  • [source,kotlin]

Bild task ki automation har software project ke liye muhim hai; Gradle, apne Kotlin DSL ke saath, istisnai murarat provide karta hai. Hamari guftugu ke dauran, humne explore kiya ke kaise build logic ko centralize karke reuse kiya ja sake, khusus test reports ke liye, istemaal karte hueتمام پروژیکٹس, buildSrc, aur مخصوص کاموں میں Kotlin.

تنظیمات کو مرکزی بنائیں allprojects اور subprojects کے ساتھ

بلوک`allprojects` et `subprojects`آپ کے`build.gradle.kts`جڑیں بنیادی ہیں، عام کنفیگریشنز لاگو کرنے کے لیے آپ کے multi‑module پروجیکٹ میں پوری طرح۔

*allprojects { …​ }`کونفیگریشن کو لاگو کریںجذری پروجیکٹ اور اس کے تمام زیرِپروجیکٹوں. مثالي طور پر ایک چیز کو تعریف کرنے کے لئے`group, ایک`version`, یا`repositories`مشترک. *subprojects { …​ }`تنظیمات لاگو کریںصرف زیر منصوبوں تک, جڑ پروژہ کو خارج کردہ۔ ماڈیولز کے لیے مخصوص پلاگن لاگو کرنے کے لیےideal (جیسے`java ou kotlin-jvm) یا مشترکہ انحصارات آپ کی لائبریریوں کے لئے

یہ ایک مثالی نمونہ :

// build.gradle.kts (projet racine)
plugins {
    base // Appliqué au projet racine
}

allprojects {
    group = "com.example"
    version = "1.0.0"

    repositories {
        mavenCentral()
    }

    tasks.withType<org.gradle.api.tasks.testing.Test> {
        useJUnitPlatform() // Configuration commune des tests pour tous les projets
    }
}

subprojects {
    apply(plugin = "java")
    apply(plugin = "org.jetbrains.kotlin.jvm")

    dependencies {
        implementation("org.jetbrains.kotlin:kotlin-stdlib-jdk8")
    }

}

\==buildSrc: بِلڈ لوجیک کا سویس آرمی چاقو

جب آپ کے کاموں کی لوجک مُعقّد بن جاتی ہے یا دوبارہ استعمال کی جانی چاہیے,buildSrcیہ ترجیحی حل ہے۔ یہ ایک خاص Gradle ماڈیول ہے جو بنیادی بنڈ سکرپٹس سے پہلے کامپائل ہوتا ہے، جس کے نتیجے میں اس کی کلاسز آپ کے پوری بنڈ کے کلاس پتھ پر دستیاب ہو جاتی ہیں۔

استعمال کیوں`buildSrc`کاموں کے لیے؟

  • دوبارہ استعمال کرنے کی قابلیت: ایک معین شدہ کام`buildSrc`یہ بِلڈ کے کسی بھی پروجیکٹ پر لاگو کیا جا سکتا ہے۔

  • تنظیم: بِلڈ کوڈ کو مرکزی بناتا ہے، اسے صاف اور رکھنے میں آسان بناتا ہے۔

  • ٹائپ سیفٹی اور اوٹو کمپلیشنکورلین کا کوڈ میں`buildSrc`کمپائل ہوتا ہے، غلطیوں کی جانچ فراہم کرتا ہے اور آپ کے IDE کی خود تکمیل فراہم کرتا ہے، ترقی کے تجربے کو بہتر بناتا ہے۔

\=== فلو ڈائاگرام`buildSrc`(کوڈ PlantUML)

اس ڈائاگرام کو بنانے کے لیے نیچے دیے گئے کوڈ کوکپی کریں اور ایک آئٹ میں پیسٹ کریں جو PlantUML کو سپورٹ کرتا ہے۔

[source,plantuml]

@startuml skinparam خط کشیدہ سچ skinparam monochrome سچ

مستطیل "Gradle Build Process" { component "buildSrc" as BS { فائل "MyCustomTask.kt" کے طور پر T فائل "MyConventionPlugin.kt" به عنوان P } component "Root Project" as RP حصہ "Subproject A" کے طور پر SA حصہ "Subproject B" SB کے طور پر }

T --\> P : "تعریف کیا گیا ہے P --\> RP : "لاگو کیا جاتا ہے P --\> SA : "لگو کیا جاتا ہے P --\> SB : "لاگو کیا جاتا ہے

RP --|\> SA : "شامل ہے RP --|\> SB : "شامل

RP -up-\> BS : "بِلڈ منطق کے لیے مستند ہے SA -up-\> BS : "مُعَلق ہے (بیلڈ لوجک کے لیے) SB -up-\> BS : "depends on (for build logic)

T کے دائیں طرف نوٹ خُصُوصی کام کی کلاسیں (مثال: OpenTestReportTask) آخری نوٹ

P کے دائیں نوٹ کنوانشن پلاگین جسے کام ریکارڈ کرتے ہیں (Empty output)

@enduml

رپورٹ کے ابسٹرکٹ کاموں کی تخلیق

ٹیسٹ رپورٹس کو منیج کرنے کے لیے، ہم نے ایک مڈولرApproach تیار کیا ہے ایک ایبسٹریٹ ٹاسک کلاس استعمال کرتے ہوئے میں`buildSrc`. آپ کی ضرورت کے مطابق، یہ کلاس وراثت لے سکتی ہے`DefaultTask` ou de Exec.

\=== ابسرکٹ ٹاسک`OpenTestReportTask`(وارث ہونے والا`DefaultTask`)

یہ ٹریک اس وقت تجویز کی جاتی ہے جب آپ کو Kotlin کی مخصوص لوژک کی ضرورت ہو جو فائل سسٹم یا دیگر Gradle APIs کے ساتھ تعامل کرے اور اس کے بعد ایک بیرونی کمانڈ چلائی جائے۔

[source,kotlin]

پیکیج com.yourpackage

import org.gradle.api.DefaultTask import org.gradle.api.tasks.Input import org.gradle.api.tasks.TaskAction import java.io.File

abstract class OpenTestReportTask : DefaultTask() {

----
----
init {
    group = "verification"
    description = "Opens a test report in Firefox."
    dependsOn("check") // Assure que les rapports sont générés
}

@get:Input
abstract var reportPath: String

@TaskAction
fun openReport() {
    val separator = File.separator
    val reportFile = project.layout.projectDirectory.asFile.toPath()
        .resolve(reportPath.replace("/", separator))
        .toAbsolutePath()
        .toFile()

    if (!reportFile.exists()) {
        logger.warn("Report file does not exist: $reportFile. Ensure 'check' ran.")
        return
    }

    project.exec {
        commandLine("firefox", "--new-tab", reportFile.absolutePath)
    }
    logger.lifecycle("Opened test report: ${reportFile.absolutePath}")
}
----

## }

\== ٹاسکس کی واضحیت`buildSrc`

آپ جو کام اور کلاسیں تعريف کرتے ہیں میں**buildSrc**ہیں :

***دیکھنے میں مرئی اور استعمال کرنے کے قابل**آپ کے بنیادی build کے تمام پروژکس (جڑ اور زیر‑پروجیکٹس). اس لیے آپ استعمال کر سکتے ہیں`com.yourpackage.ReportUnitTestsTask`میں`allprojects { ... }`. (empty)**غیر قابل اجرا**مستقیم طور پر buildSrc کی ٹاسکوں (مثلاً,`gradle :buildSrc:reportTests`إذا کام مخصوص طور پر ریکارڈ نہ کیا گیا تو یہ کام نہیں چلے گا`buildSrc/build.gradle.kts`).`buildSrc`یہ کمپائلنگ ماڈیول ہے، قابلِ 실행 تطبيق ماڈیول نہیں،ان مقامی بنیادی构建 کے کاموں کے لیے۔

\=== ٹیسٹس کے لیے ایک رپورٹ چلاؤ`buildSrc`خود

Si `buildSrc`اس کے اندر自己 کے ٹیسٹس ہیں اور یہ رپورٹس بناتا ہے؛ آپ ایک رپورٹ کا کام (یا ٹاسک) کو صرف میں ریکارڈ کر سکتے ہیں`buildSrc/build.gradle.kts`:

## [source,kotlin]

پلاگ‑ینز { `kotlin-jvm` }

ریپوزٹرز { mavenCentral() }

tasks.withType\<Test\> { useJUnitPlatform() reports.html.outputLocation.set(layout.buildDirectory.dir("reports/tests")) }

import com.yourpackage.ReportJbakeTestsTask // اپنی ٹاسک کلاس درآمد کریں

tasks.register<ReportJbakeTestsTask>("reportBuildSrcTests") { // المسار معرف مسبقًا في الفئة، سيشير إلى تقارير buildSrc }

آپ پھر نافذ کر سکتے ہو گے :`./gradlew :buildSrc:test`کے بعد`./gradlew :buildSrc:reportBuildSrcTests`.

ان طریقوں کو اپنائے، تو آپ Kotlin DSL میں Gradle بنائیں گے جو نہ صرف طاقتور ہوں گے بلکہ انتہائی ماڈیولر، مرمت پذیر اور سمجھنے میں آسانی سے قابلِ فہم بھی ہوں گے۔
