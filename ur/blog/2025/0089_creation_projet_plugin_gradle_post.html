تعارف

عامیاني ہدف : ابتدائی سے وسط سطح تک گریڈل کے ساتھ ڈویلپر

نئی گرائیڈ پلاگائن پروجیکٹ شروع کرنا ڈراؤناک لگ سکتا ہے۔ خوش قسمتی سے، گرائیڈ ایک طاقتور انٹریکٹیو اسسٹنٹ فراہم کرتا ہے، یہ کام`init`, پریjekt کے ایک مکمل، صاف اور استعمال کے لئے تیار ڈھانچہ پیدا کرنے والا۔ یہ ہدایت آپ کو دکھائے گی کہ اس آلات کا استعمال کرنے سے ایک صحت مند پلگ ان کی بنیاد کیسے بنانی ہے، اس ڈھانچے کی وضاحت کرے گی اور آپ کو ڈکھائے گی کہ کس طرح ابتدائی بنڈ ٹاسک کو شروع کرنا ہے۔

مرحلہ 1 : منصوبہ کے ایسٹنٹ کو شروع کریں

کمانڈ`gradle init`یہ شروع نقطہ ہے۔ یہ ایک کمند لائن اسسٹنٹ چلاتا ہے جو آپ سے سوالوں کی سری پوچھتا ہے تا کہ پروجیکٹ کو کنفیجر کیا جا سکے۔

اپنی ٹرمینل کو خالی ڈائریکٹری میں کھولیں اور چلائیں :

gradle init

آسسٹنٹ آپ کو راہ دے گا۔ یہ وہ انتخاب ہیں جو آپ کو ایک Kotlin میں لکھے گئے Gradle پلاگین کے لئے کرنے ہیں :

  1. پروجیکٹ تیار کرنے کی قسم منتخب کریں:چنیں`Gradle plugin`.

  2. ایمپلیمنٹیشن زبان چنیے:چنو`Kotlin`.

  3. Select build script DSL:چنیجئے`Kotlin`.

  4. پروجیکٹ کا نام:اپنا پروجیکٹ کا نام درج کریں (مثلاً:`site-baker`).

  5. پلاگن آئی ڈی:اپنے پلاگ ان کو ایک منفرد شناخت دیں (ex:`com.cheroliv.site-baker`).

  6. پلاگ ان کلاس:Implementation class ka naam batayein (mesal:`com.cheroliv.SiteBakerPlugin`).

اہم فائلیں اور فولڈرز

  • settings.gradle.kts`یہ فائل جڑ پر موجود ماڈیولز کو بیلڈ میں شامل کرنے کا تعرّف کرتی ہے۔ یہاں، یہ سب‑پروجیکٹ شامل کرتی ہے۔`plugin.

  • plugin/build.gradle.kts: یہ آپ کے پلگ ان کی کنفیگریشن کا مرکز ہے۔ یہ پلگ ان کو لاگو کرتا ہے`java-gradle-plugin`، ڈیپنڈینسیز (dependencies) کا اعلان کرتا ہے اور پلگ ان کے میٹا ڈیٹا کو کنفیگر کرتا ہے۔

gradlePlugin { val siteBaker by plugins.creating { id = "com.cheroliv.site-baker implementationClass = "com.cheroliv.SiteBakerPlugin } } Please provide the text you would like me to translate.

  • src/main/: آپ کے پلگ ان کا سورس کوڈ رکھتا ہے۔

  • src/test/: یونٹ ٹیسٹس پر مشتمل ہے۔ یہ تیزی سے اور علیحدگی میں چلتے ہیں۔

  • src/functionalTest/: فنکشنل ٹیسٹس پر مشتمل ہے۔ یہ ٹیسٹس استعمال کرتے ہیں`GradleRunner`ایک ٹیسٹ پروجیکٹ پر Gradle کا مکمل ورژن چلانے کے لیے، تاکہ آپ کے پلگ ان کے حقیقی استعمال کی نقل کی جا سکے۔

مرحلہ 3: پلگ ان کو بنانا اور ٹیسٹ کرنا

تولید شدہ پروجیکٹ میں شامل ہےGradle Wrapper(gradlew). Gradle کو چلانے کا یہ تجویز کردہ طریقہ ہے، کیونکہ یہ اس بات کو یقینی بناتا ہے کہ تمام ڈویلپرز ایک ہی ورژن استعمال کریں، جس سے ریپروڈیوسیبل بلڈز (reproducible builds) یقینی بناتے ہیں۔

نتیجہ

چند منٹوں میں،`gradle init`نے آپ کو آپ کے پلگ ان کی ڈویلپمنٹ کے لیے ایک مضبوط، جدید اور مکمل پروجیکٹ بیس فراہم کیا ہے۔ آپ کے پاس ایک واضح ڈھانچہ، پہلے سے ترتیب شدہ یونٹ اور فنکشنل ٹیسٹ، اور Gradle Wrapper کی بدولت ایک ریپروڈیوسیبل بلڈ سسٹم موجود ہے۔

اب آپ فائل کھولنے کے لیے تیار ہیں`SiteBakerPlugin.kt`اور اپنے پلگ ان کی بزنس لاجک (business logic) وہاں شامل کرنا شروع کریں!
