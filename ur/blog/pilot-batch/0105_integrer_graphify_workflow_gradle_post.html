المسئلة : ہمیشہ کُوڈ سے پیچھا ڈائاگرامات

کسی بھی منصوبے جو ہزاروں سطر سے زیادہ ہوتا ہے، اس سندرم کا سامنا کرتا ہے :

  1. ہم پروיקט کے ابتداء میں معماریت کا ڈائگرام بناتے ہیں

  2. کود تبدیل ہو رہا ہے، انحصارات بدل رہے ہیں

  3. ڈیگرام بنتا ہے زینت کا جھوٹ

  4. کسی نے اسے آپ ڈیٹ نہیں کیا کیونکہ یہ پریشان کن ہے

  5. نئے داخل ہونے والے اس پر مبنی رہتے ہیں اور غلطی کرتے ہیں

مرحلہ 1: Graphify انسٹال کریں اور Knowledge Graph نکالیں

تنصیب

Graphify ایک Python اَalat ہے جو آپ کے codebase کا تجزیہ کرتا ہے اور ایک منظم علم کا گراف بناتا ہے :

# Méthode recommandée
uv tool install graphifyy && graphify install --platform opencode

# Alternative avec pip
pip install graphifyy && graphify install --platform opencode

استثنیات کو کنفیگر کریں

فائل بنانا`.graphifyignore`پروجیکٹ کی جڑ پر، وہ فائلیں خارج کرنے کے لئے جو کاروباری منطق کا حصہ نہیں ہیں:

# Secrets — JAMAIS dans le graphe
*-context.yml
*.env

# Fichiers générés
build/
.gradle/

# Tests fonctionnels
src/functionalTest/

Knowledge Graph نکالیں

graphify . --no-viz

فلیگ`--no-viz`یہ HTML کی تولید (Gradle پائلائن میں غیر ضروری) کو چھوڑ دیتا ہے۔ نتیجہ ایک فائل ہے`graphify-out/graph.json`شامل :

  • بند: کلاسز، فنکشنز، فائلیں — ان کے ٹائپ اور کمیونٹی کے ساتھ

  • کنارے: نڈوں کے درمیان تعلقات (EXTRACTED کوڈ سے, INFERRED LLM کے ذریعے)

  • سماج: مرتبط نودز کے خودکار گروپنگ

مثال ساخت`graph.json`
{
  "nodes": [
    {"id": "0", "label": "LlmService", "file_type": "code", "community": 0},
    {"id": "1", "label": "ApiKeyPool", "file_type": "code", "community": 0},
    {"id": "2", "label": "PlantumlService", "file_type": "code", "community": 1}
  ],
  "links": [
    {"source": "1", "target": "0", "relation": "uses", "confidence": "EXTRACTED", "weight": 0.9},
    {"source": "0", "target": "2", "relation": "calls", "confidence": "INFERRED", "weight": 0.7}
  ]
}

سورس کوڈ (.kt, .java) tree-sitter کے ذریعے مقامی طور پر تجزیہ کیا جاتا ہے,قابل اعتراض نہ ہونے والی LLM. صرف دستاویزات کے فائلوں (.adoc, .md) ضرور ہیں ایک LLM کال معنوی اخراج کے لیے. لہٰذا`--update`Kotlin کوڈ پر تقریباً فوری ہے.

مرحلہ 2 : Gradle پلاگین Knowledge Graph کو PlantUML میں بدل دیتا ہے

پائلائن کی معماری

پلاگین`com.cheroliv.plantuml`ایک کام شامل کرتا ہے`generateKnowledgeGraphDiagram`جو تبدیل کرتا ہے`graph.json`PlantUML ڈائگراموں میںکاملاً تعییناتی:

@startuml
skinparam backgroundColor #FEFEFE

participant "Gradle" as G
participant "علم گراف ڈائرم بنانے کا کام" as Task
participant "KnowledgeGraphParser" as Parser
participant "علمی گراف رینڈرنر" as Renderer
participant "PlantumlService" as PS

collections "graphify-out/graph.json" as JSON

G -> Task : execute
Task -> JSON : read
Task -> Parser : parse(graph.json)
Parser --> Task : KnowledgeGraph\n(noeuds + arêtes + communautés)
Task -> Renderer : render(graph, filters)
Renderer --> Task : code PlantUML\n(déterministe)
Task -> PS : validateSyntax(plantumlCode)
alt syntaxe valide
    Task -> PS : generateImage → .png
else syntaxe invalide
    Task -> Task : save .puml avec warning
end

@enduml

اندرونی اجزاء

جز رول

KnowledgeGraphParser

پارس کریں`graph.json`— تین فارمٹس سپورٹ کرتا ہے: نیٹیف گرافی (nodes+links), legacy (communities), flat. عددī IDs کو لیبلز میں حل کرتا ہے۔

KnowledgeGraphRenderer

ایک کو ڈیٹرمنسٹ طور پر تبدیل کرتا ہے`KnowledgeGraph`پلنٹ یو ایم کے کوڈ میں. قسم کے حسب گروپ، پیکجوں میں کوميونیٹیز، خودکار لیجند۔

GenerateKnowledgeGraphDiagramTask

Gradle کام جو منظم کرتا ہے: parse → render → validate → PNG. Gradle properties کے ذریعے قابلِ تنظیم.

kgmodels.kt

ڈیٹا ماڈلز :`KnowledgeGraph`, KnowledgeGraphNode, KnowledgeGraphEdge, KnowledgeGraphCommunity, EdgeType.

PlantumlService

نحوی تصدیق + PNG رینڈر (پلاگїн کے تمام کاموں میں دوبارہ استعمال ہوتا ہے).

rendering کے قواعد

renderer بصری deterministic conventions لاگو کرتا ہے:

کنار کی قسم نوٹیشن PlantUML معنی

..>(نقطہ دار خط)

مرحلہ 3 : روزانہ استعمال

مکمل ڈائاگرام

# Générer le diagramme du Knowledge Graph complet
./gradlew generateKnowledgeGraphDiagram

خروج :`diagrams/knowledge-graph/knowledge-graph-full.puml`+.png

کميونٹی حسب فیلٹر کریں

# Une seule communauté
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.community=community_0

# Limiter le nombre de noeuds (lisibilité)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.community=community_0 \
  -Pplantuml.kg.maxNodes=15

کینارے کے نوع کے مطابق فیلٹر کریں

# Uniquement les relations certaines (EXTRACTED)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.edgeTypes=EXTRACTED

# Relations certaines + inférées
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.edgeTypes=EXTRACTED,INFERRED

فلٹر حسب نوع عقده اور اعتماد

# Uniquement les classes de code
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.nodeTypes=code

# Seuil de confiance minimum (pour les INFERRED)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.minConfidence=0.7

شخصی آؤٹ پٹ ڈائریکٹری

./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.outputDir=docs/architecture

خواص کی مکمل حوالہ

مملکت پیش‌فرض وصف

plantuml.kg.community

(سب)

نام کے مطابق سماجی گروہوں کو فیلٹر کریں (حصے کی مطابقت)

plantuml.kg.edgeTypes

(تمام)

کمی سے جداسے کردہ کنارے کے نوع :`EXTRACTED`, INFERRED, AMBIGUOUS

plantuml.kg.minConfidence

0.0

Edges کے لیے حد أدنى اعتماد

plantuml.kg.maxNodes

(لامحدود)

نمائش کے لیے زیادہ سے زیادہ نوڈز

plantuml.kg.nodeTypes

(تمام)

گہنچوں کے انواع کما سے الگ (مثلاً`class`, code)

plantuml.kg.outputDir

diagrams/knowledge-graph

فائلوں کے لیے آؤٹ پٹ ڈائریکٹری`.puml` et .png

Gradle workflow میں مکمل پائپ لائن

ورک فلو کی قسم

@startuml
skinparam backgroundColor #FEFEFE
skinparam ActivityBackgroundColor #E8F4FD
skinparam ActivityDiamondBackgroundColor #FFF3CD
skinparam ActivityBorderColor #2C3E50

start

partition "استخراج" {
    :graphify . --no-viz;
    note right: Analyse le code source\ntree-sitter (local, pas de LLM)

    :graphify-out/graph.json;
    note right: Noeuds + arêtes\n+ communautés
}

partition "پیداوار" {
    :./gradlew generateKnowledgeGraphDiagram;
    note right: Pipeline déterministe\nparse → render → validate → PNG

    if (Filtres actifs ?) then (Oui)
        :Appliquer filtres\n(community, edgeTypes,\nmaxNodes, nodeTypes);
    else (Non)
        :Diagramme complet;
    endif

    :diagrams/knowledge-graph/\nknowledge-graph-full.puml\nknowledge-graph-full.png;
}

partition "انضمام" {
    :git add diagrams/knowledge-graph/;
    :git commit;
    note right: Diagrammes versionnés\ntoujours à jour avec le code
}

stop

@enduml

پاپ لائن ترقی کے اہم مراحل میں ذاتی طور پر شامل ہوتا ہے :

@startuml

انکریمنٹل اپ ڈیٹ

جب کڈ بدل جاتا ہے، تو ہم gesamte graf سے sıfr سے دوبارہ بناتے نہیں ہیں :

# Mise à jour incrémentale (fichiers modifiés uniquement)
graphify . --update

# Puis régénérer les diagrammes
./gradlew generateKnowledgeGraphDiagram

--update`ye صرف تبدیل شدہ فائلوں کو دوبارہ نکالتا ہے (SHA256 سے متعین میں`graphify-out/cache/) Kotlin کوڈ پر، یہ تقریباً فوری ہے کیونکہ tree-sitter مقامی طور پر کام کرتا ہے بلا LLM کال.

ڈاگفوڈنگ : پلاگائن خود خود کو دستاویز بناتا ہے

پلاگ ان PlantUML پروپمپٹس کو ڈائیاگراموں میں تبدیل کرنے کے لیے موجود ہے۔ یہ بھی اپنی propre کوڈ بیس کو دستاویزاتی ڈائیاگراموں میں تبدیل کر سکتا ہے۔ یہ dogfooding ہے: پلاگ ان اپنی خدمت خود استعمال کرتا ہے۔

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

package "پائپ لائن عادی
(صارف → ڈائگرام)" as normal {
    [Fichier .prompt] as prompt
    [LlmService\n+ ApiKeyPool] as llm1
    [ProcessPlantumlPromptsTask] as task1
    [Diagramme PNG] as out1

    prompt --> task1
    task1 --> llm1
    llm1 --> out1
}

package "Pipeline Knowledge Graph
(محدد، LLM نہیں)" as kg {
    [graphify-out/graph.json] as kgjson
    [KnowledgeGraphParser] as parser
    [KnowledgeGraphRenderer] as renderer
    [PlantumlService] as ps
    [Diagramme PNG\n(documentation du plugin)] as out2

    kgjson --> parser
    parser --> renderer
    renderer --> ps
    ps --> out2
}

package "Pipeline Dogfooding
(LLM → پلاگ ان کی دستاویزات)" as dogfood {
    [GraphifyPromptAdapter] as gpa
    [Fichiers .prompt\nauto-générés] as auto_prompt
    [LlmService\n+ ApiKeyPool] as llm2
    [ProcessPlantumlPromptsTask] as task2
    [Diagramme PNG\n(documentation LLM)] as out3

    kgjson --> gpa
    gpa --> auto_prompt
    auto_prompt --> task2
    task2 --> llm2
    llm2 --> out3
}

note "ایک جیسا LlmService، ایک جیسا ApiKeyPool,
ایک جیسا PlantumlService
— صفر ڈپلیکیشن" as N

@enduml

مرتبطہ گریڈل ٹاسک:

کام LLM ? تفصیل

generateKnowledgeGraphDiagram

نہیں

generateDiagramDocs

ہاں

# Documentation déterministe (rapide, pas de LLM)
./gradlew generateKnowledgeGraphDiagram

# Documentation LLM (plus riche, consomme des tokens)

کیوں یہ محدد ہے (اور کیوں یہ اہم ہے)

@startuml

    [PlantUML code] as puml2

    prompt --> llmSvc
    llmSvc --> model : API call
    model --> puml2 : réponse non-déterministe
}

note bottom of det
  Même entrée → même sortie
  Pas de latence réseau
  Pas de coût en tokens
  Reproductible en CI
end note

note bottom of llm
  Même entrée → sortie variable
  Latence réseau (1-5s)
  Coût en tokens
  Nécessite une clave API
end note

@enduml

فائدہ اثر

مطابق CI

Le .puml`پیدا شدہ متن ہے. ہم یہ کر سکتے ہیں`diff, PR میں ریور، اس کو Git میں ورژن کرنا

خود کے پائپ لائن کے ڈائاگرام

لوپ کو بند کرنے کے لیے، یہ پائپ لائن کا ڈائیگرام ہے جس طرح یہ پلگ ان سے پیدا ہوگا:

@startuml
skinparam backgroundColor #FEFEFE

participant "ڈویلپر" as Dev
participant "گریڈل" as G
participant "ناليد گراف ڈائگرام بنانے کا کام" as Task
participant "KnowledgeGraphParser" as Parser
participant "KnowledgeGraphRenderer" as Renderer
participant "PlantumlService" as PS
collections "graphify-out/graph.json" as JSON
collections "ڈائاگرام/نолиج-گراف/" as Out

Dev -> G : ./gradlew generateKnowledgeGraphDiagram
G -> Task : execute
Task -> JSON : read
Task -> Parser : parse(graph.json)
Parser --> Task : KnowledgeGraph

alt filtres actifs
    Task -> Task : appliquer filtres\n(community, edgeTypes, maxNodes…)
end

Task -> Renderer : render(graph, filters)
Renderer --> Task : code PlantUML

Task -> PS : validateSyntax()
alt valide
    Task -> PS : generateImage()
    PS --> Out : .puml + .png
else invalide
    Task -> Out : .puml (avec warning)
end

@enduml

ہماری پروجيٽ میں، یہ پائپلاین EAGER/LAZY کنٹیکسٹ منیجمنٹ کی ایک استراتژی کے طور پر اے اے آجینٹ کے لیے شامل ہے۔ نالوج گراف (Knowledge Graph) ہینڈ‑میکڈ آرکیٹچر ڈاکمیونٹی کی جگہ ایک منظم، قابل کوئری اور خود‑آپ ڈیٹ ہونے والا گراف لے لیتی ہے۔

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

package "EAGER
(ہمیشہ چارج)" as eager {
    [PROMPT_REPRISE.adoc\n(contexte session)] as pr
