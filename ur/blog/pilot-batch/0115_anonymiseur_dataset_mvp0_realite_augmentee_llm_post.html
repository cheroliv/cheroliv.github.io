ہمارا پہلا ملازمت یافتہ: ڈیٹا سیٹ انونیمائزر — MVP0 آزمائش دور میں

پڑھنے کا وقت : 12 minutes

میں LLM کو نوکری نہیں دیتا۔ میں ایک anonymiser کو نوکری دیتا۔ RAG pgvector کرنے سے پہلے، CDA/FPA کے ماہرین کو fine-tune کرنے سے پہلے، клиئنت کے workspaces کو provision کرنے سے پہلے — کسی کو ڈیٹا کے toilet صاف کرنے کی ضرورت ہے۔ یہ employé، anonymisation کا ماہر ہے (MVP0, EPIC 2، codebase-gradle)۔ اور یہ وہ شخص ہے جو پروڈکٹ کو marketable بناتا ہے۔

ٹوک

[]

وہ مسئلے جو سب کو بھاگ کر جانے پر مجبور کر دیتا ہے

ہر AI سٹارٹ‑اپ جو تربیت کے ڈیٹس کو منیپولیٹ کرتی ہے، ایک ہی دیوار سے ٹکراتی ہے:

----
----
Données brutes client (SPG, cours, évaluations)
  ├→ Noms de stagiaires en clair dans les PDF
  ├→ Emails dans les métadonnées JSON
  ├→ IP de connexion dans les logs pgvector
  ├→ Identifiants dans les nœuds Graphify
  └→ Références OF pilote dans les schémas SQL
----

نتیجہ : یا تو آپ گندے ڈیٹا پر RAG کرتے ہیں (PII کی ہلوسینیشنز، GDPR کی عدم اطاعت، قانونی خطرہ)، یا تو آپ کچھ نہیں کرتے ہیں (کوئی مصنوعات نہیں). تیسرا راستہ — دستی صافی — scalable نہیں ہے۔

میرا جواب : masalah سے نہ بچنا۔ L'**خودکار بنانا**.

== MVP0 : الاونومیسر، پروبیشن مدت میں پہلا ملازمت پر لینے والا

MVP0 ایک فیچر نہیں ہے۔ یہ ایک**اراحت کا ماہر**— ایک ملازم جو گندہ، برا اور نفست کام کرتا ہے، اور جس کی بات کسی بھی پیچ ڈِکس میں کرنا نہیں چاہتا۔

وہ کیا کرتا ہے :

[source]
----
ENTRÉE : Données brutes multi-sources
  ├→ AsciiDoc (SPG_A2SP.adoc) → noms, dates, OF pilote
  ├→ JSON (catalogue formations) → emails, téléphones
  ├→ YAML (config workspace) → tokens OAuth2
  ├→ SQL (schémas DDL) → IP, adresses
  ├→ pgvector (métadonnées embeddings) → identifiants
  ├→ ONNX (outputs classification) → noms propres
  └→ Graphify (graph.json) → nœuds avec PII

SORTIE : Datasets propres, format standardisé
  ├→ [ANONYMIZED] remplace les PII détectées
  ├→ Classification RGPD (niveau 0→4)
  ├→ Rapport d'audit (quoi a été nettoyé)
  └→ Dataset prêt pour RAG ET fine-tuning
----

یہ سب سے واضح پٹرنز پہلے (ایمیل`.*@.*`, ٹوکن`sk-*`, `ghp_*`، IPs)، پھر وہ سیکھتا ہے۔ آزمائش کی مدت یہ ہے: ہم تصدیق کرتے ہیں کہ وہ غلط منفی نہیں چھوڑتا قبل اس کو permanent بنانے سے۔

== یہ MVP جو کھول دیتا ہے (اور یہ صرف کنپلائنسی نہیں ہے)

MVP0 کے طور پر گہنام کرنے کا عمل، RGPD کا ٹول ہائیوے سے پہلے نہیں، بلکہ خود ہائیوے ہے۔ یہ وہ ہے جو یہ کھولتی ہے:

=== حاضر: پرامپٹ میں اوگمنٹڈ ریلیٹی

[source]
----
DONNÉES BRUTES CLIENT
    ↓
Anonymiseur MVP0 → datasets propres
    ↓
RAG pgvector (MVP1) → top-K documents similaires (filtrés, anonymisés)
    ↓
LLM (deepseek-v4-pro) → réponse augmentée, zéro PII
----

RAG دھند биет clean ڈیٹا میں — وہ clean space میں دھند биет ہے**بنا پر صاف**. یہ جوابات کی معیار کے لیے سب چیز بدل دیتا ہے: LLM وہ PII جو وہ پہچانتا ہے لیکن جو اسے ذکر نہیں کرنا چاہیے، اس سے بچنے میں اپنا وقت ضائع نہیں کرتا۔

=== مستقبل: صحت مند ڈیٹا پر فائن-ٹوننگ

[source]
----
MVP0 → datasets propres accumulés (session après session)
    ↓
Fine-tuning expert métier (CDA, FPA) sur données zéro PII
    ↓
Modèle fine-tuné exposé via Ollama (sans fuite de données)
----

خام ڈیٹا پر فائن-ٹوننگ قانونی تباہی کی ممکن شکل ہے. صاف ڈیٹ پر، یہ ایک**قابل بازآفرینی طریقہ**. ہرکلائن اپنے صاف کردہ ڈیٹا سیٹس کو جمع کرتا ہے، ہرکلائن اپنے ڈیٹ پر اپنی کاروباری ماہرین (experts) کو فائن-ٹون کر سکتا ہے — کبھی بھی کوئی ذاتی ڈیٹا نہیں ظاہر کیا جاتا۔

== کیوں یہ قابلِ فروش ہے۔

یہ « GDPR کے مطابقت کا اوزار » نہیں ہے۔ یہ ایک**قابلِ تکرار طریقہ جو عمومی مسئلے کو اسٹ میں بدل دیتا ہے**:

1. *ہر تربیت کی کمپنی میں گندا ڈیٹا ہوتا ہے — یہی مسئلہ ہے*
2. *کوچ بھی خودکار 멀티‑сорس pipeline نہیں رکھتا* — یہ بازار ہے
3. لूप: گمنامی → RAG → فائن-ٹوننگ مملوک ہے — یہ رکاوٹ ہے

ایڈسٹر SaaS (MVP3) « ایک ویорк سپیس Gradle » نہیں بیچے گا۔ یہ بند لوپ بیچے گا۔ اور MVP0 ورودی دروازہ ہے۔

== SQL فارمیٹ تیسرا طریقہ سیاق و سباق

سٹرکچر شدہ ڈیٹا کا امپورٹ صرف ایک تبدیلیی فارمٹ نہیں۔ SQL اسکیم (DDL) یہ لے کر جاتی ہے**دومین کی انتیت‑رابطہ ماڈل** :

[source]
----
CREATE TABLE formation (
  id UUID PRIMARY KEY,
  titre VARCHAR NOT NULL,
  referentiel RNCP REFERENCES rncp(id),
  organisme OF REFERENCES of_pilote(id)  -- ← va être anonymisé
);
----

یہ DDL، بenamez (لائن 4) کے بعد LLM کے لیے سیاق و سباق کا middel بن جاتا ہے۔ متن نہیں —**کاروباری مودل**. RAG مواد دیتا ہے (وِیکٹر مشابہت) Graphify روابط دیتا ہے (سچائی کی ساخت) اور SQL سکیما دیتا ہے یہ**ضمنی ڈومین ڈریون ڈیزائن**: bounded contexts, جمع, value objects. LLM کاروبار کو سمجھتا ہے کیونکہ یہ اس کے سکیما کو پڑھتا ہے۔

== رُوڈمیپ : MVP0 سے SaaS تک

[source]
----
MVP0 — Anonymiseur (ce que cet article décrit)
  Sortie : datasets propres, reproductible

MVP1 — RAG pgvector (dépend de MVP0)
  Realité augmentée en prompt sur données nettoyées

MVP2 — Graphify + ONNX + SQL DDD (dépend de MVP1)
  Vecteur composite de contexte (règles + similarité + relations exactes)

MVP3 — SaaS Edster (dépend de MVP0-2)
  Provisionnement workspace client complet
----

ہر MVP اس سے پہلے والے پر مشتمل ہے۔ کوئی بھی MVP0 کے بغیر ڈلیور نہیں کیا جا سکتا۔ یہ وجہ ہے کہ أنونیسر backlog میں « P0 » نہیں ہے — یہ**MVP0**. یہ پہلا تجارتی deliverable ہے، اور باقی ساری چیزیں اس کی کامیابی پر منحصر ہیں۔

== نتیجہ : بے نظری کا کام جو ہر چیز کو ممکن بناتا ہے

ایک کلاسیک ستارٹاپ میں، ڈیٹا صاف کرنے کا کام باہری کردیا گیا، دستی ہے، یا نظر انداز کیا جاتا ہے۔ اس ڈیزائن میں، یہ**محصول کا دل**. انومائزر پہلا ملازم ہے کیونکہ بغير اس کے کچھ بھی کام نہیں کرتا :

* MVP0 کے بغیر → قانونی RAG نہیں (MVP1)
* MVP0 کے بغیر → ڈیٹا لیک کے بغیر فیntonنگ نہیں (EPIC 5)
* MVP0 کے بغیر → credible SaaS نہیں (MVP3)
* MVP0 کے بغیر → پرامپٹ میں Augmented reality نہیں
* MVP0 کے بغیر → کنٹیکسٹ کی تیسری راہ نہیں (SQL DDD)

گندا کام کرتا ہے۔ اسے کبھی بھی پچ میں نام نہیں لیا جائے گا۔ لیکن وہی ہے جو کارخانہ چلاتا ہے۔

اسی لیے ہم اسے پہلے ملازمت پر رکھتے ہیں۔
