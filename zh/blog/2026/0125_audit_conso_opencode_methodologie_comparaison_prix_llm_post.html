OpenCode 不是模型提供商。这是一个开源的命令行界面(github.com/anomalyco/opencode) 它编排 AI 代理。它不销售订阅，也不提供推理。它相当于`git`用于版本控制：一个工具，而不是服务。 Ollama Cloud 是推理提供商。我的本地 Ollama 安装就像 client —— 它通过唯一的 SSH 密钥（Device Key）向 Ollama 服务器进行身份验证，并将带标签的模型的执行委托给它们。:cloud. 专业版订阅（20欧元/月）解锁更高的配额，并允许通过 Docker 在同一台机器上累积多个账户。

介绍：为什么要进行审计？

两个月前，我在本地 Ollama 安装上免费使用模型。然后我订阅了第一个 Ollama Cloud Pro 计划，每月 20 欧元，这使我能够使用云端模型（那些带有标签的`:cloud`)通过提供者`ollama-cloud`. 第二个订阅一个月后跟进，在一个独立的 Docker 实例上，使用其自身的帐户和 SSH 密钥 — — 如 我的关于订阅叠加的文章中所述的叠加方法。

困扰我的问题是：这每月20欧元是否合理？ 不是凭感觉。有数据说话。

为了回答，我需要精确的数据。不是估计。不是平均。我的*实际*消耗，token 逐 token，模型 逐模型，会话 逐会话。

和 OpenCode — CLI — 将所有内容存储在 SQLite 数据库中。

桌子`session`非常适合全局审计：每个会话都有其累计的令牌计数、所使用的模型以及其成本。该字段`model`是原始 JSON :

{
  "id": "deepseek-v4-pro:cloud",
  "providerID": "ollama-cloud",
  "variant": "default"
}

字段`cost`在 OpenCode 数据库中仅反映了 外部 API 费用，即通过 API 密钥按使用量付费（Google Gemini、OpenAI 等）。通过 Ollama 的调用 — 无论是在本地还是通过 Ollama Cloud Pro — 都被标记`cost=0`因为费用是固定的（订阅），而不是按 token 计费。这些调用的真实成本就是每月订阅费。

提取代码

不需要安装任何东西。Node.js 22+ 集成了一个实验性的 SQLite 模块 (node:sqlite) 运行完美。这是给我一切的脚本：

const { DatabaseSync } = require('node:sqlite');
const db = new DatabaseSync(
  `${process.env.HOME}/.local/share/opencode/opencode.db`,
  { readonly: true }
);

// 1. Statistiques globales
const global = db.prepare(`
  SELECT
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(tokens_reasoning) as total_reasoning,
    SUM(tokens_cache_read) as total_cache_read,
    SUM(cost) as total_cost
  FROM session
`).get();

// 2. Ventilation par modèle et fournisseur
const byModel = db.prepare(`
  SELECT
    json_extract(model, '$.id') as model_id,
    json_extract(model, '$.providerID') as provider,
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(cost) as total_cost
  FROM session
  WHERE model IS NOT NULL
  GROUP BY model_id, provider
  ORDER BY SUM(tokens_input) DESC
`).all();

// 3. Par mois
const monthly = db.prepare(`
  SELECT
    strftime('%Y-%m', datetime(time_created/1000, 'unixepoch')) as month,
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(cost) as total_cost
  FROM session
  WHERE time_created IS NOT NULL
  GROUP BY month
  ORDER BY month
`).all();

// 4. Messages par modèle (détection des changements intra-session)
const msgByModel = db.prepare(`
  SELECT
    json_extract(m.data, '$.model.providerID') as provider,
    json_extract(m.data, '$.model.modelID') as model_id,
    COUNT(*) as messages
  FROM message m
  WHERE json_extract(m.data, '$.model') IS NOT NULL
  GROUP BY provider, model_id
  ORDER BY COUNT(*) DESC
`).all();

console.log({ global, byModel, monthly, msgByModel });
db.close();

旗帜`--experimental-sqlite`在 Node.js 22.x 上是必需的。在 Node.js 24+ 上，模块是稳定的，不再需要标志。

隐藏成本：提示工程与迭代

Token成本只是方程式的一部分。真正的成本是开发者的时间。

使用 OpenCode + Ollama Cloud Pro + 我的代理治理 (EAGER/LAZY/Hot/Warm/Cold，在 关于治理的文章 中描述)，我得到：

  • 0 提示工程 重复的: 上下文会被自动注入

  • (No content to translate): 代码一次编译通过

  • 连续8次会话未出现deepseek幻觉(记录在 Kimi/GLM/DeepSeek 比较)

与 克劳德 或 GPT 无 fine-tune 而不 治理 :

  • 每项任务平均 2-3 次迭代

  • 系统化的提示工程

  • 当上下文超过30K tokens时，Kotlin/Gradle API出现幻觉

每月有效成本 — tokens × 迭代次数 × 修正时间 — 为我方案的 27 倍至 54 倍，正如我在 关于效率比率的文章 中所证明的那样。

累计 Ollama Cloud Pro 订阅：Docker 方法

如果一个订阅不够用，我们就会把它们叠加起来。原则是将每个订阅隔离在各自的 Ollama 安装中，并使用各自的 SSH 认证密钥。Docker 让这变得轻而易举。

完整方法详细描述在 关于 Docker 累积的文章，原则如下：

模式很简单：

  1. 创建一个卷`~/ollama-b-data`

  2. 启动一个 Docker 容器`ollama/ollama:0.20.2`映射到`11435:11434`

  3. 获取容器的 SSH 密钥 → 将其保存到 ollama.com

  4. 做`ollama signin`带有一个第二封电子邮件

  5. 配置 OpenCode 使用两个提供者 (`ollama`在 :11434，`ollama-b`在 :11435)
