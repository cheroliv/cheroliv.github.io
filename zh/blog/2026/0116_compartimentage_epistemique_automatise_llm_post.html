自动化认识论分区 — 大语言模型如何保护我的心灵花园

发布于 02 May 2026

Table des matières
  • 问题：自由思考而不随意发布
  • 刺激模式 — 出生、固定、稀释、死亡
  • 对 LLM 的委托 : 为什么是 LLM 进行过滤
阅读时间 : 10 minutes

我的 LLM 不仅仅执行我的 Gradle 任务。它是我私人思维与公共表达之间边界的守护者。每一个想法在被路由之前都会被分类 — — Vision、Opinion、Strategy — — 。下面是这种自动的认识论分区如何在不使我沉默的情况下保护我的精神花园。

习惯性动作

[]

问题：自由思考而不随意发布

当一个单独的开发者使用LLM记录其思考过程时，他会遇到一个悖论：

CAPTURE TOUT (Cercle 0, jardin secret)
  ├→ Brain dump libre, pas de censure
  ├→ Idées brutes, spéculations, intuitions non vérifiées
  ├→ Allers-retours LLM : challenger, itérer, raffiner
  └→ Le LLM voit TOUT — le bon, le flou, l'embryonnaire

PUBLICATION SÉLECTIVE (Cercle 4, blog public)
  ├→ Uniquement les décisions actées
  ├→ Uniquement les patterns testés (>100 tests PASS)
  ├→ Uniquement ce qui a de la valeur pour le lecteur
  └→ JAMAIS une spéculation présentée comme une vérité

在这两个极端之间，有一个过滤器. 问题是：谁在做？疲惫的人在会议结束时？一个天真的正则表达式脚本？还是LLM自己，已经读完了所有内容？

我的回答：LLM。

刺激模式 — 出生、固定、稀释、死亡

STIMULUS 是一个文件`.adoc`临时位于工作区根目录（圆环 0）。其名称遵循富有感染力的命名惯例 —PICTURE_ME_ROLLIN.adoc, HOLD_MY_BEER.adoc, ONCE_UPON_A_TIME.adoc— 捕捉当下的探索意图。

他的生命周期是残酷的：

CRÉATION (Cercle 0)
  ├→ Fichier vide, brain dump libre
  ├→ Allers-retours LLM ← → développeur
  └→ Aucune pression de structure ou de publication

MATURATION
  ├→ Le contenu se densifie
  ├→ Des sections émergent naturellement
  └→ Le fichier devient une référence informelle de session

CLASSIFICATION ÉPISTÉMIQUE ← FAIT PAR LE LLM
  ├→ VISION    → publiable, diluer dans les docs publics + blog
  ├→ OPINION   → confiner au Cercle 0, pas de dilution externe
  └→ STRATÉGIE → dilution restreinte (docs racine, PAS de blog)

DILUTION (Cascade vers Cercles légitimes)
  ├→ VISION → WORKSPACE_AS_PRODUCT.adoc + WHAT_THE_GAMES.adoc + blog
  ├→ STRATÉGIE → WORKSPACE_AS_PRODUCT.adoc (section business)
  └→ OPINION → reste dans le stimulus, ne bouge pas

ARCHIVAGE + SUPPRESSION
  ├→ Snapshot dans configuration/vision-archive/ (trace historique)
  └→ rm du stimulus — il a fini son travail

一个在未被稀释的情况下存活超过两次会议的刺激是一种反模式。要么信息太重要而不能让它在临时文件中腐烂（→稀释），要么它太模糊而不值得存在（→删除）。

对 LLM 的委托 : 为什么是 LLM 进行过滤

我不在 Kotlin 中硬编码 Vision/Opinion 分类。我将其注入到提示系统通过 LLM`AGENT_GOVERNANCE.adoc`:

----
----
Pour chaque dilution de stimulus ou session, tu es responsable de classifier
le contenu :
- VISION : décision architecturale actée, pattern testé en production (>100 tests PASS),
  décision documentée dans BACKLOG ou ROADMAP
- OPINION : spéculation, hypothèse non validée par des tests, intuition
  sans ancrage expérimental
- STRATEGIE : positionnement business, pricing, marché cible

Règles :
- Si OPINION, le contenu reste confiné dans son cercle d'origine
- Si VISION, tu procèdes à la dilution dans les documents racine
- Si STRATEGIE, dilution restreinte (docs racine, pas de blog public)
- Cette classification détermine aussi si un article de blog est publiable
  sur cheroliv.com
----

LLM 读取此指令**之前**处理会话。 它位于其直接上下文中，而不是在一个单独的文件中。 这是*确定性提示工程*：行为源于注入的文本，而不是外部分类器。

=== 为什么有效 — 以及为什么这反直觉

标准反应：“你把分类交给AI了？如果它出错了呢？”

回答：人类在凌晨两点并不会表现得更好。区别在于，LLM 会读取一切。它拥有会话和目标文档的完整上下文。它知道`VPS ECO-16 12€ HT`是一项基础设施决策（VISION）而`« le TTS ElevenLabs sonne plus naturel que Coqui »`是一个未经过基准验证的观点。

人在会话结束时，会斜读并尽力而为。LLM 会全面阅读并应用系统化的检查表。结果是**更可靠**, 不少。

对于20%的模糊情况——即即使LLM也犹豫不决的灰色地带——答案不是“添加代码”。答案是**LangGraph4j**(EPIC 13) : 一个状态图，对于歧义情况，激活一个 Human-in-the-Loop 节点并上报给人类决策。但对于 80% 的明确情况，LLM 足够。

== 完整的管道：从脑力倾倒到博客文章

这是完整的流程 — 从原始想法到发表的文章 — 以LLM作为唯一的过滤器：

[source]
----
CERCLE 0 (jardin secret)
  PICTURE_ME_ROLLIN.adoc   ← brain dump, allers-retours LLM
       ↓
  [LLM classifie] → VISION / OPINION / STRATÉGIE
       ↓
  VISION → dilution dans WORKSPACE_AS_PRODUCT.adoc
         → dilution dans WHAT_THE_GAMES_BEEN_MISSING.adoc
         → dilution dans WORKSPACE_VISION.adoc (session context)
         → RÉDACTION ARTICLE BLOG ← le LLM écrit, pas le dev
       ↓
CERCLE 4 (blog public)
  0116_compartimentage_epistemique.adoc  ← publié sur cheroliv.com
       ↓
  ./gradlew deploy (bakery-gradle → JBake → JGit → GitHub Pages)
       ↓
  https://cheroliv.com/blog/2026/0116/  ← live
----

开发者不编写文章。他挑战、复核、验证。LLM 编写。循环是：

1. Brain dump 自由 → 没有审查
2. LLM的认识论分类 → 无泄漏
3. 由LLM撰写 → 不拖延
4. 人工复核 → 没有错误

历史瓶颈——“我没有时间写作”——已被消除。LLM完成了主要工作。人类只能做人类能做的事情：判断。

== 三篇Racine文档 — 信息如何找到其位置

每个目标文档在稀释级联中具有明确的作用：

[cols="1,3,2"]
|===
|文档 |他得到的 |内容类型 |`WORKSPACE_AS_PRODUCT.adoc` |架构决策, 技术栈, 路线图, 商业模型 |愿景 + 战略 |`WHAT_THE_GAMES_BEEN_MISSING.adoc` |模式，教训，反模式，本体论，形式规则 |视觉（已测试的模式） |`WORKSPACE_VISION.adoc` |会话上下文, 决策历史, 基础设施点 |愿景 + 战略（上下文） |`AGENT_GOVERNANCE.adoc` |治理规则, 项目组合, 程序 |愿景 (治理) |**cheroliv.com 博客** |公开文章，对外部读者的价值 |仅限视觉
|===

同一刺激可供给 4 份文档 + 博客 —  — 每个目的地获得其所需部分，既无冗余也无矛盾。

这是发生的为了`PICTURE_ME_ROLLIN.adoc`(2026年5月3日) :

| 信息 | 分类 | 目的地 | | 清单 的 13+ 项目 foundry/ | VISION | WORKSPACE_AS_PRODUCT | | VPS-2 OVH, edster.cloud, 8.49欧元/月 | VISION | WORKSPACE_AS_PRODUCT + WORKSPACE_VISION |  非洲市场已准备好迎接移动货币  | « DeepSeek > Kimi > GLM 长上下文 » | OPINION → VISION | 先被限制，随后在基准测试后晋升（文章 0112） | | 合成员工作为最终产品 | 战略 | WORKSPACE_AS_PRODUCT (没有博客) |

== Baby-Step 模式 + TestContainer + 活文档 — 能够自我测试的代码

STIMULUS/Dilution 模式管理思维。它在代码中的等价物是 Baby-Step/TestContainer/Doc Vivante 模式，经 plantuml-gradle 验证（380/380 通过测试，137 次无 Docker 泄漏会话） :

[cols="1,3"]
|===
|原则 |规则 |**婴儿步** |每个US的分数不得超过3分。如果某个US令人担忧，则进行拆分。1分且能通过的US > 8分却拖延的US |**TestContainer 首先** |业务代码之前，先有容器。基础设施测试通过 → 保证稳定的环境。 |**已提交的数据集** |最小但具有代表性的子集在`src/test/resources/`, 不含 PII。可克隆，可启动。 |**活文档** |每个Cucumber测试 = 一句自然语言。源代码就是可执行的规范。零需维护的Markdown文档。 |**自动清理** |零资源泄漏。孤儿容器,`/tmp/gradle-test-*`: 一切都已清洁。
|===

此模式是 plantuml-gradle 在 138 次会话中从未出现 Docker 回归的原因。它确保与外部基础设施（PostgreSQL、Redis、Kafka）交互的代码始终在与生产环境完全相同的环境中进行测试——版本化、可重现、可通过一条命令启动。

== 结论：无惧发表的思考自由

自动化的认识论隔离不是一种审查工具。它是一个**解放者**. 它允许自由思考，无过滤地进行推测，将脑中浮现的一切都倾倒出来——而永不必担心一个尚未成形的想法会出现在博客上。

LLM 是这条边界的守卫者。它读取一切。它进行分类。它稀释那些值得存续的内容。它将应保持私密的内容隔离。它撰写可发布的内容。

而开发者则拥有最终决定权：审阅、挑战、验证。判断。

这正是 Solo 开发者所缺少的分工：一个合成员工，负责处理脑力文书工作，使人类能够专注于他们最擅长的事情——设计、架构、决策。
