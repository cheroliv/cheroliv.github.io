Kompartemen Epistemik Otomatis — Bagaimana LLM Melindungi Taman Pikiran Saya

Diterbitkan 02 May 2026

Table des matières

waktu membaca : 10 minutes

LLM saya tidak hanya mengeksekusi tugas Gradle saya. Ia adalah penjaga perbatasan antara pikiran pribadi saya dan ekspresi publik saya. Setiap ide diklasifikasikan — Visi, Opini, Strategi — sebelum dirutakan. Ini adalah cara pembagian otomatis epistemik ini melindungi kebun mental saya tanpa membuat saya terdiam.

Masalah: Berpikir Bebas tanpa Mempublikasikan Apapun

Ketika seorang pengembang solo mendokumentasikan proses pemikirannya dengan LLM, ia bertemu dengan paradoks:

CAPTURE TOUT (Cercle 0, jardin secret)
  ├→ Brain dump libre, pas de censure
  ├→ Idées brutes, spéculations, intuitions non vérifiées
  ├→ Allers-retours LLM : challenger, itérer, raffiner
  └→ Le LLM voit TOUT — le bon, le flou, l'embryonnaire

PUBLICATION SÉLECTIVE (Cercle 4, blog public)
  ├→ Uniquement les décisions actées
  ├→ Uniquement les patterns testés (>100 tests PASS)
  ├→ Uniquement ce qui a de la valeur pour le lecteur
  └→ JAMAIS une spéculation présentée comme une vérité

Di antara kedua ekstrem ini, adapenapis. Pertanyaannya adalah: siapa yang melakukannya? Seorang manusia lelah di akhir sesi? Skrip regex yang naif? Atau LLM itu sendiri, yang sudah membaca semuanya?

Jawaban saya : LLM.

pola STIMULUS — lahir, menetapkan, mengencerkan, mati

STIMULUS adalah sebuah file`.adoc`temporaire di akar workspace (Lingkaran 0). Nama nya mengikuti konvensi yang evokatif —PICTURE_ME_ROLLIN.adoc, HOLD_MY_BEER.adoc, ONCE_UPON_A_TIME.adoc— yang menangkap niat eksploratif saat ini.

Siklus hidupnya tanpa belas kasihan:

CRÉATION (Cercle 0)
  ├→ Fichier vide, brain dump libre
  ├→ Allers-retours LLM ← → développeur
  └→ Aucune pression de structure ou de publication

MATURATION
  ├→ Le contenu se densifie
  ├→ Des sections émergent naturellement
  └→ Le fichier devient une référence informelle de session

CLASSIFICATION ÉPISTÉMIQUE ← FAIT PAR LE LLM
  ├→ VISION    → publiable, diluer dans les docs publics + blog
  ├→ OPINION   → confiner au Cercle 0, pas de dilution externe
  └→ STRATÉGIE → dilution restreinte (docs racine, PAS de blog)

DILUTION (Cascade vers Cercles légitimes)
  ├→ VISION → WORKSPACE_AS_PRODUCT.adoc + WHAT_THE_GAMES.adoc + blog
  ├→ STRATÉGIE → WORKSPACE_AS_PRODUCT.adoc (section business)
  └→ OPINION → reste dans le stimulus, ne bouge pas

ARCHIVAGE + SUPPRESSION
  ├→ Snapshot dans configuration/vision-archive/ (trace historique)
  └→ rm du stimulus — il a fini son travail

Seorang rangsangan yang bertahan lebih dari 2 sesi tanpa pengenceran adalah anti-pola. Entah informasi terlalu penting untuk disimpan di file sementara (→ pengenceran), atau informasi terlalu kabur untuk layak ada (→ menghapus).

Delegasi ke LLM : Mengapa LLM itu yang memfilter

Saya tidak meng-hardcode klasifikasi Vision/Opinion di Kotlin. Saya menyuntikkan diprompt sistemdari LLM via`AGENT_GOVERNANCE.adoc`:

----
----
Pour chaque dilution de stimulus ou session, tu es responsable de classifier
le contenu :
- VISION : décision architecturale actée, pattern testé en production (>100 tests PASS),
  décision documentée dans BACKLOG ou ROADMAP
- OPINION : spéculation, hypothèse non validée par des tests, intuition
  sans ancrage expérimental
- STRATEGIE : positionnement business, pricing, marché cible

Règles :
- Si OPINION, le contenu reste confiné dans son cercle d'origine
- Si VISION, tu procèdes à la dilution dans les documents racine
- Si STRATEGIE, dilution restreinte (docs racine, pas de blog public)
- Cette classification détermine aussi si un article de blog est publiable
  sur cheroliv.com
----

LLM membaca instruksi ini**sebelum**untuk memproses sesi. Dia berada dalam konteks imediatnya, bukan dalam file terpisah. Ini adalah *prompt engineering deterministik* : perilaku muncul dari teks yang disuntikkan, bukan dari klasifikator eksternal.

=== Kenapa ini bekerja — dan Kenapa ini kontraintuitif

Reaksi standar: « Kamu menyerahkan klasifikasi kepada AI? Bagaimana jika ia salah?

Jawaban: manusia tidak lebih baik pada pukul 2 pagi. Perbedaannya, LLM itu membaca SEMUA. Dia memiliki konteks lengkap sesi dan dokumen target. Dia tahu bahwa`VPS ECO-16 12€ HT`adalah keputusan infrastruktur (VISION) sedangkan`« le TTS ElevenLabs sonne plus naturel que Coqui »`adalah sebuah opini yang belum diverifikasi oleh sebuah benchmark.

Manusia, pada akhir sesi, membaca secara diagonal dan melakukan yang terbaik. LLM membaca secara menyeluruh dan menerapkan grade sistematis. Hasilnya adalah**lebih andal**, tidak kurang.

Dan untuk 20% kasus ambigu — zona abu-abu tempat bahkan LLM ragu — jawabannya bukan « menambahkan kode ». Jawabannya adalah**LangGraph4j**(EPIC 13) : grafik keadaan yang, untuk kasus ambigu, mengaktifkan node Human-in-the-Loop dan mengembalikan ke manusia untuk keputusan. Tapi untuk 80% kasus yang jelas, LLM cukup.

== Pipa Lengkap : dari Brain Dump ke Blog Post

Berikut adalah alur lengkap — dari ide mentah sampai artikel dipublikasikan — dengan LLM sebagai satu-satunya filter :

[source]
----
CERCLE 0 (jardin secret)
  PICTURE_ME_ROLLIN.adoc   ← brain dump, allers-retours LLM
       ↓
  [LLM classifie] → VISION / OPINION / STRATÉGIE
       ↓
  VISION → dilution dans WORKSPACE_AS_PRODUCT.adoc
         → dilution dans WHAT_THE_GAMES_BEEN_MISSING.adoc
         → dilution dans WORKSPACE_VISION.adoc (session context)
         → RÉDACTION ARTICLE BLOG ← le LLM écrit, pas le dev
       ↓
CERCLE 4 (blog public)
  0116_compartimentage_epistemique.adoc  ← publié sur cheroliv.com
       ↓
  ./gradlew deploy (bakery-gradle → JBake → JGit → GitHub Pages)
       ↓
  https://cheroliv.com/blog/2026/0116/  ← live
----

Pengembang tidak menulis artikel. Ia menantang, meninjau, memvalidasi. LLM menulis. Loop adalah:

1. Brain dump bebas → tanpa sensor
2. Klasifikasi epistemik oleh LLM → tidak ada bocoran
3. Penulisan oleh LLM → tanpa procrastinasi
4. Pemeriksaan manusia → tidak ada kesalahan

Penekanan sejarah — « Saya tidak punya waktu untuk menulis » — telah dihapus. LLM melakukan sebagian besar pekerjaan. Manusia melakukan yang hanya dapat dilakukan oleh manusia: menilai.

== Tiga Dokumen Akar — Bagaimana Informasi Menemukan Tempatnya

Setiap dokumen target memiliki peran spesifik dalam kaskade penurunan:

[cols="1,3,2"]
|===
|dokumen |Apa yang ia terima |Jenis konten |`WORKSPACE_AS_PRODUCT.adoc` |Keputusan arsitektur, stack teknis, roadmap, model bisnis |visi + strategi |`WHAT_THE_GAMES_BEEN_MISSING.adoc` |Pola, pelajaran, anti-pola, ontologi, aturan formal |VISION (pola yang telah diuji) |`WORKSPACE_VISION.adoc` |Konteks sesi, riwayat keputusan, poin infrastruktur |VISI + STRATEGI (konteks) |`AGENT_GOVERNANCE.adoc` |Aturan tata kelola, portofolio proyek, prosedur |VISI (tata kelola) |**Blog cheroliv.com** |Artikel publik, nilai untuk pembaca eksternal |Visi hanya
|===

Sama stimulasi dapat memenuhi kebutuhan 4 dokumen + blog — setiap destinasi menerima bagian yang relevan, tanpa redundansi, tanpa kontradiksi.

Ini adalah yang terjadi untuk`PICTURE_ME_ROLLIN.adoc`(3 Mei 2026) :

| Informasi | Klasifikasi | Tujuan | Inventaris 13+ proyek foundry/ | VISION | WORKSPACE_AS_PRODUCT | VPS-2 OVH, edster.cloud, 8.49€/bulan | VISI | WORKSPACE_AS_PRODUCT + WORKSPACE_VISION | | « Pasar Afrika siap untuk uang seluler » | STRATÉGIE | WORKSPACE_AS_PRODUCT (section business) | | « DeepSeek > Kimi > GLM untuk konteks panjang » | OPINION → VISION | Dikenakan pembatasan lalu dipromosikan setelah benchmark (artikel 0112) | | Karyawan Sintetis sebagai produk akhir | STRATEGI | WORKSPACE_AS_PRODUCT (tanpa blog) |

== Pola Baby-Step + TestContainer + Dokumen Hidup — Kode yang Menguji Diri Sendiri

Pola STIMULUS/Dilution mengatur pemikiran. Setara untuk kode-nya adalah pola Baby-Step/TestContainer/Doc Vivante, yang divalidasi oleh plantuml-gradle (380/380 tes LULUS, 137 sesi tanpa kebocoran Docker) :

[cols="1,3"]
|===
|Prinsip |aturan |**langkah bayi** |Tidak lebih dari 3 poin per US. Jika satu US menimbulkan ketakutan, potong. Satu US dengan 1 poin yang melewati > satu US dengan 8 poin yang menunggu. |**TestContainer pertama** |Sebelum kode bisnis, kontainer. Uji infra lulus → lingkungan stabil terjamin. |**Dataset komite** |Subhimpunan minimal tetapi representatif dalam`src/test/resources/`, tanpa PII. Dapat di-klon, dapat diluncurkan. |**Dokumentasi hidup** |Setiap test Cucumber = satu kalimat dalam bahasa alami. Kode sumber adalah spec yang dapat dieksekusi. Tidak ada dokumen Markdown yang harus dipelihara. |**Pembersihan otomatis** |Zero kebocoran sumber daya. Wadah yatim,`/tmp/gradle-test-*`: semua bersih
|===

Pola ini adalah alasan mengapa plantuml-gradle tidak pernah mengalami regresi Docker dalam 138 sesi. Dia memastikan bahwa kode yang berkomunikasi dengan infrastruktur eksternal (PostgreSQL, Redis, Kafka) selalu diuji di lingkungan yang identik dengan produksi — terkontrol versinya, dapat direproduksi, dapat dijalankan dengan satu perintah.

== Kesimpulan: kebebasan berpikir tanpa ketakutan mempublikasikan

Kompartimentasi epistemologis yang diotomatisasi bukan alat sensor. Adalah sebagai**pembebas**. Ia memungkinkan untuk berpikir secara bebas, untuk spekulasi tanpa filter, untuk brain-dumping segala yang ada di pikiran — tanpa pernah takut bahwa sebuah ide embryonnaire akan terekspos di blog.

LLM adalah penjaga batas ini. Ia membaca semuanya. Ia mengklasifikasikan. Ia meredam apa yang layak untuk bertahan. Ia membatasi apa yang harus tetap pribadi. Ia menyusun apa yang dapat dipublikasi.

Dan developer itu, dia, tetap memegang kata terakhir: membaca, menantang, memvalidasi. Menilai.

Ini adalah pembagian kerja yang tidak dimiliki oleh pengembang solo: sebuah karyawan sintetis yang mengurus administrasi mental, sehingga manusia dapat fokus pada apa yang ia lakukan dengan baik — merancang, merancang arsitektur, dan mengambil keputusan.
