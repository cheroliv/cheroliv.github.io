ビルドタスクの自動化はあらゆるソフトウェアプロジェクトにおいて極めて重要であり、Kotlin DSLを備えたGradleは例外的な柔軟性を提供します。これまでの対話を通じて、特にテストレポートなどのビルドロジックをどのように集中管理し再利用するかについて、以下を活用することで検討してきました。allprojects, buildSrc、およびKotlinによるカスタムタスク。

allprojects` と subprojects を使用して設定を共通化する

ブロック`allprojects` et `subprojects`あなたの`build.gradle.kts`ルートは、マルチモジュールプロジェクト全体に共通の設定を適用するために不可欠です。

プロの翻訳家として、フランス語から日本語へ翻訳いたします。 バックティックで囲まれたコードスパン（…​）は、内容、スペース、位置を一切変更せず、そのまま保持します。 このテキストは長い文章の一部である可能性がありますが、追加の文脈を求めることなく、その断片をそのまま翻訳します。 翻訳後のテキストのみを出力し、説明、解説、導入、代替案、オプションなどは一切含めません。allprojects { …​ }: 設定を適用しますルートプロジェクトおよびそのすべてのサブプロジェクト。un`を定義するのに最適です`group、ひとつの`version`、またはいくつかの`repositories`共通の。 プロの翻訳者です。フランス語から日本語に翻訳します。subprojects { …​ }: 設定を適用しますサブプロジェクトのみに、ルートプロジェクトを除外します。モジュール固有のプラグイン（例えば`java` ou kotlin-jvm) またはライブラリで共通の依存関係。

以下は例示的な例です：

// build.gradle.kts (projet racine)
plugins {
    base // Appliqué au projet racine
}

allprojects {
    group = "com.example"
    version = "1.0.0"

    repositories {
        mavenCentral()
    }

    tasks.withType<org.gradle.api.tasks.testing.Test> {
        useJUnitPlatform() // Configuration commune des tests pour tous les projets
    }
}

subprojects {
    apply(plugin = "java")
    apply(plugin = "org.jetbrains.kotlin.jvm")

    dependencies {
        implementation("org.jetbrains.kotlin:kotlin-stdlib-jdk8")
    }

}

\==buildSrc: ビルドロジックの万能ナイフ

タスクのロジックが複雑になった場合や、再利用する必要がある場合は、buildSrcが推奨されるソリューションです。これは、メインのビルドスクリプトよりも前にコンパイルされる特別なGradleモジュールであり、そのクラスをビルド全体のクラスパスで利用可能にします。

\=== なぜ使用するのか`buildSrc`タスク用に？

  • 再利用性：…​で定義されたタスク`buildSrc`ビルドのどのプロジェクトにも適用できます。

  • 組織: ビルドコードを集中管理し、よりクリーンでメンテナンスしやすいものにします。

  • 型安全性とオートコンプリーション: Kotlin コードは`buildSrc`はコンパイルされるため、IDEによるエラーチェックとオートコンプリートが提供され、開発体験が向上します。

\=== 抽象タスク`OpenTestReportTask`（héritant de を継承する`DefaultTask`)

ファイルシステムやその他のGradle APIとやり取りするカスタムKotlinロジックが必要で、その後に外部コマンドを実行したい場合は、このアプローチが推奨されます。

[ソース,kotlin]

package com.yourpackage

import org.gradle.api.DefaultTask import org.gradle.api.tasks.Input import org.gradle.api.tasks.TaskAction import java.io.File

abstract class OpenTestReportTask : DefaultTask() {

----
init {
    group = "verification"
    description = "Opens a test report in Firefox."
    dependsOn("check") // Assure que les rapports sont générés
}

@get:Input
abstract var reportPath: String

@TaskAction
fun openReport() {
    val separator = File.separator
    val reportFile = project.layout.projectDirectory.asFile.toPath()
        .resolve(reportPath.replace("/", separator))
        .toAbsolutePath()
        .toFile()

    if (!reportFile.exists()) {
        logger.warn("Report file does not exist: $reportFile. Ensure 'check' ran.")
        return
    }

    project.exec {
        commandLine("firefox", "--new-tab", reportFile.absolutePath)
    }
    logger.lifecycle("Opened test report: ${reportFile.absolutePath}")
}
----

## }

\== 抽象タスク`AbstractJbakeExecTask`（`...` を継承する`Exec`)

タスクの内容が主に、可変引数を用いて外部コマンドを実行することである場合は、直接 `...` を継承してください。**実行**の方がより直接的です。

## [ソース,kotlin]

package com.yourpackage

import org.gradle.api.tasks.Exec import org.gradle.api.tasks.Input import java.io.File

abstract class AbstractJbakeExecTask : Exec() {
init {
    group = "verification"
    description = "Opens a Jbake project report in Firefox."
    dependsOn("check")
}

@get:Input
abstract var reportRelativePath: String

override fun exec() {
    val separator = File.separator
    val reportFile = project.layout.projectDirectory.asFile.toPath()
        .resolve(reportRelativePath.replace("/", separator))
        .toAbsolutePath()
        .toFile()

    if (!reportFile.exists()) {
        logger.warn("Report file does not exist: $reportFile. Ensure 'check' ran.")
        return
    }

    commandLine("firefox", "--new-tab", reportFile.absolutePath)
    logger.lifecycle("Attempting to open report: ${reportFile.absolutePath}")
    super.exec() // Appelle la méthode exec() de la super-classe Exec
}

}

\=== 次のテストのレポートを実行する`buildSrc`彼自身

Si `buildSrc`独自のテストを実行してレポートを生成します。レポートタスクを直接以下に保存できます。`buildSrc/build.gradle.kts`翻訳してください。

[source,kotlin]

plugins { kotlin-jvm }

repositories { mavenCentral() }

tasks.withType\<Test\> { useJUnitPlatform() reports.html.outputLocation.set(layout.buildDirectory.dir("reports/tests")) }

import com.yourpackage.ReportJbakeTestsTask // タスククラスをインポートしてください

tasks.register\<ReportJbakeTestsTask\>("reportBuildSrcTests") { // パスはクラス内で既に定義されているため、buildSrcのレポートを指します }
