問題：端末がビジー

すべての開発者はこの状況を経験したことがある：

$ ./gradlew build
> Building...

ターミナルがフリーズしています。もうコマンドを入力することはできません。そして、ファイルを確認して、起動する必要があります`git status`または、使用中のポートを確認する。

skinparam backgroundColor #FEFEFE

actor Développeur as dev
participant "ターミナル" as term
participant "Gradle
( プロセス )" as gradle

dev -> term : ./gradlew build
term -> gradle : Lance le build
gradle -> term : Occupe le terminal\n(pas de prompt)
dev -> term : veut taper une commande
term --> dev : ❌ Terminal bloqué

note right of dev
  Le développeur est
  paralysé pendant
  toute la durée du build
end note
@enduml

ほとんどの開発者は新しいターミナルを開きます。しかし、もっとエレガントで速く、ネイティブなソリューションがあります：ジョブ管理です。

必須の3つのコマンド

Ctrl+Z — 一時停止 (SIGTSTP)

`Ctrl+Z`信号を送る`SIGTSTP`フォアグラウンド プロセスに。 プロセスは中断された— 死んでいない — ターミナルはプロンプトを取り戻す。

$ ./gradlew build
> Building...
^Z
[1]+  Stoppé    ./gradlew build
$

括弧の中の数`[1]`ですジョブ番号. Le `+`デフォルトのジョブを示します。

fg — フォアグラウンドで復帰する

`fg`サスペンドされたジョブをフォアグラウンドに戻す。プロセスは、停止した場所から正確に再開される。

$ fg
./gradlew build
> Building... (reprend où il en était)

特定のジョブ番号：

$ fg %2

bg — バックグラウンドで再開

`bg`端末をブロックせずにプロセスを再開します。長いビルドに最適です。

$ bg
[1]+ ./gradlew build &
$

Le `&`終わりにあることは、プロセスがバックグラウンドで実行されていることを意味します。

jobs — シェルのジョブを一覧表示

$ jobs
[1]-  Stoppé    vim README.md
[2]+  En cours   ./gradlew build

ショートカット/コマンド 信号 効果 �戻る？

Ctrl+Z

SIGTSTP

プロセスを一時停止する（凍結、メモリ上）

はい :`fg` ou bg

Ctrl+C

SIGINT

プロセスを終了させる (完了)

いいえ : プロセスが破壊されました

Ctrl+\

SIGQUIT

プロセスを kill + コアダンプ

いいえ: 破壊されたプロセス

commande &

—

バックグラウンドで直接起動

`fg`それを前面に出すために
`Ctrl+Z`です非破壊的. プロセスはそのまま固定され、メモリに保持されています。あなたはすぐに再開できますに`fg`これは pause であって、 stop ではありません。

高度なヒント

fg 最新の仕事と交互に

fg`引数なしでは、マークされたジョブが戻ります+(最新の)。 しかし、あなたはまた使用することもできます%-`前のジョブを対象にする :

$ vim file1.txt
^Z
[1]+  Stoppé    vim file1.txt

$ vim file2.txt
^Z
[2]+  Stoppé    vim file2.txt

$ fg      # ramène job [2] (le plus récent)
$ fg %-   # ramène job [1] (le précédent)

ジョブをきれいに殺す

$ jobs
[1]-  Stoppé    vim config.yml
[2]+  Stoppé    ./gradlew test

$ kill %2       # envoie SIGTERM au job 2
$ kill -9 %1    # envoie SIGKILL au job 1 (force)

désown : シェルから切り離す

disown`シェルのジョブテーブルからジョブを削除します。プロセスは実行を継続しますが、再度呼び出すことはできません。`fg:

$ ./gradlew build &
[1] 12345

$ disown %1
# Le processus continue mais n'est plus lié au shell
# Ça survives à la fermeture du terminal

長いプロセスに対して nohup と組み合わせる

ターミナルが閉じられたときにプロセスが生き残るように：

$ nohup ./gradlew build &
[1] 12345
$ disown %1
# Le build continue même si vous fermez le terminal

よくある落とし穴と間違い

Ctrl+ZとCtrl+Cを混同する

これが最も頻繁な間違いです。`Ctrl+C`プロセスを殺す。`Ctrl+Z`それを一時停止します。もしあなたが押すと`Ctrl+C`反射的に、すべての状態が失われます — 開いているファイル、LLMセッション、進行中のビルド。

  card "損失なし" as z3
}

ジョブはシェルにローカルです

jobs, fg et `bg`ジョブは、それらを起動したシェル内でのみ機能します。新しいターミナルを開くと、他のジョブは表示されません。

# Terminal 1
$ vim file.txt
^Z
[1]+  Stoppé    vim file.txt

# Terminal 2 (nouveau)
$ jobs
# (rien — les jobs sont locaux au shell)

システム全体のプロセスを見るには、ps ou htop:

ps aux | grep vim

ジョブはシェルの終了後に生き残らない

ターミナルを閉じると、一時停止またはバックグラウンドで実行中のすべてのジョブが破棄されます。プロセスが存続するようにするには、使ってください`nohup`+disown(Empty)

$ nohup ./gradlew build &
[1] 12345
$ disown %1
# Fermer le terminal → le build continue

対話型プロセスと fg

一部のインタラクティブなプログラムはその後良くない状態になる`Ctrl+Z` + fg. 稀ですが、起こります：

  • シグナルを使用する一部のプログラムは（vim、htop、lessはうまく機能しています`Ctrl+Z`)

  • 長時間のネットワークプログラム (ssh、opencode) は通常、正常に取得できます

  • ターミナル (ncurses) を変更するプログラムは、ときどきターミナルを予期しない状態に残すことがあります

端末が破損した後の`fg`, 入力して :

reset

なぜ fg が過小評価されているのか

ほとんどの最新の開発者は発見する`fg`�遅れたり、あるいは決して起こらないこともあります。 いくつかの理由：

  1. IDEはターミナルを隠す: VS Codeは統合ターミナルを提供しますが、複数のタブは`fg`表面的には必要性が低い

  2. グラフィカルツールは CLI を置き換えるファイルマネージャー、システムモニター、グラフィカルGitクライアント

  3. tmux と screen: これらのマルチプレクサは同じ問題を異なる方法で解決しますが`fg`よりシンプルで常に利用可能です

しかし、`fg`は：

  1. 普遍的: POSIXシェルすべてに存在する (bash, zsh, fish…​)

  2. 依存性のない: tmuxまたはscreenをインストールする必要はありません

  3. スナップショット: 2回の打撃 (Ctrl+Z`それから`fg) 一時停止および再開する

  4. コンテキスト保存者: プロセスの状態は無傷です

結論

`fg`これは obscure tips ではない — Unix シェルの基本的なメカニズムで、1970 年代から利用可能です。ほとんどの開発者がこれを無視するのは、私たちの時代の症状です：IDE とマルチプレクサーが私たちを基本から遠ざけている。

しかし、SSHサーバーにいるとき、ミニマルなターミナルで、あるいは単純に使っているときでも`opencode`そしてLLMはまさに作業中です —Ctrl+Z, fg, bg, `jobs`彼らはあなたの親友です。

_ Ctrl+Zで一時停止、fgで再開。これはターミナルの一時停止・再生です。 _
