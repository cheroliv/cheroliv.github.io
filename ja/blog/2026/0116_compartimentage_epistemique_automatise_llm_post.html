自動化された認識の区画化 — LLMが私のメンタルガーデンをどのように守るか

公開日: 02 May 2026

Table des matières
  • 問題：何も発表せずに自由に考える
  • STIMULUS パターン — 生まれる、固定する、薄める、死ぬ
  • LLMへの委任 : なぜLLMがフィルタリングするのか
読了時間 : 10 minutes

私のLLMはGradleタスクを実行するだけにとどまらない。それは私のプライベートな思考と公的な表現の間の境界の守護者である。各アイデアはルーティングされる前に、Vision、Opinion、Stratégieと分類される。これがどのようにして自動化された認識的コンパートメンタル化が私の精神的な庭を守り、私を黙らせずにいるかを示す。

問題：何も発表せずに自由に考える

一人の開発者がLLMを使って思考プロセスをドキュメント化するとき、パラドックスにぶつかる：

CAPTURE TOUT (Cercle 0, jardin secret)
  ├→ Brain dump libre, pas de censure
  ├→ Idées brutes, spéculations, intuitions non vérifiées
  ├→ Allers-retours LLM : challenger, itérer, raffiner
  └→ Le LLM voit TOUT — le bon, le flou, l'embryonnaire

PUBLICATION SÉLECTIVE (Cercle 4, blog public)
  ├→ Uniquement les décisions actées
  ├→ Uniquement les patterns testés (>100 tests PASS)
  ├→ Uniquement ce qui a de la valeur pour le lecteur
  └→ JAMAIS une spéculation présentée comme une vérité

これらの二つの極端の間に、一つフィルター. 質問は：誰がそれをするのか？疲れた人間（セッションの終わり）？ naïveな正規表現スクリプト？それとも、すでに全部読んでいるLLM自身か？

私の回答 : LLM。

STIMULUS パターン — 生まれる、固定する、薄める、死ぬ

STIMULUS は ファイル です`.adoc`一時的なワークスペースのルート（Cercle 0）。その名前は印象的な命名規則に従っています —PICTURE_ME_ROLLIN.adoc, HOLD_MY_BEER.adoc, ONCE_UPON_A_TIME.adoc— その瞬間の探求的意図を捉える。

そのライフサイクルは容赦がない：

CRÉATION (Cercle 0)
  ├→ Fichier vide, brain dump libre
  ├→ Allers-retours LLM ← → développeur
  └→ Aucune pression de structure ou de publication

MATURATION
  ├→ Le contenu se densifie
  ├→ Des sections émergent naturellement
  └→ Le fichier devient une référence informelle de session

CLASSIFICATION ÉPISTÉMIQUE ← FAIT PAR LE LLM
  ├→ VISION    → publiable, diluer dans les docs publics + blog
  ├→ OPINION   → confiner au Cercle 0, pas de dilution externe
  └→ STRATÉGIE → dilution restreinte (docs racine, PAS de blog)

DILUTION (Cascade vers Cercles légitimes)
  ├→ VISION → WORKSPACE_AS_PRODUCT.adoc + WHAT_THE_GAMES.adoc + blog
  ├→ STRATÉGIE → WORKSPACE_AS_PRODUCT.adoc (section business)
  └→ OPINION → reste dans le stimulus, ne bouge pas

ARCHIVAGE + SUPPRESSION
  ├→ Snapshot dans configuration/vision-archive/ (trace historique)
  └→ rm du stimulus — il a fini son travail

2回以上のセッションで希釈されずに生存する刺激は、アンチパターンです。情報が一時ファイルに保存されるほど重要である場合は（→ diluer）、あるいは情報が不明確で存在する価値がない場合は（→ supprimer）。

LLMへの委任 : なぜLLMがフィルタリングするのか

KotlinでVision/Opinionの分類をハードコードしません。これを注入しますシステムプロンプトLLMを経由して`AGENT_GOVERNANCE.adoc`:

----
----
Pour chaque dilution de stimulus ou session, tu es responsable de classifier
le contenu :
- VISION : décision architecturale actée, pattern testé en production (>100 tests PASS),
  décision documentée dans BACKLOG ou ROADMAP
- OPINION : spéculation, hypothèse non validée par des tests, intuition
  sans ancrage expérimental
- STRATEGIE : positionnement business, pricing, marché cible

Règles :
- Si OPINION, le contenu reste confiné dans son cercle d'origine
- Si VISION, tu procèdes à la dilution dans les documents racine
- Si STRATEGIE, dilution restreinte (docs racine, pas de blog public)
- Cette classification détermine aussi si un article de blog est publiable
  sur cheroliv.com
----

LLMはこの指示を読む**前に**セッションを処理する。それはその直近のコンテキストにあり、別ファイルにはありません。これは *決定的プロンプトエンジニアリング* : 振る舞いは注入されたテキストから生じ、外部の分類器からではありません。

=== なぜそれが機能するのか — そしてなぜそれが直感に反するのか

標準的な反応： 「AIに分類を任せるの？ もし間違えたらどうするの？」

回答 : 人間は午前2時にもっと良くなるわけではない。違いは、LLMはすべてを読むということだ。セッションと対象ドキュメントのコンテキストを完全に把握している。それは`VPS ECO-16 12€ HT`はインフラストラクチャーの決定 (VISION) である一方で`« le TTS ElevenLabs sonne plus naturel que Coqui »`ベンチマークで検証されていない意見です。

人間はセッションの終わりに斜め読みし、できるだけのことをする。LLMは網羅的に読み、体系的なグリッドを適用する。結果は**より信頼できる**、決して少なくない

そして20％の曖昧なケースについては — つまりLLMでも躊躇する灰色の領域 — 答えは「コードを追加すること」ではありません。答えは**LangGraph4j**(EPIC 13) : あいまいなケースでは Human-in-the-Loop ノードを起動し、人間に判断を仰ぐ状態グラフ。ただし、80% の明確なケースでは LLM で十分。

== 完全なパイプ: ブレインダンプからブログ投稿まで

ここに完全なフローがあります — 原始的なアイデアから公開された記事まで — LLMだけがフィルターとして機能しています：

[source]
----
CERCLE 0 (jardin secret)
  PICTURE_ME_ROLLIN.adoc   ← brain dump, allers-retours LLM
       ↓
  [LLM classifie] → VISION / OPINION / STRATÉGIE
       ↓
  VISION → dilution dans WORKSPACE_AS_PRODUCT.adoc
         → dilution dans WHAT_THE_GAMES_BEEN_MISSING.adoc
         → dilution dans WORKSPACE_VISION.adoc (session context)
         → RÉDACTION ARTICLE BLOG ← le LLM écrit, pas le dev
       ↓
CERCLE 4 (blog public)
  0116_compartimentage_epistemique.adoc  ← publié sur cheroliv.com
       ↓
  ./gradlew deploy (bakery-gradle → JBake → JGit → GitHub Pages)
       ↓
  https://cheroliv.com/blog/2026/0116/  ← live
----

開発者は記事を書かない。彼は挑戦し、見直し、検証する。LLMが書く。ループは：

1. ブレインダンプ フリー → 検閲なし
2. LLMによる認識論的分類 → 漏洩なし
3. LLM による執筆 → 先延ばししない
4. 人間による校閲 → エラーなし

歴史的なボトルネック — 「書く時間がない」 — が解消されました。LLMが大半の仕事をこなす。人間がすることは、人間だけができること：判断する。

== 三つのルートドキュメント — 情報がその場所を見つける方法

各ターゲットドキュメントは希釈のカスケードにおいて正確な役割を果たします：

[cols="1,3,2"]
|===
|ドキュメント |受けるもの |コンテンツの種類 |`WORKSPACE_AS_PRODUCT.adoc` |アーキテクチャ上の意思決定, 技術スタック, ロードマップ, ビジネスモデル |ビジョン＋戦略 |`WHAT_THE_GAMES_BEEN_MISSING.adoc` |パターン、教訓、アンチパターン、オントロジー、形式的ルール |ビジョン (テスト済みのパターン) |`WORKSPACE_VISION.adoc` |セッションコンテキスト, 意思決定の履歴, インフラストラクチャポイント |ビジョン + 戦略 (コンテキスト) |`AGENT_GOVERNANCE.adoc` |ガバナンス規則, プロジェクトポートフォリオ, 手順 |ビジョン(ガバナンス) |**ブログ cheroliv.com** |公開記事、外部読者への価値 |VISIONのみ
|===

同じ刺激は4つのドキュメント + ブログに栄養を与えることができます — 各宛先は自分に関係する部分を受け取り、冗長も矛盾もありません。

それが起きたのは`PICTURE_ME_ROLLIN.adoc`(2026年5月3日):

| 情報 | 分類 | 行き先 | | 13+個のファウンドリープロジェクトの在庫 foundry/ | VISION | WORKSPACE_AS_PRODUCT | | VPS-2 OVH, edster.cloud, 8.49€/月 | VISION | WORKSPACE_AS_PRODUCT + WORKSPACE_VISION |  アフリカ市場はモバイルマネーに備えている » | 戦略 | WORKSPACE_AS_PRODUCT (section business)  DeepSeek > Kimi > GLM 長いコンテキスト用 » | 意見 → ビジョン | 閉じ込められた後、ベンチマーク後に昇進 (記事 0112) | 合成従業員として最終製品 | 戦略 | WORKSPACE_AS_PRODUCT (ブログなし) |

== ベビーステップパターン＋TestContainer＋生きているドキュメント ― 自己テストするコード

STIMULUS/Dilution パターンは思考を管理します。コードにおけるその相当物は、plantuml-gradle によって検証された Baby-Step/TestContainer/Doc Vivante パターンです（380/380 テスト PASS、ドッカーレークがゼロの 137 セッション）：

[cols="1,3"]
|===
|原理 |ルール |**ベイビーステップ** |USあたり3ポイントを超えてはならない。USが恐ろしいと感じたら、分割する。通過する1ポイントのUS > 遅れる8ポイントのUS。 |**TestContainer まず** |ビジネスコードの前に、コンテナ。 インフラテストがパス → 安定した環境が保証される。 |**コミット済みデータセット** |最小限ながら代表的な部分集合である`src/test/resources/`, PIIなし. クローン可能、起動可能。 |**生きたドキュメンテーション** |各Cucumberテスト = 自然言語の文章。ソースコードが実行可能なスペックである。Markdownドキュメントを維持する必要はゼロ。 |**自動クリーンアップ** |リソース漏れゼロ。 孤児コンテナ,`/tmp/gradle-test-*`: すべてが掃除されました。
|===

このパターンが、plantuml-gradle が 138 セッションで Docker の回帰を一度も経験していない理由です。これは、PostgreSQL、Redis、Kafka などの外部インフラストラクチャと通信するコードが、常に本番と同一の環境でテストされることを保証します — バージョン管理され、再現可能で、1 コマンドで起動できます。

== 結論：出版を恐れずに考える自由

自動化された認識論的な区画化は検閲ツールではありません。それは**解放者**. これにより、自由に考え、フィルターなしで推測し、頭に浮かぶことを全部ブレインダンプすることができます — つまり、未熟なアイデアがブログに載ってしまうことを恐れずに済む。

LLMはこの境界の守護者だ。 すべてを読む。 分類する。 生き残るに値するものを薄める。 秘密にしておくべきものを閉じ込める。 公開に適したものを作成する。

そして開発者は、最後の言葉を保つ：読み返す、挑戦する、検証する。判断する。

それはソロ開発者に欠けていた仕事の分担だった：精神的な事務処理を担当する合成従業員で、人間が最も得意とすること―設計、アーキテクチャ、意思決定―に集中できるようにする。
