  1. 1日目： READMEをご紹介します（最終更新：18か月前）

  2. 3日目：あなたはそのモジュールであることを発見します。billing`秘密にモジュールを呼び出す`notification

  3. 7日目：シニアがこう言います。「ああ、実はこのクラスは2つのことをやっているんだ。それを分割する予定だった」

  4. 14日目：あなたは気づく、ビジネスインテリジェンスのすべてがに`utils/LegacyHelper.java`— どこにも参照されていないファイル

Knowledge Graphは構造化された表現の知るあなたのコードベースの内容 :

新しい開発者、アナイスがプロジェクトに参加することを想像してください。彼女はLLMの呼び出しのための「クォータートラッキング」機能を追加する必要があります。

Knowledge Graph があれば、アナイスは(en)を見たでしょう。5分 :

  • QuotaTracker`関連している`ApiKeyPool(稜線抽出)

  • RateLimiter`関連している`QuotaTracker(稜線推論された, 信頼 0.82)

  • これらの3つのノードはコミュニティクォータ管理

  • ハイパーエッジもまた接続します`LlmService`— エントリーポイント

パイプライン: 好きなコードを選んで、1つのコマンドで

Graphify パイプライン + Gradle プラグインは、あなたのコードベースをPlantUML図に変換します二つのコマンド:

@startuml
skinparam backgroundColor #FEFEFE
skinparam sequenceArrowThickness 2

actor "開発者" as dev
participant "グラフ化する" as gfy
participant "graphify-out/graph.json" as json
participant "Gradle プラグイン" as plg
participant "KnowledgeGraphParser" as kgp
participant "知識グラフレンダラー" as kgr
participant "�図表/知識グラフ/" as out

dev -> gfy : graphify update . --no-viz
gfy -> json : extrait nœuds, arêtes,\ncommunautés, confiances

dev -> plg : ./gradlew generateKnowledgeGraphDiagram
plg -> kgp : parse graph.json
kgp -> kgr : nodes + edges + communities
kgr -> out : génère .puml + .png

out --> dev : diagramme interactif

@enduml

ゼロ LLM。すべてが決定的です：同じコード、同じグラフ、同じ図。再現可能、バージョン管理可能、オフラインで閲覧可能。

エッジの種類：信頼が言うこと

@startuml
skinparam backgroundColor #FEFEFE

node "LlmService" as ls
node "ダイアグラムプロセッサー" as dp
node "ConfigLoader" as cl
node "ApiKeyPool" as akp
node "レガシーヘルパー" as lh #F1948a

ls --> dp : EXTRACTED\n(calls, direct)
cl ..> akp : INFERRED 0.75\n(creates, probable)
ls -[#FF5722]-> lh : AMBIGUOUS\n(legacy, douteux)

legend right
  |= Type |= Symbole |= Signification |
  | EXTRACTED | <b>--></b> | Relation visible dans le code |
  | INFERRED | <b>..></b> | Relation déduite (score de confiance) |
  | AMBIGUOUS | <b>--x</b> | Relation incertaine, à vérifier |
endlegend

@enduml

エッジタイプはオンボーディングにとって重要です：

  • 抜粋:あなたは落ち着いてナビゲートできます — それはコードの中にあります

  • 推測された(0.6-0.8) : おそらく正しいですが、リファクタリングする前に確認して

  • 推論された(0.8+) : 非常に信頼できる — これを参考に使ってください

  • �曖昧な注意、敏感なポイント。先輩に尋ねてください。

自分のKnowledge Graphを生成するのに5分

@startuml
skinparam backgroundColor #FEFEFE
skinparam ActivityBackgroundColor #D5f5e3

start

:pip install graphify==0.4.29;

:graphify update . --no-viz;
note right: Génère graphify-out/graph.json

:Ajouter le plugin Gradle;
note right: plugins { id("com.cheroliv.plantuml") }

:./gradlew generateKnowledgeGraphDiagram;
note right: Génère .puml + .png

:Vérifier diagrams/knowledge-graph/;
note right: knowledge-graph-full.puml\nknowledge-graph-full.png

stop

@enduml
具体的なコマンド
# 1. Installer graphify
pip install graphify==0.4.29

# 2. Générer le Knowledge Graph
graphify update . --no-viz

# 3. Vérifier le JSON
cat graphify-out/graph.json | jq '.nodes | length'
# → 47 nœuds

# 4. Générer le diagramme
./gradlew generateKnowledgeGraphDiagram

# 5. Filtrer par communauté
./gradlew generateKnowledgeGraphDiagram -Pplantuml.kg.community="service layer"

# 6. Limiter la taille
./gradlew generateKnowledgeGraphDiagram -Pplantuml.kg.maxNodes=20

限界と展望

Knowledge Graphは魔法の杖ではありません:

限界 説明 回避策

静的なコードのみ

ランタイムなし、データフローなし

APMトレースで補完する

INFERRED 誤っている可能性があります

導出されたエッジは検証が必要です

信頼スコア + 人間によるレビュー

業務の意味論なし

KGは"LlmService が ConfigLoader を呼び出す"ことを知っていますが、"これが auth のエントリポイント"ではありません。

手動アノテーションまたは LLM 後処理

時間性はありません

コードのスナップショット、進化ではない

定期的に生成 + バージョンを比較

展望 :

  • Diff KG: 二つのバージョンを比較して、コミュニティの移動を見る

  • インタラクティブKG: ノードをクリック → 対応する行で IDE が開く

  • 歴史的なKG: 時間の経過とともにコミュニティの進化を可視化する (移行する技術的負債)

結論

Knowledge Graphは行為を変換します孤独で長い(コードベースを理解する) を一幕で共有かつ迅速(地図を確認する).

ドキュメントではありません — それは地図作成. 自動的に更新されるマップで、実際の領土を示し、新人でもベテランでもすべての開発者が自信を持ってナビゲートできるようにします。

pip install graphify==0.4.29
graphify update . --no-viz
./gradlew generateKnowledgeGraphDiagram

3つのコマンド。5分。あなたのコードベースのマップ。
