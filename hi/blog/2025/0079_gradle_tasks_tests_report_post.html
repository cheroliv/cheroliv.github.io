सॉफ्टवेयर प्रोजेक्ट के लिए बिल्ड कार्यों का स्वचालन महत्वपूर्ण है, और Gradle, अपने Kotlin DSL के साथ, असाधारण लचीलापन प्रदान करता है। हमारी बातचीत के दौरान, हमने बिल्ड लॉजिक को केंद्रीकृत और पुनः उपयोग करने के तरीकों का पता लगाया, विशेष रूप से टेस्ट रिपोर्ट के लिए, का लाभ उठाते हुएसभी परियोजनाएँ, बिल्डSrc, और Kotlin में कस्टम कार्य

allprojects` और subprojects के साथ Configurations को केंद्रीकृत करें

ब्लॉक`allprojects` et `subprojects`आपके`build.gradle.kts`जड़ आपके मल्टी-मॉड्यूल प्रोजेक्ट में सामान्य कॉन्फ़िगरेशन लागू करने के लिए बुनियादी है।

*allprojects { …​ }`कॉन्फ़िगरेशन लागू करेंमूल परियोजना और इसकी सभी उप-परियोजनाओं के लिए। परिभाषित करने के लिए आदर्श`group, एक`version`, या कुछ`repositories`सामान्य (No output)subprojects { …​ }`कॉन्फ़िगरेशन लागू करेंकेवल उप-परियोजनाओं तक, मूल परियोजना को छोड़कर. परफेक्ट मॉड्यूल-विशिष्ट प्लगिन लागू करने के लिए (जैसे`java ou kotlin-jvm) या आपकी लाइब्रेरी के सामान्य निर्भरताएँ।

यहाँ एक उदाहरणात्मक उदाहरण :

// build.gradle.kts (projet racine)
plugins {
    base // Appliqué au projet racine
}

allprojects {
    group = "com.example"
    version = "1.0.0"

    repositories {
        mavenCentral()
    }

    tasks.withType<org.gradle.api.tasks.testing.Test> {
        useJUnitPlatform() // Configuration commune des tests pour tous les projets
    }
}

subprojects {
    apply(plugin = "java")
    apply(plugin = "org.jetbrains.kotlin.jvm")

    dependencies {
        implementation("org.jetbrains.kotlin:kotlin-stdlib-jdk8")
    }

}

\==`buildSrc`बिल्ड तर्क का स्विस आर्मी चाकू

जब आपके कार्यों की तर्क जटिल हो जाती है या इसे पुनः उपयोग में लाने की आवश्यकता होती है,buildSrcयह प्राथमिक समाधान है। यह एक विशेष Gradle मॉड्यूल है जो मुख्य बिल्ड स्क्रिप्ट्स से पहले संकलित किया जाता है, जिससे इसकी क्लासेस आपके बिल्ड के पूरे क्लासपाथ पर उपलब्ध हो जाती हैं।

\=== क्यों उपयोग करें`buildSrc`कार्यों के लिए ?

  • पुन: उपयोगिताएक परिभाषित कार्य में`buildSrc`इस बिल्ड के किसी भी प्रोजेक्ट में लागू किया जा सकता है।

  • संगठन: बिल्ड कोड को सेंट्रलाइज़ करें, जिससे यह अधिक साफ़ और रखरखाव योग्य हो।

  • टाइप सुरक्षा और ऑटो‑कम्प्लीशन: कोटलिन कोड में`buildSrc`इसे संकलित किया जाता है, जो आपके IDE में त्रुटि जाँच और स्वत पूर्णता प्रदान करता है, विकास अनुभव को बेहतर बनाता है।

\== अभिव्यक्त रिपोर्ट कार्यों का निर्माण

टेस्ट रिपोर्ट्स को संभालने के लिए, हमने एक मॉड्यूलर दृष्टिकोण तैयार किया एक अमूर्त कार्य क्लास का उपयोग करके में`buildSrc`. आपकी आवश्यकताओं के अनुसार, यह वर्ग से विरासत में ले सकता है`DefaultTask` ou de `Exec`.

\=== अमूर्त कार्य`OpenTestReportTask`(से विरासत में प्राप्त`DefaultTask`)

यदि आपको फ़ाइल सिस्टम या अन्य Gradle API के साथ बातचीत करने वाली कस्टम Kotlin तर्क चाहिए, और फिर बाहरी कमांड चलाने की आवश्यकता हो, तो इस दृष्टिकोण की सिफारिश की जाती है।

## [source,kotlin]

package com.yourpackage

आयात org.gradle.api.DefaultTask आयात org.gradle.api.tasks.Input import org.gradle.api.tasks.TaskAction import java.io.File

abstract class OpenTestReportTask : DefaultTask() {








init {
    group = "verification"
    description = "Opens a test report in Firefox."
    dependsOn("check") // Assure que les rapports sont générés
}






@get:Input
abstract var reportPath: String






@TaskAction
fun openReport() {
    val separator = File.separator
    val reportFile = project.layout.projectDirectory.asFile.toPath()
        .resolve(reportPath.replace("/", separator))
        .toAbsolutePath()
        .toFile()








if (!reportFile.exists()) {
    logger.warn("Report file does not exist: $reportFile. Ensure 'check' ran.")
    return
}










    project.exec {
        commandLine("firefox", "--new-tab", reportFile.absolutePath)
    }
    logger.lifecycle("Opened test report: ${reportFile.absolutePath}")
}










## }

\== कार्यों की दृश्यता`buildSrc`

आप जो कार्य और वर्ग परिभाषित करते हैं**buildSrc**हैं :

***दृश्य और उपयोगी**आपके मुख्य बिल्ड के सभी प्रोजेक्ट्स (रूट और सब-प्रोजेक्ट्स)। इसलिए आप उपयोग कर सकते हैं`com.yourpackage.ReportUnitTestsTask`में`allprojects { ... }`. ***गैर-निष्पाद्य**सीधे buildSrc कार्यों के रूप में (उदाहरण के लिए,`gradle :buildSrc:reportTests`यदि कार्य को विशिष्ट रूप से में दर्ज नहीं किया गया है तो यह काम नहीं करेगा`buildSrc/build.gradle.kts`).`buildSrc`यह एक संकलन मॉड्यूल है, एक निष्पादन योग्य एप्लिकेशन मॉड्यूल नहीं, इन मुख्य बिल्ड कार्यों के लिए।

\=== परीक्षणों के लिए एक रिपोर्ट चलाएँ`buildSrc`खुद

Si `buildSrc`अपने स्वयं के परीक्षण होते हैं और यह रिपोर्ट उत्पन्न करता है, आप रिपोर्ट कार्य को सीधे में दर्ज कर सकते हैं`buildSrc/build.gradle.kts`(Empty)

आप फिर इसे निष्पादित कर सकते हैं:`./gradlew :buildSrc:test`के बाद`./gradlew :buildSrc:reportBuildSrcTests`.
