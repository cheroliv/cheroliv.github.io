OpenCode एक मॉडल प्रदाता नहीं है।यह एक ओपन सोर्स CLI है (github.com/anomalyco/opencode) जो IA एजेंट्स को ऑर्केस्ट्रेट करता है। यह सदस्यता नहीं बेचता, यह अनुमान नहीं देता। यह समतुल्य है`git`संस्करण नियंत्रण के लिए : एक उपकरण, सेवा नहीं Ollama Cloud इन्फरेंस प्रदाता है।मेरी स्थानीय Ollama स्थापना client के रूप में कार्य करती है — इसे Device Key के माध्यम से एक अद्वितीय SSH कुंजी के माध्यम से Ollama सर्वरों के साथ प्रमाणित किया जाता है और वह टैग वाले मॉडलों के निष्पादन को उन पर प्रतिनिधिमित करती है`:cloud`. पेशेवर सब्सक्रिप्शन (20€/माह) उच्च कोटे अनलॉक करता है और एक ही मशीन पर कई खातों को Docker के माध्यम से संचय करने की अनुमति देता है।

परिचय: क्यों एक ऑडिट?

दो महीने पहले, मैं अपने स्थानीय ओला इंस्टॉलेशन पर मॉडल्स मुफ्त में उपयोग कर रहा था। फिर मैंने ओला क्लाउड प्रो का पहला सब्सक्रिप्शन लिया, जो 20€/महीने की लागत से है, जो मुझे क्लाउड मॉडल्स (जिनके टैग`:cloud`) के माध्यम से प्रदाता`ollama-cloud`. दूसरा सब्सक्रिप्शन एक महीने बाद अनुसरण किया, एक अलग Docker इंस्टेंस पर, जिसमें उसका अपना खाता और अपनी स्वयं की SSH कुंजी थी — संचय विधि जो मेरे सब्सक्रिप्शनों के संचय पर लेख में वर्णित है।

वह प्रश्न जो मुझे परेशान कर रहा था : क्या ये 20€ प्रति माह न्यायसंगत हैं ? केवल अनुमान से नहीं। संख्याओं के साथ।

जवाब देने के लिए, मुझे सटीक डेटा की आवश्यकता थी। अनुमान नहीं। औसत नहीं। मेरी वास्तविक उपभोग, टोकन दर टोकन, मॉडल दर मॉडल, सेशन दर सेशन।

और OpenCode — CLI — इसे SQLite डेटाबेस में संग्रहीत करता है।

ओपेनकोड डेटाबेस : एक सोने की खान

OpenCode अपने सत्रों के इतिहास का पूरा रिकॉर्ड एक स्थित SQLite फ़ाइल में संग्रहीत रखता है`~/.local/share/opencode/opencode.db`. La mienne pèse 660 Mo pour 73 jours d’utilisation — une base de données de production tout à fait respectable.

टेबल`session`यह एक वैश्विक ऑडिट के लिए आदर्श है : प्रत्येक सत्र का एग्रीगेटेड टोकन count, उपयोग किया गया मॉडल, और लागत होती है। क्षेत्र`model`रॉ JSON है :

{
  "id": "deepseek-v4-pro:cloud",
  "providerID": "ollama-cloud",
  "variant": "default"
}

क्षेत्र`cost`ओपनकोड डेटाबेस में केवल बाह्य API शुल्क दिखाए जाते हैं, जो API कुंजी (Google Gemini, OpenAI, आदि) के माध्यम से उपयोग के आधार पर भुगतान किए जाते हैं। ओल्लामा के माध्यम से किए गए कॉल — चाहे वे स्थानीय हों या ओल्लामा क्लाउड प्रो के माध्यम से — चिह्नित किए जाते हैं।`cost=0`क्योंकि लागत सदस्यता के कारण निश्चित शुल्क है, per-token के बजाय। इन कॉल्स का वास्तविक लागत मासिक सदस्यता है।

निष्कर्षण कोड

किसी भी चीज़ को स्थापित करने की आवश्यकता नहीं है। Node.js 22+ में एक प्रायोगिक SQLite मॉड्यूल एम्बेडेड है (node:sqlite) यह पूरी तरह से काम करता है। यह स्क्रिप्ट है जिसने मुझे सब कुछ दिया :

const { DatabaseSync } = require('node:sqlite');
const db = new DatabaseSync(
  `${process.env.HOME}/.local/share/opencode/opencode.db`,
  { readonly: true }
);

// 1. Statistiques globales
const global = db.prepare(`
  SELECT
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(tokens_reasoning) as total_reasoning,
    SUM(tokens_cache_read) as total_cache_read,
    SUM(cost) as total_cost
  FROM session
`).get();

// 2. Ventilation par modèle et fournisseur
const byModel = db.prepare(`
  SELECT
    json_extract(model, '$.id') as model_id,
    json_extract(model, '$.providerID') as provider,
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(cost) as total_cost
  FROM session
  WHERE model IS NOT NULL
  GROUP BY model_id, provider
  ORDER BY SUM(tokens_input) DESC
`).all();

// 3. Par mois
const monthly = db.prepare(`
  SELECT
    strftime('%Y-%m', datetime(time_created/1000, 'unixepoch')) as month,
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(cost) as total_cost
  FROM session
  WHERE time_created IS NOT NULL
  GROUP BY month
  ORDER BY month
`).all();

// 4. Messages par modèle (détection des changements intra-session)
const msgByModel = db.prepare(`
  SELECT
    json_extract(m.data, '$.model.providerID') as provider,
    json_extract(m.data, '$.model.modelID') as model_id,
    COUNT(*) as messages
  FROM message m
  WHERE json_extract(m.data, '$.model') IS NOT NULL
  GROUP BY provider, model_id
  ORDER BY COUNT(*) DESC
`).all();

console.log({ global, byModel, monthly, msgByModel });
db.close();

झंडा`--experimental-sqlite`Node.js 22.x पर आवश्यक है। Node.js 24+ पर, मॉड्यूल स्थिर है और अब फ़्लैग की आवश्यकता नहीं है।

छिपी हुई लागत: प्रॉम्प्ट इंजीनियरिंग और इटरेशन

टोकन लागत केवल समीकरण का एक हिस्सा है। वास्तविक लागत, डेवलपर का समय है।

OpenCode + Ollama Cloud Pro + मेरे governance agent (EAGER/LAZY/Hot/Warm/Cold, शासन पर लेख में वर्णित) के साथ, मुझे मिलता है :

  • 0 दोहराव वाला प्रॉम्प्ट इंजीनियरिंग: संदर्भ स्वचालित रूप से इंजेक्ट किया जाता है

  • 90%+ पहला शॉट सही: कोड पहले ही प्रयास में संकलित होता है

  • डीपसीक का शून्य हलुसिनेशन 8 लगातार सत्रों में(में दस्तावेज़ीकृत Kimi/GLM/DeepSeek की तुलना)

क्लॉड या GPT sans fine-tune ni शासन :

  • प्रति कार्य के लिए औसत 2-3 पुनरावृत्तियाँ

  • प्रॉम्प्ट इंजीनियरिंग सिस्टेमैटिक

  • Kotlin/Gradle API पर हलूसिनेशन तब होता है जब संदर्भ 30K टोकन से अधिक हो जाता है

मासिक प्रभावी लागत — टोकन × इटरेशन × सुधार का समय — मेरा समाधान की तुलना में 27× से 54× है, जैसा कि मैंने l’article sur le ratio d’efficacité में दिखाया है।

_ यह केवल टोकन प्रति मूल्य की बात नहीं है। 57× मूल्य वाले Claude Opus को 3× अधिक इटरेशन की आवश्यकता होती है, जिससे प्रभावी लागत ~170× अधिक हो जाती है। स्पष्ट रूप से कहें तो: एक इंटर्न को मैकिन्ज़ी पार्टनर की तनख्वाह देना। _

ओलमा क्लाउड प्रो सदस्यताओं को संचित करें: डॉकर की विधि

यदि एक सदस्यता पर्याप्त नहीं है, तो हम उन्हें इकट्ठा करते हैं। सिद्धांत यह है कि प्रत्येक सदस्यता को उसकी propia ओल्लामा इंस्टॉलेशन में अलग किया जाए, उसकी propria SSH प्रमाणीकरण कुंजी के साथ। डॉकर इसे आसान बना देता है।

पूर्ण विधि को l’article sur le cumul Docker में विस्तृत रूप से बताया गया है, सिद्धांत यह है :

पैटर्न सरल है :

  1. एक वॉल्यूम बनाएँ`~/ollama-b-data`

  2. एक Docker कंटेनर लॉन्च करें`ollama/ollama:0.20.2`मैप्ड पर`11435:11434`

  3. कंटेनर से SSH कुंजी प्राप्त करें → इसे ollama.com पर सहेजें

  4. करना`ollama signin`के साथ एक दूसरा ईमेल

  5. OpenCode को दो providers के साथ कॉन्फ़िगर करें(`ollama`पर :11434,`ollama-b`पर :11435)

दो खाते, एक नीला कार्ड, शून्य संघर्ष।
