Bölüm 1: Python ve PyPI için basit bir CI/CD pipeline'ı kurma

Giriş

Hedef : Okuyucuyu, bir Python uygulaması için minimalist ama işlevsel bir CI/CD pipeline kurmakta ve PyPI’ye otomatik dağıtımla birlikte destekleyin.

Geliştirme süreçlerinin otomasyonu modern projelerde kaçınılmaz bir hale gelmiştir. İyi tasarlanmış bir CI/CD hattı, sadece geliştirme döngüsünde regresyonları erken tespit etmeyi değil, aynı zamanda dağıtım sürecinin tamamen otomatize edilmesini de sağlar.

Bu makalede, bir Python uygulaması için GitHub Actions ile tam bir pipeline nasıl kurulacağını keşfedeceğiz, sürekli entegrasyon (CI) den sürekli dağıtım (CD) PyPI’ye kadar.

Pipeline Mimarisi

Pipeline’ımız iki ayrı workflow’tan oluşur :

  1. CI işlem hattı: Her push ve pull request’te çalıştırılır

  2. CD PipelineYalnızca GitHub yayınlarında tetiklendi

Sürekli Entegrasyon (CI) Boru Hattı Yapılandırması

CI İş Akışı Yapısı

CI iş akışı her kod katkısını doğrulamak için tasarlanmıştır. İşte tam yapılandırması:

name: CI/CD Pipeline

on:
  push:
    branches:
      - main
  pull_request:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
    - name: Checkout code
      uses: actions/checkout@v4

    - name: Set up Python
      uses: actions/setup-python@v5
      with:
        python-version: '3.x'

    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install -r requirements.txt
        pip install ruff pytest pytest-mock

    - name: Run Linting (Ruff)
      run: ruff check .

    - name: Run Tests (Pytest)
      run: pytest

CI aşamaları analizi

1. Tetikleyiciler (on)

----
----
on:
  push:
    branches:
      - main
  pull_request:
    branches:
      - main
----

Pipeline ... tetiklenir: - Her push branch üzerinde`main` - Her pull request doğru`main`

Bu yaklaşım, ana kodun stabil kalmasını sağlar ve tüm katkının entegrasyonundan önce doğrulanmasını garantiler.

==== 2. Çalışma Ortamı

----

runs-on: ubuntu-latest

Ubuntu Latest, çoğu Python projesi için performans, maliyet ve uyumluluk arasında iyi bir kompromis sunar.

==== 3. Kodun Checkout'u

```yaml
----
----
- name: Checkout code
  uses: actions/checkout@v4
----

Eylem`checkout@v4`deposodan kaynak kodunu alır. v4 sürümü performans ve güvenlik iyileştirmeleri sunar.

==== 4. Python yapılandırması

----

- name: Set up Python uses: actions/setup-python@v5 with: python-version: '3.x'

Kullanımının`'3.x'`Python 3'ün en son stabil sürümü kullanmasını sağlar, bakımı basitleştirir.

==== 5. Bağımlılıkların Kurulumu

```yaml
----
----
- name: Install dependencies
  run: |
    python -m pip install --upgrade pip
    pip install -r requirements.txt
    pip install ruff pytest pytest-mock
----

Bu adım: - Pip'i son sürüme güncelleyin - Proje bağımlılıklarını kur - Geliştirme araçlarını ekleyin (lint ve test)

==== 6. Ruff ile lintleme

----

- name: Run Linting (Ruff) run: ruff check .

**Ruff**Çok hızlı Rust ile yazılmış bir Python linter'idir. Birkaç araç (Flake8, Black, isort) işlevlerini tek performanslı bir araçta birleştirir.

==== 7. Testlerin yürütülmesi

```yaml
----
----
- name: Run Tests (Pytest)
  run: pytest
----

Pytest, test süitinin tamamını çalıştırarak, değişikliklerin regresyon getirmediğini garanti eder.

== Dağıtım pipeline'ı (CD) yapılandırması

=== CD workflowün yapı

CD workflow'u yalnızca GitHub yayınlarında tetiklenir ve PyPI üzerindeki yayınlamayı otomatikleştirir :

[source,yaml]
----
name: Publish to PyPI

on:
  release:
    types:
      - published

jobs:
  deploy:
    runs-on: ubuntu-latest

    steps:
    - name: Checkout code
      uses: actions/checkout@v4

    - name: Set up Python
      uses: actions/setup-python@v5
      with:
        python-version: '3.x'

    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install setuptools wheel twine

    - name: Build and publish
      env:
        TWINE_USERNAME: __token__
        TWINE_PASSWORD: ${{ secrets.PYPI_API_TOKEN }}
      run: |
        python setup.py sdist bdist_wheel
        twine upload dist/*
----

=== CD Aşamaları Analizi

==== Tetikleyici Serbest Bırakma

----

on: release: types: - published

CD boru hattı, sadece bir GitHub yayınının yayınlandığı zaman tetiklenir. Bu yaklaşım, dağıtımların hassas kontrolünü sağlar.

==== 2. Derleme Araçlarının Kurulumu

```yaml
----
----
pip install setuptools wheel twine
----

- **setuptools**: Python paketleme araçları - **teknek**Modern Python dağıtım formatı - **iplik**PyPI'ye güvenli yükleme aracı

==== 3. Kimlik Doğrulama Yapılandırması

----

env: TWINE_USERNAME: __token__ TWINE_PASSWORD: ${{ secrets.PYPI_API_TOKEN }}

Kimlik doğrulaması, PyPI API jetonunu GitHub'de bir gizli olarak depolayarak yapılır, klasik kimlik bilgilerinden daha güvenlidir.

==== 4. Derleme ve Yayın

```yaml
----
----
run: |
  python setup.py sdist bdist_wheel
  twine upload dist/*
----

- `sdist`: Kaynak dağıtımı oluştur - `bdist_wheel`: Bir wheel (ikili dağıtım) oluştur - `twine upload`Dağıtımları PyPI'ye yayınla

== Python Paketi Yapılandırması

=== setup.py yapısı

Pipeline çalışması için projeniz bir dosya içermelidir.`setup.py`:

[source,python]
----
from setuptools import setup, find_packages

with open("README.adoc", "r", encoding="utf-8") as fh:
    long_description = fh.read()

setup(
    name="playlist-downloader",
    version="1.0.0",
    author="Votre Nom",
    author_email="votre.email@example.com",
    description="CLI tool for managing YouTube playlists",
    long_description=long_description,
    long_description_content_type="text/plain",
    url="https://github.com/cheroliv/playlist-downloader",
    packages=find_packages(),
    classifiers=[
        "Development Status :: 4 - Beta",
        "Intended Audience :: Developers",
        "License :: OSI Approved :: MIT License",
        "Operating System :: OS Independent",
        "Programming Language :: Python :: 3",
        "Programming Language :: Python :: 3.8",
        "Programming Language :: Python :: 3.9",
        "Programming Language :: Python :: 3.10",
        "Programming Language :: Python :: 3.11",
    ],
    python_requires=">=3.8",
    install_requires=[
        "typer>=0.9.0",
        "yt-dlp>=2023.1.6",
        "google-api-python-client>=2.70.0",
        "google-auth-oauthlib>=0.7.1",
        "pymonad>=2.4.0",
        "pyyaml>=6.0",
    ],
    entry_points={
        "console_scripts": [
            "playlist-downloader=cli:app",
        ],
    },
)
----

=== setup.py'nin temel noktaları

1. **meta veriler**: İsim, sürüm, yazar, açıklama
2. **bağımlılıklar**Gereken paketler listesi
3. **Giriş Noktaları**: Açık CLI komutları
4. **Sınıflandırıcılar**: PyPI için metadata

== GitHub Secrets ile Güvenlik

=== PyPI Belirteci Yapılandırması

1. **PyPI'de bir API jetonu oluştur** :

PyPI'ye giriş yapın - Hesap Ayarları > API jetonlarına gidin - İzinleri uygun olan yeni bir jeton oluşturun

1. **GitHub'da sırrı ekle**:

- Depo Ayarları > Gizli Bilgiler ve Değişkenler > Eylemler - Yeni bir isimli gizli anahtar oluşturun`PYPI_API_TOKEN` - PyPI token'ınızı yapıştırın

CI_Running --> CI_Success : All checks pass
CI_Running --> CI_Failed : Linting/Tests fail
CI_Success --> Idle : Merge completed
CI_Failed --> Idle : Fix and retry

Idle --> CD_Running : Release published
CD_Running --> CD_Success : Package published
CD_Running --> CD_Failed : Build/Upload error
CD_Success --> Idle : Package available on PyPI
CD_Failed --> Idle : Fix and retry release

note on link #red : Blocks merge
note on link #green : Allows deployment

== İyi Uygulamalar ve Optimizasyonlar

=== 1. Versiyon Yönetimi

Semantik Git taglarını kullanın

----

git tag -a v1.2.3 -m "Release version 1.2.3" git push origin v1.2.3

=== 2. Matris Testleri

Birden fazla Python sürümü için test yapmak :

```yaml
----
----
strategy:
  matrix:
    python-version: [3.8, 3.9, "3.10", "3.11"]
----

=== 3. Bağımlılık Önbelleği

Önbellekle derlemeleri hızlandırın :

----

- name: Cache pip dependencies uses: actions/cache@v3 with: path: ~/.cache/pip key: ${{ runner.os }}-pip-${{ hashFiles('**/requirements.txt') }}

=== 4. Dağıtım Ortamları

GitHub ortamlarını kontrollü dağıtımlar için kullanın:

```yaml
----
----
jobs:
  deploy:
    environment: production
    runs-on: ubuntu-latest
----

== Nazaret ve Hata Ayıklama

=== Günlükler ve İzleme

GitHub Actions her adım için detaylı loglar sağlar. Hata ayıklamak için:

1. **Logları inceleyin**her bir adım
2. **Hata ayıklamayı etkinleştir**ile`ACTIONS_STEP_DEBUG`
3. **Artifact'ları kullanın**derleme dosyalarını kaydetmek için

----

- name: Upload build artifacts uses: actions/upload-artifact@v3 if: failure() with: name: build-logs path: build/

=== Bildirimler

Slack veya e-posta bildirimleri ekleyin :

```yaml
----
----
- name: Notify on failure
  if: failure()
  uses: 8398a7/action-slack@v3
  with:
    status: ${{ job.status }}
    webhook_url: ${{ secrets.SLACK_WEBHOOK }}
----

== Sonuç

GitHub Actions ile sağlam bir CI/CD pipeline'ı kurmak, geliştirme deneyimini radikal olarak dönüştürür. Linting, testleri ve dağıtımı otomatikleştirerek, siz :

- **Hata azalt**üretimde - **Döngüleri hızlandırın**gelişim - **Güveni artırın**sürümlerinizde - **İşbirliğini kolaylaştırın**ekip olarak

Bu pipeline, linting araçları, test çerçeveleri veya dağıtım hedefleri ayarlanarak farklı türdeki Python projelerine uyarlanabilir.

Bu iş akışlarını yapılandırmaya yönelik ilk yatırım, dağıtımlar sırasında zaman kazancı ve manuel hataların azalması sayesinde hızla geri kazanılır.

Python'un çoklu sürüm testleri,

Otomatik güvenlik analizi,

Test PyPI üzerinden aşamalı dağıtım,

Pipeline izleme ve ölçümleri,

Bir sonraki bölümde, bir üst seviyeye geçeceğiz. Temel bu pipeline'ı, üretim için hazır, sağlam, güvenli ve gerçek bir endüstriyel dağıtım zinciri haline dönüştürmeyi öğreneceksiniz.
