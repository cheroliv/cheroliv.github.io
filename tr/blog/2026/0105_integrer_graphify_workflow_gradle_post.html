Kod tabanınız büyüyor. Modüller arasındaki bağımlılıklar artıyor. Mimari dokümantasyon yazılmadan önce eski hale geliyor. Ve Gradle build’iniz otomatik olarak gerçek kod yapısından güncel diyagramlar üretebilseydi? İşte bu tam olarak Graphify + PlantUML Gradle Plugin pipeline’inin yaptığı şeydir:`graphify . --no-viz`Knowledge Graph’i çıkarır`./gradlew generateKnowledgeGraphDiagram`Onu PlantUML diyagramlarına dönüştürür. Sıfır LLM, sıfır kılavuz, %100 deterministik.

Sorun: şema her zaman kodun arkasında

Binlerce satırı aşan her proje bu sendromu yaşar:

  1. Proje başında bir mimari diyagram çizeriz

  2. Kod gelişiyor, bağımlılıklar değişiyor

  3. Diyagram, süslenmiş bir yalan olur

  4. Hiç kimse bunu güncellemez çünkü yorucu.

  5. Yeni gelenler ona dayanır ve hatalar yapar.

Çözüm: bir deterministik Knowledge Graph → PlantUML hattı

Diagramları elle çizmek yerine, onlarıgerçek kod yapısından üretir.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

actor Développeur
component "Graphify\n(pip install graphifyy)" as Graphify
collections "graphify-out/graph.json\n(Bilgi Grafiği)" as KGJSON
component "PlantUML Gradle Eklentisi\n(generateKnowledgeGraphDiagram)" as Plugin
component "KnowledgeGraphParser" as Parser
component "KnowledgeGraphRenderer" as Renderer
component "PlantumlService\n(doğrulama + PNG oluşturma)" as PS
collections "diyagramlar/bilgi-grafiği/\n(.puml + .png)" as Output

Développeur --> Graphify : graphify . --no-viz
Graphify --> KGJSON : extrait la structure\ndu code source
Développeur --> Plugin : ./gradlew generateKnowledgeGraphDiagram
Plugin --> Parser : parse(graph.json)
Parser --> Plugin : KnowledgeGraph\n(noeuds + arêtes + communautés)
Plugin --> Renderer : render(graph, filters)
Renderer --> Plugin : code PlantUML\ndéterministe
Plugin --> PS : validateSyntax + generateImage
PS --> Output : .puml + .png

note bottom of Plugin
  Pipeline DÉTERMINISTE
  Aucun appel LLM
  Résultat reproductible
end note

@enduml

İki komut. Sadece bu.

# Étape 1 : extraire le Knowledge Graph
graphify . --no-viz

# Étape 2 : générer les diagrammes PlantUML
./gradlew generateKnowledgeGraphDiagram

Sonuç? Dosyalar`.puml` et .png`içinde`diagrams/knowledge-graph/, Git’te sürüm kontrolü altında, kodla her zaman güncel.

Adım 1: Graphify’i kurun ve Knowledge Graph’i çıkarın

Kurulum

Graphify, kod tabanınızı analiz eden ve yapılandırılmış bir bilgi grafiği oluşturan bir Python aracıdır:

# Méthode recommandée
uv tool install graphifyy && graphify install --platform opencode

# Alternative avec pip
pip install graphifyy && graphify install --platform opencode

İstisnaları yapılandır

Bir dosya oluştur`.graphifyignore`proje kökünde iş mantığına ait olmayan dosyaları hariç tutmak için:

# Secrets — JAMAIS dans le graphe
*-context.yml
*.env

# Fichiers générés
build/
.gradle/

# Tests fonctionnels
src/functionalTest/

Knowledge Graph’i çıkart

graphify . --no-viz

Bayrak`--no-viz`HTML oluşturmayı atlar (Gradle pipeline’ında gereksiz). Sonuç bir dosyadır.`graphify-out/graph.json`içeren :

  • düğümler: sınıflar, fonksiyonlar, dosyalar — tipi ve topluluğu ile

  • kenarlar: düğümler arasındaki ilişkiler (koddan çıkarılan, LLM tarafından çıkarılan)

  • Topluluklar: otomatik bağlı düğüm gruplamaları

Örnek yapı`graph.json`
{
  "nodes": [
    {"id": "0", "label": "LlmService", "file_type": "code", "community": 0},
    {"id": "1", "label": "ApiKeyPool", "file_type": "code", "community": 0},
    {"id": "2", "label": "PlantumlService", "file_type": "code", "community": 1}
  ],
  "links": [
    {"source": "1", "target": "0", "relation": "uses", "confidence": "EXTRACTED", "weight": 0.9},
    {"source": "0", "target": "2", "relation": "calls", "confidence": "INFERRED", "weight": 0.7}
  ]
}

Kaynak kod (.kt, .java) tree-sitter tarafından yerel olarak analiz edilir,itiraz edilemez LLM. Sadece belge dosyaları (.adoc, .md) gerektirir bir LLM çağrısı anlamsal çıkarma için. Bu yüzden`--update`Kotlin kodu üzerinde çalıştırma neredeyse anlık.

Adım 2: Gradle eklentisi, Knowledge Graph’i PlantUML’e dönüştürür.

İşlem hattı mimarisi

Eklenti`com.cheroliv.plantuml`bir görevi içerir`generateKnowledgeGraphDiagram`dönüştüren`graph.json`PlantUML diagramları olarak bir şekildetamamen belirleyici :

@startuml
skinparam backgroundColor #FEFEFE

participant "Gradle" as G
participant "Bilgi Grafiği Diyagramı Görevi Oluştur" as Task
participant "KnowledgeGraphParser" as Parser
participant "Bilgi Grafiği Görüntüleyici" as Renderer
participant "PlantumlService" as PS

collections "graphify-out/graph.json" as JSON

G -> Task : execute
Task -> JSON : read
Task -> Parser : parse(graph.json)
Parser --> Task : KnowledgeGraph\n(noeuds + arêtes + communautés)
Task -> Renderer : render(graph, filters)
Renderer --> Task : code PlantUML\n(déterministe)
Task -> PS : validateSyntax(plantumlCode)
alt syntaxe valide
    Task -> PS : generateImage → .png
else syntaxe invalide
    Task -> Task : save .puml avec warning
end

@enduml

İç bileşenler

bileşen Rol

KnowledgeGraphParser

ayıklamak`graph.json`— 3 formatı destekler: yerel graphify (nodes+links), miras (communities), flat. Sayısal ID’leri etiketlere çözer.

KnowledgeGraphRenderer

Belirleyici şekilde bir dönüştürür`KnowledgeGraph`PlantUML kodu. Tiplere göre gruplar, paketlerde topluluklar, otomatik efsane.

GenerateKnowledgeGraphDiagramTask

Gradle tarafından parse → render → validate → PNG işlemini orkestralayan görev. Gradle özellikleri üzerinden yapılandırılabilir.

kgmodels.kt

Veri modelleri :`KnowledgeGraph`, KnowledgeGraphNode, KnowledgeGraphEdge, KnowledgeGraphCommunity, EdgeType.

PlantumlService

Sözdizimi doğrulama + PNG işleme (pluginin tüm görevleri tarafından yeniden kullanılır).

Render kuralları

Renderer, deterministik görsel kuralları uygular:

kenar tipi PlantUML notasyonu anlam

EXTRACTED

-→(düz çizgi, siyah)

Kaynak koddan çıkarılan ilişki (güven)

çıkarılmış

..>(noktalı çizgi)

LLM tarafından çıkarılan ilişki (güven skoru)

belirsiz

--x(kırmızı noktalı çizgi)

Belirsiz ilişki (kontrol edilecek)

Topluluklar, otomatik renk paleti içeren PlantUML paketleri olarak gösterilir.

Adım 3: Günlük kullanım

Tam diagram

# Générer le diagramme du Knowledge Graph complet
./gradlew generateKnowledgeGraphDiagram

Çıktı:`diagrams/knowledge-graph/knowledge-graph-full.puml`+.png

Topluluğa göre filtrele

# Une seule communauté
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.community=community_0

# Limiter le nombre de noeuds (lisibilité)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.community=community_0 \
  -Pplantuml.kg.maxNodes=15

Kenar tipine göre filtrele

# Uniquement les relations certaines (EXTRACTED)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.edgeTypes=EXTRACTED

# Relations certaines + inférées
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.edgeTypes=EXTRACTED,INFERRED

Düğüm tipi ve güvenilirlik göre filtrele

# Uniquement les classes de code
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.nodeTypes=code

# Seuil de confiance minimum (pour les INFERRED)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.minConfidence=0.7

Özel çıktı dizini

./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.outputDir=docs/architecture

Özelliklerin tam referansı

Mülkiyet varsayılan Açıklama

plantuml.kg.edgeTypes

plantuml.kg.minConfidence

0.0

plantuml.kg.maxNodes

(sınırsız)

Gösterilecek maksimum düğüm sayısı

plantuml.kg.nodeTypes

(herkes)

Virgülle ayrılmış düğüm türleri (örnek.class, code)

plantuml.kg.outputDir

Tam boru hattı bir Gradle iş akşında

İş akışı tipi

@startuml
skinparam backgroundColor #FEFEFE
skinparam ActivityBackgroundColor #E8F4FD
skinparam ActivityDiamondBackgroundColor #FFF3CD
skinparam ActivityBorderColor #2C3E50

start

partition "ÇIKARMA" {
    :graphify . --no-viz;
    note right: Analyse le code source\ntree-sitter (local, pas de LLM)

    :graphify-out/graph.json;
    note right: Noeuds + arêtes\n+ communautés
}

partition "NESİL" {
    :./gradlew generateKnowledgeGraphDiagram;
    note right: Pipeline déterministe\nparse → render → validate → PNG

    if (Filtres actifs ?) then (Oui)
        :Appliquer filtres\n(community, edgeTypes,\nmaxNodes, nodeTypes);
    else (Non)
        :Diagramme complet;
    endif

    :diagrams/knowledge-graph/\nknowledge-graph-full.puml\nknowledge-graph-full.png;
}

partition "ENTEGRASYON" {
    :git add diagrams/knowledge-graph/;
    :git commit;
    note right: Diagrammes versionnés\ntoujours à jour avec le code
}

stop

@enduml

Geliştirme döngüsüne entegrasyon

Pipeline, geliştirmenin temel aşamalarına doğal olarak entegre olur:

@startuml
skinparam backgroundColor #FEFEFE

state "Gelişme" as dev
state "Çıkarım\ngraphify . --no-viz" as extract
state "Oluşturma\n./gradlew generateKnowledgeGraphDiagram" as generate
state "Commit\nsürümlenmiş diyagramlar" as commit

[*] --> dev
dev --> extract : Code modifié
extract --> generate : graph.json à jour
generate --> commit : .puml + .png générés
commit --> dev : Diagrammes dans le repo

note right of extract
  Quasi instantané sur du code Kotlin
  (tree-sitter, pas de LLM)
end note

note right of generate
  Déterministe
  Pas de LLM
  Résultat reproductible
end note

@enduml

Artımlı güncelleme

Kod değiştiğinde, tüm grafiği sıfırdan yeniden inşa etmemize gerek yok:

# Mise à jour incrémentale (fichiers modifiés uniquement)
graphify . --update

# Puis régénérer les diagrammes
./gradlew generateKnowledgeGraphDiagram

--update`sadece değiştirilen dosyaları yeniden çıkarır (SHA256 ile tespit edilen`graphify-out/cache/). Kotlin kod üzerinde, tree-sitter yerel olarak çalıştığı için LLM çağrısı yapmadan hemen hemen anlık olarak çalışır.

Dogfooding: eklenti kendi kendini belgeliyor

PlantUML eklentisi, prompt’ları diyagramlara dönüştürmek için vardır. Ayrıca kendi propre kod tabanının Knowledge Graph’ını da belgeleme diyagramlarına dönüştürebilir. Bu dogfooding : eklentiyi kendi hizmetini tüketiyor.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

package "Normal işlem hattı\n(kullanıcı → diyagramlar)" as normal {
    [Fichier .prompt] as prompt
    [LlmService\n+ ApiKeyPool] as llm1
    [ProcessPlantumlPromptsTask] as task1
    [Diagramme PNG] as out1

    prompt --> task1
    task1 --> llm1
    llm1 --> out1
}

package "Pipeline Bilgi Grafiği\n(deterministik, LLM yok)" as kg {
    [graphify-out/graph.json] as kgjson
    [KnowledgeGraphParser] as parser
    [KnowledgeGraphRenderer] as renderer
    [PlantumlService] as ps
    [Diagramme PNG\n(documentation du plugin)] as out2

    kgjson --> parser
    parser --> renderer
    renderer --> ps
    ps --> out2
}

package "Pipeline Dogfooding\n(LLM → eklenti dokümantasyonu)" as dogfood {
    [GraphifyPromptAdapter] as gpa
    [Fichiers .prompt\nauto-générés] as auto_prompt
    [LlmService\n+ ApiKeyPool] as llm2
    [ProcessPlantumlPromptsTask] as task2
    [Diagramme PNG\n(documentation LLM)] as out3

    kgjson --> gpa
    gpa --> auto_prompt
    auto_prompt --> task2
    task2 --> llm2
    llm2 --> out3
}

note "Aynı LlmService, aynı ApiKeyPool,\naynı PlantumlService\n— SIFIR tekrar" as N

@enduml

Neden determinist (ve neden önemli)

Pipeline’ın ana noktası`generateKnowledgeGraphDiagram`:Hiçbir LLM aramıyor. Dönüşüm`graph.json`→ PlantUML pure bir fonksiyondur.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

rectangle "Deterministik İşlem Hattı\n(generateKnowledgeGraphDiagram)" as det {
    [graph.json] as json
    [KnowledgeGraphParser] as parser
    [KnowledgeGraphRenderer] as renderer
    [PlantUML code] as puml

    json --> parser : parse
    parser --> renderer : KnowledgeGraph
    renderer --> puml : render (fonction pure)
}

rectangle "LLM İşlem Hattı\n(processPlantumlPrompts)" as llm {
    [.prompt] as prompt
    [LlmService] as llmSvc
    [ChatModel] as model
    [PlantUML code] as puml2

    prompt --> llmSvc
    llmSvc --> model : API call
    model --> puml2 : réponse non-déterministe
}

note bottom of det
  Même entrée → même sortie
  Pas de latence réseau
  Pas de coût en tokens
  Reproductible en CI
end note

note bottom of llm
  Même entrée → sortie variable
  Latence réseau (1-5s)
  Coût en tokens
  Nécessite une clave API
end note

@enduml

Somut faydalar :

Avantaj Etki

Tekrarlanabilirlik

Bile`graph.json`→ aynı diyagram. Tam olarak. Her zaman.

Ücretsiz

LLM çağrısı yok = token yok = API faturalandırması yok.

Sıfır gecikme

Parse + render yaklaşık ~100ms sürer, 1-5 saniye değil.

CI ile uyumlu

API anahtarı gerekli değil. Değişken LLM yanıtı nedeniyle kararsız test yok.

sürüm yapılabilir

Le .puml`oluşturulmuş bir metindir. Bunu yapabiliriz`diff, PR’deki inceleyen, Git’te sürümle

Döngüyü kapatmak için, eklenti tarafından üretilmiş olduğu şekilde pipeline diyagramı şu şekildedir:

@startuml
skinparam backgroundColor #FEFEFE

participant "Geliştirici" as Dev
participant "Gradle" as G
participant "GenerateKnowledgeGraphDiagramTask" as Task

participant "KnowledgeGraphRenderer" as Renderer

collections "graphify-out/graph.json" as JSON
collections "diyagramlar/bilgi-grafiği/" as Out

Dev -> G : ./gradlew generateKnowledgeGraphDiagram
G -> Task : execute
Task -> JSON : read
Task -> Parser : parse(graph.json)
Parser --> Task : KnowledgeGraph

alt filtres actifs
    Task -> Task : appliquer filtres\n(community, edgeTypes, maxNodes…)

Renderer --> Task : code PlantUML

@enduml

Proje yönetimine entegrasyon

Bizim projemizde, bu pipeline, IA ajanı için EAGER/LAZY bağlam yönetimi stratejisine entegre edilir. Knowledge Graph, manuel mimari dokümantasyonunun yerine yapılandırılmış, sorgulanabilir ve otomatik güncellenebilen bir grafik konur.

@startuml
skinparam backgroundColor #FEFEFE
skinparam componentStyle rectangle

package "EAGER\n(her zaman yüklü)" as eager {
    [PROMPT_REPRISE.adoc\n(contexte session)] as pr
    [INDEX.adoc\n(vue d'ensemble)] as idx
    [GRAPH_REPORT.adoc\n(~50 lignes)] as gr
}

package "LAZY — Strateji\n(talep üzerine)" as lazy_strat {
    [Méthodologies] as meth
    [Archives sessions] as sessions
}

package "LAZY — Graphify\n(hedefli sorgular)" as lazy_graph {
    [graph.json] as gj
    [Queries\n(query/path/explain)] as queries
}

package "PlantUML İşlem Hattı\n(otomatik oluşturulmuş)" as puml {
    [generateKnowledgeGraphDiagram] as kgTask
    [generateDiagramDocs] as ddTask
    [Diagrammes PNG] as diagrams
}

Agent --> eager : Lit en début de session
Agent ..> lazy_strat : Charge si type détecté
Agent ..> lazy_graph : Query si besoin structurel
kgTask --> diagrams : Déterministe
ddTask --> diagrams : Via LLM

note right of gr
  Condensé du Knowledge Graph
  God nodes + communautés
  Remplace ECOSYSTEM_OVERVIEW
  (225 lignes → 50 lignes)
end note

@enduml

İki sistemin birleşimi tamamlayıcıdır :

  • Strateji NE zaman ve NASIL’i yönetir— yönetim, iş akışı, arşivleme

  • Graphify, neyi ve nerede’yi yönetir.kod yapısı, ilişkiler, hedefli sorgular

_ Oturum stratejisi yönetirNE ZAMAN et le nasıl(yönetim, iş akışı, eşikler), Graphify yönetirNE et le nerede(kod yapısı, ilişkiler, hedefli sorgular). PlantUML iş hattı yönetirNeyle?(deterministik diyagramlar, versiyonlanmış, her zaman güncel). _

Kullanmak`graphify . --update`düzenli olarak veya git kancası`graphify hook install`

Güncellenmiş maliyet

Artımlı güncellemeler neredeyse ücretsizdir (tree-sitter local)

Sadece belgeler (.adoc) LLM tokenları tüketir

Sonuçta elde edilen

@startuml
skinparam backgroundColor #FEFEFE

rectangle "ÖNCE" as avant {
    card "Elle çizilmiş diyagramlar\nHer zaman eskimiş\nKimse onları güncellemiyor" as av1 #FDEDEC
}

rectangle "SONRA" as apres {
    card "Otomatik oluşturulan diyagramlar\nKodla her zaman güncel\nGit'te sürümlenmiş\nDeterministik ve yeniden üretilebilir" as ap1 #E8F8E8
}

avant --> apres : graphify . --no-viz\n+ ./gradlew generateKnowledgeGraphDiagram

@enduml

Somut faydalar:

Kar detay

Her zaman güncel dokümantasyon

Diyagramlar, mevcut kodu yansıtır, manuel bir anlık görüntü değildir.

Sıfır bakım çabası

Diagramlar her bir build’te yeniden oluşturulur.

Teknik borcun azaltılması

Diyagramları elle tutmak zorunda kalmanıza gerek yok.

Yeni başlayanlar için görsel bağlam

Yeni bir geliştirici, diyagramları inceleyerek mimariyi anlar.

Potansiyel fine-tuning

Çiftler (alt-grafik → diyagram) IA eğitimi örnekleridir.

Otomatik doğrulama

`PlantumlService.validateSyntax()`Oluşturulan her diyagramı kontrol eder

Hızlı onboarding

5 diyagram = mimarinin tam görünüm

_ Bir _neden olan herkes, tüm nasıl_lar dayanabilir. _

Neden : Her zaman güncel diyagramlar. Nasıl : Bir Gradle pipeline’ında iki komut.
