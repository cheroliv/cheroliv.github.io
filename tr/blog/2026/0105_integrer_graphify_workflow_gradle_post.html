Okuma süresi : 12 minutes

Codebaseniz büyüyor. Modüller arasındaki bağımlılıklar artıyor. Mimari dokümantasyon, yazılmadan önce güncelliğini yitiriyor. Ve Gradle build’inizin otomatik olarak gerçek kod yapısından güncel diyagramlar üretebileceğinizi hayal edin? Bu, Graphify + PlantUML Gradle Plugin işlem hattının tam olarak yaptığı şey:`graphify . --no-viz`Knowledge Graph’ı çıkarır`./gradlew generateKnowledgeGraphDiagram`onu PlantUML diagramlarına dönüştürür. Sıfır LLM, sıfır kılavuz, %100 determinist.

Sorun: diagramlar her zaman koddan geride kalıyor

Binlerce satırı aşan her proje bu sendromu yaşar:

  1. Projenin başında bir mimari diyagramı çizeriz.

  2. Kod gelişir, bağımlılıklar değişir

  3. Diyagram, dekoratif bir yalan hâline geliyor

  4. Kimse onu güncellemez çünkü zorlayıcıdır.

  5. Yeni gelenler ona dayanır ve hatalar yapar.

Soru şema gerekir mi ? — herkes evet bilir. Soru :Onları güncel kim tutar?

Cevap: kimse. Otomatik olduğu zaman.

Çözüm : bir deterministik pipeline Knowledge Graph → PlantUML

Prinsip basittir : Diagramleri elle çizmek yerine, onlarıgerçek kod yapısından üretir.

İki komut. Sadece.

# Étape 1 : extraire le Knowledge Graph
graphify . --no-viz

# Étape 2 : générer les diagrammes PlantUML
./gradlew generateKnowledgeGraphDiagram

Sonuç ? Dosyalar`.puml` et .png`içinde`diagrams/knowledge-graph/, Git’te versiyon kontrolü altında, kodla her zaman güncel.

Adım 1: Graphify’i yükleyin ve Knowledge Graph’i çıkarın

Kurulum

Graphify, kod tabanınızı analiz eden ve yapılandırılmış bir bilgi grafiği oluşturan bir Python aracıdır.

# Méthode recommandée
uv tool install graphifyy && graphify install --platform opencode

# Alternative avec pip
pip install graphifyy && graphify install --platform opencode

Istisnaları yapılandır

Dosya oluştur`.graphifyignore`proje kök dizininde, iş mantığının bir parçası olmayan dosyaları dışlamak için :

# Secrets — JAMAIS dans le graphe
*-context.yml
*.env

# Fichiers générés
build/
.gradle/

# Tests fonctionnels
src/functionalTest/

Knowledge Graph’ı çıkarma

graphify . --no-viz

bayrak`--no-viz`HTML üretimini atlar (Gradle pipeline’ında gereksiz). Sonuç bir dosya.`graphify-out/graph.json`içeren :

  • düğümlersınıflar, fonksiyonlar, dosyalar — tipi ve topluluğu ile

  • Kenarlardüğümler arasındaki ilişkiler (EXTRACTED koddan, INFERRED LLM tarafından)

  • topluluklarbağlı düğümlerin otomatik gruplamaları

Yapı örneği`graph.json`
{
  "nodes": [
    {"id": "0", "label": "LlmService", "file_type": "code", "community": 0},
    {"id": "1", "label": "ApiKeyPool", "file_type": "code", "community": 0},
    {"id": "2", "label": "PlantumlService", "file_type": "code", "community": 1}
  ],
  "links": [
    {"source": "1", "target": "0", "relation": "uses", "confidence": "EXTRACTED", "weight": 0.9},
    {"source": "0", "target": "2", "relation": "calls", "confidence": "INFERRED", "weight": 0.7}
  ]
}

Kaynak kod (.kt, .java) yerel olarak tree-sitter tarafından analiz edilir,çağrı olmadan LLM. Sadece belge dosyaları (.adoc, .md) bir LLM çağrısı semantik çıkarma için gerektirir. Dolayısıyla`--update`Kotlin kodunu tarama hemen hemen anıktır.

Adım 2: Gradle eklentisi, Knowledge Graph’ü PlantUML’e dönüştürür.

Pipeline mimarisi

Eklenti`com.cheroliv.plantuml`Bir görevi entegre eder`generateKnowledgeGraphDiagram`dönüştürür`graph.json`PlantUML diyagramlarında biçimindetamamen deterministik:

İç bileşenler

Bileşen rol

KnowledgeGraphParser

Ayrıştır`graph.json`— destekler 3 formatlar : graphify yerel (nodes(Empty output)links), miras (communities), düz. Çözer IDs sayısal etiket olarak.

KnowledgeGraphRenderer

Deterministik şekilde bir`KnowledgeGraph`PlantUML kodunda. Tiplere göre gruplar, Paketlerdeki topluluklar, Otomatik legend.

GenerateKnowledgeGraphDiagramTask

Gradle görevi, parse → render → validate → PNG akışını düzenler. Gradle özellikleri aracılığıyla yapılandırılabilir.

kgmodels.kt

Veri modelleri :`KnowledgeGraph`, KnowledgeGraphNode, KnowledgeGraphEdge, KnowledgeGraphCommunity, EdgeType.

PlantumlService

Söz dizimi doğrulama + PNG oluşturma (eklentinin tüm görevleri tarafından yeniden kullanılır).

Görüntüleme kuralları

Renderer, deterministik görsel kurallarını uygular:

Kenar tipi PlantUML notasyonu Anlam

Çıkarılmış

-→(sabit çizgi, siyah)

Kaynak koddan çıkarılmış ilişki (kesinlik)

INFERRED

..>(noktalı çizgi)

LLM tarafından çıkarılan ilişki (güven skoru)

AMBIGUOUS

--x(kırmızı noktalı çizgi)

Belirsiz ilişki (doğrulanmalı)

Topluluklar, otomatik renk paleti olan PlantUML paketleri olarak gösterilir.

Adım 3: Günlük kullanım

Tam diyagram

# Générer le diagramme du Knowledge Graph complet
./gradlew generateKnowledgeGraphDiagram

Çıktı :`diagrams/knowledge-graph/knowledge-graph-full.puml`+.png

Topluluk göre filtrele

# Une seule communauté
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.community=community_0

# Limiter le nombre de noeuds (lisibilité)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.community=community_0 \
  -Pplantuml.kg.maxNodes=15

Kenar tipine göre filtrele

# Uniquement les relations certaines (EXTRACTED)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.edgeTypes=EXTRACTED

# Relations certaines + inférées
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.edgeTypes=EXTRACTED,INFERRED

Düğüm tipi ve güvene göre filtrele

# Uniquement les classes de code
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.nodeTypes=code

# Seuil de confiance minimum (pour les INFERRED)
./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.minConfidence=0.7

Özel Çıktı Dizini

./gradlew generateKnowledgeGraphDiagram \
  -Pplantuml.kg.outputDir=docs/architecture

Geliştirme döngüsü entegrasyonu

Pipeline, geliştirmenin ana aşamalarına doğal bir şekilde entegre olur:

Artımlı güncelleme

Kod değiştiğinde, tüm grafiği sıfırdan yeniden oluşturmamız gerekmez:

# Mise à jour incrémentale (fichiers modifiés uniquement)
graphify . --update

# Puis régénérer les diagrammes
./gradlew generateKnowledgeGraphDiagram

--update`sadece değiştirilmiş dosyaları yeniden çıkarır (SHA256 ile algılanan`graphify-out/cache/) Kotlin kodunda, tree-sitter yerel olarak çalıştığı için bir LLM çağrısı yapmadan hemen hemen anlık olur.

Dogfooding: Eklenti kendi belgesini yazar.

PlantUML eklentisi, prompt’ları diyagramlara dönüştürmek için vardır. Ayrıca kendi kendi kod tabanının Knowledge Graph’ını da dokümantasyon diyagramlarına dönüştürebilir. Bu dogfooding: eklenti kendi hizmetini tüketir.

İlgili Gradle görevleri:

Görev LLM ? Açıklama

generateKnowledgeGraphDiagram

Hayır

Dönüştür`graph.json`PlantUML’de (deterministik)

generateDiagramDocs

Evet

Oluştur`.prompt`Grafikten beri, bunları LLM üzerinden ele alır (dogfooding)

 
# Documentation déterministe (rapide, pas de LLM)
./gradlew generateKnowledgeGraphDiagram

# Documentation LLM (plus riche, consomme des tokens)
./gradlew generateDiagramDocs

Neden determinist olduğu (ve neden önemli)

Pipelinanın ana noktası`generateKnowledgeGraphDiagram`:O hiçbir LLM çağırmıyor.. dönüşüm`graph.json`PlantUML bir saf fonksiyondur.
