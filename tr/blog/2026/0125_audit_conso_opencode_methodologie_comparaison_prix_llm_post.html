Stack’ı Anlamak: Kim Ne Yapar?

Rakamlara dalmadan önce mimariyi netleştirelim. Kurulumumda üç farklı aktör var ve bunları birbirine karıştırmamak önemli:

OpenCode bir model sağlayıcısı DEĞİLDİR.Bu, açık kaynaklı bir CLI (github.com/anomalyco/opencode) yapay zeka ajanlarını yöneten. Abonelik satmıyor, çıkarım (inference) sağlamıyor. Şununla eşdeğerdir:`git`versiyonlama için: bir hizmet değil, bir araç. Ollama Cloud çıkarım sağlayıcısıdır.Yerel Ollama kurulumum bir istemci gibi davranır — benzersiz bir SSH anahtarı (Cihaz Anahtarı) aracılığıyla Ollama sunucularında kimlik doğrulaması yapar ve etiketlenmiş modellerin yürütülmesini onlara devreder`:cloud`. Pro aboneliği (20€/ay) daha yüksek kotaların kilidini açar ve Docker aracılığıyla aynı makine üzerinde birden fazla hesabın birleştirilmesine olanak tanır.

Giriş: Neden Denetim?

İki ay önce, yerel Ollama kurulumumda modelleri ücretsiz olarak kullanıyordum. Sonra, bulut modellerini (şu etikete sahip olanları`:cloud`) sağlayıcı aracılığıyla`ollama-cloud`Bir ay sonra, kendi hesabı ve SSH anahtarı olan ayrı bir Docker örneği üzerinde ikinci bir abonelik geldi — abonelikleri birleştirme hakkındaki makalemde açıklanan birleştirme yöntemi.

Beni kemiren soru şuydu: aylık bu 20€ haklı çıkarılabilir mi? Göz kararıyla değil. Rakamlarla.

Yanıtlamak için kesin verilere ihtiyacım vardı. Tahminlere değil. Ortalamalara değil. Token token, model model, oturum oturum gerçek tüketimime.

Ve OpenCode — CLI — tüm bunları bir SQLite veri tabanında saklar.

OpenCode Veri Tabanı: Bir Altın Madeni

OpenCode, oturum geçmişinin tamamını şu konumdaki bir SQLite dosyasına kaydeder:`~/.local/share/opencode/opencode.db`. La mienne pèse 660 Mo pour 73 jours d’utilisation — une base de données de production tout à fait respectable.

$ ls -lh ~/.local/share/opencode/opencode.db
-rw-r--r-- 1 cheroliv cheroliv 660M mai 18 12:25 opencode.db

Şema

Veritabanı yirmi civarında tablo içeriyor ancak bunlardan üçü denetimimiz için kritik öneme sahip:

Tablo`session`genel bir denetim için mükemmeldir: her oturumun kendi toplu token sayımı, kullanılan modeli ve maliyeti vardır. Alan`model`ham JSON’dur:

{
  "id": "deepseek-v4-pro:cloud",
  "providerID": "ollama-cloud",
  "variant": "default"
}

Alan`cost`OpenCode veritabanındaki veriler yalnızca API anahtarı aracılığıyla kullanım bazlı ödenen harici API ücretlerini (Google Gemini, OpenAI, vb.) yansıtmaktadır. Ollama üzerinden yapılan çağrılar —ister yerel olarak ister Ollama Cloud Pro üzerinden olsun— işaretlenmiştir`cost=0`çünkü maliyet sabit (abonelik), token başına değil. Bu çağrıların gerçek maliyeti, aylık aboneliktir.

Çıkarma Kodu

Herhangi bir şey kurmanıza gerek yok. Node.js 22+, deneysel bir SQLite modülü içerir (node:sqlite) mükemmel çalışan. İşte bana her şeyi veren betik:

const { DatabaseSync } = require('node:sqlite');
const db = new DatabaseSync(
  `${process.env.HOME}/.local/share/opencode/opencode.db`,
  { readonly: true }
);

// 1. Statistiques globales
const global = db.prepare(`
  SELECT
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(tokens_reasoning) as total_reasoning,
    SUM(tokens_cache_read) as total_cache_read,
    SUM(cost) as total_cost
  FROM session
`).get();

// 2. Ventilation par modèle et fournisseur
const byModel = db.prepare(`
  SELECT
    json_extract(model, '$.id') as model_id,
    json_extract(model, '$.providerID') as provider,
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(cost) as total_cost
  FROM session
  WHERE model IS NOT NULL
  GROUP BY model_id, provider
  ORDER BY SUM(tokens_input) DESC
`).all();

// 3. Par mois
const monthly = db.prepare(`
  SELECT
    strftime('%Y-%m', datetime(time_created/1000, 'unixepoch')) as month,
    COUNT(*) as sessions,
    SUM(tokens_input) as total_input,
    SUM(tokens_output) as total_output,
    SUM(cost) as total_cost
  FROM session
  WHERE time_created IS NOT NULL
  GROUP BY month
  ORDER BY month
`).all();

// 4. Messages par modèle (détection des changements intra-session)
const msgByModel = db.prepare(`
  SELECT
    json_extract(m.data, '$.model.providerID') as provider,
    json_extract(m.data, '$.model.modelID') as model_id,
    COUNT(*) as messages
  FROM message m
  WHERE json_extract(m.data, '$.model') IS NOT NULL
  GROUP BY provider, model_id
  ORDER BY COUNT(*) DESC
`).all();

console.log({ global, byModel, monthly, msgByModel });
db.close();

Flag`--experimental-sqlite`Node.js 22.x üzerinde gereklidir. Node.js 24+ üzerinde modül stabildir ve artık bayrak gerektirmez.

Gizli Maliyet: Prompt Mühendisliği ve İterasyonlar

Token maliyeti denklemin sadece bir parçasıdır. Asıl maliyet, geliştirici zamanıdır.

OpenCode + Ollama Cloud Pro + benim ajan yönetişimimle (yönetişim hakkındaki makalede açıklanan EAGER/LAZY/Hot/Warm/Cold), şunları elde ediyorum:

  • 0 tekrarlayıcı prompt engineering: bağlam otomatik olarak enjekte edilir

  • %90+ ilk denemede doğru: kod ilk seferde derleniyor

  • 8 ardışık oturumda sıfır deepseek halüsinasyonu(Kimi/GLM/DeepSeek karşılaştırması içerisinde belgelenmiştir)

Fine-tune veya yönetişim olmadan Claude veya GPT ile:

  • görev başına ortalama 2-3 yineleme

  • Sistematik prompt mühendisliği

  • Bağlam 30K token’ı geçtiği anda Kotlin/Gradle API’leri hakkında halüsinasyonlar

Aylık "efektif" maliyet — tokens × iterasyonlar × düzeltme süresi — verimlilik oranı hakkındaki makalede kanıtladığım gibi, benim çözümümün 27× ile 54× katıdır.

Lütfen çevrilmesini istediğiniz metni sağlayın. Bu sadece token başına fiyat meselesi değil. 57 kat daha pahalı olan ve 3 kat daha fazla iterasyon gerektiren bir Claude Opus, ~170 kat daha yüksek bir efektif maliyet demektir. Açıkça söylemek gerekirse: bir stajyere McKinsey ortağı maaşı ödemek gibi. Lütfen çevirmek istediğiniz metni sağlayın.

Ollama Cloud Pro Aboneliklerini Biriktirme: Docker Yöntemi

Tek bir abonelik yeterli değilse, birden fazla abonelik birleştirilir. Prensip, her aboneliği kendi kimlik doğrulama SSH anahtarıyla birlikte kendi Ollama kurulumunda izole etmektir. Docker bunu basit hale getirir.

Kapsamlı yöntem Docker birleştirme makalesinde detaylandırılmıştır, mantık şöyledir:

Desen kalıbı basittir:

  1. Bir birim oluşturun`~/ollama-b-data`

  2. Bir Docker konteyneri başlatmak`ollama/ollama:0.20.2`eşlenmiş`11435:11434`

  3. Konteynerin SSH anahtarını al → ollama.com üzerine kaydet

  4. Yapmak`ollama signin`ikinci bir e-posta ile

  5. OpenCode’u iki sağlayıcı ile yapılandırın (`ollama`üzerinde :11434,`ollama-b`üzerinde :11435)

İki hesap, bir banka kartı, sıfır çatışma.
