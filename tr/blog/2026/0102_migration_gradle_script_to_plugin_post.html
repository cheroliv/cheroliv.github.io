Bağlam ve hedef

Başlangıç noktası

Proje`slider-gradle`AsciiDoc dosyalarından Gradle eklentisi üzerinden Reveal.js sunumları oluşturur.org.asciidoctor.jvm.revealjs. Ana görevin yapılandırması`asciidoctorRevealJs`doğrudan kök buildscript’te yaşıyordu`build.gradle.kts` :

plugins { id("org.asciidoctor.jvm.revealjs") }

apply<slides.SlidesPlugin>()

project.tasks.getByName<AsciidoctorJRevealJSTask>(TASK_ASCIIDOCTOR_REVEALJS) {
    repositories { ruby { gems() } }
    revealjs {
        version = "3.1.0"
        templateGitHub {
            setOrganisation("hakimel")
            setRepository("reveal.js")
            setTag("3.9.1")
        }
    }
    revealjsOptions {
        // ... configuration complète
    }
}

Hedef

Tüm bu yapılandırma’yı içine taşımak`buildSrc/src/main/kotlin/slides/SlidesPlugin.kt`tüketici buildscripti şuna indirgenebilmesi için :

apply<slides.SlidesPlugin>()

Plug‑in tamamen bağımsız olmalıdır: kendi eklenti bağımlılıklarını uygular, depolarını yapılandırır ve Ruby gem’lerini yönetir.

İlk engel: `ruby { gems() }

Groovy sözdizim şekeri ne gizler

Satır`repositories { ruby { gems() } }`Bu, buildscript çalıştırma bağlamında yalnızca kullanılabilecek bir Groovy DSL uzantısıdır. buildSrc’ten erişilebilecek statik bir Kotlin API’si olarak mevcut değildir.

Onu aramaya çalışırken`SlidesPlugin.kt`, derleme hemen başarısız olur.

mekanizsansın ayrートルmansı

Gradle önbelleğini analiz ettikten sonra (~/.gradle/caches/modules-2/files-2.1/rubygems/), dosyada buluyoruz`ivy-3.1.0.xml`:

<artifact type='gem' url='https://rubygems.org/gems/asciidoctor-revealjs-3.1.0.gem' />

`ruby { gems() }`aslında yapıyorduüç ayrı işlem:

  1. İşaret eden bir Ivy repo’yu kaydet`https://rubygems.org/gems/`

  2. Grubu hariç tut`rubygems`çatışmalardan kaçınmak için Maven depoları

  3. Gem’i konfigürasyona kaydet`asciidoctorGems`JRuby’nin çalışma zamanında onu yüklemesi için

Bu üç sorumluluk, Kotlin’de ayrı ayrı üretilmelidir.

Üç bölümlü çözüm

Bölüm 1: Ivy repo rubygems için

project.repositories.mavenCentral() {
    content { excludeGroup("rubygems") }
}
project.repositories.ivy {
    url = project.uri("https://rubygems.org/gems/")
    patternLayout { artifact("[module]-[revision].gem") } (1)
    metadataSources { artifact() }
    content { includeGroup("rubygems") }
}
1 Uzantı`.gem`Kodlanmış olarak ayarlanmalıdır.[ext]`varsayılan olarak çözer.jar`, bir hataya neden olur`Resource missing`.

Ivy deposu doğrudan üzerinde beyan edilmiştir`project.repositories`ve bir blok içinde değil`repositories { }`çünkü bu bloğun alıcı bu değil`RepositoryHandler`Gradle standardı ama bir API grolifant uzantıyla uyumsuz`ivy`Kotlin DSL.

Bölüm 2 : asciidoctorGems bağımlılığı

eklenti`org.asciidoctor.jvm.gems`ilk önce uygulanmalıdır — yapılandırmayı oluşturur`asciidoctorGems`ve görev`asciidoctorGemsPrepare`:

project.plugins.apply("org.asciidoctor.jvm.gems")
project.plugins.apply("org.asciidoctor.jvm.revealjs") (1)

project.dependencies {
    add("asciidoctorGems", "rubygems:asciidoctor-revealjs:3.1.0@gem") (2)
}
1 Uygulama sırası önemlidir:`gems`önce`revealjs`. <2> Belirleyici`@gem`Bağımlılığa doğru uzantıyı zorla uygula

Bölüm 3 : settings.gradle.kts

`dependencyResolutionManagement`içinde`settings.gradle.kts`Projeleríe kendi depolarını tanımlamaya izin vermelidir:

@Suppress("UnstableApiUsage")
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.PREFER_PROJECT)
}

Bu satır olmadan, Gradle eklentide bildirilen depoları görmezden gelir ve gem çözümlemesi başarısız olur.

Bytecode’lar tarafından API introspection

Neden javap ?

Eklenti`asciidoctor-gradle-jvm-slides`sürümdedir`4.0.0-alpha.1`. Belgesi mevcut değil veya eksiktir. Güveniliren tek kaynak derlenmiş sınıfların doğrudan incelenmesidir.

Görev hiyerarşisi

javap -p -classpath asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar \
  org.asciidoctor.gradle.jvm.slides.AsciidoctorJRevealJSTask

Sonuç :

public class AsciidoctorJRevealJSTask
  extends org.asciidoctor.gradle.jvm.AbstractAsciidoctorTask
  implements org.asciidoctor.gradle.base.slides.SlidesToExportAware

forkOptions` keşfi

İnceleyerek`AbstractAsciidoctorTask`:

javap -p -classpath asciidoctor-gradle-jvm-4.0.0-alpha.1.jar \
  org.asciidoctor.gradle.jvm.AbstractAsciidoctorTask | grep -i "fork\|exec\|jvm"

Bulunur:

final org.ysb33r.grolifant.api.v4.JavaForkOptions javaForkOptions;
public void forkOptions(org.gradle.api.Action<org.ysb33r.grolifant.api.v4.JavaForkOptions>);
public static final org.asciidoctor.gradle.base.process.ProcessMode JAVA_EXEC;

JavaForkOptions API’si (grolifant)

`javaLauncher`Bu görevde mevcut değil. Gerçek API’nin`org.ysb33r.grolifant.api.v4.JavaForkOptions`göster :

public void executable(java.lang.Object);  (1)
public void setExecutable(java.lang.Object);
1 Yöntem`executable(Object)`atamayı değiştirir`executable = …​`derlemeyen (`val`yeniden atanamaz).

RevealJSExtension

`revealjs { }`görev bir yöntem değil, birproje uzantısı :

javap -p -classpath asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar \

Bu yolla erişilir :

    version = "3.1.0"

        setOrganisation("hakimel")
        setRepository("reveal.js")

    }

Java araç zinciri yapılandırması

JavaToolchainService sorunu

`JavaToolchainService`Bir proje uzantısı değil. Aşağıdaki çağrı başarısız olur:

// ERREUR : Extension of type 'JavaToolchainService' does not exist
project.extensions.getByType<JavaToolchainService>()

İyi API`serviceOf`:

import org.gradle.kotlin.dsl.support.serviceOf

project.tasks.getByName<AsciidoctorJRevealJSTask>(TASK_ASCIIDOCTOR_REVEALJS) {
    setInProcess("JAVA_EXEC")
    forkOptions {
        executable(
            project.serviceOf<JavaToolchainService>()
                .launcherFor {
                    languageVersion.set(JavaLanguageVersion.of(17))
                    vendor.set(JvmVendorSpec.ADOPTIUM)
                }
                .get()
                .executablePath
                .asFile
                .absolutePath
        )
    }
}

Docker otomatik tespiti

Bağlam

Asciidoctor/JRuby eklentisi Java 17 gerektirir. buildSrc içindeki Kotlin 2.0.x Java 25’i desteklemiyor (sürüm parseri çöküyor`"25.0.2"`). Gradle daemonı bu yüzden Java 17’de çalıştırılmalı veya Docker kullanılmalıdır.

strateji

  1. Docker kullanılabilir → konteyner üzerinden yürütme`eclipse-temurin:17`(varsayılan davranış)

  2. Docker eksik + Java 17 → yerel yürütme

  3. Docker eksik + Java > 17 → açık hata

val isDockerAvailable = try {
    Runtime.getRuntime().exec(arrayOf("docker", "info")).waitFor() == 0
} catch (e: Exception) {
    false
}

val javaVersion = JavaVersion.current().majorVersion.toInt()

when {
    isDockerAvailable -> project.tasks.register<Exec>(TASK_ASCIIDOCTOR_REVEALJS) {
        group = GROUP_TASK_SLIDER
        description = "Slider settings and generation (via Docker)"
        dependsOn(TASK_CLEAN_SLIDES_BUILD)
        finalizedBy(TASK_DASHBOARD_SLIDES_BUILD)
        commandLine(
            "docker", "run", "--rm",
            "-v", "${project.rootDir.absolutePath}:/workspace",
            "-v", "${System.getProperty("user.home")}/.gradle:/root/.gradle",
            "-w", "/workspace",
            "eclipse-temurin:17",
            "./gradlew", TASK_ASCIIDOCTOR_REVEALJS
        )
        workingDir = project.rootDir
    }
    javaVersion == 17 -> {
        project.repositories.mavenCentral() {
            content { excludeGroup("rubygems") }
        }
        project.repositories.ivy {
            url = project.uri("https://rubygems.org/gems/")
            patternLayout { artifact("[module]-[revision].gem") }
            metadataSources { artifact() }
            content { includeGroup("rubygems") }
        }
        project.extensions.getByType<RevealJSExtension>().apply {
            version = "3.1.0"
            templateGitHub {
                setOrganisation("hakimel")
                setRepository("reveal.js")
                setTag("3.9.1")
            }
        }
        project.tasks.getByName<AsciidoctorJRevealJSTask>(TASK_ASCIIDOCTOR_REVEALJS) {
            setInProcess("JAVA_EXEC")
            forkOptions {
                executable(
                    project.serviceOf<JavaToolchainService>()
                        .launcherFor {
                            languageVersion.set(JavaLanguageVersion.of(17))
                            vendor.set(JvmVendorSpec.ADOPTIUM)
                        }
                        .get()
                        .executablePath
                        .asFile
                        .absolutePath
                )
            }
            // ... reste de la configuration
        }
    }
    else -> error(
        "Docker est requis pour exécuter $TASK_ASCIIDOCTOR_REVEALJS " +
        "avec Java $javaVersion. Installez Docker ou utilisez Java 17."
    )
}

Araştırma yöntemi: javap ile bilinmeyen bir API’yi okumak

Prensip

Belgeleme eksik veya eksik olduğunda, bytecode’ler gerçeklik kaynağıdır. javap`JDK’nin standart aracıdır ve dosyaları dekompiler eder.class`okunabilir Java imzaları, kaynak kod gerektirmeden.

Adım 1: Gradle önbelleğinde jar dosyasını bul

Gradle tüm bağımlılıklarını içinde indirir`~/.gradle/caches/modules-2/files-2.1/`. İlk adım, incelenecek sınıfı içeren jar dosyasını bulmaktır:

find ~/.gradle/caches -name "asciidoctor-gradle-jvm-slides*.jar" 2>/dev/null
Sonuç :
/home/user/.gradle/caches/modules-2/files-2.1/org.asciidoctor/
asciidoctor-gradle-jvm-slides/4.0.0-alpha.1/.../
asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar

Adım 2 : jar dosyasındaki sınıfları listele

Bir sınıfı incelemeden önce, jar içinde mevcut olduğunu doğruluyoruz :

jar tf asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar | grep -i "RevealJS\|revealjs"

Adım 3: bir sınıfı incelemek

Kullanılabilir tüm sınıfları gösterir : AsciidoctorJRevealJSTask, RevealJSExtension, RevealJSOptions, vb.
javap -p -classpath asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar \
org.asciidoctor.gradle.jvm.slides.AsciidoctorJRevealJSTask

Seçenek`-p`tüm üyeleri, gizli olanları da gösterir. Sonuç anahtar satırını hemen gösterir:

public class AsciidoctorJRevealJSTask
extends org.asciidoctor.gradle.jvm.AbstractAsciidoctorTask

Adım 4 : hiyerarşiye çıkma

Görev genişletir`AbstractAsciidoctorTask`Sırasıyla incelenir. Önce jar dosyasını bulup :

find ~/.gradle/caches -name "asciidoctor-gradle-jvm-[0-9]*.jar" 2>/dev/null

javap -p -classpath asciidoctor-gradle-jvm-4.0.0-alpha.1.jar \
org.asciidoctor.gradle.jvm.AbstractAsciidoctorTask | grep -i "fork\|exec\|jvm\|java"

Orada keşfediliyor`forkOptions`, JAVA_EXEC, et javaForkOptions tip`org.ysb33r.grolifant.api.v4.JavaForkOptions`.

Adım 5: bilinmeyen türleri izlemek

`JavaForkOptions`bir grolifant sınıfı bilinmiyor. Onun JAR’ını buluyoruz :

find ~/.gradle/caches -name "grolifant*.jar" 2>/dev/null

Sonra onu inceler:

javap -p -classpath grolifant40-legacy-api-2.0.0-alpha.6.jar \
org.ysb33r.grolifant.api.v4.JavaForkOptions

Burada bulunur`executable(java.lang.Object)— doğru çağrılacak yöntem, karşıt olarak`executable = …​`derlenmeyen bir özelliktir`val.

Adım 6: proje uzantılarını kontrol et

için`revealjs { }`, soru şuydu: bu bir görevin metodu mu? ya da bir proje genişletmesi mi? Denetim`AsciidoctorJRevealJSTask` herhangi bir yöntem göstermez`revealjs`. Sonra inceleriz`RevealJSExtension`:

javap -p -classpath asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar \
org.asciidoctor.gradle.jvm.slides.RevealJSExtension | head -5
public class RevealJSExtension implements groovy.lang.GroovyObject {
public static final java.lang.String NAME;

varlığı`NAME`projeye kayıtlı bir uzantı olduğunu onaylar, erişilebilir`project.extensions.getByType<RevealJSExtension>()`.

Sonraki adım

Bu buildSrc eklentisi, Gradle Plugin Portal veya Maven Local’de yayınlanan bağımsız bir projeye çıkartılacak ve tüketen buildscript şöyle olacak:

plugins { id("slides") version "1.0.0" }

Et settings.gradle.kts`sadece zorunlu minimum seviyeye indirilecek, bir şeye atıfta bulunmadan`foojay-resolver-convention, JDK sağlama, eklenti tarafından yönetiliyor veya ön koşul olarak belgelenmiş.
