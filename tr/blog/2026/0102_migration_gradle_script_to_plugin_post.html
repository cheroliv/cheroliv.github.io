Bağlam ve Hedef

Başlangıç noktası

Proje`slider-gradle`AsciiDoc dosyalarından Gradle eklentisi üzerinden Reveal.js sunumları oluşturur.org.asciidoctor.jvm.revealjs. Ana görev yapılandırması`asciidoctorRevealJs`Kök buildscript’te doğrudan yaşıyordu`build.gradle.kts`(Note: The assistant outputs nothing because no text was provided for translation.)

plugins { id("org.asciidoctor.jvm.revealjs") }

apply<slides.SlidesPlugin>()

project.tasks.getByName<AsciidoctorJRevealJSTask>(TASK_ASCIIDOCTOR_REVEALJS) {
    repositories { ruby { gems() } }
    revealjs {
        version = "3.1.0"
        templateGitHub {
            setOrganisation("hakimel")
            setRepository("reveal.js")
            setTag("3.9.1")
        }
    }
    revealjsOptions {
        // ... configuration complète
    }
}

Hedef

Bütün bu yapılandırmayı içine taşı`buildSrc/src/main/kotlin/slides/SlidesPlugin.kt`Tüketici buildscriptini sadece şu hale getirmek için :

apply<slides.SlidesPlugin>()

Eklenti tamamen otonom olmalıdır : kendi eklenti bağımlılıklarını uygular, depolarını yapılandırır ve Ruby gem’lerini yönetir.

İlk engel: `ruby { gems() }

Groovy sözdizimi şekeri ne saklar.

Satır`repositories { ruby { gems() } }`Bu, yalnızca buildscript yürütme bağlamında mevcut olan bir Groovy DSL uzantısıdır. Bu, buildSrc’ten erişilebilen statik bir Kotlin API olarak mevcut değildir.

Onu aramaya çalışırken`SlidesPlugin.kt`, derleme hemen başarısız olur.

Mekanizmanın ayrıştırılması

Gradle önbelleği analiz ettikten sonra (~/.gradle/caches/modules-2/files-2.1/rubygems/), dosyada keşfederiz`ivy-3.1.0.xml` :

<artifact type='gem' url='https://rubygems.org/gems/asciidoctor-revealjs-3.1.0.gem' />

`ruby { gems() }`Aslında yapıyorduüç ayrı işlem :

  1. İsaret eden bir Ivy deposu kaydet`https://rubygems.org/gems/`

  2. Grubu hariç tut`rubygems`Maven deposları çakışmaları önlemek için

  3. Gem’i yapılandırmaya kaydedin`asciidoctorGems`JRuby’nun çalışma zamanında yüklemesi için

Bu üç sorumluluk, Kotlin’de ayrı ayrı yeniden oluşturulmalıdır.

Üç bölümlü çözüm

Bölüm 1: RubyGems için Ivy deposu

project.repositories.mavenCentral() {
    content { excludeGroup("rubygems") }
}
project.repositories.ivy {
    url = project.uri("https://rubygems.org/gems/")
    patternLayout { artifact("[module]-[revision].gem") } (1)
    metadataSources { artifact() }
    content { includeGroup("rubygems") }
}
1 Uzantı`.gem`Hardcode edilmelidir.[ext]`Varsayılan olarak çözer.jar`, bu bir hataya yol açar`Resource missing`.

Ivy deposu doğrudan üzerinde beyan edilmiştir`project.repositories`ve değil içinde bir blok`repositories { }`Bu bloğun alıcısı değil`RepositoryHandler`gradle standartı ancak bir grolifant api uzantıyla uyumsuz`ivy`Kotlin DSL.

Parça 2 : asciidoctorGems bağımlılığı

Eklenti`org.asciidoctor.jvm.gems`İlk olarak uygulanmalıdır — yapılandırmayı oluşturur.asciidoctorGems`ve görevi`asciidoctorGemsPrepare:

project.plugins.apply("org.asciidoctor.jvm.gems")
project.plugins.apply("org.asciidoctor.jvm.revealjs") (1)

project.dependencies {
    add("asciidoctorGems", "rubygems:asciidoctor-revealjs:3.1.0@gem") (2)
}
1 Uygulama sırası önemlidir :`gems`önce`revealjs`. Nitelikleyici`@gem`Doğru uzantıyı bağımlılığa zorla uygula

Bölüm 3 : settings.gradle.kts

`dependencyResolutionManagement`içinde`settings.gradle.kts`Proje’lerin kendi depolarını bildirmesine izin verilmeli:

@Suppress("UnstableApiUsage")
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.PREFER_PROJECT)
}

Bu satır olmadan, Gradle eklentide bildirilen depoları yoksayar ve gem çözümlemesi başarısız olur.

Bytekodla API introspeksiyonu

Neden javap ?

Eklenti`asciidoctor-gradle-jvm-slides`sürümde`4.0.0-alpha.1`. Dokümantasyonu yok ya da eksiktir. Tek güvenilir kaynak, derlenmiş sınıfların doğrudan incelenmesidir.

Görev hiyerarşisi

javap -p -classpath asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar \
  org.asciidoctor.gradle.jvm.slides.AsciidoctorJRevealJSTask

Sonuç :

public class AsciidoctorJRevealJSTask
  extends org.asciidoctor.gradle.jvm.AbstractAsciidoctorTask
  implements org.asciidoctor.gradle.base.slides.SlidesToExportAware

Keşif `forkOptions

İnceleyerek`AbstractAsciidoctorTask`:

javap -p -classpath asciidoctor-gradle-jvm-4.0.0-alpha.1.jar \
  org.asciidoctor.gradle.jvm.AbstractAsciidoctorTask | grep -i "fork\|exec\|jvm"

Bulunur :

final org.ysb33r.grolifant.api.v4.JavaForkOptions javaForkOptions;
public void forkOptions(org.gradle.api.Action<org.ysb33r.grolifant.api.v4.JavaForkOptions>);
public static final org.asciidoctor.gradle.base.process.ProcessMode JAVA_EXEC;

JavaForkOptions API’si (grolifant)

`javaLauncher`Bu görevde mevcut değil. Gerçek API’nin`org.ysb33r.grolifant.api.v4.JavaForkOptions`göster :

public void executable(java.lang.Object);  (1)
public void setExecutable(java.lang.Object);

Yöntem`executable(Object)`atamayı değiştirir`executable = …​`derlemeyen (`val`yeniden atanamaz).

Java araç zinciri yapılandırması

JavaToolchainService’nin sorunu

`JavaToolchainService`bir proje uzantısı değil. Aşağıdaki çağrı başarısız olur :

// ERREUR : Extension of type 'JavaToolchainService' does not exist
project.extensions.getByType<JavaToolchainService>()

Doğru API’dir`serviceOf`:

import org.gradle.kotlin.dsl.support.serviceOf

project.tasks.getByName<AsciidoctorJRevealJSTask>(TASK_ASCIIDOCTOR_REVEALJS) {
    setInProcess("JAVA_EXEC")
    forkOptions {
        executable(
            project.serviceOf<JavaToolchainService>()
                .launcherFor {
                    languageVersion.set(JavaLanguageVersion.of(17))
                    vendor.set(JvmVendorSpec.ADOPTIUM)
                }
                .get()
                .executablePath
                .asFile
                .absolutePath
        )
    }
}

Docker otomatik algılama

Bağlam

Asciidoctor/JRuby eklentisi Java 17 gerektiriyor. buildSrc’teki Kotlin 2.0.x, Java 25’i desteklemiyor (sürüm parserı çöker`"25.0.2"`). Gradle daemonının Java 17’de çalıştırılması gerekir ya da Docker kullanılmalıdır.

strategi

  1. Docker kullanılabilir → konteyner üzerinden çalıştırma`eclipse-temurin:17`(varsayılan davranış)

  2. Docker eksik + Java 17 → yerel yürütme

  3. Docker eksik + Java > 17 → açık hata

val isDockerAvailable = try {
    Runtime.getRuntime().exec(arrayOf("docker", "info")).waitFor() == 0
} catch (e: Exception) {
    false
}

val javaVersion = JavaVersion.current().majorVersion.toInt()

when {
    isDockerAvailable -> project.tasks.register<Exec>(TASK_ASCIIDOCTOR_REVEALJS) {
        group = GROUP_TASK_SLIDER
        description = "Slider settings and generation (via Docker)"
        dependsOn(TASK_CLEAN_SLIDES_BUILD)
        finalizedBy(TASK_DASHBOARD_SLIDES_BUILD)
        commandLine(
            "docker", "run", "--rm",
            "-v", "${project.rootDir.absolutePath}:/workspace",
            "-v", "${System.getProperty("user.home")}/.gradle:/root/.gradle",
            "-w", "/workspace",
            "eclipse-temurin:17",
            "./gradlew", TASK_ASCIIDOCTOR_REVEALJS
        )
        workingDir = project.rootDir
    }
    javaVersion == 17 -> {
        project.repositories.mavenCentral() {
            content { excludeGroup("rubygems") }
        }
        project.repositories.ivy {
            url = project.uri("https://rubygems.org/gems/")
            patternLayout { artifact("[module]-[revision].gem") }
            metadataSources { artifact() }
            content { includeGroup("rubygems") }
        }
        project.extensions.getByType<RevealJSExtension>().apply {
            version = "3.1.0"
            templateGitHub {
                setOrganisation("hakimel")
                setRepository("reveal.js")
                setTag("3.9.1")
            }
        }
        project.tasks.getByName<AsciidoctorJRevealJSTask>(TASK_ASCIIDOCTOR_REVEALJS) {
            setInProcess("JAVA_EXEC")
            forkOptions {
                executable(
                    project.serviceOf<JavaToolchainService>()
                        .launcherFor {
                            languageVersion.set(JavaLanguageVersion.of(17))
                            vendor.set(JvmVendorSpec.ADOPTIUM)
                        }
                        .get()
                        .executablePath
                        .asFile
                        .absolutePath
                )
            }
            // ... reste de la configuration
        }
    }
    else -> error(
        "Docker est requis pour exécuter $TASK_ASCIIDOCTOR_REVEALJS " +
        "avec Java $javaVersion. Installez Docker ou utilisez Java 17."
    )
}

Araştırma yöntemi: javap ile bilinmeyen bir API okumak

Prensip

Dokümantasyon eksik veya tamamlanmamışsa, bytecode’lar doğruluk kaynağıdır. javap`JDK’nin standart aracıdır ve dosyaları dersini çözer.class`okunabilir Java imzalarıyla kaynak kodu gerektirmeden.

Adım 1: Gradle önbellekte jar’ı bul

Gradle tüm bağımlılıklarını indirir`~/.gradle/caches/modules-2/files-2.1/`. İlk adım, incelenecek sınıfı içeren jar’ı bulmaktır:

find ~/.gradle/caches -name "asciidoctor-gradle-jvm-slides*.jar" 2>/dev/null
Sonuç :
/home/user/.gradle/caches/modules-2/files-2.1/org.asciidoctor/
asciidoctor-gradle-jvm-slides/4.0.0-alpha.1/.../
asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar

Adım 2: JAR dosyasındaki sınıfları listele

Bir sınıfı incelemeden önce, JAR içinde mevcut olduğundan emin oluruz :

jar tf asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar | grep -i "RevealJS\|revealjs"

Adım 3 : bir sınıfı incelemek

Bu tüm kullanılabilir sınıfları gösterir: AsciidoctorJRevealJSTask, RevealJSExtension, RevealJSOptions, etc.
javap -p -classpath asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar \
org.asciidoctor.gradle.jvm.slides.AsciidoctorJRevealJSTask

Seçenek`-p`Gizli olanlar da dahil tüm üyeleri gösterir. Sonuç, anahtar satırını hemen gösterir:

public class AsciidoctorJRevealJSTask
extends org.asciidoctor.gradle.jvm.AbstractAsciidoctorTask

Adım 4 : Hiyerarşiyi tırmanın

Görev genişletir`AbstractAsciidoctorTask`. Bir kez daha incelenir. ilk önce jar’ını bularak :

find ~/.gradle/caches -name "asciidoctor-gradle-jvm-[0-9]*.jar" 2>/dev/null

javap -p -classpath asciidoctor-gradle-jvm-4.0.0-alpha.1.jar \
org.asciidoctor.gradle.jvm.AbstractAsciidoctorTask | grep -i "fork\|exec\|jvm\|java"

Orada keşfederiz`forkOptions`, JAVA_EXEC, et javaForkOptions tipindeki`org.ysb33r.grolifant.api.v4.JavaForkOptions`.

Adım 5 : Bilinmeyen türleri takip etmek

`JavaForkOptions`bir bilinmeyen grolifant sınıfıdır. Jar’ını buluyoruz:

find ~/.gradle/caches -name "grolifant*.jar" 2>/dev/null

Sonra onu inceleriz:

javap -p -classpath grolifant40-legacy-api-2.0.0-alpha.6.jar \
org.ysb33r.grolifant.api.v4.JavaForkOptions

Burada bulunur`executable(java.lang.Object)— doğru yöntemi çağırmak, karşısında`executable = …​`Derlenmeyen, çünkü bir özelliğidir`val.

Adım 6 : proje uzantılarını kontrol et

İçin`revealjs { }`, soru şöyleydi: bu bir görevin yöntemi mi? Veya bir proje uzantısı? Denetimi`AsciidoctorJRevealJSTask` Herhangi bir yöntem göstermez`revealjs`. Sonra kontrol ederiz`RevealJSExtension`(Empty)

javap -p -classpath asciidoctor-gradle-jvm-slides-4.0.0-alpha.1.jar \
org.asciidoctor.gradle.jvm.slides.RevealJSExtension | head -5
public class RevealJSExtension implements groovy.lang.GroovyObject {
public static final java.lang.String NAME;

varlığı`NAME`Bu projeye kayıtlı bir uzantı olduğunu doğruluyor erişilebilir`project.extensions.getByType<RevealJSExtension>()`.

Sonraki adım
