দৃশ্য: একটি অন্ধ এজেন্ট টুলের জগতে

এটা একটি মঙ্গলবারের সন্ধ্যা ছিল। আমি তাজা ইন্সটল করেছি।https://opencode.ai[মুক্ত কোড], এজেন্ট কৃত্রিম বুদ্ধিমত্তা যা বলিত ছিল যে আমার কোডিং পদ্ধতিকে রূপান্তর করবে। প্রথম পরীক্ষা: তাকে বলা যাতে আমার GitHub রেপোজিটরিগুলো তালিকাভুক্ত করুন।

$ opencode
> Utilise gh pour lister mes repos
❌ bash: gh: command not found

অস্বাভাবিক।`gh`আমার টার্মিনালে এটি পুরোপুরি ভালোভাবে কাজ করতো। আমি কিছু অন্য চেষ্টা করছি :

> Vérifie la version de Java
❌ bash: java: command not found

তবে :

> Lance le build Gradle
❌ bash: gradle: command not found

Java, Gradle, Node,gh— এজেন্টের জন্য সব شيء দৃশ্যমান ছিল না। আমার টারমিনাল, সে, সব شيء দেখত। য budsি এজেন্ট ও আমি দুটি সমান্তরাল বিশ্বে বাস করতessem.

আমি বুঝতে ঘন্টা জুড়ে লেগেছি। ঘন্টা`echo $PATH`, de which java, বৃদ্ধিমান निराशা। আমি অবশেষে বুঝলাম যে সমস্যাটি সরঞ্জামগুলো ছিল না — এটি ছিলশেল. OpenCode, যে কোন এজেন্ট য.launch করে সাবপ্রসেসের মতো, শেলসে কাজ করেঅতিইন্টারঅ্যাক্টিভ। এবং Zsh, এই শেলস গুলোতে, আপনারকে পূর্ণরূপে উপেক্ষা করে`.zshrc`.

এটি হল সেই ডায়াগনস্টিক, সমাধান এবং আমি যে শিক্ষা নিলাম তার পূর্ণ বর্ণনা। যদি আপনি একটি AI এজেন্ট ব্যবহার করেন — OpenCode, Aider, Cursor, বা এমনকি cron স্ক্রিপ্ট — একটি দিন আপনি এই সমস্মুখীন হবেন।

বাগের অ্যানাটমি: দুই শেল, দুই বিশ্ব

একটি টার্মিনাল খুললে, Zsh এটি একটি শেল হিসাবে বিবেচনা করে।অন্তঃক্রিয়াশীল। ও চার্জ করছে`.zshrc`, যে সবকিছু শুরু করে: SDKMAN, NVM, pnpm, alias, আপনার সুন্দর প্রম্পট। আপনার পরিবেশটি সম্পূর্ণ।

কিন্তু যখন OpenCode একটি কমান্ড চালায়, তা একটি ইন্টারেক্টিভ টার্মিনাল চালায় না। এটি একটি শেল চালায়অন-ইন্টারেক্টিভ— একটি কাজের শেল, স্ক্রীন পিছনে কোনো মানুষ নেই। এছাড়াও Zsh, এই প্রেক্ষাপটে, লাফটি`.zshrc`. শুধুমাত্র পড়ে`.zshenv`.

এই পার্থক্য কেন বিদ্যমান? কারণ একটি non-interactive শেল স্ক্রিপ্ট চালatorze ডিজাইন করা হয়েছে, একজন মানব ব্যবহারকারীকে সেবা প্রদানের জন্য নয়। একটি ব্যাকগ্রাউন্ডে চলমান স্ক্রিপ্টে অ্যালিয়াস, প্রম্পট ও অটো-কমপ্লিট লোড করা একটি বর্জ্য হবে। সমস্যা হল, আপনার PATH — executables খুঁজে পानेের জন্য সবচেয়ে গুরুত্বপূর্ণ তথ্য — প্রায়শই initialize করা হয়।.zshrc, না`.zshenv`.

  • `.zshenv`এটিপ্রবেশ দালান— সবাই এই জায়গ দিয়ে যায়, ভিজিটর বা বাসিন্দা। আপনি যদি কিছু এখানে রাখেন, কোনো শেলও এটি দেখতে পাবে।

  • .zprofile et `.zlogin`এগুলো লগইন শেলের জন্য বিশেষ অংশ (যেমন আপনি SSH-এর মাধ্যমে সংযুক্ত থাকা সময়)।

দরুণ কঠিনতা হল যে আমাদের অধিকাংশ আমরা PATH কে বাসাগারে রাখি। এবং এই AI এজেন্টকে কখনো সেখানে প্রবেশ করার অধিকার নেই।

সমস্যা একটি আলোকচিত্রে:

যখন আপনি একটি টার্মিনাল খোলেন, Zsh ইন্টারেক্টিভ হয়: এটি পড়ে`.zshrc`, সবSomething কাজ করে। OpenCode একটি শেল চালু করে একটি কমান্ড চালানোর জন্য, Zsh অন-ইন্টার্যাক্টিভ: তা কूदে`.zshrc`, শুধু পড়ে`.zshenv`. Et si `.zshenv`অস্তিত্ব নেই অথবা PATH ধারণ করে না — এটি বাঘুনি।

কেন Zsh এটি这样做？এটি Unix থেকে উত্তরাধিকার পেল একটি ডিজাইন নির্বাচন। একটি নন-ইন্টারেক্টিভ শেলকে হওয়া উচিতদ্রুত et প্রতিলিপিযোগ্য. ইলিয়াসগুলো, রঙিন প্রম্পটগুলো এবং SDKMAN-এর ভারী ইনিশিয়ালাইজেশনগুলোকে একটি cron স্ক্রিপ্ট বা একটি AI এজেন্টে লোড করলে তা ধীর ও ভঙ্গু হত। অতএব, বিভাজনটি যুক্তিমূলক:`.zshenv`মূলত (variables, PATH)`.zshrc`আরামের জন্য (alias, প্রম্পট, পূর্ণ করি)। সমস্যা তখন উঠে আসে যখন আমরা জরুরি বিষয়গুলোকে আরামের মধ্যে রাখি।

ধাপে ধাপে নিদান

কোনো সংশোধনের আগে, আপনাকে সঠিকভাবে বুঝতে হবে যে কি পড়ছে না। এখানে একটি পুনরাবৃত্তিমূলক নিদর্শন পদ্ধতি দেওয়া হল — যদি আপনি কৃত্রিম বুদ্ধিমত্তা-এজেন্টদের সাথে কাজ করেন, তাহলে এটি আপনার বুকমার্কে রাখুন।

.zshenv এবং .zshrc একই প্যাথ যোগ করলে, তা দুবার দেখা যায়।

`.zshenv`উৎস থেকে আসাআগে.zshrc. দুটিি یک ইন্টারেক্টিভ শেলে পড়া হয়। PATH দ্বিগুণিত হতে পারে। এটি কস্মেটিক, ফাংশনাল নয়। .zshenv এ শুধুমাত্র ডিফল্ট PATH‑এ অনুপস্থিত পথ রাখুন।

NVM : .zshenv-এ হ্যার্ডকোডেড সংস্করণ

রাখা`~/.nvm/versions/node/v22.19.0/bin`পরবর্তীতে কঠিন হয় মিথ্যা`nvm install`

সিমলিংক ব্যবহার করুন`$HOME/.nvm/current/bin`+ র্যাপার`_nvm`.zshrc-এ

SDKMAN : source sdkman-init.sh .zshenv-এ

ভারী ফাংশন বা ইন্টারেক্টিভ ইনিশিয়ালাইজেশন .zshenv-এ রাখুন

.zshenv = পরিবেশ চলবده + PATH শুধু. না`source`, কোনো ভারী ফাংশন নেই, কোনো প্রম্পট নেই.

শেখা পাওয়া

  1. .zshrc` ইন্টার্যাক্টিভ, .zshenv সার্বজনীন— যদি একটি ভেরিয়েবল সব শেল (AI এজেন্ট, cron, স্ক্রিপ্ট, IDE) এ থাকতে দরকার, তাহলে Jaya এtte`.zshenv`. সালোনটি আরামদায়ক, কিন্তু প্রবেশের হলে একমাত্র স্থান যেখানে সবার গমন হয়।

  2. বার্জন ম্যানেজার সমান নেই— SDKMAN সিমলিংক তৈরি করে`current`ডিজাইনের মাধ্যমে। NVM না। এই ঘাটতি ম্যানুয়ালি পূর্ণ করতে হবে। এটি একটি গুরুত্বপূর্ণ শিক্ষা: আপনার PATH কনফিগার করার আগে, যাচাই করুন যে আপনার প্যাকেজ ম্যানেজার একটি স্থabile নকড়ি পয়েন্ট দান করে কি না।

  3. .zshenv-এ প্রারম্ভ স্ক্রিপ্টগুলো উৎস নিন না—sdkman-init.sh et `nvm.sh`এইগুলি ইন্টারেক্টিভ শেলের জন্য ডিজাইন করা হয়েছে। এইগুলো ধীর এবং নাজুক একটি নন-ইন্টারেক্টিভ পরিবেশে। সিমলিংকগুলি`current`পর্যাপ্ত এবং তৎক্ষণিক।

  4. অ-ইন্টারেক্টিভ শেলে সর্বদা পরীক্ষা করুন—`zsh -c 'echo $PATH'`একটি এজেন্টের যা দেখে তা ঠিকভাবে অনুকরণ করে। এটি যাচাই পরীক্ষা। এই পরীক্ষা না থাকলে, আপনি জâne না যে আপনার কনফিগারেশন এজেন্টদের জন্য কাজ করে কিনা।

  5. ওয়্র্যাপার প্যাটার্নটি পুন:প্রয়োগযোগ্য— একই প্যাটার্ন`_nvm`+`alias nvm='_nvm'`যে কোনও টুল যা ডাইনামিকভাবে PATH পরিবর্তন করে কোনও স্থিতিশীল চিহ্ন ছোড়াই না, সেগুলিতে প্রয়োগ করা হয়। এটি আপনার টুলবক্সের আরেকটি টুল।

শেষ যাচাই

এই তৈরি করার পরে`.zshenv`এবং NVM সিমলিংক যাচাই করুন যে সব شيء কাজ করে — দুটো প্রেক্ষাপটের মধ্যে:

# Shell interactif (votre terminal)
gh --version && java -version && node --version
# Shell non-interactif (simulation OpenCode)
zsh -c 'gh --version && java -version && node --version'

উভয়কে সফল হতে হবে। যদি হ্যাঁ, তাহলে আপনার AI এজেন্ট আপনার মতো একই টুলগুলো দেখবে। যদি না, ধাপে ধাপে নিরীক্ষনে ফিরিয়ে যান — আপনি সম্ভবত একটি পথ ভুলে গেছেন বা NVM সিমলিঙ্ক আপ-টু-ডেট নেই।

এই পরীক্ষাটি অটোমেটাইজ করুন।এই পরীক্ষাটি আপনার সরঞ্জামগুলোর প্রতিটি আপডেটের পরে চালানোর জন্য একটি হেলথচেক স্ক্রিপ্টে যোগ করুন। Un`zsh -c 'which java && which node && which gh'`CI-এ, এটি আকস্মিক ঘটনাদের বিরুদ্ধে একটি নিশ্চয়তা।
