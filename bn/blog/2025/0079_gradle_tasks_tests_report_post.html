Kotlin DSL এবং buildSrc ব্যবহার করে Gradle কাজের ব্যবস্থা অপ্টিমাইজ করা

Publié le 11 July 2025

বিল্ড কাজের অটোমেশন কোনো সফটওয়্যার প্রকল্পের জন্য অত্যন্ত গুরুত্বপূর্ণ, এবং Gradle, এর Kotlin DSL সহ, অসাধারণ নমনীয়তা প্রদান করে। আমাদের সংলাপের সময়, আমরা বিল্ড লজিককে কেন্দ্রিক ও পুন:ব্যবহারযোগ্য করার উপায় খুঁজে বের করেছি, বিশেষ করে টেস্ট রিপোর্টের জন্য, ব্যবহার করেসকল প্রকল্প, buildSrc, এবং Kotlin-এ কাস্টম টাস্ক.

allprojects` এবং subprojects ব্যবহার করে কনফিগারেশনগুলোকে কেন্দ্রীয় করুন

ব্লকগুলো`allprojects` et `subprojects`আপনার`build.gradle.kts`মূলগুলো মৌলিক আপনার মাল্টি-মডিউল প্রকল্প জুড়ে সাধারণ কনফিগারেশন প্রয়োগ করতে.

*allprojects { …​ }`প্রয়োগ করুন কনফিগারেশন কেমূল প্রকল্প এবং তার সব উপ-প্রকল্পে. একটি সংজ্ঞায়িত করার জন্য উপযুক্ত`group, একটি`version`, অথবা কিছু`repositories`সাধারন. *subprojects { …​ }`কনফিগারেশন প্রয়োগ করুনশুধু উপ-প্রকল্পগুলোরই, মূল প্রকল্প বাদ দেওয়া। উপযুক্ত, মডিউলের জন্য ویژه প্লাগইন প্রয়োগ করার জন্য (como`java ou kotlin-jvm) অথবা আপনার লাইব্রেরির সাধারণ নির্ভরতা.

এটি একটি উদাহরণমূলক উদাহরণ:

// build.gradle.kts (projet racine)
plugins {
    base // Appliqué au projet racine
}

allprojects {
    group = "com.example"
    version = "1.0.0"

    repositories {
        mavenCentral()
    }

    tasks.withType<org.gradle.api.tasks.testing.Test> {
        useJUnitPlatform() // Configuration commune des tests pour tous les projets
    }
}

subprojects {
    apply(plugin = "java")
    apply(plugin = "org.jetbrains.kotlin.jvm")

    dependencies {
        implementation("org.jetbrains.kotlin:kotlin-stdlib-jdk8")
    }

}

\==`buildSrc`বিল্ড লজিকের সুইস আর্মি ছুরি

আপনার কাজের লজিক জটিল হয়ে গেলে অথবা এটি পুনরায় ব্যবহার করতে হলে,buildSrcপছন্দের সমাধান। এটি একটি বিশেষ Gradle মডিউল যা প্রধান বিল্ড স্ক্রিপ্টের আগে কম্পাইল করা হয়, এর ক্লাসসমূহ আপনার বিল্ডের সম্পূর্ণ classpath-এ উপলব্ধ করে।

কেন ব্যবহার`buildSrc`টাস্কগুলো জন্য?

  • পুনরায় ব্যবহারযোগ্যতাএকటి কাজ নির্ধারিত মধ্যে`buildSrc`কোনো বিল্ডের যেকোনো প্রকল্পে প্রয়োগ করা যায়।

  • সংগঠন: বিল্ড কোডকে কেন্দ্রীয় করুন, যা আরও পরিষ্কার ও রক্ষণযোগ্য করে তোলে।

  • টাইপ সেফটি এবং অটো-কম্প্লিশন: কোটলিন কোড এ`buildSrc`কম্পাইল করা হয়, আপনার IDE-র ত্রুটি যাচাই ও স্বয়ংসম্পূর্ণ করার সুবিধা প্রদান করে, উন্নয়ন অভিজ্ঞতাকে উন্নত করে।

\=== প্রবাহ ডায়াগ্রাম`buildSrc`(কোড PlantUML)

সারাংশ প্রতিবেদন টাস্ক গঠন

পরীক্ষা প্রতিবেদন পরিচালনা করতে, আমরা একটি মডিউলার পদ্ধতি ডিজাইন করেছি একটি অ্যাবস্ট্রাক্ট টাস্ক ক্লাস ব্যবহার করে এতে`buildSrc`. আপনার প্রয়োজনের উপর নির্ভর করে, এই শ্রেণি উত্তরাধিকার পেতে পারে`DefaultTask` ou de Exec.

\=== অবস্ট্রাক্ট টাস্ক`OpenTestReportTask`(উত্তরাধিকারী`DefaultTask`)

এই পদ্ধতি সুপারিশ করা হয়, যদি আপনি কটলিনের কাস্টম লজিক প্রয়োজন হয় যা ফাইল সিস্টেমের বা Gradle-এর অন্যান্য API-এর সাথে tươngодей করে, তারপর একটি বাহ্যিক কমান্ড চালানোর জন্য।

[source,kotlin]

package com.yourpackage

import org.gradle.api.DefaultTask import org.gradle.api.tasks.Input import org.gradle.api.tasks.TaskAction import java.io.File

অ্যাবস্ট্র্যাক্ট ক্লাস OpenTestReportTask : DefaultTask() {

----
----
init {
    group = "verification"
    description = "Opens a test report in Firefox."
    dependsOn("check") // Assure que les rapports sont générés
}

@get:Input
abstract var reportPath: String

@TaskAction
fun openReport() {
    val separator = File.separator
    val reportFile = project.layout.projectDirectory.asFile.toPath()
        .resolve(reportPath.replace("/", separator))
        .toAbsolutePath()
        .toFile()

    if (!reportFile.exists()) {
        logger.warn("Report file does not exist: $reportFile. Ensure 'check' ran.")
        return
    }

    project.exec {
        commandLine("firefox", "--new-tab", reportFile.absolutePath)
    }
    logger.lifecycle("Opened test report: ${reportFile.absolutePath}")
}
----

## }

\== কাজের দৃশ্যমানতা`buildSrc`

আপনি যে কাজগুলো ও ক্লাসগুলো সংজ্ঞায়িত করেন**buildSrc**আছেন :

***দृশ্যমান ও ব্যবহারযোগ্য**আপনার মূল বিল্ডের (মূল ও উপ-প্রকল্প) সব প্রকল্পের দ্বারা। এজন্য আপনি ব্যবহার করতে পারেন`com.yourpackage.ReportUnitTestsTask`মধ্যে`allprojects { ... }`. * **অন-এক্সিকিউটেবল**সরাসরি buildSrc-এর কর্মেরূপে (উদাহরণস্বরূপ,`gradle :buildSrc:reportTests`�যদি কাজটি নির্দিষ্টভাবে রেকর্ড করা না হলে, এটি কাজ করবে না`buildSrc/build.gradle.kts`).`buildSrc`এটি একটি কম্পাইলেশন মডিউল, একটি এক্সিকিউটেবল অ্যাপ্লিকেশন মডিউল নয় এই বিল্ডের প্রধান কাজের জন্য।

\=== একটি প্রতিবেদন চালু করুন পরীক্ষার জন্য`buildSrc`তানেই

Si `buildSrc`এনার নিজস্ব পরীক্ষা আছে এবং রিপোর্ট তৈরি করে, আপনি রিপোর্টের কাজটি সরাসরি মধ্যে`buildSrc/build.gradle.kts`:

## [source,kotlin]

প্লাগইন { `kotlin-jvm` }

রিপোজিটরি { mavenCentral() }

tasks.withType\<Test\> { useJUnitPlatform() reports.html.outputLocation.set(layout.buildDirectory.dir("reports/tests")) }

import com.yourpackage.ReportJbakeTestsTask // আপনার টাস্ক ক্লাস আমদানি করুন

tasks.register\<ReportJbakeTestsTask\>("reportBuildSrcTests") { // Le chemin est déjà défini dans la classe, il pointera vers les rapports de buildSrc }

আপনি তারপর এটি চালু করতে পারবেন :`./gradlew :buildSrc:test`এর পরে`./gradlew :buildSrc:reportBuildSrcTests`.

এই অনুশীলনগুলো গ্রহণ করে, আপনি Kotlin DSL-এ Gradle বিল্ড সিস্টেম তৈরি করবেন, যা শুধুমাত্র শক্তিশালী নয়, বরং অসাধারণভাবে মডুলার, রক্ষণযোগ্য এবং বোঝার জন্য সহজও।
