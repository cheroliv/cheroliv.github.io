Compartimentación Epistémica Automatizada — Cómo el LLM protege mi Jardín Mental

Publié le 02 May 2026

Table des matières

  • El Patrón STIMULUS — Nacer, Fijar, Diluir, Morir

tiempo de lectura: 10 minutes

Mi LLM no se limita a ejecutar mis tareas Gradle. Es el guardián de la frontera entre mi pensamiento privado y mi expresión pública. Cada idea se clasifica — Visión, Opinión, Estrategia — antes de ser dirigida. Aquí está cómo este compartimentaje epistémico automatizado protege mi jardín mental sin silenciarme.

El Problema: Pensar libremente sin publicar nada

Cuando un desarrollador solo documenta su proceso de pensamiento con un LLM, se topa con un paradoje:

CAPTURE TOUT (Cercle 0, jardin secret)
  ├→ Brain dump libre, pas de censure
  ├→ Idées brutes, spéculations, intuitions non vérifiées
  ├→ Allers-retours LLM : challenger, itérer, raffiner
  └→ Le LLM voit TOUT — le bon, le flou, l'embryonnaire

PUBLICATION SÉLECTIVE (Cercle 4, blog public)
  ├→ Uniquement les décisions actées
  ├→ Uniquement les patterns testés (>100 tests PASS)
  ├→ Uniquement ce qui a de la valeur pour le lecteur
  └→ JAMAIS une spéculation présentée comme une vérité

Entre estos dos extremos, hay unfiltro. La pregunta es: ¿quién lo hace? ¿Un humano cansado al final de la sesión? ¿Un script de regex ingenuo? ¿O el LLM mismo, que ya lo ha leído todo?

Mi respuesta: el LLM.

El Patrón STIMULUS — Nacer, Fijar, Diluir, Morir

El estímulo es un archivo`.adoc`temporal en la raíz del workspace (Círculo 0). Su nombre sigue una convención evocativa —PICTURE_ME_ROLLIN.adoc, HOLD_MY_BEER.adoc, ONCE_UPON_A_TIME.adoc— que captura la intención exploratoria del momento.

Su ciclo de vida es despiadado :

CRÉATION (Cercle 0)
  ├→ Fichier vide, brain dump libre
  ├→ Allers-retours LLM ← → développeur
  └→ Aucune pression de structure ou de publication

MATURATION
  ├→ Le contenu se densifie
  ├→ Des sections émergent naturellement
  └→ Le fichier devient une référence informelle de session

CLASSIFICATION ÉPISTÉMIQUE ← FAIT PAR LE LLM
  ├→ VISION    → publiable, diluer dans les docs publics + blog
  ├→ OPINION   → confiner au Cercle 0, pas de dilution externe
  └→ STRATÉGIE → dilution restreinte (docs racine, PAS de blog)

DILUTION (Cascade vers Cercles légitimes)
  ├→ VISION → WORKSPACE_AS_PRODUCT.adoc + WHAT_THE_GAMES.adoc + blog
  ├→ STRATÉGIE → WORKSPACE_AS_PRODUCT.adoc (section business)
  └→ OPINION → reste dans le stimulus, ne bouge pas

ARCHIVAGE + SUPPRESSION
  ├→ Snapshot dans configuration/vision-archive/ (trace historique)
  └→ rm du stimulus — il a fini son travail

Un estímulo que sobrevive más de 2 sesiones sin dilución es un anti-patrón. O bien la información es demasiado importante para pudrirse en un archivo temporal (→ diluer), o bien es demasiado vaga para merecer existir (→ supprimer).

La delegación al LLM: Por qué es el LLM quien filtra

No hardcodeo la clasificación Visión/Opinión en Kotlin. Lo inyecto en elprompt del sistemadel LLM via`AGENT_GOVERNANCE.adoc`:

----
----
Pour chaque dilution de stimulus ou session, tu es responsable de classifier
le contenu :
- VISION : décision architecturale actée, pattern testé en production (>100 tests PASS),
  décision documentée dans BACKLOG ou ROADMAP
- OPINION : spéculation, hypothèse non validée par des tests, intuition
  sans ancrage expérimental
- STRATEGIE : positionnement business, pricing, marché cible

Règles :
- Si OPINION, le contenu reste confiné dans son cercle d'origine
- Si VISION, tu procèdes à la dilution dans les documents racine
- Si STRATEGIE, dilution restreinte (docs racine, pas de blog public)
- Cette classification détermine aussi si un article de blog est publiable
  sur cheroliv.com
----

El LLM lee esta directiva**antes**de tratar la sesión. Está en su contexto inmediato, no en un archivo separado. Es *prompt engineering determinista*: el comportamiento surge del texto inyectado, no de un clasificador externo.

=== ¿Por qué funciona — y por qué es contraintuitivo?

La reacción estándar: « ¿Confías la clasificación a la IA? ¿Y si se equivoca?

Respuesta: el ser humano no lo hace mejor a las 2 a.m. La diferencia es que el LLM, él, lo lee TODO. Tiene el contexto completo de la sesión y de los documentos objetivo. Sabe que`VPS ECO-16 12€ HT`es una decisión de infraestructura (VISION) mientras que`« le TTS ElevenLabs sonne plus naturel que Coqui »`es una opinión no verificada por un benchmark.

El ser humano, al final de la sesión, lee en diagonal y hace lo mejor que puede. El LLM lee exhaustivamente y aplica una cuadrícula sistemática. El resultado es**más fiable**, ni menos.

Y para el 20% de casos ambigüos — la zona gris donde incluso el LLM duda — la respuesta no es « agregar código ». La respuesta es**LangGraph4j**(EPIC 13): un grafo de estado que, para los casos ambiguos, activa un nodo Human-in-the-Loop y remite al humano para la decisión. Pero para el 80% de los casos claros, el LLM basta.

== El Tubo Completo: del Brain Dump al Blog Post

Aquí está el flujo completo — desde la idea bruta hasta el artículo publicado — con el LLM como único filtro :

[source]
----
CERCLE 0 (jardin secret)
  PICTURE_ME_ROLLIN.adoc   ← brain dump, allers-retours LLM
       ↓
  [LLM classifie] → VISION / OPINION / STRATÉGIE
       ↓
  VISION → dilution dans WORKSPACE_AS_PRODUCT.adoc
         → dilution dans WHAT_THE_GAMES_BEEN_MISSING.adoc
         → dilution dans WORKSPACE_VISION.adoc (session context)
         → RÉDACTION ARTICLE BLOG ← le LLM écrit, pas le dev
       ↓
CERCLE 4 (blog public)
  0116_compartimentage_epistemique.adoc  ← publié sur cheroliv.com
       ↓
  ./gradlew deploy (bakery-gradle → JBake → JGit → GitHub Pages)
       ↓
  https://cheroliv.com/blog/2026/0116/  ← live
----

El desarrollador no escribe el artículo. Él desafía, revisa, valida. El LLM escribe. El bucle es:

1. Volcado libre → sin censura
2. Clasificación epistemológica por el LLM → sin fuga
3. Redacción por el LLM → sin procrastinación
4. Revisión humana → sin error

El cuello de botella histórico — « no tengo tiempo para escribir » — se ha eliminado. El LLM hace la mayor parte del trabajo. El ser humano hace lo que solo el ser humano puede hacer: juzgar.

== Los Tres Documentos Raíz — Cómo La Información Encuentra Su Lugar

Cada documento objetivo tiene un papel específico en la cascada de dilución :

[cols="1,3,2"]
|===
|Documento |Lo que recibe |Tipo de contenido |`WORKSPACE_AS_PRODUCT.adoc` |Decisiones arquitectónicas, stack técnico, hoja de ruta, modelo de negocio |VISIÓN + ESTRATEGIA |`WHAT_THE_GAMES_BEEN_MISSING.adoc` |Patrones, lecciones, anti-patrones, ontología, reglas formales |VISIÓN (patrones probados) |`WORKSPACE_VISION.adoc` |Contexto de la sesión, historial de decisiones, puntos de infraestructura |VISIÓN + ESTRATEGIA (contexto) |`AGENT_GOVERNANCE.adoc` |Reglas de gobierno, cartera de proyectos, procedimientos |VISIÓN (gobernanza) |**Blog cheroliv.com** |Artículos públicos, valor para el lector externo |Visión únicamente
|===

Un mismo estímulo puede nutrir los 4 documentos + el blog — cada destino recibe la parte que le corresponde, sin redundancia, sin contradicción.

Es lo que pasó para`PICTURE_ME_ROLLIN.adoc`(3 mayo 2026) :

| Información | Clasificación | Destinos | | Inventario de los 13+ proyectos foundry/ | VISION | WORKSPACE_AS_PRODUCT | | VPS-2 OVH, edster.cloud, 8.49€/mes | VISION | WORKSPACE_AS_PRODUCT + WORKSPACE_VISION | | « El mercado africano está listo para el mobile money » | estrategia | WORKSPACE_AS_PRODUCT (section business) | | « DeepSeek > Kimi > GLM para contexto largo » | OPINION → VISION | Confinado y luego promovido tras benchmark (artículo 0112) | | Empleado sintético como producto final | Estrategia | WORKSPACE_AS_PRODUCT (sin blog) |

== El patrón Baby-Step + TestContainer + Doc Vivante — el Código que se prueba a sí mismo

El patrón STIMULUS/Dilution gestiona el pensamiento. Su equivalente para el código es el patrón Baby-Step/TestContainer/Doc Vivante, validado por plantuml-gradle (380/380 tests PASS, 137 sesiones sin fuga Docker) :

[cols="1,3"]
|===
|Principio |Regla |**paso de bebé** |Nunca más de 3 puntos por US. Si una US da miedo, dividir. Una US de 1 punto que pasa > una US de 8 puntos que se arrastra. |**TestContainer primero** |Antes del código de negocio, el contenedor. La prueba de infra pasa → entorno estable garantizado. |**Dataset comité** |Subconjunto mínimo pero representativo en`src/test/resources/`, sin PII. Clonable, lanzable. |**Documentación viva** |Cada test de Cucumber = una frase en lenguaje natural. El código fuente ES la spec ejecutable. Cero doc Markdown que mantener. |**Limpieza automática** |Cero fugas de recursos. Contenedores huérfanos,`/tmp/gradle-test-*`: todo está limpio.
|===

Este patrón es la razón por la cual plantuml-gradle nunca ha tenido una regresión de Docker en 138 sesiones. Garantiza que el código que habla con una infraestructura externa (PostgreSQL, Redis, Kafka) siempre se prueba en un entorno idéntico al de producción — versionado, reproducible, ejecutable con un solo comando.

== Conclusión: la Libertad de Pensar sin el Miedo de Publicar

La compartimentación epistémica automatizada no es una herramienta de censura. Es un**liberador**. Le permite pensar libremente, especular sin filtro, hacer un brain-dump de todo lo que pasa por la cabeza — sin nunca temer que una idea embrionaria termine en el blog.

El LLM es el guardián de esta frontera. Lee todo. Clasifica. Diluye lo que merece sobrevivir. Confina lo que debe permanecer privado. Redacta lo que es publicable.

Y el desarrollador, él, tiene la última palabra: revisar, desafiar, validar. Juzgar.

Era la división del trabajo lo que le faltaba al desarrollador solo: un empleado sintético que gestiona la papelada mental, para que el humano pueda concentrarse en lo que hace mejor — concebir, arquitectar, decidir.
